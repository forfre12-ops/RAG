# 고객사 시험 원고의 문체·주제 교차 작성 명세 0.1

2026-09-15. 내부 합성 원고 작성·진단 명세이며 고객 정책 승인이나 학습/평가 배포 허가가 아니다.
정책은 [가이드 기반 내부 참조 0.1](CUSTOMER_GUIDE_REFERENCE_V0_1.md)을 유지한다.
현재 조건부 참조 164개를 수정하거나 새 등급으로 재라벨하지 않는다.

## 1. 해결할 문제와 판단 원칙

등급 판단에 필요한 사실과 무관한 말투·형식·업무 주제가 정답을 대신 알려주지 않도록 작성한다.
단, 본문에 정당한 내용 신호가 있을 수 있으므로 **문자 분류기 점수를 낮추는 것 자체가 목표가 아니다.**
사실 단어 삭제, 조건·비용 조작, 오답 부여로 낮춘 점수는 품질 개선이 아니다.

이번 [짝지은 문체 실험](CUSTOMER_GUIDE_STYLE_AUDIT_RESULT_2026-09-15.md)은 제한된 종결어 변환만으로도
같은 진단 분류기의 예측이 바뀜을 확인했다. 두 말투를 함께 적합하면 민감도가 줄었으나 남아 있다.
주제 편향·전체 의미 독립성·장문 처리·고객 모델 성능은 이 실험으로 해결하지 않았다.

## 2. 작성 순서와 분리해야 할 항목

1. 먼저 실제 업무 형태의 정보 내용을 집필한다. 주장, 수치, 비교 대상, 시점, 예외와 적용 범위를 명시한다.
2. 합성 공개 상태·직접 귀속 투입·관리 조치를 별도 맥락으로 작성한다. 실제 관측 사실처럼 표시하지 않는다.
3. 고정 정책으로 조건부 답을 산출하고 근거 위치·상하위 배제 이유를 결합한다. 정보가 부족하면 HOLD다.
4. 등급과 별개로 말투·형식·분야를 배정한다. 한 등급에만 특정 종결어·템플릿·주제가 몰리는지 집계한다.
5. 문체 변형은 진단 뷰로 별도 보관한다. 동일 사실의 말투만 다른 사본은 신규 문서 수에 더하지 않는다.
6. 사실/산술/근거 검산, 원본 보존, 중복과 계열 검사를 통과한 원고만 제작 후보에 남긴다.

본문 입력에는 등급, S/V/M 점수, 규칙 번호, 정답 해설, 문서 계열·문체 태그를 넣지 않는다.
정책에 필요한 공개/접근 등 사실 맥락은 정당한 입력이며 답안 필드와 구별한다.
`unknown`은 false/0이 아니다. 비용은 전체 사업비·매출·자산이 아니라 해당 정보 취득에 직접 귀속된 투입이다.
S3는 외부 공개 허가가 아니다. 외부 검수자 확보를 내부 합성 답안 작성의 선행조건으로 삼지 않는다.
이 자체 작성 답안이 고객 실제 등급·서명·공인 GOLD라는 뜻도 아니다.

## 3. 다음 소규모 집필: 32개 슬롯, 아직 원고 0개

먼저 아래 분야별 평서체 4개/정중체 4개, 총 32개를 서로 다른 내용으로 작성한다.
각 4개 묶음은 네 등급의 근거 있는 사례를 고루 담는 **작성 목표**이며 자동 배정된 정답이 아니다.
정책상 해당 등급이 나오지 않으면 사실을 바꾸지 말고 부족 슬롯으로 남기거나 다른 독립 사례를 집필한다.

| 분야 | 평서체 목표 | 정중체 목표 | 별도로 다룰 내용 예시 |
| --- | ---: | ---: | --- |
| 측정·실험 | 4 | 4 | 측정 조건, 실패 조건, 관측과 해석의 구분 |
| 소프트웨어·시스템 | 4 | 4 | 재현 절차, 설정 비교, 장애 범위 |
| 영업·거래·조사 | 4 | 4 | 표본/집계 범위, 거래 조건, 조사 한계 |
| 운영·물류·시설 | 4 | 4 | 순서/예외, 인수인계, 자원 배치 |

같은 분야에서도 등급마다 고정적인 형식을 배정하지 않는다. 예를 들어 정중체의 기술 절차와 평서체의 일반 안내도 작성한다.
같은 소재의 숫자·제목만 바꾼 사례를 8개로 세지 않는다. 독립된 업무 내용인지 근거를 기록한다.
장문 흉내를 위해 무관한 문장을 붙이지 않는다. 장문 파일은 먼저 입력 길이·근거 보존 계약을 정한 뒤 별도 진행한다.
32개 슬롯은 현재 164개/부족 836개 집계에 포함하지 않는다.

## 4. 변형 뷰의 허용 범위

현재 도구는 전체 단어 단위로 사전에 작성한 종결어 쌍과 제한된 숫자 단위 서술어만 변환한다.
`한다/합니다`, `아니다/아닙니다` 등의 대응이며 임의 접미사 치환이나 LLM 재작성은 아니다.
제목, 숫자열, 부정·조건, 요청형 `주세요`, 단편·표제, 본문 이외 맥락은 보존한다.
미등록 종결어는 자동 추측하지 않고 실패 처리한다. 주장 경계 안의 단어 일부를 자르는 변경도 거절한다.
근거 인용문·오프셋·본문 해시는 변형 뷰에 맞춰 재결합하고 원본 답안 해시를 연결한다.

자동 검사는 화용적 뉘앙스까지 포함한 전체 의미 동등성 인증이 아니다.
`whole_semantic_equivalence_certified=false`를 유지한다. 이번 변환 가능 범위를 새 문장에 무조건 확대하지 않는다.
원문과 동일한 뷰도 대조군으로 명시하며 실제 변경 건수와 분리한다.

## 5. 비교 실험과 분할

동일 원문 집합, 정책, 라벨, seed, 부모/계열 fold에서 세 군을 비교한다.

| 군 | 학습 fold 안에서만 사용하는 뷰 | 목적 |
| --- | --- | --- |
| 원문 | 부모당 원문 1개 | 기존 기준점 |
| 복제 대조 | 모든 부모의 원문 2개, 각각 가중치 0.5 | 단순 복제 효과 확인 |
| 문체 균형 | 대상 부모는 두 말투, 나머지는 원문 2개, 각각 0.5 | 복제 대조와 같은 행 수/부모 가중치에서 문체 효과 확인 |

단어 사전·IDF는 각 학습 fold 안에서만 적합한다. 변형본은 부모 및 연결된 의미 계열과 같은 fold에 둔다.
같은 부모의 다른 말투가 학습/검증에 걸쳐 들어가는 행 단위 무작위 분할을 금지한다.
개별 seed의 결과와 모든 부모별 예측을 보관한다. 반복 seed·변형 수를 독립 문서 수로 계산하지 않는다.

필수 보고: 원문 대비 변경 수, 원문 정답→변형 오답/역방향, 평서↔정중 불일치, 등급별 변경,
본문/본문+맥락 각각의 조건부 참조 일치도, 분모, 중복/계열 범위, 악화된 지표, 미해결 한계.
본문만으로 식별 불가능한 조건부 라벨에 대한 일치도는 고객 정확도가 아니다.
고객 모델에서는 별도로 S1↔S2, S2→S3, TS/S1→S3, S3 과분류와 검토 라우팅을 평가해야 한다.

## 6. 최종 200개를 보존하는 규칙

현재 164개는 이미 여러 진단기의 적합·교차검증·작성 방향 선택에 활용됐다.
따라서 이 164개를 나중에 무작위로 뽑아 **미노출 최종 블라인드 200개**라고 부르면 안 된다.
현재 파일의 배포 플래그나 분할은 바꾸지 않으며, 이후 채택 시 개발/학습 측 후보로만 취급한다.

최종 200개는 새 독립 계열에서 별도 제작해 시험 전에 봉인한다. 작성 계약·채점 기준·모델 선택 절차를 먼저 고정한다.
봉인 전 구조/산술/근거 검증은 허용하되 그 200개의 모델 예측을 이용한 원고 선별·프롬프트/모델 조정을 금지한다.
제작자가 답안을 만드는 것과 그 답안을 보고 모델을 조정하는 것은 별개다. 테스트 답안은 학습 입력과 분리한다.
봉인 뒤 결함 발견 시 이유와 영향을 남기고 시험 버전을 변경한다. 점수가 낮은 사례만 교체하지 않는다.
학습 800/평가 200, 등급별 200/50 목표는 유지하되 계열 전체를 함께 배정한다.

## 7. 완료 기준과 남은 작업

이번 완료: 원본 보존형 제한적 문체 변형, 짝지은 세 군 진단, 복제 대조, 반복/계열 누설 방지 테스트와 결과 기록.
다음: 32개 교차 집필 → 사실/산술/문체 검산 → 의미 계열 후보 확장 → 같은 진단으로 효과와 부작용 확인.
그다음 부족 원고 확장, 본문+맥락 시험 입력 연결·장문 계약, 계열 분리 및 새 최종 200개 봉인으로 진행한다.
문체 지표의 합격 수치를 사후에 만들지 않는다. 현재 결과는 개선 방향 근거이며 출시 합격 기준이 아니다.
운영 API·등급 공식·검수 경로·생산 모델 변경과 학습/평가 배포는 별도 단계로 남긴다.
