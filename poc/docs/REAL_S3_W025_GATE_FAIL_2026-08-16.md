# 가중치 0.25 도 FAIL — 가중치 조절로는 안 풀린다

작성 2026-08-16. `REAL_S3_GATE_FAIL_2026-08-16.md`(가중치 0.5) 의 후속이다.
채택 기준은 `REAL_S3_ADOPTION_CRITERIA_2026-08-16.md` 에 학습 전에 고정해 둔 것을 썼다.

---

## 1. 두 가중치 비교

```
                     배포본     w0.5      w0.25
S3 학습 신호 비중       -       43.4%     27.7%
공개문서 과분류       0.0400    0.0125    0.0150     <- 효과는 유지된다
axis1 고→S3 미탐        0         5         4
axis3 고→S3 미탐        1         7         7        <- 전혀 안 줄었다
axis1 S1 재현율       0.857     0.643     0.714
axis1 f1_macro        0.917     0.809     0.834
OVERALL               기준선     FAIL      FAIL
```

---

## 2. 이것이 말해주는 것 — 가중치가 원인이 아니다

**가중치를 절반으로 낮췄는데 안전 대가가 거의 안 줄었다.**

```
axis1 미탐   5 -> 4     1건만 개선
axis3 미탐   7 -> 7     변화 없음
```

반면 효과는 거의 그대로다(과분류 0.0125 -> 0.0150, 배포본 0.0400 보다 여전히 훨씬 낮음).

**더 낮추면 효과만 사라지고 미탐은 남을 가능성이 크다.** 0.1 을 시도할 이유가 약하다.

원인은 가중치가 아니라 **데이터 구성**이다. S3 만 600건을 넣으면 등급 균형이 깨지고,
그 영향은 가중치로 상쇄되지 않는다.

---

## 3. 봉인 400건은 이번에도 쓰지 않았다

채택 기준 §1 이 "안전 - 하나라도 어기면 탈락" 이다. 두 후보 모두 안전에서 탈락했으므로
효과를 재지 않았다. 봉인셋은 무결하다(sha256 `e04d07fa850d401231ac40e0...`).

⚠ 이것이 규율의 값이다. 만약 봉인셋으로 두 후보를 비교했다면 **봉인셋에 맞춰 고르는 것**이
  되고, 그 뒤로 그 셋은 판정면이 아니게 된다.

---

## 4. 다음에 시도한다면 — 가중치 말고

```
S3 를 줄이고 등급을 균형있게      TS·S1 실문서가 없어 지금은 불가
등급별 손실 가중 조정              S3 쪽 가중을 학습 손실에서 낮춘다(데이터가 아니라 손실)
2단계 분류                        S3/비-S3 를 먼저 나누고 세부 등급을 뒤에
서식을 학습이 아니라 규칙으로       "공개 배포 양식" 을 출처 prior 로 처리
```

**마지막 것이 가장 현실적으로 보인다.** 서식은 출처가 정답을 보증하므로, 학습으로 배우게
하는 대신 `source_type` 같은 메타데이터로 처리하면 등급 균형을 안 건드린다.

⚠ 다만 그것은 "공개 양식인지" 를 판별하는 문제로 옮기는 것이지 없애는 것이 아니다.

```
그 대가로 위험 미탐이 는다                 axis3 기준 1 -> 7 (가중치 무관)
가중치 조절(0.5 -> 0.25)로는 안 풀린다
현행 배포본 v-fe4b386b 를 유지한다
```

## 6. 곁가지 — cp949 사고가 또 났다

axis2 실행부에 `text=True` 만 주었더니 Windows 가 cp949 로 디코드하려다 죽었다
(자식 프로세스는 utf-8 을 낸다). 판정에는 영향이 없었지만(axis2 는 PASS 로 나옴)
오류 메시지를 잃는다. `encoding="utf-8", errors="replace"` 로 고쳤다.

**오늘 네 번째 cp949 사고다.** 출력만이 아니라 **입력(서브프로세스 읽기)** 도 같은 함정이
있다는 것이 이번에 드러났다.

---

## 7. 원인 진단 — 뒤집힌 문서를 열어 봤다

게이트는 '몇 건' 만 알려준다. 왜 그런지는 문서를 봐야 안다.

### 뒤집힌 문서

```
경화 홀드아웃 (151~189자)
  [TS] S1 -> S3   Non-public acquisition valuation memo
  [TS] TS -> S3   Internal API credential rotation plan
  [S1] S1 -> S3   Patent license negotiation draft
  [S1] S1 -> S3   Vendor negotiation status note

적대 셋 (16~34자)
  [S1] S2 -> S3   이사회 의사록 (확정·서명본)
  [TS] S2 -> S3   이사회 의사록 (M&A 결정·미공시)
  [TS] S2 -> S3   M&A 후보 기업 디스커션 메모 (예비)
  [S1] S2 -> S3   M&A 사후 통합 PMI 계획 (공개 발표 후)
  [TS] S2 -> S3   내부 신고 사례 (피신고자 포함)
  [S2] S2 -> S3   신용평가 결과 (외부 기관 평가본)
```

### 길이 가설은 틀렸다

```
뒤집힌 문서   중앙 174자 (151~189)
유지된 문서   중앙 182자 (154~317)
```

거의 같다. 길이로 갈린 것이 아니다.

### 진짜 원인 — 문서 **종류**가 겹친다

뒤집힌 문서의 종류를 보면 학습에 넣은 서식과 정확히 겹친다.

```
인수 가치평가 메모   <- 서식모음의 '인수계약서' 양식
특허 라이선스 협상   <- '라이선스 계약서' 양식
공급사 협상 현황     <- '거래계약서' 양식
이사회 의사록       <- '이사회 의사록' 양식
신용평가 결과       <- '신용조사 의뢰서' 양식
```

모델이 배운 것은 **"이 종류 문서는 S3"** 다. 그런데 실제 영업비밀 문서도 같은 이름·같은
형식을 쓴다. 빈 "이사회 의사록" 양식과 M&A 결정이 적힌 진짜 "이사회 의사록" 은 제목이
같고 형식이 같다. 다른 것은 **내용에 실제 비밀이 있느냐**뿐이다.

### 그래서 가중치로 안 풀렸다

신호 세기의 문제가 아니라 **모델이 배운 개념이 두 등급에 걸쳐 있기 때문**이다.
0.5 든 0.25 든 "이 종류는 S3" 라는 방향은 같다.

### 근본 문제 — 짝이 없다

```
우리가 준 것   빈 '이사회 의사록' 양식      -> S3
없는 것        채워진 '이사회 의사록'       -> TS
```

**한쪽만 주면 "이 종류 = S3" 를 배운다.** 짝이 있어야 "빈 것과 채워진 것이 다르다" 를
배운다. 그리고 채워진 진짜 문서가 바로 우리가 못 구하는 것이다.

### 유력한 대안 — 학습이 아니라 출처로

```
학습으로 배우게 하면   "이 종류는 S3" 를 배운다  -> 진짜 비밀도 S3
메타데이터로 주면     "이 문서는 공개 양식" 이라는 사실만 전달 -> 종류를 오염 안 시킴
```

배관은 이미 있다 - `source_type=public` 이면 S3 로 cap 된다(pipeline Gate-1).
**서식 업로드 시 출처를 표시하면 학습 없이 해결된다.**

⚠ 다만 이것은 "공개 양식인지 누가 판별하는가" 로 문제를 옮기는 것이다. 회원사가 문서를
  올릴 때 그 표시를 해 줄 것인지가 전제다 - EDMS 메타데이터 요청과 같은 성질의 의존이다.
