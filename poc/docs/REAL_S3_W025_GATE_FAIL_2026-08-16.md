# 가중치 0.25 도 FAIL — 가중치 조절로는 안 풀린다

작성 2026-08-16. `REAL_S3_GATE_FAIL_2026-08-16.md`(가중치 0.5) 의 후속이다.
채택 기준은 `REAL_S3_ADOPTION_CRITERIA_2026-08-16.md` 에 학습 전에 고정해 둔 것을 썼다.

---

## 1. 두 가중치 비교

```
                     배포본     w0.5      w0.25
S3 학습 신호 비중       -       43.4%     27.7%
공개문서 과분류       0.0400    0.0125    0.0150     <- 효과는 유지된다
axis1 고→S3 미탐        0         5         4
axis3 고→S3 미탐        1         7         7        <- 전혀 안 줄었다
axis1 S1 재현율       0.857     0.643     0.714
axis1 f1_macro        0.917     0.809     0.834
OVERALL               기준선     FAIL      FAIL
```

---

## 2. 이것이 말해주는 것 — 가중치가 원인이 아니다

**가중치를 절반으로 낮췄는데 안전 대가가 거의 안 줄었다.**

```
axis1 미탐   5 -> 4     1건만 개선
axis3 미탐   7 -> 7     변화 없음
```

반면 효과는 거의 그대로다(과분류 0.0125 -> 0.0150, 배포본 0.0400 보다 여전히 훨씬 낮음).

**더 낮추면 효과만 사라지고 미탐은 남을 가능성이 크다.** 0.1 을 시도할 이유가 약하다.

원인은 가중치가 아니라 **데이터 구성**이다. S3 만 600건을 넣으면 등급 균형이 깨지고,
그 영향은 가중치로 상쇄되지 않는다.

---

## 3. 봉인 400건은 이번에도 쓰지 않았다

채택 기준 §1 이 "안전 - 하나라도 어기면 탈락" 이다. 두 후보 모두 안전에서 탈락했으므로
효과를 재지 않았다. 봉인셋은 무결하다(sha256 `e04d07fa850d401231ac40e0...`).

⚠ 이것이 규율의 값이다. 만약 봉인셋으로 두 후보를 비교했다면 **봉인셋에 맞춰 고르는 것**이
  되고, 그 뒤로 그 셋은 판정면이 아니게 된다.

---

## 4. 다음에 시도한다면 — 가중치 말고

```
S3 를 줄이고 등급을 균형있게      TS·S1 실문서가 없어 지금은 불가
등급별 손실 가중 조정              S3 쪽 가중을 학습 손실에서 낮춘다(데이터가 아니라 손실)
2단계 분류                        S3/비-S3 를 먼저 나누고 세부 등급을 뒤에
서식을 학습이 아니라 규칙으로       "공개 배포 양식" 을 출처 prior 로 처리
```

**마지막 것이 가장 현실적으로 보인다.** 서식은 출처가 정답을 보증하므로, 학습으로 배우게
하는 대신 `source_type` 같은 메타데이터로 처리하면 등급 균형을 안 건드린다.

⚠ 다만 그것은 "공개 양식인지" 를 판별하는 문제로 옮기는 것이지 없애는 것이 아니다.

## 6. 곁가지 — cp949 사고가 또 났다

axis2 실행부에 `text=True` 만 주었더니 Windows 가 cp949 로 디코드하려다 죽었다
(자식 프로세스는 utf-8 을 낸다). 판정에는 영향이 없었지만(axis2 는 PASS 로 나옴)
오류 메시지를 잃는다. `encoding="utf-8", errors="replace"` 로 고쳤다.

**오늘 네 번째 cp949 사고다.** 출력만이 아니라 **입력(서브프로세스 읽기)** 도 같은 함정이
있다는 것이 이번에 드러났다.
