## 2. 완료 — 시드 결함 수정 (플랜 §1.1)

`expected_factor_scores` 의 `0` 이 proven_absent 와 unknown 을 동시에 뜻해 8건이 두 규칙으로
갈려 있었다. 본문을 열어 판정하니 **0값 4건 전부 부재가 명시적으로 입증**돼 있었고
(`열람 제한을 걸지 않았다` · `선점 효과가 생기지 않는다`), 따라서 raw 규칙이 맞고
**저술자 라벨 2건이 틀린 것**이었다.

```
v8-seed-0005  S2 -> S3
v8-seed-0008  S2 -> S3
```

`v8_factor_labels.py` 로 3상태 스키마를 만들고 등급을 상태에서 파생시켰다. **저술자가 등급을
잘못 적을 자리가 구조적으로 사라졌다.** 산출: `datasets/v8_seed/seed_authored.v2.jsonl`

### 규칙에서 유도된 사실 (설계가 여기 의존한다)

```
27조합 -> 등급     S3 18 · S2 6 · TS 2 · S1 1     균등 표집하면 S3 67% — 금지
인접 경계          18개  S3<->S2 11 · S2<->TS 4 · S3<->S1 2 · S1<->TS 1
S3-입증형 조건     상태만 알 때: secrecy 또는 value 가 proven_absent
                   레벨까지 알 때: management 도 가능 — 단 s 또는 v 가 2 미만 확정 시에만
```

플랜 §3.3 에 "management 단독 불가"라고만 적었는데 좁았다. 레벨을 아는 서빙 시점에는
(1,2,0) -> S3 로 성립한다. 모듈 주석과 assert 로 두 층위를 구분해 뒀다.

## 4. 완료 — tell 감사 (플랜 §3.6)

**생성 직후 감사에서 실패했고, 세 번 고쳐 통과시켰다.** 학습 전에 잡으라고 만든 관문이 실제로
작동했다.

```
                     1차      2차      3차     4차     문턱      v7 달성
길이-only 1NN        0.637    0.323    0.286   0.310   <=0.55    0.378
Theil's U            0.093    0.014    0.013   0.017     -       0.023
tell 문장             4        2        3       0      (커버)     0종
tell 커버리지          0.072    0.049    0.035   0.000  <=0.1     0.000
등급토큰 노출           0        0        0       0       0         0
```

이 시점 규모는 632건이다. 확대와 계보 도입 후 한 번씩 더 샜고 그때마다 고쳤다(§5·§6).

### 세 번의 진단

1. **길이가 고정이었다** — 등급별 길이 분포는 완전히 겹치는데 1NN 이 0.637 이었다. 문서
   길이가 거의 같아 같은 경계·같은 쪽 문서끼리 뭉친 것이다. 분량을 문서마다 흔들되
   등급과 무관한 rng 에서만 뽑게 해 0.323 으로 내렸다.
2. **중립 문장이 unknown 에만 나왔다** — 그 자체가 S3 tell 이 됐다. 상태와 무관하게 35%
   확률로 섞고, `(2,2,None) -> S1` 패턴을 넣어 고등급에도 unknown 이 들어가게 했다.
3. **순환 배정은 오히려 나빴다** — 문장을 슬롯 번호로 순환시키니 tell 이 1종에서 3종으로
   늘었다. S1 은 조합이 하나뿐이라 그 등급 문서가 한 위상에 정렬됐기 때문이다. 무작위로
   되돌리고 **경계를 교대로 생성**하니(한 경계가 연속 슬롯을 차지하지 않게) 0종이 됐다.

3번은 되돌린 변경이라 시도 기록만 남긴다 — 같은 아이디어를 다시 만들지 않도록.

## 5. 완료 — 표현 분리 (v6 가 무너진 지점)

형태만 홀드아웃하면 "미관측 형태"는 검증되지만 "미관측 표현"은 검증되지 않는다. v6 사전등록
문서가 바로 이 분리로 두 가설을 갈랐다 — (A) 문자열→수준을 외웠다 vs (B) 사실→수준을
일반화했다. 학습 손실만으로는 구분할 수 없고, 표현이 분리된 홀드아웃만이 분리 검정이 된다.

문장 풀을 `SPLIT_RATIO=0.6` 으로 갈랐다(앞 60% 학습 · 뒤 40% 홀드아웃). `split_overlap()`
가 교집합을 0 으로 강제한다.

### 최종 상태 — 사전등록 규모로 확대, 두 분할 모두 전 축 통과

```
                   n      길이-only   Theil U   tell    커버      등급토큰
train            2,448     0.381      0.005     0종     0.000       0
holdout_forms    1,536     0.378      0.009     0종     0.000       0

본문 해시 겹침 0건 · 요소 근거문장 겹침 0종 · 각 분할 내부 중복 0건
문턱  tell_coverage <= 0.1 · length_leak <= 0.55      v7 달성 0.000 / 0.378
```

길이는 v7 과 동급, Theil's U 는 4배 좋고, tell 은 v7 과 같다. 등급별 길이 구간이
완전히 겹친다(TS 298~1578 · S1 340~1546 · S2 312~1543 · S3 299~1536).

```
학습    S3 878 · S2 736 · S1 354 · TS 480    고등급 34.0%   형태 406~409 균등
홀드    형태당 768건 — 사전등록 요구치(750) 충족
S3      입증형 643 · 무신호형 235
```

**규모 확대에서 한 번 더 막혔다.** 632 -> 2,448 건으로 늘리자 길이-only 가 0.310 -> 0.434
로 **올랐다.** 분량 값이 `[0,0,1,2,4,7]` 여섯 개뿐이라 문서 길이가 이산적으로 뭉치고,
표본이 커지자 같은 길이 문서가 대량 생겨 1NN 이 그 뭉치를 타고 등급을 맞힌 것이다.
분량을 연속에 가깝게 흩고 섹션마다 다시 뽑게 해 0.381 로 되돌렸다.

교훈: **누출 지표는 표본 크기에 따라 달라진다.** 작은 표본에서 통과했다고 안심하면
확대 후 다시 샌다. 규모를 올릴 때마다 재감사해야 한다.

홀드아웃 tell 은 4종(0.060) -> 1종(0.016) -> 0종으로 두 번 줄였다. 원인은 홀드아웃 몫 풀이
얇았던 것이라 풀 뒤쪽(홀드아웃 구간)을 넓혔다. 판정면은 학습셋보다 엄격해야 한다 —
판정면에 tell 이 있으면 모델이 그것으로 점수를 올리고, 그게 `final_800` 이 못 쓰게 된 경위다.

## 6. 완료 — 저술 계보 3종 (`v8_registers.py`)

생성기가 하나면 문서 전체가 한 사람이 쓴 것처럼 보이고, 문체가 다음 tell 이 된다. 형태와
어휘를 갈라 놨어도 문장 구조·어투가 한 종류면 회원사 문서에서 무너진다.

```
prose   서술형 평서문     공개 자료만으로는 같은 조건 조합을 다시 만들 수 없다.
terse   개조식 명사형     ○ 공개 자료만으로는 같은 조건 조합을 다시 만들 수 없음
field   항목:값 기재형    공개 여부 : 본 문서 전문을 회사 홈페이지 자료실에 게재했음
```

세 계보는 **사실을 바꾸지 않는다.** 같은 근거를 다르게 적을 뿐이라 정답 요소값이 보존되고,
계보를 가로질러 성적이 유지되는지가 곧 "사실을 읽는가"의 검정이 된다.

### 종결어미 표는 계속 샜다 — 종성 규칙으로 일반화

처음에는 `("한다","함")` 식으로 어미를 나열했다. **149종 중 66종이 실패**했다("게재했다",
"옮겼다", "동일하다" 등이 전부 안 걸렸다). 표를 늘려도 계속 새는 구조라 국어의 실제 규칙으로
바꿨다 — 어간 끝에 받침이 있으면 `음`, 없으면 `ㅁ` 을 한글 코드로 합성한다. 불규칙(ㅂ/ㄹ)만
표로 남겼다. 149종 전부 통과했다.

### 두 결함을 실측으로 잡았다

**(1) counterfactual 쌍의 양쪽이 서로 다른 계보를 받고 있었다.** 쌍은 한 요소만 달라야
하는데 문체까지 달라지면 경계 검정이 오염된다. 형태·계보를 **쌍 단위**로 배정하게 고쳤다.

**(2) 슬롯 나머지 배정이 경계 구조와 정렬됐다.** `slot % 6`(형태) · `slot % 3`(계보)로
뽑으니 고등급 경계가 3배 예산을 받는 탓에 위상이 맞아 쏠렸다. 쌍 식별자 해시로 뽑아
경계와 무관하게 만들었다.

```
                    이전      현재
계보-등급 Cramer V   0.1233   0.0233
형태-등급 Cramer V   0.1597   0.0268
쌍 무결성            -        1,024쌍 전부 형태·계보 공유 · 요소차 정확히 1
```

계보 도입 후 재감사(학습 2,448 · 홀드 1,536): tell 0종/0.000 · 길이-only 0.403/0.359 ·
Theil's U 0.005/0.006. 전 축 유지.
