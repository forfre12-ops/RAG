# 근거 공급 항목·조직 경계 대조 v1 — 2026-09-15

상태: 현재 checkout의 **코드 대조와 연동 설계 초안**. 운영 DB/포털/문서관리시스템에는 접속하지 않았다.
필드를 받을 코드가 있다는 것과 실제 자료가 공급된다는 것은 다르다. 아래 실제 공급 확인은 모두 미완료다.
이 문서는 D01~D08을 승인하거나, 새로운 멀티테넌트 배포를 결정하지 않는다.

## 1. 코드에서 확인한 공급 경로

| 항목 | 현재 코드 경로 | 새 계약으로 옮길 때 남은 일 | 필요한 담당 역할 |
|---|---|---|---|
| 조직 ID | API/JWT/Actor/Document에 고객사 격리를 KL 포털이 담당한다는 단일 엔진 전제 | 신뢰할 조직 바인딩의 실제 공급 방식·배포 단위 확인; 요청 문자열을 인증으로 사용 금지 | KL 연동·배포 책임자 |
| 문서 ID | `Document.doc_id`, `external_ref` | 외부 문서 식별자와 내부 ID 대응 확인; external_ref를 판본으로 간주하지 않음 | 문서관리·수집 담당 |
| 문서 판본 | Document에 별도 판본 필드 없음 | 원천 시스템 판본과 추출 작업을 연결; 파일명/업로드 시각을 판본으로 대체하지 않음 | 문서관리 담당 |
| 원본 해시 | ingestion의 `sha256(content_bytes)` → `Document.file_hash` | 실제 저장 바이트 재검산; 공급자가 적은 해시와 실측 해시 구분 | 수집·저장소 담당 |
| 원본 위치 | ingestion의 raw_uri → Document.raw_text_uri | 컬럼명만으로 추출 문자열이라고 판단하지 않고 저장 버킷/객체 실체 대조 | 저장소 담당 |
| 추출 문자열 해시 | `ExtractResult.text`는 있으나 Document에 전용 해시 없음 | 정확한 UTF-8 문자열 해시 생성·보존; normalized 본문/청크 해시와 분리 | 추출 담당 |
| 추출 작업/버전 | method/quality/ocr_used 보유 | 작업 ID·빌드/설정/추출기 버전 공급. method 문자열만으로 재현 가능하다고 보지 않음 | 추출 담당 |
| 회수/전체 페이지 | metadata의 pages_processed/pages_total | 총 페이지 미수신 시 회수 수로 대체하는 기존 처리를 새 완전성 증거로 사용 금지 | 추출 담당 |
| 추출 완전성 | metadata의 extraction_complete | 현재는 일부 경고/페이지 조건에서 계산된 신호. 표·첨부·원본 대조 완료를 뜻하지 않음 | 추출·원문 소유자 |
| 보안표식 | 업로드 form → metadata.security_marking → 분류 요청 결합 | 요청값/보관값/인증된 원천값을 구분하고 원시 값·매핑·수신 시각 결합 | 문서관리 담당 |
| 접근범위 | 업로드 form → metadata.access_scope → 분류 요청 결합 | 실제 유효 ACL의 스냅샷인지 확인; 상속·예외·외부 공유 범위 포함 여부 확인 | 권한관리 담당 |
| 소유조직 | 새 계약은 owner_org를 받음; 확인한 업로드 경로에 전용 공급 없음 | created_by를 소유조직으로 치환하지 않음. 원천 필드/부재 정의 수신 | 문서관리 담당 |
| DLP 라벨 | 새 계약은 dlp_label을 받음; 해당 경로의 전용 공급 미확인 | DLP 제공 범위·판본·시점·라벨 의미 수신 | DLP 담당 |
| 실제 열람 범위 | 새 계약은 actual_reader_scope를 받음; 해당 경로의 전용 공급 미확인 | 의도된 ACL과 실제 열람 기록/범위 정의를 구분. 조회 기간·집계 방식 필요 | 감사·권한관리 담당 |
| 공개 상태 | 기존 source_type 및 본문 출처 추정 경로 존재 | 공개 원문·문서 동일성·공개 범위/시점의 별도 근거 필요. internal은 비공개 증거 아님 | 문서 소유자·검토자 |
| 가치/사업 영향 | 본문 특성·기존 요소 추정과 별개 | 고객사 가치 기준·사업 맥락과 판단 기록 필요. 기술 용어 존재를 가치 확인으로 승격 금지 | 업무·정책 책임자 |
| 수집 시각/만료 | uploaded_at/processed_at 존재 | 원천 ACL 관측 시각과 다름. 근거별 captured_at/valid_until 공급 또는 미수신 표시 | 공급 시스템 담당 |
| 정책·매핑 판본 | 별도 파일형 정책/매핑 모듈 존재 | 승인된 적용 조직/범위·시행 시각·판본 선택과 근거 필요 | 정책 책임자 |

`metadata_`는 확장 가능한 JSON이므로 전용 공급 코드가 없다는 것이 운영 데이터에 절대 없다는 증거는 아니다.
실제 값·빈도·공급 가능 여부는 승인된 스냅샷이나 담당자 회신으로 별도 확인한다.

대조한 코드:

- `src/koipa/api/documents.py`: 업로드 표식/접근범위 및 KL 격리 전제.
- `src/koipa/db/models.py:138`: Document 필드와 전역 file_hash UNIQUE.
- `src/koipa/services/document_ingestion_service.py:210`: 원본 해시/저장/추출, 페이지 수 및 완전성 신호.
- 같은 파일 `:479`: 동일 file_hash 재업로드는 기존 doc_id를 반환하는 경로.
- `src/koipa/services/classify_service.py:1614`: 요청값 우선, 없는 표식/접근범위만 DB에서 결합.
- `src/koipa/api/_jwt_auth.py`, `src/koipa/schemas/common.py`: 인증 actor/role과 조직 경계 구별.

## 2. 수신 값의 권위 구별

| 분류 | 의미 | 이번 허용 |
|---|---|---|
| request_metadata | 요청자가 제출한 값 | 원시 입력/매핑 검토 후보; 실제 ACL 확인 아님 |
| unverified_stored_metadata | DB에서 읽었으나 원천/관측 시점 미검증 | 보관된 주장으로 유지; DB 존재만으로 인증하지 않음 |
| system_export | 제공자가 원천 시스템 내보내기라고 선언한 스냅샷 | 판본/해시/위치 검산; 공급자 인증은 별도 |
| authenticated source receipt — 후속 | 허용된 공급자·조직·문서 범위·판본·신선도 확인을 완료한 수신 이력 | 실제 연결 구현/검증 전에는 생성하지 않음 |

새 매핑 검토기는 앞의 세 유형을 받지만 어느 것도 observed FactPacket으로 내보내지 않는다.
검수 후보에 `approved`가 있어도 입력자의 선언일 뿐 승인 진위가 확인된 것은 아니다.

## 3. 조직 경계 선택안 — 실제 배포 확인 필요

현 소스는 단일 고객사 엔진/상위 KL 격리를 전제로 한다. 공유 엔진의 안전성을 보증하지 않는다.

| 대안 | 얻는 것 | 비용·필수 확인 |
|---|---|---|
| 고객사별 엔진·DB·저장소 분리 + 서버 고정 org 바인딩 | 현 코드의 전역 조회/해시 공간 전제를 유지하기 쉬움 | 실제 배포/라우팅이 분리됐는지 증거 필요. 요청 org와 서버 바인딩 불일치 차단 |
| 여러 고객사가 하나의 엔진/DB 공유 | 배포 자원 공유 | 현재 전역 조회·dedup·저장 키·정책/캐시 선택 전체에 조직 격리 설계와 마이그레이션 필요; 이번 범위 밖 |

확인 전 서버 org 기본값을 임의로 만들지 않는다. 외부 입력 org를 그대로 신뢰하는 서비스 연결도 하지 않는다.
유효한 KL JWT/공유키는 호출 인증이다. 그 결과만으로 고객사 문서 접근 권한까지 검증됐다고 할 수 없다.

후속 경계 검증 목록:

1. 인증 주체와 선택된 엔진/배포 조직의 결합 확인.
2. 요청 조직·문서 판본·매핑 조직·정책 조직 불일치 거절.
3. 교차 조직 doc_id/동일 파일 해시/저장 객체/캐시 재사용 시험.
4. 요청 표식/ACL이 원천 스냅샷을 덮어써 권위를 높이지 않는지 시험.
5. 공급 중단·권한 취소·만료 시 근거 미확인 처리. S3/비공개/공개로 추정하지 않음.

이번 매핑 모듈 테스트는 **제공된 조직 식별자 간 불일치**만 검증한다. 실제 조직 격리/인증 시험이 아니다.

## 4. 담당자에게 받을 최소 회신

실제 사람/시스템/승인 정보는 아직 받지 않았다. 아래 역할 배정은 요청 사항이다.

- KL/배포: 고객사별 배포 여부, 조직 바인딩 공급 방법, 문서 권한 확인 책임.
- 문서관리: 사용 허가된 원시 JSON 예시, 문서 판본, 표식/ACL/소유조직과 부재/미수신 정의.
- 추출: 원본→추출→정규화 이력, 페이지/표/첨부 회수 근거, 추출 버전.
- 정책: 매핑표 원본과 적용 범위·시행일·승인 기록, D01~D05 회신.
- 검수: 실제 문서 사용 목적/보관 범위, 검수 주체와 최종 승인 경로, D06~D08 회신.

회신 상태는 `미수신 / 일부 수신 / 대조 필요 / 대조 완료`로 관리한다. 미수신을 공급 불가로 단정하지 않는다.
인증키·토큰·비밀 원문을 이 문서나 작업 메모에 붙이지 않는다. 승인된 로컬 보관 참조를 사용한다.
