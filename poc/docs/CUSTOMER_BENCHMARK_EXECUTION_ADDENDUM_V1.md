# 고객사 합성 시험 실행 보충 계약 v1

2026-09-15. 적용 범위는 사용자 요청의 내부 합성 문서 제작·진단·시험 준비다.
과거 동결 계약·원고·정답·운영 정책을 수정하지 않는 현행 안내다.

## 1. 무엇이 선택됐고 무엇이 선택되지 않았는가

내부 제작은 `customer-guide-synthetic-reference` 정책 0.1을 사용한다.
정책 SHA256은 `e3aa2854120397342574c2487a46c83a4b74b9108c706bbc3c4b47c8dfbe1ac9`다.
가이드 곱셈과 명시한 내부 V 앵커 아래, 제공된 합성 전제에 대한 조건부 참조 답을 작성한다.
외부 검수자를 기다리는 것이 내부 작성의 선행조건은 아니다. AI의 합의 수를 정답 권위로 사용하지 않는다.

구 `CUSTOMER_BENCHMARK_800_200_V1.md`의 ‘정책 선택 대기/12개’는 당시 제작 준비 상태다.
최신 내부 선택과 원고 수는 새 팩 및 이번 병렬 작업 결과를 따른다. 과거 파일은 지문 보존을 위해 덮어쓰지 않는다.
이 내부 선택은 D01~D08의 고객사·사업 승인, guide/v22/fnr 운영 모드 변경, 실제 문서 공개 허가가 아니다.
현재 모든 원고의 학습/모델평가/GOLD/사람서명 플래그는 false를 유지한다.
시험용 배포는 별도 채택 기록과 버전이 필요하며 원본의 false를 지워 우회하지 않는다.

## 2. 세 가지 시험을 구별한다

| 시험 | 입력과 검증 대상 | 이번 범위 |
| --- | --- | --- |
| 사실 추출 | 본문에서 근거와 추출 가능한 사실을 찾는 능력 | 근거 위치 검사는 존재하나 실제 추출 모델 시험은 별도 |
| 정책 적용 | 제공된 사실을 고정 기준에 대입하는 과정 | 독립 구현의 맥락 해석/판정표 검산 |
| 전체 처리 | 실제 추출→사실/관리 근거→정책→등급·보류 | 입력 사전 검사까지; 운영·실제 모델 연결 미완료 |

현재 조건부 등급은 별도 맥락의 사실에서 산출한다. 본문만으로 정답을 식별할 수 있다고 주장하지 않는다.
규칙 엔진의 자기 일치도, 별도 정책 구현의 일치도, 문자 진단기의 점수, 고객 모델 성능은 서로 다른 지표다.
실제 ACL/공개 상태/투입 귀속은 본문 말투로 창작하지 않는다. 미수신은 0/false가 아니다.
합성 전제 자체의 현실 진위나 정책 적합성을 자동 검사가 인증하지 않는다.

## 3. 병렬 작업의 소유권

- 집필: 새 batch05 원고·빌더·해당 테스트만 수정한다. 동일 사례의 말투 사본은 새 수량이 아니다.
- 독립 검산: 별도 parser/명시적 27조합표와 반례로 생성기 출력과 대조한다. 기존 생성기 함수를 기대값으로 재사용하지 않는다.
- 입력 연결: 공개 입력 필드만 받아 기존 직렬화와 같은 표현·토큰 수·입력 해시를 계산한다. 답안 파일을 읽지 않는다.
- 중앙 통합: 노출 이력·분할 제약·최종 산출물·메모·보존 확인을 담당한다.

공통 정책/스키마/기존 소스는 이번에 수정하지 않는다. 새 모듈로 확장해 이전 팩의 소스 지문을 보존한다.
작업자는 각자 다른 새 출력 경로를 사용한다. 병렬 에이전트는 같은 워크스페이스를 공유하므로 보안 격리가 아니다.
이번 병렬 집필은 개발용이다. 최종 미노출 평가 200개를 같은 작업 중 함께 제작·모델 검사하지 않는다.

## 4. 개발 노출 이력과 분할 제약

새 `customer_eval_partition_v1.py`는 기존 분할기를 변경하지 않는 별도 제안기다.
노출 원장은 ID, 입력/본문/정규화/숫자마스킹 해시, 원문/사례/표현 계열, 사용 이유, 근거 산출물 지문을 저장한다.
비밀 원문이나 정답 자체는 노출 원장에 넣지 않는다. 원장 추가는 기존 행을 보존하고 새로운 해시를 만든다.

분할 호출자는 사용할 원장 해시를 별도로 지정한다. 원장 내 행을 지우고 자기 해시만 다시 계산해도 기존 pin과 달라 거절된다.
원장 전체가 완전하거나 작성자가 신뢰된다는 인증은 아니다. 다른 원장을 임의로 지정할 권한을 이 모듈이 통제하지는 않는다.

다음 중 하나에 해당하면 평가 배정 금지다.

1. 개발에 사용한 ID 또는 알려진 입력/본문 복사본이다.
2. 공백·숫자만 달라진 본문 또는 같은 원문/사례/표현 계열로 연결된다.
3. 후보 집합의 근접 중복이나 명시한 의미 계열 연결을 따라 개발 문서와 연결된다.

같은 ID의 입력/계열 지문 변경은 오류다. 이전 부모가 현재 후보에서 빠져도 알려진 본문/계열 지문과 비교한다.
이 검사는 기록되지 않은 재작성본과 전체 의미 중복을 완전히 탐지하지 못한다.
새 문서가 기존 이력에 일치하지 않는다는 것만으로 미노출이라고 인증하지 않는다.
CLI는 입력의 manifest 보유 상위 폴더 안에 새 결과를 추가하지 못하게 한다.
같은 경로를 두 입력 역할로 사용해도 첫 snapshot을 덮어쓰지 않으며, 출력 전후 입력 바이트를 다시 확인한다.
이는 파일 잠금이 아니다. 출력 도중 변경을 탐지해 실패하면 새 진단 파일이 남을 수 있으므로 종료0 확인 전에는 채택하지 않는다.

분할은 연결 성분 전체를 함께 배정한다. 개발 노출 성분의 평가 선택 상한을 0으로 제한한다.
등급별 학습200/평가50, 실제 문서1,000개를 동시에 충족해야 한다.
개발 강제 배정이 쿼터를 초과하거나 그룹 분리가 불가능하거나 solver가 제한 시간에 완료되지 않으면 실패한다.
숫자/제목만 바꾼 복제, 기존 정책 fixture를 수량 채우기로 넣지 않는다. 제안 성공은 배포나 블라인드 인증이 아니다.

현재까지 개발에 사용한 원고는 최종 미노출200개로 전용하지 않는다.
최종200개는 작성 계약·정책·모델 선택 절차를 고정한 뒤 새 독립 계열에서 별도 제작·봉인한다.
그 예측으로 원고/모델/프롬프트를 선택하지 않는다. 오류 수정은 이유와 새 시험 버전을 남긴다.

## 5. 입력 길이와 실행 경계

시험 입력은 `doc_id/text/context/input_sha256`와 false 사용 제한만 받는다.
정답·규칙·S/V/M 점수·문체/계열 태그가 입력에 있으면 거절한다.
본문+맥락을 기존 `presented_text`와 같은 방식으로 직렬화하고 지정한 tokenizer 바이트 해시를 검증한다.
패딩/자동 잘라내기를 끈 토큰 수를 기록한다. 512를 넘거나 필수 맥락이 없으면 HOLD이지 자동 잘라내기가 아니다.
본문 전용 뷰는 필요한 맥락이 모델에 제시되지 않으므로 등급 채점 허용으로 승격하지 않는다.

사전 검사 통과는 모델 실행·학습·배포 허가가 아니다. 실제 모델을 호출하지 않으며 고객 정확도를 계산하지 않는다.
장문 청크 집계와 실제 추출기 연결은 별도 구현/검증 단계다.

## 6. 이후 진행 순서

교차 원고와 독립 검산·입력 사전 검사를 통합한 뒤 개발 자료에서 편향·중복·의미 계열을 계속 개선한다.
부족 학습 원고 확장과 별개로 실제 모델 실행/시험용 배포를 연결한다.
마지막에 새 평가200개와 학습800개를 고정하고 800 내부에서 설정을 선택한 모델로 최종 시험한다.
고객사 적용 정책·합격 지표·자료 이용 범위·운영 변경은 별도 결정이며 이를 내부 작성 대기 사유로 확대하지 않는다.
