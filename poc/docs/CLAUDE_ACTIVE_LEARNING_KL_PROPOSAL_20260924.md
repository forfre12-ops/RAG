# 능동학습 검수데이터 — KL 협의용 제안 초안 (2026-09-24)

KL 이메일 요청2(API 통신 프로토콜 재협의) 중 "능동학습 검수데이터" 항목에 대한 답. 결론부터: **지금
KL과의 계약(회신·ICD·OpenAPI)에는 이 항목이 아예 없다.** 내부적으로는 이미 도는 루프가 있으니,
그걸 KL에 어디까지·어떤 형태로 보여줄지 세 안을 만들었다 — 발주처·KL과 협의해 하나를 고르면 된다.
아직 코드로 만들지 않았다(협의 전에 만들면 죽은 코드가 될 위험).

## 1. 지금 있는 것 — 내부 루프(KL은 모른다)

`기술구현_백서_v7.html` §2.4·§2.4.1에 이미 설계·구현돼 있다.

    G1 검수결과 자동수집   사람이 /confirm·/relabel 로 교정 → Correction 테이블(tad_cm_crct_mng) 적재
    G2 재학습              누적 교정 50건 도달 시 스케줄러 또는 수동 트리거
    G3 평가게이트          F1·FNR·적대케이스 중 하나라도 미달이면 폐기(자동배포 안 함)
    G4 관리자 사인오프     retrain_auto_activate 기본 OFF — 사람이 눌러야 배포됨

KL이 지금 API로 받는 건 `GET /classify/{doc_id}`의 `confirmed_label`/`confirmed_by`/`confirmed_at`
세 필드뿐(IF-06, `doc/03_openapi_koipa_kl.yaml:346-351`)이다. "이 문서가 나중에 어떻게 교정됐는지"는
KL이 그 세 필드로 알 수 있지만, "그 교정들이 모여서 재학습에 쓰였는지·모델이 언제 바뀌었는지"는
KL에게 전혀 안 보인다.

## 2. 세 가지 안 — 무엇을 얼마나 보여줄지

| 안 | KL이 받는 것 | 우리 쪽 개발량 | 리스크 |
|---|---|---|---|
| **A. 현행 유지** | 없음(지금 그대로, confirmed_label 세 필드만) | 0 | KL이 "검수데이터 협의"를 요청했는데 답이 없는 모양새 |
| **B. 주기적 조회(권장)** | `GET /learning/status`류 신규 엔드포인트 1개 — 최근 재학습 시각·버전·게이트 통과여부·활성화여부만(개별 교정 원문·검수자 신원은 안 줌) | 적음(읽기 전용 1개) | 없음 — 내부 상태만 요약해 노출, 교정 원문은 안 나감 |
| **C. 이벤트 통지(웹훅)** | 재학습 완료·모델 활성화 시점에 KL 서버로 POST 통지 | 중간(콜백 인프라는 이미 있음 — §4 Outbox 패턴 재사용 가능) | KL 쪽에 수신 엔드포인트 구현 부담을 지움 |

**권장은 B다.** 이유: KL의 원래 관심사("능동학습이 실제로 도는지, 검증되는지")에 답하면서도 검수자
개인정보·교정 원문(영업비밀 자체일 수 있음)은 안 내보낸다. C는 KL 쪽 작업이 생겨 항목1의 "코드·Docker
전달"과 별개로 부담을 더 지우는 모양이 된다.

## 3. B안을 고르면 만들 것 (협의 후 착수)

```
GET /api/v1/learning/status         (x-audience: kl 후보)
응답: {
  "last_retrain_at": "...", "last_retrain_result": "gated_pass|gated_fail|not_run",
  "active_model_version": "v-fe4b386b", "active_since": "...",
  "corrections_pending": 12, "corrections_consumed_total": 963
}
```
개인정보·문서원문·검수자 신원 없음 — 집계 수치와 상태만. `deploy_gate.py`·`training_service.py`가
이미 이 값들을 갖고 있어 새 계산 로직은 거의 필요 없다(신규 라우터 1개 + 기존 상태 조합).

## 4. KL에 보낼 때 이렇게 답하는 걸 제안

"능동학습 재학습 루프는 이미 운영 중이며(사람 승인 없이는 자동배포 안 됨), 지금은 KL에 그 상태를
보여주는 API가 없습니다. 진행상황 조회용 엔드포인트(재학습 시각·게이트 통과여부·활성 모델버전)를
신설하는 안(위 B)을 제안드리며, 검수자 신원·교정 원문 같은 민감정보는 이 API에 포함하지 않습니다.
필요 범위를 확인해 주시면 다음 스프린트에 반영하겠습니다."

## 5. 결정 전까지 하지 말 것

- B/C 어느 쪽이든 **KL 확정 전에 엔드포인트를 미리 만들지 않는다** — [[policy-engine-needs-70pct-acl-2026-09-13]]와
  같은 이유로, 협의 안 끝난 인터페이스를 먼저 만들면 죽은 코드가 되거나 나중에 필드를 바꿔야 한다.
- 이 문서 자체를 KL에 그대로 보내지 않는다 — [[feedback-no-docs-to-kl-list-findings-first-2026-09-10]]
  규약대로, 회신 문안은 사용자가 검토 후 별도로 다듬어 보낸다.
