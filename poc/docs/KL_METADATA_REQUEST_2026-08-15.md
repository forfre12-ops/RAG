# KL 협의 요청 — EDMS 가 세 필드를 실어 보내야 한다

작성 2026-08-15. **코드로 풀 수 없는 항목**이고, 분류 품질을 올릴 유일한 남은 레버다.
배관은 8/15 자로 세 경로 모두 뚫려 배포까지 끝냈다(182 `ab780792b2f5` 검증 완료).
남은 것은 **보내주는가** 하나다.

---

## 1. 요청 내용 — ICD §2 세 필드

문서와 함께 아래 세 값을 보내달라는 것이다. 셋 다 KL 과 **이미 합의된 ICD 규약**에 있고
새로 만드는 항목이 아니다.

```
§3.1  source_type       public | registered_patent | academic | internal | external_confidential
§3.2  security_marking   top_secret | secret | confidential | none
§3.3  access_scope       approved_only | designated | department | all_employees
```

전송 방법은 셋 중 아무거나 된다 — 이미 다 받는다.

```
POST /api/v1/classify           JSON  metadata: { ... }
POST /api/v1/documents          multipart  폼 필드 3개
POST /api/v1/documents/analyze  multipart  폼 필드 3개
```

**빈 문자열을 보내지 말 것.** 값이 없으면 필드를 아예 빼야 한다. 빈 값은 "모름" 과
"명시적으로 없음" 을 구분하지 못하게 만들고, 그 둘은 등급을 반대로 가른다.

---

## 2. 왜 이 세 값이 등급을 가르는가

영업비밀 판정은 세 요소의 곱이다 — **비공지성(S) · 경제적가치(V) · 비밀관리성(M)**.
이 중 **관리성은 본문에서 관측되지 않는다.** 문서를 아무리 잘 읽어도 "누가 열람할 수
있는가" 는 본문에 없다.

실측(실문서 코퍼스): 업무문서 중 관리 표시를 가진 것이 **17~21%** 뿐이다.
사내 일상문서와 금융보고서는 **0%** 다.

그래서 우리는 미지의 M 을 **보수적으로 최악값(2)** 으로 채운다 — 안전 방향이다.
그런데 정본 등급식에서 S1 은 `(S,V,M) = (2,2,0)` **한 조합뿐**이다.

```
M 이 0 으로 확정되지 않으면  →  S1 이 구조적으로 도달 불가  →  전부 TS 로 간다
```

봉인 판정면의 **28%(18/64)** 가 이 이유로 어떤 모델에서도 TS 가 됐다. 모델을 아무리
개선해도 안 풀린다 — 정보 자체가 입력에 없기 때문이다.

`access_scope=all_employees` 한 값이 M=0 을 확정한다. 그것이 자물쇠의 열쇠다.

---

## 3. 얼마나 좋아지는가 — 시뮬레이션 실측

메타데이터 제공률과 오류율을 바꿔가며 측정했다.

```
 제공률  오류율   4등급F1   S1재현율   자동확정   미탐  미탐상한(95%)
   0%     0%     0.7543    0.5458    78.3%      0    0.00133
  50%     0%     0.7889    0.7106    74.6%      0    0.00140
 100%     0%     0.8310    0.8791    71.0%      0    0.00147
 100%     5%     0.8092    0.8352    71.0%     33    0.01768
 100%    20%     0.7345    0.6923    71.5%    140    0.06241
```

```
전량 제공 시   4등급 F1  +7.7pp      S1 재현율  +33.3pp
```

자동확정이 78.3% → 71.0% 로 내려가는 것은 **정상이자 의도된 동작**이다. M=0 인 문서가
TS 가 아니라 S1 로 가면서 경계 사례가 검수로 돌아가는 것이고, 그 대가로 미탐이 0 이다.

---

## 4. 합의가 필요한 것 — 오류율 경계 5%

위 표에서 갈리는 지점이 명확하다.

```
오류율  5%   미탐 상한 0.0177   사전등록 한계 0.02 이내   ✅
오류율 20%   미탐 상한 0.0624   한계 3배 초과            ❌
```

**메타데이터 오류율 5% 를 계약 경계로 합의해야 한다.** 이것이 지켜지지 않으면 사전등록한
안전 조건이 깨지고, 그때는 메타데이터를 받는 것이 되레 해가 된다.

ICD §6 개방 항목(K1~K5)에 추가할 문항이다.

---

## 5. 안 보내주면 어떻게 되는가

시스템은 **정상 동작한다.** 메타데이터 부재는 silent no-op 로 설계돼 있어 분류가 막히지
않는다. 다만 위 표의 첫 줄 상태로 고정된다.

```
4등급 F1 0.7543 · S1 재현율 0.5458 · 미탐 0
```

즉 **안전하지만 S1 을 절반밖에 못 찾는다.** 그리고 이 갭은 우리가 코드로 좁힐 수 없다.

---

## 6. 요청 요약

```
(1) EDMS 가 문서 전송 시 ICD §3.1·§3.2·§3.3 세 필드를 함께 보낼 것
(2) 값이 없는 필드는 빈 문자열이 아니라 **생략**할 것
(3) 메타데이터 오류율 5% 를 계약 경계로 합의할 것 (ICD §6 개방 항목)
```

받는 쪽 준비는 끝나 있다 — 세 HTTP 경로 모두 배포·검증 완료(182 `ab780792b2f5`).
