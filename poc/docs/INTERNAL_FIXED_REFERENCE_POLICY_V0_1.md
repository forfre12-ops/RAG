# 내부 고정 정답 참조 정책 v0.1 — 제한된 가상 원장

2026-09-15. 정책 ID `internal-fixed-ledger-reference`, 버전 `0.1`.

## 무엇을 확정하는가

사람 검수 없이도 **명시한 정책과 제공한 사실에서 유일하게 도출되는 참조 답**은 확정할 수 있다.
이를 위해 첫 40건은 자연어 전체가 아닌 제한된 가상 원장 문법으로 작성한다.
각 등급 10건의 기계적 검산 파일럿이며, 등급별 250건 완성이나 일반 보안문서 의미 판정의 완료가 아니다.

정답의 권위는 AI의 자신감이나 검수자의 투표가 아니라 이 정책의 조건부 정의다.
정책의 사업 적합성까지 증명한 것은 아니다. 사람 서명, 고객 GOLD, 운영 승인, 법정 등급을 만들지 않는다.
기존 D01~D08 결정을 승인하지 않으며 guide/v22/S·V·M 정책을 변경하거나 대체하지 않는다.

## 입력과 적용 범위

- 본문: 가상 인물 연결표, 지급표, 업무 배정표를 모두 포함하는 `LEDGER-01` 텍스트.
- 맥락: `origin=synthetic_assumption`, `scope_complete`, `identity_scope`, `release_authorized`.
- 정책: 위 ID/버전과 정책 SHA256. 전체 본문 및 맥락이 판정기 입력이다.
- 정답/판정 설명/목표 라벨/계열/분할은 별도 답안 파일에 둔다. ID는 특징으로 쓰지 않는다.

가상 세계에서 개인의 식별은 제공된 연결표와 지급표의 연결키 JOIN으로만 정의한다.
외부 식별정보가 없는 완전한 세계라는 **가정**을 입력에 명시한다. 실제 익명화·재식별 방지 증명이 아니다.
연결표 자체의 가상 인물ID/표시명은 현실 개인정보가 아니다. 이 파일의 현실 관리등급을 TS라 부르는 것도 아니다.
실제 개인정보·인증정보·핵심 제조법·계약정보·자유로운 자연어 문서는 지원 범위 밖이다.
지원되지 않는 본문은 조용히 무시하지 않고 오류 처리한다. 이 범위 밖 문서를 이 정책으로 낮춰 분류하지 않는다.

## 유일 결정표

N = 연결표와 지급표를 연결한 뒤 중복을 제거한 **인물ID 수**. 지급 행 수나 연결키 수가 아니다.

| 등급 | 충분조건 | 나머지 등급을 배제하는 이유 |
|---|---|---|
| TS | N ≥ 1,000 | S1의 범위를 초과하고 S2/S3의 N=0 조건 불충족 |
| S1 | 1 ≤ N < 1,000 | TS의 수량 미달, S2/S3의 N=0 조건 불충족 |
| S2 | N=0, 공개 허가=false | TS/S1의 연결 지급정보 없음, S3 공개 허가 조건 불충족 |
| S3 | N=0, 공개 허가=true | TS/S1의 연결 지급정보 없음, S2 비공개 조건 불충족 |

1,000은 기존 v1.1의 인원 경계 제안을 **이번 내부 시험에서만 채택한 설계값**이며 법률/고객/가이드 정본이 아니다.
연결 지급정보가 있으면 공개 허가를 true로 바꿔도 TS/S1을 낮추지 않는다.
N=0에서 공개 허가가 unknown이면 가능 등급은 S2/S3, 고정 답 없이 HOLD다.
전체 범위가 불명하거나 외부 연결 배제가 없으면 N만 계산할 수 있어도 HOLD다.
알 수 없는 세계 전체를 열거해 안전성을 증명했다고 주장하지 않는다.
사용자가 수치 S·V·M을 입력하지 않아도 검산되지만, 공개/범위 등의 판단요소와 맥락은 없애지 않는다.

## 문법 및 근거 계약

UTF-8, LF, 지정된 제목 10개 중 하나, `기록형식: LEDGER-01`, 세 개 표와 `[끝]`.
표 순서/열 순서는 바뀔 수 있으나 열 집합은 고정이며 모든 문자를 파싱한다.
연결키·처리키·작업키는 중복 금지, 같은 인물ID에 충돌하는 표시명은 오류다.
한 인물에 여러 연결키/여러 지급이 있어도 인원수는 하나로 계산한다.
빈 연결/지급표는 허용하지만 배정표는 하나 이상의 실제 가상 행이 필요하다.

증명서에는 입력/본문/정책/맥락 SHA256, 적용 규칙, 제외 이유, 인원수 및 각 연결 인물의
연결표·지급표 행 위치와 해시를 담는다. 위치는 Python Unicode 문자 기준 start 포함/end 제외다.
근거 재생성과 전체 증명서 일치를 검증한다. 해시는 진위나 작성자 신원을 인증하지 않는다.

## 채택 조건과 독립 검산

1. 제작기는 표와 맥락을 만들고 목표 라벨은 답안 메타에만 남긴다.
2. Python 전체 파서+집합 JOIN+네 조건식으로 답을 계산한다. 목표 라벨은 입력받지 않는다.
3. 별도 모듈의 CSV 파서+메모리 SQLite JOIN/COUNT DISTINCT/CASE로 재계산한다.
4. 두 결과 일치·유일 등급·완전한 가상 맥락·정책/본문/근거 해시 일치 때만 `fixed_under_internal_policy`.
5. 목표 라벨과 다르면 조용히 고치지 않고 실패. 둘 다 틀릴 수 있으므로 경계/변형/오류 주입 시험을 병행한다.

두 검산기는 서로 다른 계산 경로이지만 같은 제작 주체와 정책을 공유한다.
이는 독립 기관의 검증이나 정책의 외적 타당성 검증이 아니다.

## 자료 구성·누설·확대 중단 조건

- 10개 서식 계열 각각 TS/S1/S2/S3를 모두 포함한다. 같은 계열의 본문 길이/행 수는 동일하다.
- S2/S3는 같은 본문과 다른 공개 맥락의 대조쌍이다. 본문만 입력하고 맥락 정답을 채점하면 잘못된 평가다.
- 개발 7계열 28건/예비후보 3계열 12건. 예비후보도 제작·검증 때 열람하므로 봉인/블라인드라 부르지 않는다.
- 문체 진단은 제목·표 순서·열·행 수의 제한된 관점이다. 전체 내용의 모든 지름길을 검증한 것은 아니다.
- `dataset_role=policy_fixture`, training/model_evaluation=false 유지. 내부 정답 고정과 모델평가 사용허가는 별개다.
- 기존 140건·v1.1 40건을 재라벨하거나 고객 정확도 분모에 넣지 않는다.

다음 250건씩은 이 원장 40건을 숫자만 바꿔 복제하여 채우지 않는다. 독립 문서군과 검증 가능한
핵심정보/부분정보/일반업무/공개정보 경계를 추가하고, 문서군별 네 등급 및 정보부족/경계 대조시험을 마련한다.
지원 범위가 늘 때 정책 새 버전과 별도 oracle이 필요하다. 변형본은 같은 분할에 묶는다.
모델의 본문 입력 한도/잘림과 맥락 지원, 전체 내용 지름길 검사, 기존 학습 풀 중복 검사가 끝나기 전
학습·성능 평가용 전환은 하지 않는다. 정책 일치율과 고객 분류 정확도를 구별한다.
