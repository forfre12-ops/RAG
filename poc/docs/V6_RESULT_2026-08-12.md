문자열이 아니라 그 문장이 서술하는 사실 쪽을 잡았다고 보는 것이 맞다.

## 3. ⛔ 이 표를 "v6 가 v5 보다 낫다"로 읽으면 안 된다

v5 는 800건 중 **S3 를 7건만** 예측했다(정답 240건). 무작위(0.25)보다 낮은 F1 0.26 이다.
이건 "성능이 나쁘다"가 아니라 **이 평가셋이 v5 에게 분포 밖(OOD)** 이라는 신호다.

- v6 학습셋과 v3 평가셋은 계보상 독립이다(가족·시나리오·생성기·문장 공유 전부 0 — 확인함).
  그러나 **같은 저술 프로그램 계열**이라 문서 장르·구조·어휘대가 가깝다.
- v5 는 전혀 다른 코퍼스(`labeled_p1_v5_clean`, gold_real 계열)로 학습됐다.
  이 문서들을 본 적이 없다.

즉 **이 자는 한쪽에는 in-domain, 다른 쪽에는 OOD 다.** 공정한 맞대결이 아니다.
이 표로 배포본 교체를 판단하면 안 된다.

### 그럼 이 수치로 말할 수 있는 것은

1. **v6 는 표현 변화에 견딘다.** 학습셋과 문장을 하나도 공유하지 않는 셋에서 0.70 —
   문자열 암기만으로는 나올 수 없는 값이다. 이것이 이번 측정의 유일한 확정 소득이다.
2. **v3 final_800 은 v5 계보 모델의 비교자가 될 수 없다.** 배포본 교체를 판단하려면
   두 모델 모두에게 공평한 셋이 필요하다 — 지금은 없다.
3. **둘 다 미탐 기준으로는 쓸 수 없다**(아래).

## 4. 진짜 문제 — F1 이 가리는 것

```
고등급 미탐(underclassification FNR)
   v5   0.5472   (360건 중 197건)
   v6   0.4028   (360건 중 145건)
```

**본 사업의 1차 목표는 미탐 최소화인데 고등급 10건 중 4~5건을 놓친다.**
v6 는 정밀도가 높고(TS 0.93 · S1 0.90) 재현율이 낮다 — 확신할 때만 고등급을 주고
나머지는 S3 로 미는 전형적 미탐 패턴이다.

### 단, 이건 **모델 단독** 수치다

채점 경로는 M5 **집계**(청크→overflow 윈도→온도→길이가중 평균→심각도 max→재정규화→argmax)
까지이고 **서빙 가드는 타지 않는다** — FNR-safe override · source-prior cap · metadata
floor · escalation tau · 합의 게이트가 전부 빠져 있다(계약이 명시적으로 제외하는 항목들).

문서 기록상 v4 에서 원시 argmax FNR 0.167 → 서빙 경로 0.018 로 **약 9배** 차이가 났다.
2026-08-12 라이브 확인에서도 합의 게이트가 실제로 발화해 conf 0.793 짜리 판정을
needs_review 로 보냈다. **운영 FNR 은 위 값보다 상당히 낮다.**

위 수치는 "모델이 혼자서 얼마나 아는가"이지 "운영에서 얼마나 놓치는가"가 아니다.
후자는 서빙 경로 전체로 다시 재야 한다 — 미실시.

## 5. 부수 발견 — 온도 보정이 퇴화했다

v6 모델의 `temperature.json` 이 **T = 0.05** 다(정상 2~3). 검증셋 정확도가 100% 라
보정할 신호가 없어서 나온 값이다. argmax 채점에는 영향이 없지만(단조 변환)
**confidence 를 쓰는 게이트에는 영향이 있다.**

→ finalize 전에 온도를 다시 잡아야 한다. **v6 val 셋은 보정용으로 부적합하다**(너무 쉽다).
   보정은 난이도가 있는 독립 셋에서 해야 한다.

## 6. v6 자체 test 는 정보가 없었다

가족을 분리했는데도 F1 1.00 이 나왔다. 등급이 `grade_from_svm` 의 함수라 세 요인 문장만
읽으면 규칙으로 풀리기 때문이다. **v6 자체 test 로는 문자열 암기와 사실 일반화를 구분할 수
없다** — 둘 다 1.00 을 만든다. 사전 예측 문서에 적어 둔 그대로였고, 그래서 문장 풀이 다른
v3 로 재는 것이 필요했다.

## 7. 다음에 해야 할 것

1. **배포본 교체 판단은 보류.** 공평한 비교자가 없다. 두 모델 모두에게 OOD 이거나 모두에게
   in-domain 인 셋이 필요하다.
2. **서빙 경로 전체로 FNR 재측정.** 모델 단독 40% 가 가드를 태우면 얼마가 되는지가
   실제 판단 근거다.
3. **온도 재보정.** v6 val 은 쓰면 안 된다.
4. **미탐 40% 자체를 줄이는 작업.** 정밀도를 희생해서라도 고등급 재현율을 올려야 한다 —
   RFP 핵심목표가 그쪽이고, F1 은 마지막 게이트다.
