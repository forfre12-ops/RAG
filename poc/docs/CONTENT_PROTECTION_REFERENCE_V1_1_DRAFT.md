# 내용 기반 보호등급 참조 기준 v1.1 — 근거·입력 범위 개정안

정책 ID: `content-protection-reference-v1.1-draft` / 작성일: 2026-09-15.
상태: AI 작성·미승인. 기준 책임자 결정, 독립 검수, GOLD 자격 없음.
고객사 관리등급·법정 등급·반출 허가가 아니라 내부 **보호 필요 추천**을 위한 제안이다.
S·V·M 숫자는 필요하지 않지만 아래 사실과 근거는 필요하다.
이 문서는 독립된 개정안이다. 기존 v1 문서·140건·봉인후보50·옛 라벨은 대체하지 않는다.

## 1. 무엇을 보고 판단하는가

판정 단위는 `문서 판본 + 본문/첨부 목록과 해시 + 판정 기준일 + 적용 정책`이다.
본문 직접값, 그 값에 대한 주장, 확인된 외부 맥락, 합성 시험 전제를 구별한다.

| 근거 유형 | 의미 | 금지할 해석 |
|---|---|---|
| body_direct_value | 실제 수록된 행·값·코드·단계의 위치 | 값이 보인다고 진위·현행성·권한까지 확인됐다고 하지 않음 |
| content_assertion | “원장이 있다/핵심이다” 등의 서술 | 실제 원장·코드·권한 증거로 치환하지 않음 |
| verified_context | 승인된 시스템 기록/소유자 확인을 같은 판본·시점에 결합 | 모델의 추정·작성자 주장에 이 유형을 붙이지 않음 |
| synthetic_assumption | 허구 시험 세계를 정의하는 명시적 입력 | 실제 고객사 사실·사람 확인으로 사용하지 않음 |

긍정 사실과 부재 사실은 다르다. 직접 보인 정보는 근거가 되지만, 보이지 않는 정보의
부재를 확인하려면 추출 완료·누락 페이지·첨부·합산 범위를 확인해야 한다.
미수신/미확인은 `unknown`이다. `false`, 0, 공개, 무해로 변환하지 않는다.
확인되지 않은 문서 전체의 상한을 관찰한 일부 내용만으로 제한하지 않는다.

## 2. 네 등급과 인접 경계

### TS — 집중된 핵심 재현·통제·민감정보 위험

- **CP-TS-01**: 보호할 현행 핵심 제품/공정/알고리즘의 재현 묶음.
  직접 확인한 단계·결정 변수·검증 기준이 모두 있고, 동일 기능 재현에 충분하다는
  범위 확인과 핵심성·해당 판본 비공개 맥락이 결합되어야 한다.
  제목, 전문용어, “완전한 자료”라는 주장, 일반 교재, 일부 실험 결과만으로는 불충분하다.
  구현을 실행해 샘플 출력이 같다는 것은 그 작은 명세의 검산일 뿐 실제 제품 재현성 증명이 아니다.
- **CP-TS-02**: 직접 수록된 인증/서명/복구 재료로 기준일 현재 핵심 배포·자금 집행·저장소를
  통제할 수 있음이 확인된다. 값·대상 자산·권한·유효기간·필요한 추가 요소를 함께 확인한다.
  추가 인증 요소가 필요하지만 제공되지 않았거나, 만료/폐기/견본/마스킹 값이면 이 규칙은
  성립하지 않는다. 유효성 모름은 보류이지 무효가 아니다. 분류를 위해 실제 로그인,
  서명, 자금 집행, 토큰 사용을 시도하지 않는다. 승인된 관리 기록을 요청한다.
- **CP-TS-03**: 같은 판정 묶음에서 **식별 가능한 고유 개인 N ≥ 1,000명**과
  건강·금융계좌/채무·생체인증 세부정보가 연결된다. 원장과 재식별 키가 함께 제공되는 경우도 포함한다.
  N은 행 수가 아니다. 파일 간 같은 개인은 중복 제거하고, 일대일 식별/연결 근거를 확인한다.
  분할 파일의 공동 접근 범위를 먼저 정한다. 집계·익명화 검증본·일반 업무 연락처만으로는 적용하지 않는다.

`bulk_person_threshold=1000`은 **내부 제안 파라미터**다. 법정·보편적 기준이라는 근거는 없다.
999명은 다른 TS 조건이 없고 식별 민감정보가 남으면 S1, 1000명은 해당 조건에서 TS 후보다.
규모만으로 위험을 설명할 수 없는 예외는 기준 책임자가 승인할 별도 정책 사항이다.
인원 상한/연결 범위를 모르면 낮은 등급으로 확정하지 않는다.

### S1 — 특정 개인·사업·제품의 실질 보호 내용

**CP-S1-01**: TS를 적용하지 않는다는 범위 확인과 함께 다음 중 하나가 직접 수록된다.

- 특정 개인과 연결된 평가·보수·건강·금융 내역 또는 **생체인증 템플릿/특징값**.
- 비공개 거래별 가격, 원가, 협상 하한, 지급·공급 조건, 계약상 제한,
  수급 대응, 미공개 수요 판단/투자 선택 등 경쟁 상대가 활용할 실질적 사업 세부사항.
- 특정 제품의 설계·코드·실험 조건·결함·노하우의 실질적 일부.

사업정보에 반드시 숫자가 있어야 하는 것은 아니다. “독점 공급을 수락하되 재판매권은 주지 않는다”와
같은 구체 협상 선택도 대상이 될 수 있다. “견적서/전략/주문서 포함”이라는 명칭 나열은 대상이 아니다.
일반 교육용 수치, 공개 예제, 조직과 연결되지 않은 계산은 그 자체로 S1이 아니다.
단순 출시 일정은 S2 조건을, 일정과 함께 미공개 수요/우선순위 판단이 있으면 S1 조건을 확인한다.
생체자료도 1,000명 미만이면 이 규칙으로 연결한다. 인원/연결 상태가 불명확하면 TS 가능성을 보류한다.

### S2 — 내부 운영 세부사항

**CP-S2-01**: 확인한 전체 범위에 TS/S1 내용이 없고, 조직별 일정·역할·설비 배정·
작업 식별자·실제 업무 절차가 수록되며 해당 판본이 안전한 공개본으로 확인되지 않았다.
“내부 작성” 표제만으로 S2가 아니다. 실질 운영값이 있어야 한다.
과거 문서라는 이유만으로 S3가 되지 않는다. 현행성이 필요한 판단에는 `as_of`와 절대 날짜를 요청한다.

### S3 — 일반 정보·빈 서식·안전한 배포본

**CP-S3-01**: 전체 범위에 상위 보호 내용이 없고 일반 지식, 값 없는 공통 서식,
무해한 예제 또는 보호 내용을 제거한 안전한 배포 판본임이 확인된다.
빈 칸과 추출되지 않은 칸은 다르다. 인터넷 게시/공개 예정/이전 판본의 배포 승인은 충분하지 않다.
개인 민감자료나 현재 유효한 비밀값은 인터넷에 노출되어도 자동 하향하지 않는다.
S3는 반출·저작권·법률상 이용 허가가 아니다.

## 3. 결정 절차와 미결 상태

1. 정책·판본·해시·시점·범위를 결합한다. 모순된 근거는 출처와 적용 범위/예외로 먼저 조정한다.
2. 필요한 사실을 근거 유형과 함께 참/거짓/미확인으로 기록한다. 제목/표시/전문용어는 결정 사실이 아니다.
3. 확인된 TS → S1 → S2 → S3 조건을 적용한다. 여러 조건이 성립하면 높은 등급을 추천한다.
4. 미확인 사실을 달리 채웠을 때 결과가 바뀌면 **CP-HOLD-01 / needs_evidence**.
   어떤 규칙도 입증되지 않아도 보류한다. 이미 독립적으로 입증된 TS는 하위 사실 미확인으로 낮추지 않는다.
5. 같은 판본의 해소되지 않은 모순은 **CP-HOLD-02 / needs_policy_review**, 사유 `context_conflict`.
   사실이 충분해도 규칙 적용 경계가 정의되지 않았으면 같은 상태, 사유 `policy_gap`.
6. 보류는 `grade=null`. 필요한 증거, 해결 역할, 해소 조건을 기록한다.
   후보 등급 범위는 명시된 가정 안의 집합이며 미수신 원문 전체의 위험 상한이 아니다.

공개·만료·익명화 예외는 해당 값·판본·시점·범위에만 적용한다. 오늘 날짜나 파일명만으로 하향하지 않는다.
관찰된 정보만에 대한 조건부 설명과 전체 문서 확정 추천을 같은 필드에 넣지 않는다.

## 4. 입력과 정답의 일치

자세한 계약은 [입력·근거 계약](CONTENT_REFERENCE_INPUT_CONTRACT_V1_1.md)을 따른다.
본문만 받은 모델을, 별도 맥락까지 받은 검수자의 정답으로 채점하지 않는다.
이번 보완40건은 **합성 세계 정책 적용 시험**이며 현실에서는 무효인 문자열/가상 개인/장난감 수치 모형이다.
그 현실의 예제 파일 자체에 TS/S1 관리등급을 선언하지 않는다.

- `body_only`: 합성 세계 맥락이 미제공된 입력. 이번40건의 전체 보호등급 후보는 보류하며
  4등급 정확도 분모에 넣지 않는다. 맥락 누락 검토 라우팅만 별도 시험 가능하다.
- `body_plus_synthetic_context`: 본문과 명시적 가상 맥락을 함께 보고 TS20/S1 20 후보를 검토한다.
  근거/답안/규칙 만족 플래그는 입력에 붙이지 않는다. 고객사 사실 추출 성능과 분리한다.

모델에서 구조화된 맥락을 받을 경로는 이번에 만들지 않는다. 운영 API와 본문+등급 학습 계약도 변경하지 않는다.
새 입력 계약은 오프라인 검토·후속 실험 설계용이다. 새 자료 추가 효과와 라벨 정제 효과는 별도 실험이다.

## 5. 승인·변경 이력·평가 경계

CPR-I01/I02: 근거 유형/전체 범위/입력 차이. I03/I04: 인원 집계/가상 통제.
I05/I06: 실질 사업내용/생체정보. I07/I08: 판본·시점/보류 사유.
I09/I10: 옛 라벨 이력 보존/권위 구분. 10개 쟁점을 모두 이 개정안에 연결했다.

기존 라벨에 정책 버전이 없으면 모름으로 보존한다. 새 해석을 옛 정책의 확정 정답이라고 하지 않는다.
AI 작성, 같은 작성자 검산, 독립 검수, 정책 승인, 모델 평가, 배포 결정은 각각 다른 기록이다.
현재 문서와 후보는 모두 미승인이고 학습 사용 금지다. 봉인후보50은 재튜닝에 열지 않는다.

남은 결정: 핵심 자산/완전 재현 범위, 1,000명 및 규모 외 예외, 안전한 공개 확인 절차,
S1 사업/개인정보 적용 범위, 독립 검수자와 조정자, 고객사별 실제 정책·허용 오류/검수량.
이 결정 전에도 초안/합성 후보/구조 검증은 진행하지만 사람 서명·GOLD·모델 교체는 하지 않는다.
