## 2. 6차 "통과" 는 오판이었다

외부 검토 지적을 전부 재현했다. 세 가지가 틀렸다.

**형태별 판정이 없었다.** 사전등록 §2 는 "홀드아웃 형태 각각에서 충족" 을 명시하는데
게이트는 `form_id` 를 읽지 않았다. 두 형태가 각각 미달인데 합산으로 통과했다:

```
tau 0.999 (6차 보고값)   합산 n=213 미탐 0 상한 0.0177  통과
    contract_terms       n=104 미탐 0 상한 0.0356      미달
    customer_list        n=109 미탐 0 상한 0.0340      미달
```

**보고된 PASS 가 무보정 값이었다.** `--temperature` 없이 실행했다. 게다가 기록에
`head_dist`(4-way 전체 분포)가 있는데도 게이트 주석은 "최대확률만 있다" 고 적고
`p^(1/T)` 근사를 썼다. 근사할 이유가 없었고 값도 달랐다.

**표본수 기준이 틀렸다.** 사전등록 표의 "2.0% -> 150건" 은 산술 오류다.
`0/150 -> 0.02497`(초과) · `0/189 -> 0.01992`(충족). 189 가 맞다.

세 가지를 고쳐 게이트에 넣었다(`--min-form-n 189` 기본).

## 3. 2차 판정면도 결함이 있었다

`pool_split="holdout"` 을 그대로 써서 1차 판정면과 근거문장이 **108/109 겹쳤다.**
형태만 새롭고 표현은 같았다 — 그 상태로는 "1차 통과가 좁은 조합의 산물인지" 를 가릴 수 없다.

전용 프레임 14종을 새로 써서 겹침을 0 으로 만들었다(secrecy 4 · value 6 · management 4).
분할이 목록 **끝에서부터** 떼는 구조라 학습·보정·1차 판정면은 그대로 유지된다
(1차 판정면 본문 2,096/2,096 = 100% 동일).

첫 측정에서 미달이 나왔는데 성능이 아니라 표본 때문이었다 — tau 0.90 에서 6개 형태 전부
미탐 0건인데 형태당 n=102~162 라 상한이 0.023~0.036 이었다. 3,680건으로 키워 해결했다.
