# 독립 검수·불일치 조정·실제 문서 파일럿 계약 v1

작성일: 2026-09-15. 상태: 미승인 오프라인 절차. 운영 정책/API/학습 경로 변경 없음.
적용 후보 정책: `content-protection-reference-v1.1-draft`.
여기서 ‘검증’은 파일·근거 연결과 절차 조건의 검사다. 사람 신원, 진실, 승인 권한을 인증하지 않는다.

## 1. 이번에 준비하는 두 작업

1. 기존 합성 문서형40건을 두 검수자가 각각 판단하도록 입력·빈 양식을 나눈다.
2. 실제 문서를 받을 때 필요한 허가·판본·추출·계열·중복 명세를 내용 없는 접수 양식으로 준비한다.

합성40건을 실제 문서40건으로 취급하거나 새 합성물을 만들어 실제 파일럿을 채우지 않는다.
검수자 R1/R2는 역할 슬롯이며 실제 사람이 배정됐다는 뜻이 아니다.
이번 생성 결과의 사람 답안·조정 결정·실제 문서 접수는 모두0건이어야 한다.

## 2. 역할과 책임

| 역할 | 맡는 일 | 대신할 수 없는 일 |
|---|---|---|
| 기준 책임자 | 핵심 범위·1,000명·규모 외 예외·S1 경계·공개/시점 기준 결정 | AI 결과나 투표를 근거 없이 승인으로 바꾸기 |
| 원문 소유자/추출 담당 | 허가된 판본·첨부·표·전체 범위와 추출 검증 제공 | 없는 맥락을 추측해서 채우기 |
| 검수자 R1/R2 | 상대 답/AI 답을 보기 전, 같은 입력·정책으로 근거와 후보 판단 제출 | 자기 판단을 고객사 최종 관리등급으로 선언하기 |
| 조정자 | 독립 제출본을 잠근 뒤 차이를 분류하고 추가 증거/정책 결정 요청 | 다수결이나 단순 상위 등급 선택으로 불일치를 숨기기 |
| 인증·승인 시스템/책임자 | 계정·제출 이력·접근 기록·승인 권한 검증 | 파일 안의 reviewer_id 문자열만으로 사람 인증 완료 처리 |

R1/R2는 서로 다른 실제 계정이어야 하고 조정자도 둘과 분리한다.
이 도구는 그 계정의 형식과 서로 다른지까지만 검사한다. 실제 신원 확인은 외부 절차다.
`human_declared` 역시 본인의 선언이다. AI 보조 사용은 `ai_assisted_declared`로 공개한다.

## 3. 검수 진행 순서

1. 제작 담당자는 동결 후보/정책/코드 지문을 확인하고 **새 폴더**로 검수 패킷을 생성한다.
2. R1에는 `reviewers/R1/`, R2에는 `reviewers/R2/`만 전달한다. 각 폴더에는 정책, 입력,
   안내, 빈 제출 양식만 있다. AI 답안·예측·부모ID·계열ID·분포 요약은 넣지 않는다.
3. 각 검수자는 `forms.template.jsonl`을 패킷 밖의 새 파일로 복사해 채운다.
   패킷과 원본 템플릿을 덮지 않는다. 판본이 달라지면 기존 양식을 재사용하지 않는다.
4. 제출본은 완성 행만 `state=submitted`, 나머지는 `pending`으로 둔다.
   도구는 모든 배정 ID를 요구하고, 중복/미배정/정책·입력 해시 불일치는 거절한다.
5. 조정자는 대조 명령으로 두 파일의 해시·완료 범위·근거 위치를 확인한다.
   같은 계정, AI 보조 선언, AI 답/상대 답 사전 열람 선언은 독립성 확인 대상으로 남긴다.
6. 대조 결과는 새 출력 폴더에 저장한다. 기존 제출본은 수정하지 않는다.
   정정 제출은 새 파일로 내고 대조를 새 실행으로 다시 만든다.
7. 조정자는 `resolution_template.jsonl`을 새 파일로 복사해 근거 있는 **조정 제안**을 작성한다.
   제안은 양쪽 제출 레코드 해시에 묶이며, 입력/제출 변경 후 예전 제안의 재사용은 거절한다.
8. 최종 신원·근거·정책 승인 확인과 GOLD 승격은 기존 승인 절차에서 별도 수행한다.
   이 도구는 원라벨/운영 DB를 바꾸거나 학습 파일을 내보내지 않는다.

파일 분리는 전달 편의를 위한 것이다. 폴더 ACL 설정, 외부 전송, 사람 초대, 독립 블라인드 인증은 하지 않는다.
같은 워크스페이스의 작성자가 이미 답을 알고 있으므로 이를 독립 검수로 계산하지 않는다.

## 4. 제출 양식의 판정과 근거

고정 결합: case_id, reviewer_slot, input_sha256, text_sha256, context_sha256, policy_version/sha256, view.
입력 관점은 `body_plus_synthetic_context`. 이 작업에서 본문만의 시험과 섞지 않는다.

제출값: state, reviewer_id, actor_kind, reviewed_at(시간대 포함), prior_answers_seen,
decision(status/grade/rule_ids), evidence, reason_codes, rationale, not_higher_reason,
not_lower_reason, evidence_requests. 빈 양식에는 실제 계정·판정·서명을 채우지 않는다.

- recommended: TS/S1/S2/S3 중 하나, 그 등급을 뒷받침하는 규칙, 직접 근거와 경계 설명 필요.
- needs_evidence: grade=null, CP-HOLD-01, 필요한 추가 증거 요청 필요.
- needs_policy_review: grade=null, CP-HOLD-02, context_conflict 또는 policy_gap 사유와 해결 요청 필요.
- 본문 근거: `{kind: body, start, end, quote}`. Python 문자 기준 `[start,end)`와 원문 일치.
- 맥락 근거: `{kind: context, pointer, value_sha256}`. 입력 context의 허용 경로와 값 해시 일치.
  가상 맥락의 위치를 정확히 인용했다고 실제 고객사 사실이 되는 것은 아니다.

필드에 승인/GOLD/학습 허용 칸을 추가하거나 grade와 보류 상태를 같이 넣으면 거절한다.
판정 코드/인용이 형식상 맞아도 의미상 정답이라는 증명은 아니다.

## 5. 불일치 대조와 조정 제안

| 대조 결과 | 의미 | 다음 조치 |
|---|---|---|
| awaiting_reviews | 한쪽 또는 양쪽 제출 전 | 미제출 요청; 분모에 포함하지 않음 |
| independence_check_required | 같은 계정/AI 보조/사전 답 열람 선언 | 독립성 확인 또는 새 검수자 배정 |
| decision_disagreement | 등급 또는 추천/보류 상태 차이 | 증거 부족·범위·규칙 해석·라벨 오류로 원인 분류 |
| basis_disagreement | 결론은 같으나 규칙/사유가 다름 | 어떤 규칙이 성립하는지 조정 |
| agreement_pending_adjudication | 결론·규칙·사유 일치 | 근거·판본·정책 승인 확인 후 조정 제안 |

근거 위치 차이는 별도 플래그로 남긴다. 서로 다른 유효 근거를 인용한 것만으로 오답을 선언하지 않는다.
TS/S1 대 S3의 불일치는 우선 검토 표지이며 모델의 위험한 하향 오류로 계산하지 않는다.
AI 후보와의 비교는 이 버전에 구현하지 않는다. 검수자끼리의 독립 제출을 먼저 고정한다.

대조 요약은 전체 배정 수, 각 슬롯 제출 수, 양쪽 완료 수, 독립성 자기신고 조건 충족 수,
결론 일치 수/비율, 규칙 불일치, 고등급 대 S3 불일치, 보류 건수를 별도 표시한다.
분모0이면 비율은 null이다. 자기신고 조건 충족 비율을 인증된 독립 합의율/정확도라 부르지 않는다.

조정 제안은 resolution_id 대신 case_id와 양쪽 제출 레코드 해시로 연결한다.
제안자는 두 제출 계정과 달라야 하며 원인 코드, 수용/반박 이유, 규칙/근거/경계 설명을 작성한다.
상태는 pending 또는 proposal_recorded뿐이다. 정책 공백을 해결했다고 주장하면 필요한 정책 결정 참조를
evidence_requests/설명에 남기고 별도 승인 절차로 보낸다. 이 파일 자체는 정책을 개정하지 않는다.
제안을 제출해도 final_grade=null, approval_status=unapproved, gold_eligible=false, training_allowed=false다.

## 6. 실제 문서 접수 계약

`pilot/intake.template.json`은 필드 설명용 빈 레코드이고 `pilot/intake.json`은 처음에 빈 배열이다.
원문 본문·비밀값·실명은 접수 JSON에 복사하지 않는다. 승인된 로컬 보관소의 불투명 참조와 해시만 기록한다.
접수 검증기는 **참조된 원문/허가 문서를 열거나 외부 URL을 호출하지 않는다**.

필수 확인:

- 사용 허가: 범위가 local_review인 허가 참조·해시·대상 조직. 단순 파일 접근 가능성과 구분.
- 출처: customer_real/public_real/unknown/synthetic. 실제 원문 근거가 없는 합성물을 real로 바꾸지 않음.
- 판본/범위: 원본 파일·추출 본문·정규화 본문 SHA-256, 기준일, 전체 페이지/첨부 수.
- 추출: 원문 페이지와 추출 결과의 연결, 표/누락 검증 참조. 페이지 수 같음만으로 완전성을 증명하지 않음.
- 계열: 원문·변형·중복을 묶는 family_id와 계열 확인 참조. 같은 문서가 서로 다른 고객 계열이라고 추정하지 않음.
- 맥락: 공개 여부·현행성·권한 등이 필요한지, 확보했는지, 입력으로 제공할지. synthetic_assumption은 실제 자료의 확인 맥락이 아님.
- 정책: 내용 보호 추천인지 고객사 실제 관리등급인지 구분. 서로 다른 정책 라벨을 같은 정답으로 섞지 않음.
- 용도: reference_review, label_only_ab_pool, customer_eval_pool 중 하나. 후속 사용 허가는 별도.
- 격리/중복: 원본문서ID·원본/본문/정규화 해시·계열ID의 제외 인덱스와 대조. 불완전 인덱스는 중복0의 증명이 아님.

제외 인덱스도 담당자가 제공해야 한다. 템플릿의 coverage_complete=false, entries=[]는
“겹침 없음”이 아니라 “아직 검사에 필요한 전체 명세 미제공”이다.
고정평가·검토보류·교정·합성후보는 학습 A/B에 넣지 않는다. customer_eval_pool에는 train/dev 이력도 제외한다.
라벨만 바꾸는 학습 후보는 이미 학습 풀에 있다는 이유만으로 제외하지 않되, 고정평가/보류 격리는 우선한다.

결과 상태:

- excluded: 용도에 맞지 않는 합성·고정/보류 자료 또는 금지된 중복/허가 거절.
- needs_metadata: 허가/원문 범위/계열/맥락/정책/제외 인덱스 등이 부족함.
- candidate_pending_source_verification: 필요한 명세가 형식상 채워짐. 아직 원문·허가·신원 진위 미확인.

어느 상태도 자동 입수·전송·검수 선정·학습 허가가 아니다. 결과에는 selected=false를 유지한다.
입력에 존재하지 않는 실제 고객문서나 사람 검수 결과를 만들어 접수 건수를 채우지 않는다.

## 7. 실제 파일럿 선정안과 완료 조건

첫 파일럿은 **40문서·20개 이상 계열을 목표로 하는 절차 점검안**이다. 통계적 정확도 보장 수량이 아니다.
허가된 모집단을 먼저 잠그고, 문서 출처/업무 영역/표 포함 여부/길이/추출 방식으로 층을 나눈다.
목표등급이나 모델 예측으로만 뽑지 않는다. TS/S1/S2/S3 포함 여부는 실제 검수 후에 확인한다.
부족한 층은 실제 추가 자료를 요청하며, 원하는 등급이 되도록 원문을 편집하지 않는다.

선정 전에 원문 소유자가 참조·해시·권한·전체 범위·추출 검증을 확인하고 계열/중복 검사를 끝낸다.
그 후 seed·모집단·제외 사유·층별 선정/부족 수를 고정해 별도 선택 도구로 표집한다.
이번 버전에는 실제 자료 표집·라벨 A/B 출력·모델 학습 기능이 없다.

이번 묶음 완료 조건: 검수 패킷40×2, 불일치/조정 계약과 검증 도구, 빈 실제 접수/제외 인덱스,
준비 상태 리포트, 단위/회귀 테스트, 원본 보존, 프로젝트 기록.
다음 사람/외부 입력: R1/R2·조정자·기준 책임자 배정, 사용 승인된 실제 원문 범위와 제외 인덱스.
