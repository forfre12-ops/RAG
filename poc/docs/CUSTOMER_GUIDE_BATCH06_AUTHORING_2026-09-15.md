# 교차 원고 64개 추가와 잔여 작성 신호

2026-09-15. 병렬 집필 A의 결과. 내부 합성 조건부 참조 후보이며 학습 배포·고객 GOLD·모델 품질 합격 보고가 아니다.

**작성 품질 상태: `AUTHORING_QUALITY_HOLD`.** 신규64개는 아래의 비정책 대상 코드 편향 때문에 학습 준비 완료로 인정하지 않는다.
기존196개도 미해결 검증 경계가 있어 준비 완료라고 주장하지 않는다. 누적260개는 원고 후보 수이며 채택 수가 아니다.

## 1. 제작 범위

기존196개의 본문·맥락·답안·근거와 정책0.1을 보존하고 신규64개를 작성했다.
4분야×2말투의 각 조합에8개, 각 등급2개씩이다. 문체 변형본이나 제목·숫자만 바꾼 사본을 새 원고로 세지 않았다.
메모·일지·문답·절차 형식은 각 등급에4개씩 배치했다. 분야·말투·형식·독립 집필 설명은 모델 입력 밖에 둔다.

| 구분 | TS | S1 | S2 | S3 | 합계 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 기존 | 38 | 56 | 49 | 53 | 196 |
| 추가 | 16 | 16 | 16 | 16 | 64 |
| 누적 후보 | 54 | 72 | 65 | 69 | 260 |
| 등급별250개까지 부족 | 196 | 178 | 185 | 181 | 740 |

부족740개는 후보260개가 나중에 모두 채택된다는 가정이다. 학습800개 측 부족540개와 별도 최종 평가200개다.
현재 **학습/평가 채택0, 본문단독 등급 채점 가능0, 새 원고의 최종 블라인드 평가 적격0**이다.

소결 승온·초음파 반사창·시료 분주 이력, 스냅샷 절단점·필터 판본·임대 시계,
계약 좌석·위탁 귀속·표본 이탈, 환류구·보충 파동·운송 기록계 등 서로 다른 사건 경계를 집필했다.
공개 여부·해당 정보에 직접 귀속된 비용과 인시·관리 조치는 명시된 가상 맥락이다.
업무 금액·재고가·장비 자산을 정보 취득 비용으로 사용하지 않는다. S3 사내 공용 안내4개도 외부 배포 허가는 없다.

## 2. 완료된 검증

- 신규64개 산술식을 본문에서 추출해 Decimal로 검산했다. 각 계산 결과를 바꾸면 실패하는 시험64개도 통과했다.
- 신규 본문 인용128개와 맥락 사실896개를 결합했다. 누적 본문 인용520개·맥락3,640개다.
- 이전 산술 근거를 보존한 누적 나열 검사는207개다. 모든 문장의 현실 진실성을 인증하는 검사가 아니다.
- 누적260개에 대해 기존 검사기의 정확 중복·숫자변형 중복·유사 본문·알려진 fixture 일치0쌍이다.
- 이전 작성 메타와 산술 감사 자료를 새 팩에도 보존했다. 기존4개 의미 계열 제안만 적용한 이 팩의 구성요소는246개이며 전체 의미 독립성 인증이 아니다.
- 신규 본문252~300자. 신규 본문115~139토큰, 본문+맥락380~405토큰이다.
- 로컬 tokenizer의 누적520뷰 모두512토큰 이내이며 최댓값491이다. 장문·의미 근거 보존·운영 연결의 증명은 아니다.
- 최종 신규 테스트167개 통과(30.64초), 신규 Python3개 ruff 통과.

첫 시험의2개 실패는 이전 누적196을 기대한 테스트 상수 잔존이었다. 테스트 기대값을260으로 바로잡았으며
원고나 정답을 테스트에 맞춰 바꾸지 않았다. 이후162개 통과, 경계 회귀5개 추가 후167개가 통과했다.

빌더는 출력 경로를 해석한 뒤 **기존 manifest가 있는 모든 조상 폴더, 부모팩 내부, tokenizer 폴더 내부 출력**을 거절한다.
부모팩을 초기·쓰기 직전·payload 작성 후·최종 검증 후 재검증하고 고정 manifest 해시를 확인한다.
스캔 중 부모 변경은 출력 전에 실패하며, 쓰기 중 부모 변경은 완성 manifest를 만들지 않는다.
동결팩 안에 자식 팩을 만들어 원본 검증을 깨뜨리는 경로를 새 batch06에서 차단했다. 이전 소스는 수정하지 않았다.

## 3. 해결하지 못한 중요한 작성 신호

동결 전 정성 검토에서 비용 규모를 암시하던 일률적 “이번 작은/소규모”와 “장기간/반복해서 정한 조건” 프레이밍을
사건 연결·기록 범위 설명으로 정리했다. 모델 점수를 보고 사실이나 라벨을 바꾸지 않았고 수치·가상 맥락은 유지했다.

그러나 **익명 영문 대상 코드가 TS 쪽에 집중된 잔여 문제가 확인됐다.** 다음 정적 표현은 TS16/16개에 있고 나머지 등급은 각각0/16개다.

```text
(분말|표면|효소|저장소|분할|저장 경로|거래군|공급군|경로|상품|구역|라인) [A-Z]
```

예를 들어 “분말 R”, “구역 D” 같은 표기다. 이러한 식별 표기는 정책의 등급 판단요소가 아니다.
따라서 수량 교차와 구조 검증이 통과했더라도 **본문의 등급 관련 작성 신호가 제거됐다고 할 수 없다.**
이 정적 집계는 모델 정확도 측정이나 실제 고객 문서의 누설 판정이 아니다. 확정된 원고는 더 수정하지 않고 한계를 통합 담당에게 전달했다.

외부 전체 풀 스캔·n-gram·고객 모델 학습·독립 의미 계열 검토는 이 집필 작업에서 수행하지 않았다.
팩의 외부 검사 결과는 `null`이다. 통합 담당의 별도 진단 결과와 의미 계열 연결을 결합해야 한다.
후속 교정이 필요하면 기존 팩을 덮어쓰지 말고 새 판본에서 사유·변경 범위를 기록한다.
다음 교정은 같은64개 계열에서 비정책 대상 이름·형식을 등급 선택과 독립되게 교차 배치하고 새 판본으로 짝지어 검사해야 한다.
통합 담당이 작성 신호의 재현 가능한 감사와 기계 판독 가능한 HOLD를 별도로 결합한다. 현재 팩의 원문이나 답안을 조용히 교체하지 않는다.

## 5. 재현과 사용 범위

작업 위치 `F:\antigravity\rag\poc`. 생성 출력은 미존재·비동결 경로여야 한다.

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:PYTHONDONTWRITEBYTECODE='1'
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'
.\.venv\Scripts\python.exe -B -m pytest --confcutdir=tests/data_quality tests/data_quality/test_customer_guide_batch06.py -q
.\.venv\Scripts\python.exe -B scripts/build_customer_guide_batch06.py verify --pack reports/CUSTOMER_GUIDE_PARALLEL02_20260915/authoring/reference_v0_6
.\.venv\Scripts\python.exe -B scripts/build_customer_guide_batch06.py prepare --out reports/CUSTOMER_GUIDE_PARALLEL02_20260915/authoring/reproduce_v0_6 --parent-pack reports/CUSTOMER_GUIDE_PARALLEL_20260915/reference_v0_5 --tokenizer artifacts/classifier_p1_v5_clean/v-fe4b386b/tokenizer.json
```

`build_new_cases()`는64개의 `(record, answer, evidence)`, `core_payload()`는 누적260개의 `(docs, answers, payload)`를 반환한다.
`prepare(out, *, parent_pack=None, corpus_root=None, tokenizer=None)`, `verify(root)`의 호출 계약은 이전 묶음과 같다.
CLI에서는 부모팩이 필수이며 함수의 테스트용 생략은 manifest에 부모 미검증으로 명시한다.

고정 가능한 답은 명시된 가상 사실과 내부 정책0.1 아래 조건부 답이다. 외부 검수자 부재를 제작 중단 사유로 삼지는 않지만,
작성자의 확신이나 AI 간 합의만으로 실제 고객 등급·사람 서명·공인 GOLD를 생성하지 않는다.
운영 API·정책 공식·검수 경로·생산 모델·학습/평가 허용 플래그·워크스페이스 메모는 이 집필 작업에서 바꾸지 않았다.
