# 고객사 합성 문서 시험 제작 계약 v1 — 학습800 / 평가200

2026-09-15. 사용자는 우리가 문서를 제작하고 고객사가800건을 학습한 뒤 골든셋200건으로 시험한다고 설명했다.
현재 제작 목표는 이800/200이다. 이전에 제안한 평가400건 확대는 승인된 수량 변경이 아니다.

## 목표와 권위

| 구분 | TS | S1 | S2 | S3 | 합계 |
|---|---:|---:|---:|---:|---:|
| 학습 | 200 | 200 | 200 | 200 | 800 |
| 평가 골든 후보 | 50 | 50 | 50 | 50 | 200 |
| 전체 | 250 | 250 | 250 | 250 | 1,000 |

1,000은 납품 대상 문서 수 목표다. 집필 계획 행, 코드 테스트, 맥락만 다른 입력, 숫자만 바꾼 복제본을 독립 문서로 세지 않는다.
기존 원장40/짧은 본문9/정책 fixture140 및 v1.1을 재분할하거나 사용 금지 플래그를 해제하지 않는다.
기존 `frozen_proxy_eval_only` 평가 자료를 학습800으로 전용하지 않는다.

새 정답의 채점 정책은 **선택 대기**다. 원 가이드 기반 기준안, 내부 내용보호 기준, 고객 별도 기준의 결과가 같지 않다.
이번 제작 요청만으로 D01~D08을 승인하거나 guide/v22/fnr 중 하나를 운영 기본값으로 바꾸지 않는다.
정책을 선택하면 기준 ID/버전/본문 해시, 충분조건/배제조건/예외/unknown 처리부터 고정한다.
외부 검수자 전원 서명 대기는 내부 답안 제작의 선행조건이 아니다. 고객사 시험 기준 채택은 별도 기록한다.

## 현재 구현의 경계

이번 구현은 **제작 준비·입력/근거 바인딩·중복 진단·분할 제안·예측 결과 채점기**다.
등급을 자동으로 확정하거나 고객 승인을 생성하는 도구가 아니다.
첫 원고 묶음은6개 업무 영역의12개 집필 초안이다. 선정한24개 주장과 원문 인용 위치를 연결한다.
현재 고정 등급0/학습 채택0/평가 채택0이며,1,000건 제작 완료가 아니다.

모든 원고·맥락은 합성이다. 현실 개인정보·인증정보·실제 고객 내부자료를 사용하지 않는다.
관리 상태·공개 여부·사업 영향은 아직 unknown이다. unknown을 false/0으로 채우거나 등급에서 역산하지 않는다.
정책 결정 후에는 실제 입력에 제공할 가상 조건을 작성하고, 답안과 함께 새 버전으로 저장한다.

주장에 맞는 문자열이 있는지 검증하는 것은 주장 전체의 의미/산술/현실 진위 검증이 아니다.
별도 의미 검산 및 단일 정책 적용 후에야 정답 후보를 채택할 수 있다. 동일 AI의 합의율은 그 대체가 아니다.

## 제작·데이터 계약

- `Document.input`: 불투명 문서 ID, 본문, 별도 가상 맥락. 정답/규칙/근거 해설/계열은 모델 입력에서 제외한다.
- `Document.claims`: 주장 이름/설명/인용/start/end/SHA256. 원문 구간 결합만 검증한다.
- `family_id`, `scenario_id`, `template_family_id`: 원문/사례/표현 계열의 제작 추적값. 모델 특징으로 사용하지 않는다.
  각기 다른 ID를 붙였다고 의미적으로 독립이라는 보장은 없다.
- `Answer`: 문서 입력 해시, 한 정책 ID/버전/해시, 정답 등급, 규칙, 본문 주장 참조, 나머지 세 등급 배제 이유.
  현재는 `authored_candidate`만 허용한다. 정답 기준의 타당성·고객 채택 진위를 계약 검사가 인증하지 않는다.
- `Prediction`: 문서/실제 제시 문자열/정책/모델 해시, 실행 ID, 입력 프로필, 상태, 예측 등급.
  다른 모델·정책·실행·입력 프로필을 한 보고서로 섞지 않는다. 해시 제출 자체는 실제 모델 실행의 인증이 아니다.

입력 프로필은 본문만 또는 본문+가상 맥락 직렬화다. 두 결과를 구분해서 기록한다.
본문만 보는 시험에는 누락된 맥락으로 달라지는 답을 강요하지 않는다. 현재12건은 필요한 맥락도 미정이라 채점하지 않는다.
운영 API 또는 기존 trainer에 맥락 직렬화를 연결한 것은 아니다.

## 분할과 중복 검사

1. 동일 본문은 NFKC/공백 제거/대소문자 통일 후 비교한다.
2. 숫자만 바뀐 텍스트 및 숫자 마스킹 후 문자5-gram Jaccard0.85 이상 근접쌍을 찾는다.
   0.85는 내부 진단 기본값이며 의미적 중복이 없음을 증명하는 임계값이 아니다.
3. 원문/사례/표현 계열 또는 근접쌍으로 연결된 문서는 전이적 연결 성분 전체를 같은 분할로 묶는다.
4. 모든 답이 같은 정책에 묶이고 등급별250건인 경우에만 각50건 평가/200건 학습 제안을 계산한다.
   seed 기반 목적함수의 정수계획법을 사용한다. 단순 균등 무작위 독립 추출이라고 주장하지 않는다.
5. 쿼터와 그룹 분리를 동시에 충족하지 못하거나30초 제한에서 풀리지 않으면 실패한다. 그룹을 쪼개 수량만 맞추지 않는다.
6. `split`의 성공은 분할 가능성이다. 자료 의미 검증·사용 승인·고객 최종시험 통과가 아니다.

외부 학습풀 검사에서는 지정한 JSONL의 최상위 text/body/content/desc를 읽어 정규화 및 숫자 마스킹 일치를 검사한다.
파싱 실패·본문 없는 행·지원하지 않는 중첩 형식은 따로 집계한다. 파일0개를 통과로 처리하지 않는다.
이 검사는 전체 학습풀의 의미적/퍼지 근접중복 검사가 아니다. 원문을 결과 로그에 복사하지 않는다.
기존 fixture fingerprint registry도 읽기만 한다. 플래그/출처를 제거한 새 원고 복사본의 전수 사용 차단은 미구현이다.

## 채점 계약

최종 고객사 시험의 분모는200건이다. 단위 테스트에서는 작은 명세를 쓰되 고객사 수량 충족 여부를 별도 표시한다.

- 정답과 제안 등급의 일치율: 검토 상태라도 등급을 제안했다면 별도 원시 일치율에 반영한다.
- 검토 불필요 응답의 일치율: 상태ok이면서 정답과 일치한 건수/전체200.
  이는 시스템 상태 지표이며 저장된 사람 최종확정률이 아니다.
- needs_review·error·missing은 따로 기록한다. 보류/실패/미제출을 분모에서 빼지 않는다.
- error에는 가짜S3/TS 등급을 넣지 않는다. 실제 TS/S1→S3 오분류와 고등급 미해결을 분리한다.
- 등급별 재현율/정밀도/F1, S1↔S2, S2→S3, TS/S1→S3, S3 과분류, 검토율을 기록한다.
- 중복 ID·추가 ID·입력/정책 해시 불일치·실행 혼합은 거절한다. 누락 응답은 미제출로 남기고 실행 미완료로 표시한다.

기존 평가 모듈은 DB 의존성을 포함하며 오류를 최저등급 예측으로 치환하는 경로가 있다.
이번 채점기는 오프라인 입력 결과만 받아 오류를 별도 열로 유지한다. 기존 운영/평가 경로는 수정하지 않는다.
`score`는 모델을 호출하지 않는다. 정답 후보를 복사해 만든 시험 예측의 점수는 채점기 검증일 뿐 모델 정확도가 아니다.

1. **제작 준비:** 계약·12개 초안·근거 바인딩·중복/입력 크기 진단·분할/채점 테스트. 이번 실행 범위.
2. **정책 및 의미 고정:** 정책 선택, 공개/관리/가치 가상 조건, 기준별 근거와 독립 의미 검산. 미완료.
3. **1,000건 집필·선별:** 다양한 업무·표현·판정 경계, 부족한 등급을 억지로 채우지 않기. 미완료.
4. **골든200 분리:** 전체 누설/중복/입력 적합성 검사,800/200 분할 및 격리, 기준/정답 동결. 미완료.
5. **시험용 배포:** 새 학습 경로800 및 평가 입력/정답200의 역할별 사용권한, 고객 프로토콜 채택. 미완료.
6. **고객사 실행:**800내부에서 설정 선택 후 모델 고정,200최종 평가. 운영 자동 교체 없음. 미실행.

정책 미선택이나 내부 초안 단계의0건을 성공적인 최종 골든셋으로 포장하지 않는다.
