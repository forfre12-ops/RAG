# 주 출력·적용 정책 결정 검토안 — D01 / D02

상태: **AI 작성 권고안, 미승인**. 기존 운영 기본값·출력·모델·정답을 변경하지 않는다.
이 문서의 작성 완료나 사용자의 작업 진행 요청을 발주처/고객사 정책 승인으로 기록하지 않는다.
`classification_decisions.pending.json`의 D01/D02는 여전히 pending이다.

## 제안하는 결론

본 사업의 주 결과는 **확인 가능한 증거를 선택된 정책에 적용한 보안등급 후보**로 제안한다.
현재 보유한 증거에 따른 정책 평가이지, 문서 본문만으로 고객사의 기존 저장등급을 추측하는 기능이 아니다.
관리자 최종확정은 별도다. 내용 보호필요도는 필요하면 보조 의견으로 분리한다.

기본 정책의 검토 출발점은 제공된 **원 가이드(guide)**로 제안한다. 고객사별 예외와 네 조합의
처리를 승인받기 전에는 현재 운영 v22를 전환하지 않는다. guide를 제안한다는 것도 자동 승인이나
모든 고객에게 동일 정책을 강제한다는 뜻은 아니다.

근거: 선행 요구사항 대조에서 FUN-004/005의 모델 학습·자동 보안등급 판별·관리자 최종확정,
FUN-023의 가이드 기반 라벨 매핑·핵심 판단요소 연계/활용을 확인했다.
이 방향이 요건과 더 직접적으로 연결된다는 **설계 판단**이며, 요건 문구가 아래 제품 정의를
이미 모두 확정해 준다는 주장은 아니다. 대조 범위는 [재발 방지 계획](CLASSIFICATION_RELIABILITY_PLAN_2026-09-15.md)을 참고한다.

## D01: 무엇을 판단할 것인가

정책 출처와 분류 대상은 다른 축이다. 아래 대안은 각각의 제품 의미를 드러내기 위한 것이며,
주 출력의 문구만 바꾸고 정답·증거 기준은 그대로 쓰면 안 된다.

| 대안 | 정답을 정하는 기준 | 얻는 것 | 필요한 것 / 위험 |
|---|---|---|---|
| A. 증거·정책에 따른 보안등급 후보 **권고** | 판정 시점에 확인된 S/V/M 등 사실과 승인된 정책 | 판단요소·근거·재현 가능한 정책 결정 연결 | 공개/가치/공유·관리 정보가 없으면 보류가 늘어남 |
| B. 고객사의 기존 관리등급 재현 | 고객사가 실제 부여한 판본별 등급과 적용 정책 | 기존 업무 분류와의 일치 여부 측정 가능 | 기존 오분류를 그대로 학습할 수 있고 실제 고객 라벨 필요 |
| C. 필요한 내용 보호수준 추천 | 별도 승인한 위험·보호 필요도 기준 | 관리가 미흡한 고가치 내용도 보호 의견 제시 가능 | 지금의 내용보호 초안은 사업 주 기준으로 승인되지 않음 |

A를 채택해도 ‘필요한 보호 수준’을 주 의미로 삼을지, ‘현재 확인된 정책 요건의 충족 정도’를
주 의미로 삼을지 최종 문구를 정책 책임자가 고정해야 한다. 이 검토안의 A는 **후자**다.
현재 승인 초안 A01/D01의 관리등급 재현/보호필요도 선택을 대신 확정하지 않으며,
두 선택지만으로 부족하다면 위 의미를 명시하는 수정안을 승인해야 한다.

### 입력과 출력의 경계

- 입력: 본문·판본·조직 정책 ID와 공개 상태/가치/정보공유·관리 범위의 확인 가능한 근거.
  본문에서 추출한 내용, 관리시스템 제공 사실, 사람 확인, 모델 추정은 출처를 구분한다.
- 숫자 S/V/M을 사용자가 반드시 직접 입력할 필요는 없다. 다만 사실을 모델이 추정했다는 것과
  사실이 확인됐다는 것은 다르다. `evaluation_factors`처럼 등급에서 역산한 값은 독립 증거가 아니다.
- 출력: 후보 등급, 검토 상태, 적용 정책/규칙, 근거 위치, 확인되지 않은 항목, 판정 시점.
  모델의 등급 예측·요소 추정과 정책 적용 결과도 구별한다. 불일치 처리는 D05 승인 대상이다.
- 필수 근거가 없으면 `needs_evidence`, 정책 충돌은 `needs_policy_review`로 제안한다.
  보류를 낮은 등급으로 치환하지 않는다. 실제 응답 필드 도입은 별도 구현/호환성 검토 대상이다.
- 기존 고객사 저장등급은 별도 비교값으로 두며, 보호필요도 보조 의견과 하나의 정답으로 합치지 않는다.
- S3 후보라고 외부 공개·전송 권한이 생기는 것은 아니다. 등급 판정과 접근/반출 승인은 별도다.

## D02: 어느 정책을 적용할 것인가

1. 내부 비교의 기준점으로 원 가이드 guide를 제시한다. 현행 v22는 내부 보정 모드로 구분한다.
2. 27조합 중 서로 다른 네 조합은 D04 표의 **구현 비교값**이며 아직 정답이 아니다.
   guide/v22/fnr 중 적용 모드, 예외 조건, 승인자를 함께 기록한다.
3. 고객사 정책을 받으면 조직·문서 범위·판본·시행일을 묶어 버전 관리한다.
   고객사 정책이 없다고 내부 내용보호 초안을 자동 대체 정책으로 선택하지 않는다.
4. M=unknown과 M=0은 다르다. 정책 모드를 바꾸어도 증거 부족 문제가 해결되지는 않는다.
5. 가이드의 S 또는 V만으로 분류 가능한 예외는 고객사 상황과 승인된 적용 범위에 따라 선택한다.
   숫자 단계 중복 실험을 근거로 M 전체를 삭제하지 않는다.

| 결정 | 이 문서의 제안 | 실제 결정 상태 |
|---|---|---|

| 관리자 최종확정과 구분 | 후보/보류와 최종 등급 분리 | 미정 |
| 기본 정책 검토안 | guide를 기준점으로, 고객사 예외는 승인·버전 관리 | 미정 |
| 실제 운영 적용 모드 | D04 네 조합 검토 후 결정; 현재 v22 유지 | 미정 |
| 필수 요소·정보 부족 | D03/D05에서 증거와 unknown 처리 확정 | 미정 |
| 정답 모집단·평가 분모 | D06/D07에서 별도 확정 | 미정 |

실제 담당자·결정 내용·근거 문서가 오면 D01/D02에 결정 기록을 연결하고 승인 진위를 별도로 확인한다.
그 전에는 추가 정답 대량 제작·라벨 A/B 재학습·고객 정확도 발표를 재개하지 않는다.
