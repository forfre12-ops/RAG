# v6 학습 결과에 대한 사전 예측 — 결과를 보기 전에 적는다

작성 2026-08-12 07:35 KST. **학습 진행 중, 평가 전에 작성.**
결과를 본 뒤에 설명을 붙이면 무슨 말이든 맞출 수 있다. 그래서 먼저 적는다.

---

## 1. 관찰된 것 — 학습 손실이 너무 빨리 떨어졌다

```
epoch 0.17  loss 1.403
epoch 0.43  loss 0.758
epoch 0.61  loss 0.104
epoch 0.87  loss 0.005
epoch 0.96  loss 0.003
```

4등급 분류에서 1 epoch 만에 loss 0.003 이면 **학습셋을 거의 완전히 외웠다**는 뜻이다.

## 2. 왜 그런가 — v6 는 결정적으로 풀린다

v6 는 등급을 요인 조합으로 드러내게 다시 썼다. 그런데 등급은
`grade_from_svm(secrecy, value, management)` 의 **함수**다. 즉 문서에서 세 요인 문장을
읽어내면 등급이 규칙으로 결정된다. loss → 0 은 이 구조에서 **예상되는 결과**이며
그 자체가 결함은 아니다.

문제는 그다음이다. 각 (요인, 수준) 마다 문장 변형이 6~16종뿐이다. 모델이 배울 수 있는
것이 두 가지로 갈린다:

| 무엇을 배웠나 | 실문서에서 |
|---|---|
| **(A) 문자열 → 수준** 매핑을 외움 | 무너진다. 실문서는 그 16개 문장을 쓰지 않는다 |
| **(B) 사실 → 수준** 을 일반화 | 버틴다. 다르게 쓰여도 같은 사실이면 읽는다 |

학습 손실만으로는 A 와 B 를 구분할 수 없다. 둘 다 loss 0 을 만든다.

## 3. 그래서 v3 평가셋이 결정적이다 — 이게 분리 검정이다

평가셋 v3 는 **의도적으로 다른 문장 풀**로 만들었다(`eval_fact_pools.py` ↔
`v6_fact_pools.py`, 문장 공유 0종을 테스트로 고정). 사실은 같고 표현만 다르다. 예:

```
학습셋 secrecy=2  "공개 자료만으로는 같은 결과를 다시 만들 수 없는 조건이 함께 적혀 있다"
평가셋 secrecy=2  "본문의 조건 결합은 배포된 문서를 모두 모아도 복원되지 않는다"
```

처음에는 "같은 풀을 쓰면 오염된다"는 이유로 분리했는데, 결과적으로 **A/B 를 가르는
검정**이 됐다. 의도한 것보다 쓸모가 크다.

## 4. 사전 예측 (결과 미확인 상태에서 작성)

`artifacts_out/classifier_v6_baseline` 을 `v3/final_800.locked` 로 채점했을 때:

- **F1_macro 0.25~0.40 (무작위~약간 위)** → 가설 A. 모델이 문자열을 외웠다.
  v6 의 문장 풀이 너무 좁다는 뜻이고, **변형 수를 크게 늘리거나(수백 종) 요인 서술을
  생성적으로 만들어야** 한다. 코퍼스 설계 문제이지 학습 문제가 아니다.
- **F1_macro 0.60~0.85** → 가설 B 쪽. 표현이 달라도 사실을 읽었다. 이 경우에도
  실문서 일반화 근거는 아니다(둘 다 합성이고 어휘·문형이 같은 계열이다) —
  **"표현 변화에 견딘다"까지**가 정직한 주장이다.
- **F1_macro 0.85 이상** → 의심한다. 두 풀 사이에 내가 못 본 공유 신호가 있는지
  다시 센다(문장 공유 0 은 확인했지만 어절·연어 수준은 안 봤다).

**나는 A 쪽(0.25~0.40)에 무게를 둔다.** 변형이 수준당 6~16종이면 1,833건 학습에서
각 문장이 수십 번 반복된다. 그 정도면 외우는 쪽이 쉽다.

## 5. A 로 나와도 실패가 아니다

A 는 **v6 코퍼스의 천장을 정확히 잰 것**이고, 그 천장은 지금까지 아무도 재지 않았다.
종전 셋으로는 잴 수조차 없었다 — 학습셋과 평가셋이 같은 지름길을 공유해서 항상
높은 값이 나왔기 때문이다(v4_3 이 dev200 0.99 를 받고 실문서 0.61 로 무너진 구조).

A 가 나오면 다음 조치는 분명하다: **요인 서술의 표현 다양성을 늘린다.** 그건 문장 풀을
키우는 기계적 작업이고, 무엇을 고쳐야 할지 모르는 상태보다 훨씬 낫다.
