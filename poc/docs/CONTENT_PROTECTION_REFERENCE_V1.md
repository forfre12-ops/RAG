# 내용 기반 보호등급 참조 기준 v1 — 완성 검토안

- 정책 ID: `content-protection-reference-v1-draft`
- 상태: **미승인 내부 제안**. 고객사 정책·법률 판단·실제 관리등급이 아님.
- 목적: 문서 내용과 명시된 사례 조건으로 **필요한 보호등급**을 추천한다.
- 작성: AI 초안. 승인자·사람 검수 서명: 없음.
- 적용 범위: 일반 기업 업무·기술·개인정보를 포함한 참조 사례. 국가기밀·특정 법률의 법정 등급은 제외.
- 기존 TS/S1/S2/S3 코드를 빌려 쓰되, 고객사에서 같은 이름을 쓴다는 이유로 의미가 같다고 보지 않는다.

## 1. 판정 대상과 입력

판정 대상은 지정된 버전의 **문서 전체**다. 추출 실패·누락 페이지·미확인 첨부가 등급을
바꿀 수 있으면 필요한 부분을 확보하기 전까지 `needs_evidence`로 남긴다.

본문에 직접 있는 사실과 작성자가 알려 준 맥락은 출처를 분리한다. 실제 데이터에서는
문서 소유자·시스템·보관 원문으로 확인해야 하는 사실을 모델 추정으로 확정하지 않는다.
이번 합성 사례의 맥락은 `synthetic_scenario`라는 **가상 시험 조건**이며 실제 고객사 증거가 아니다.

제목, 전문용어, 문서 길이, 작성 부서, “극비/대외비”라는 단어만으로 등급을 결정하지 않는다.
실제 보안표시는 별도 관리정보로 보존하되 이 내용 추천을 이미 확정된 관리등급처럼 표시하지 않는다.

## 2. 네 등급의 포함·제외 기준

### TS — 핵심 재현·통제 또는 결합 민감정보의 집중 위험

다음 세 규칙 중 하나를 충족해야 한다. “중요하다”는 주장만으로 적용하지 않는다.

| 규칙 ID | 포함 조건 | 필요한 근거 | 제외·경계 |
|---|---|---|---|
| CP-TS-01 | 아직 안전하게 공개된 것으로 확인되지 않은 핵심 제품·공정·알고리즘의 **완전한 재현 묶음**. 핵심 단계, 결정 변수, 검증 기준이 함께 있고 같은 기능을 재현할 수 있다는 사례 맥락이 명시됨 | 해당 단계·변수·검증 기준, 완전성·현행성·핵심성 확인 | 일반 기술 설명, 공개 교재, 일부 실험 결과·일부 파라미터는 이 규칙만으로 TS 아님 |
| CP-TS-02 | 현재 유효하며 그 자체 또는 함께 제공된 절차로 운영 배포·자금 집행·핵심 저장소 통제를 가능하게 하는 인증·서명·복구 재료 | 실제 값의 존재와 유효성·권한 범위. 시험 사례는 모두 허구로 명시 | 만료·폐기·마스킹·견본 값, 단순 설정 항목명은 제외. 유효성 미확인은 추가 확인 |
| CP-TS-03 | **1,000명 이상**의 식별 가능한 개인과 건강·금융계좌/채무·생체인증 중 하나 이상의 민감 세부정보가 연결된 원장, 또는 그 원장과 재식별 키가 함께 제공됨 | 인원 수, 개인 식별 가능성, 민감 필드, 연결·재식별 가능성 | 집계·유효 익명화 결과와 단순 업무 연락처 명부는 이 규칙에서 제외. 1,000은 이 제안의 내부 경계이며 법정 기준이 아님 |

TS와 S1의 경계는 완전 재현성·현재 통제 가능성·명시한 결합 규모다.
1,000명 미만의 민감 개인자료나 일부 핵심 기술자료는 다른 조건을 확인하여 S1을 검토한다.
TS보다 높은 등급은 이 정책에 없다. 그것이 안전성이나 실제 피해 한계의 증명은 아니다.

### S1 — 특정 개인·거래·제품에 대한 구체적 보호 정보

`CP-S1-01`: TS 세 조건은 충족하지 않지만 다음 중 하나가 실제로 담겨 있다.

- 개인과 연결된 평가·보수·건강·금융 세부내역.
- 아직 배포 승인되지 않은 거래별 가격·원가·협상 하한·계약 조건·수요나 투자 판단의 구체 값.
- 제품별 설계·코드·실험 조건·결함·노하우의 실질적인 일부로서 일반 지식보다 구체적인 경쟁 정보를 제공하는 내용.

필요 근거는 실제 데이터·조건이 있는 위치, 연결 대상, 공개·폐기·익명화 여부다.
빈 입력칸, 가명이라는 이름만 붙인 재식별 가능 자료, 일부 숫자를 가린 원본은 각각 구별한다.
가명처리했다고 자동 S3로 내리지 않는다. 반대로 일반 업무 제목만으로 S1을 부여하지 않는다.

S1과 S2의 경계는 **보호해야 할 구체적인 개인·거래·기술 세부값의 존재**다.

### S2 — 내부 운영 세부사항

`CP-S2-01`: TS/S1 조건은 충족하지 않으며, 현재 업무의 일정·역할·설비 배정·내부 식별자·
실행 중인 업무 흐름 등 조직별 운영 세부사항이 담겨 있다. 공개 배포 대상으로 확인되지 않았다.

단순히 내부에서 작성했다는 이유만으로 S2가 아니다. 외부인이 얻을 수 없는 업무상 세부내용이
본문에 있어야 한다. 공개 행사 일정처럼 안전한 배포 범위가 명시된 자료는 S3 조건을 확인한다.
개인 이름만 있다는 이유로 민감 평가자료라고 확대하지 않되, 이름과 금융·건강·평가가 결합되면 S1/TS를 확인한다.

### S3 — 일반 지식·빈 공통 서식·안전한 배포본

`CP-S3-01`: TS/S1/S2의 보호 내용을 포함하지 않고 다음 중 하나가 확인된다.

- 특정 조직·개인·거래와 연결되지 않은 일반 지식·교육 설명.
- 실제 값이 입력되지 않은 공통 서식 또는 무해한 예시.
- 해당 버전에서 보호 정보가 제거되었고 안전한 배포 범위가 확인된 공개·배포본.

“인터넷에서 찾았다”, “공개 예정”, “공개 승인이 있었던 이전 버전”만으로 S3를 부여하지 않는다.
공개된 자료라도 보호 대상 개인자료·유효 인증정보가 남아 있으면 상위 규칙을 검토한다.
S3는 법률상 무제한 이용 허가나 외부 전송 허가를 뜻하지 않는다.

## 3. 결정 순서와 예외

1. 적용 정책·문서 버전·판정 범위를 확인한다. 근거 간 모순은 `CP-HOLD-02`로 기록한다.
2. 필요한 페이지·첨부·현행성·유효성·맥락이 없으면 `CP-HOLD-01`로 추가 증거를 요청한다.
3. 확인된 사실에 CP-TS-01/02/03 → CP-S1-01 → CP-S2-01 → CP-S3-01 순으로 적용한다.
4. 여러 보호 조건이 동시에 성립하면 높은 등급을 선택하고 함께 성립한 규칙도 기록한다.
5. 공개·익명화·만료라는 예외는 **해당 버전과 대상 필드**에 확인된 범위에서만 적용한다.
   공개라는 표제가 구체적인 보호 내용보다 우선하지 않는다.
6. 어떤 규칙도 입증되지 않으면 S3로 기본 처리하지 않고 `CP-HOLD-01`로 남긴다.

`CP-HOLD-01`: `grade=null`, `decision_status=needs_evidence`, 후보 등급·빠진 증거 기록.
`CP-HOLD-02`: `grade=null`, `decision_status=needs_policy_review`, 충돌 근거·해결 책임 기록.
검토 상태는 다섯 번째 등급이 아니다. 조건부 설명을 쓸 수 있지만 확정 등급 필드와 혼합하지 않는다.
이미 충분히 입증된 TS를 더 낮은 규칙의 미확인 정보 때문에 임의로 낮추지 않는다.

## 4. 근거와 정답 후보 계약

각 사례는 원문 입력과 답안을 분리한다.

- 입력: doc_id, family_id, text, 본문 SHA-256, 정책 버전·해시, 합성 출처와 전체 문서 여부.
- 답안: expected_grade 또는 검토 상태, rule_ids, 결정 사실, 근거 span과 인용,
  상·하위 등급 배제 이유, 누락 증거·충돌 조건, AI 작성 및 미승인 상태.
- span은 Python 문자열 인덱스, 0부터 시작하는 `[start,end)`이며 정확히 원문 인용과 일치해야 한다.
- 부재 근거는 단순히 “키워드가 없다”가 아니다. 완전한 합성 사례 범위에 대한 작성자 가정임을
  별도 표시한다. 실제 자료의 부재 확인을 대신하지 않는다.
- 규칙 검산 함수는 명시된 시험 사실을 계산할 뿐 **본문에서 사실을 추출하는 분류 모델이 아니다**.
- AI 작성 답안을 그 함수 출력으로 채우지 않는다. 먼저 작성한 답안을 함수와 대조해 모순을 찾는다.
  이 교차검사도 작성자와 독립된 전문가 검수나 정답 진위 인증은 아니다.

## 5. 사례·분할·평가

30개 업무 계열마다 TS/S1/S2/S3 사례를 한 건씩 작성하여 등급 후보 120건을 구성한다.
10개 검토 계열마다 정보 부족·맥락 충돌 사례를 한 건씩 작성하여 검토 후보 20건을 구성한다.
계열의 변형은 분할을 넘지 않는다. 고정 seed 20260914로 개발용 90(등급80+검토10),
봉인 후보 50(등급40+검토10)을 구분한다. 각 등급은 개발20/봉인후보10이다.

이 묶음은 **짧은 합성 미시 사례의 후보집**이다. 장문·OCR·표·고객사 분포를 대표하지 않는다.
대량 원장·코드 묶음은 해당 자료의 존재·범위를 서술한 가상 상황 카드이며 실제 1,000행 표나
완전한 제품 소스를 생성한 것이 아니다. 이 단계는 **기준 경계의 예시화**이고 실문서 분류 성능 시험은 아니다.
`SIMULATED-*` 통제 재료도 현실에서는 무효이며 가상 세계 안에서만 유효하다는 시험 조건이다.
생성 템플릿·작성자가 공통이므로 계열 분리가 의미·문체 독립성을 보증하지 않는다.
`sealed_candidate`는 파일 분할 이름이지 접근 통제나 독립 블라인드 평가 인증이 아니다.
이 AI 작성자는 양쪽 내용을 알고 있다. 검수 전후 봉인 절차는 별도로 수행한다.

모델 입력은 `text`만 사용한다. 답안의 규칙·사실·등급·분할 정보는 모델 입력에 붙이지 않는다.
외부 맥락에 의존하는 실제 자료는 별도 입력 계약이 필요하다. 이번 가상 조건은 본문에 명시한다.
검토 대상에 실제 등급 정답을 억지로 넣지 않는다. 등급 평가는 등급 후보120건,
검토 평가는 140건 전체에서 각각 분모를 공개한다. 검수로 보내도 등급 오답은 없어지지 않는다.

## 6. 비교 학습 준비와 보호 경계

이번 후보 140건과 기존 교정20건은 학습에 넣지 않는다. 기존 train/held_review/locked_gold_eval
격리를 유지하고, 검토받지 않은 후보를 학습기로 자동 전달하지 않는다.

향후 실험 A/B는 같은 원문·분할·초기 모델·seed·학습 조건에서 **라벨만** 바꾼다.
라벨을 확정하지 못한 문서는 A/B 양쪽에서 동일하게 제외하고 제외 수·등급 분포를 보고한다.
새 문서 추가·모델 구조·가중치·임계 변경은 별도 실험이다. 본문+label 학습 입력은 유지하고
정책·근거·라벨 변경 이력은 doc_id와 해시로 결합된 sidecar에 보존한다.

지표: 4등급 혼동행렬, 등급별 precision/recall, S1↔S2, S2→S3, TS/S1→S3,
S3 과분류, 검토 포착/누락/불필요 검토, 검수 미라우팅 오류와 처리 비율.
후보의 자기 일치도를 고객사 정확도로 발표하거나 배포 허가로 사용하지 않는다.

## 7. 기존 기준과의 차이 및 남은 승인 쟁점

기존 S×V×M은 비공지성·유용성·관리성을 점수화하여 등급을 계산한다. 이 초안은 필요한
보호를 내용 조건으로 직접 정의하며, 실제 관리가 미흡하다는 이유로 보호 필요가 낮아지지 않는다.
이 때문에 기존 guide/v22/fnr 또는 고객사 정답과 다른 결과가 정상적으로 생길 수 있다.

검토할 쟁점:

1. TS의 완전 재현 묶음 범위, 유효 통제 재료의 권한 범위, 1,000명 경계의 채택 여부.
2. 공개되었지만 보호 정보가 남은 문서의 처리와 적절한 배포본 확인 절차.
3. S1 개인·거래·기술 범위 및 S2 내부 운영정보의 고객사별 예외.
4. 정답 검수자·불일치 조정자와 승인 권한. 승인·사람 서명은 아직 없음.
5. 고객사 실제 평가 표본·오류 허용치·검수량·외부 연동 계약.

이 쟁점이 남아 있어도 **본 초안 조건에 따른 답안 후보 작성**은 진행한다.
다만 미승인 후보를 GOLD나 운영 정책으로 바꾸는 단계는 진행하지 않는다.

## 8. 오프라인 검산 구현과 사용법

`scripts/content_reference_cases.py`에는 30×4개 등급 사례와 10×2개 검토 사례의 작성 원고가 있다.
답안은 작성 원고의 의도에 따라 먼저 지정하고, `scripts/content_reference_contract.py`가 명시된
가상 조건과 답안의 일관성만 검산한다. 두 자료 모두 같은 AI 작성자가 만들었으므로 독립 정답 검증이 아니다.

| 조건 키 | 내용이 존재하는 조건 | 우선 적용 규칙 |
|---|---|---|
| core_package | 핵심 완전 재현 묶음 | CP-TS-01 |
| live_control | 현행 핵심 통제 재료 | CP-TS-02 |
| bulk_sensitive | 1,000명 이상 식별·민감 필드 연결 | CP-TS-03 |
| specific | 특정 개인·거래·실질 기술 세부값 | CP-S1-01 |
| internal | 현재 내부 운영 세부사항 | CP-S2-01 |
| generic | 일반 설명·빈 서식·안전한 배포 조건 | CP-S3-01 |

조건들은 낮은 위험의 내용이 함께 존재함도 기록할 수 있다. 실제 **적용 등급 규칙**은 상위
조건 우선 및 각 등급의 제외 조건을 거친다. 예를 들어 TS 원장에는 specific 내용도 있지만
S1로 결정하지 않는다. 미확인 조건의 가능한 참/거짓 조합을 열거하여 결과가 달라지면
`needs_evidence`, 이미 입증된 최상위 결과가 변하지 않으면 그 결과를 추천한다.
대상 버전·맥락의 충돌은 이 열거로 임의 해소하지 않고 `needs_policy_review`로 남긴다.

재현 명령(poc 폴더, 새 출력 경로):

```powershell
./.venv/Scripts/python.exe -B scripts/prepare_content_reference.py --out reports/CONTENT_REFERENCE_새실행/reference_v1
./.venv/Scripts/python.exe -B scripts/validate_content_reference.py --pack reports/CONTENT_REFERENCE_새실행/reference_v1 --out reports/CONTENT_REFERENCE_새실행/recheck.json
```

외부에서 생성한 추론 레코드를 측정하려면 검증 명령에 `--predictions 경로 --split development`를
추가한다. 레코드마다 `doc_id`, `text_sha256`, `policy_version`, `policy_sha256`, `predicted`,
`model_grade`, `status`가 필요하다. 등급은 TS/S1/S2/S3 또는 null, 상태는 staging/needs_review다.
전체 또는 지정 분할의 ID 집합이 정확히 같아야 하며 누락·중복·다른 본문/정책은 오류로 막는다.

등급을 추천하지 않은 결과(null)는 120건 분모의 정확도에서는 오답으로 남기고 미추천 수를
따로 낸다. 기존 4등급 혼동행렬은 유효 등급 예측만 넣고 그 분모를 따로 공개한다.
검토 정답20건에 임의 등급을 붙이지 않으며 검토 라우팅은 전체140건에서 측정한다.
모델 raw 등급이 없으면 기존 평가기의 최종 등급 대체 동작을 사용하지만 누락 수와 한계를 표시한다.
이번 제작에서는 추론 레코드를 생성하지 않았으므로 **모델 품질 점수는 미측정**이다.
