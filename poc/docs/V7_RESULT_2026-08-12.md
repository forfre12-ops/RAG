# v7 결과 — 결박 두 개를 동시에 풀었다

작성 2026-08-12. `V6_RESULT_2026-08-12.md` 의 후속이다.

## 1. 오늘 드러난 것 — 결박이 두 종류였다

같은 검사를 여러 셋에 돌려 보니 두 계보가 **서로 다른 지름길**을 쓰고 있었다.

| 계보 | 결박 | 증거 |
|---|---|---|
| v5 (배포본) | **장르** — S3 = 판례 | 학습셋 S3 의 24.8% 가 판례, 중앙 1,096자(다른 등급 336~429) |
| v6 (신규) | **길이** — 2,140자 미만을 본 적 없음 | 학습셋 전 등급 2,140~3,625 로 균일 |

증거가 되는 측정(같은 모델, 다른 길이대):

```
v6 → v3 final_800 (2,100~3,600자)   S3 recall 0.858
v6 → mundane_s3   (120~276자)       S3 recall 0.000   ← 500건 전부 S2
v5 → mundane_s3                     S3 recall 0.202
```

**v6 는 장르 결박을 없앴지만 길이 결박이 생겼고, 짧은 문서에서는 v5 보다 나빴다.**
하나만 고치고 끝낼 문제가 아니었다.

## 2. v7 — 두 축을 같이 고친다

v6 + mundane_s3(짧은 비-판례 S3) + patent_proxy(TS/S1) + v5train 에서 재구성.

**설계에서 배운 것**: 등급 *안에서*만 길이를 고르면 부족하다(1차 시도 길이-only 0.692).
등급마다 출처가 달라 주변 분포가 갈린다 — 중앙 길이가 S3 193 vs S2 1,037 로 5배 벌어졌다.
**전역 길이 구간을 잡고 모든 등급이 각 구간에서 같은 수를 가져가야** 길이가 정보를 잃는다.

**판례를 빼지 않았다.** 유일한 실데이터이고 정당한 S3 다. 바꾼 것은 "S3 = 판례"라는
등식이지 판례의 존재가 아니다.

```
학습셋 지표   길이-only 0.378 · Theil's U 0.023 · tell 0종(커버 0.000)
             S3 판례 24.8% → 2.6%
             등급별 500자 미만  TS 154 · S1 145 · S2 148 · S3 260
분할          train 1,936 · val 443 · test 443 (가족 분리 · 겹침 0)
```

## 3. 결과 — 모든 축에서 개선

### 긴 문서 (v3 final_800 · 800건 · 봉인 · 계보 독립 확인)

| | v5 배포본 | v6 | **v7** |
|---|---|---|---|
| F1_macro | 0.2613 | 0.7035 | **0.7436** |
| accuracy | 0.3425 | 0.700 | **0.7525** |
| 고등급 FNR | 0.5472 | 0.4028 | **0.3500** |
| TS recall | 0.0625 | 0.569 | 0.525 |
| S1 recall | 0.720 | 0.615 | 0.715 |
| S3 recall | 0.025 | 0.858 | 0.804 |

### 짧은 문서 (mundane_s3 · 500건 · 120~276자)

| | v5 | v6 | **v7** |
|---|---|---|---|
| S3 recall | 0.202 | **0.000** | **1.000** |

⚠ mundane_s3 는 **전부 S3 단일 등급**이라 "모든 문서를 S3 라고 해도" 1.0 이 나온다.
그래서 v3 의 예측 분포를 함께 봐야 한다 — v7 은 S1 145 · S2 287 · S3 259 · TS 109
(정답 200/200/240/160)로 **네 등급에 고루 분포**한다. S3 로 몰아붙인 것이 아니다.

### 자체 test 가 처음으로 정보를 가졌다

```
v6   F1 1.000 · accuracy 1.000   ← 규칙으로 풀려 아무것도 못 알려줌
v7   F1 0.940 · accuracy 0.941 · fnr_high 0.053
     TS 0.92 · S1 0.92 · S2 0.96 · S3 0.96 (F1)
```

**온도 보정도 같이 정상화됐다:**

```
v6   T 0.05 (퇴화 — val 정확도 100% 라 보정 신호 없음) · 재보정 후 2.4755, ECE 0.138→0.177 악화
v7   T 1.2628 · ECE 0.0328 → 0.0199 개선
```

v6 는 검증셋이 너무 쉬워 온도를 추정할 수 없었고, 재보정해도 ECE 가 나빠졌다.
v7 은 94% 라 여유가 있어 **정상 적합됐고 ECE 도 개선**됐다.
길이·장르 다양성을 넣자 **셋이 측정 가능해진 것**이다.

## 4. 서빙 경로 무음 미탐 — 셋에 따라 0% 와 3.8%

모델 단독 FNR 과 운영 FNR 은 다른 값이다. 서빙 가드를 태우고 쟀다.

**처음에 v3 에서만 재고 "무음 미탐 0.0%"라고 적었다. 셋을 하나 더 대자 무너졌다.**
같은 배포본·같은 서빙 경로인데 결과가 갈린다:

| | v3 final_800 (배포본에게 분포 밖) | hardened42 (배포본 자기 계보) |
|---|---|---|
| 고등급 | 360건 | 26건 |
| **무음 미탐** | **0건 = 0.0%** | **1건 = 3.8%** |
| 자동확정률 | 0.0% (0/800) | 40.5% (17/42) |
| 자동확정 정밀도 | - | 94.1% |
| confidence 중앙 | 0.389 (최대 0.635) | 0.755 (최대 0.895) |
| 룰 미검출 | 99.4% | 38.1% |
| 모델 정확도 | 32.5% | 92.9% |

**"무음 미탐 0"은 v3 한정 수치다.** v3 에서 0 이 나온 이유는 가드가 강해서가 아니라
모델이 그 셋에서 32.5% 밖에 못 맞혀 confidence 가 임계 아래로 깔렸고, 그래서 800건
**전부**가 검수로 갔기 때문이다. 자동확정이 0 이면 무음 미탐도 정의상 0 이다.
안전의 증거가 아니라 **자동화가 멈춘 것의 부산물**이다.

자동확정이 실제로 열리는 셋(hardened42, 40.5%)에서 재니 무음 미탐이 나왔다:

```
truth S1 → predicted S2 · confidence 0.843 · status staging · warnings 없음
```

confidence 게이트도 룰 합의 게이트도 통과했다. **모든 가드를 통과한 조용한 등급 하락**이다.

### 임계 0.70 은 유지가 맞다 (측정으로 확인)

자동확정 0% 를 보고 "임계가 잘못 잡혔다"고 판단했는데 **틀렸다.** 임계를 내리면
모델 정확도 32.5% 구간에서 자동확정이 열린다:

```
임계 0.70 → 자동확정  0.0% · 무음 미탐   0건   ← 현행
임계 0.60 → 자동확정  1.2% · 정밀도 0.600 · 무음 미탐   2건
임계 0.50 → 자동확정 13.5% · 정밀도 0.518 · 무음 미탐  23건
임계 0.35 → 자동확정 66.6% · 정밀도 0.385 · 무음 미탐 113건
```

confidence 게이트는 **OOD 탐지기로 정상 작동**했다. 모델이 자기 능력 밖인 문서 뭉치를
만나 전건을 사람에게 넘긴 것이다.

덧붙여 임계는 애초에 구속 조건도 아니었다. 합의 게이트까지 넣고 재계산하면 임계를
0.20 까지 내려도 v3 자동확정은 **0.6%(5건)** 뿐이다. 진짜 병목은 **룰 추출기가 v3
문체에서 99.4% 미검출**이라는 점이다.

### 무음 미탐 1건을 파보니 라벨 경계였다

문제의 문서(178자, 공급망 대응 계획)의 심판 요소 평균은 **s=2 · v=1.67 · m=0** 이다.
이산화 방식만 바꾸면 정본 규칙에서 **네 등급이 다 나온다**:

```
v 반올림→2, m=0 유지    → S1   ← 평가셋이 채택한 라벨
v 반올림→2, m→1 floor   → TS
v 내림→1,  m=0 유지     → S3
v 내림→1,  m→1 floor    → S2   ← 모델이 예측한 등급
```

라벨 이력도 흔들린다: `gold_intended=S2` · `claude_rejudge=TS` · `judge_consensus=S1(2/3)` ·
`eval_truth_level=machine_adjudicated_silver`(사람 서명 없음) · `reviewer_id=public_gold_collector`
(사람 아님). 증거 스팬 텍스트는 `"S2 — 공개 법령/판례 기반 분류 근거 있음"` 이라 **라벨과
모순**된다. 그리고 배포본 룰 추출기가 독립적으로 S2 에 합의했다.

**hardened42 는 이 문서를 판정할 능력이 없다.** 같은 성질(반올림/내림에서 등급이 갈림)이
고등급 26건 중 3건 = 11.5% 이고 전부 심판 합의 2/3 다.

참고로 `floor_restored_S2` 9건은 전부 s<2 라 규칙상 S2 가 맞다. 셋 제작자는 m=0 을
일관되게 처리했다 — 처음 의심한 불일치는 없었다.

### 경계 게이트를 만들었다가 측정하고 뺐다

"요소값이 분기점에 있으면 검수로" 게이트를 구현해 재 봤다. 두 변형 다 채택 불가였다:

| | 경계로 잡히는 조합 | 자동확정률 | 미탐 개선 |
|---|---|---|---|
| 1단계 탐침 | 59% (16/27) | 40.5% → **33.3%** | **0건** (잡힌 3건 전부 예측 정답) |
| 2단계 탐침 | 93% (25/27) | 40.5% → **16.7%** | 1건 (사실상 자동화 해제) |

1단계가 못 잡은 이유가 핵심이다: 룰은 S1·V1·M1 로 봤고 심판은 s=2·v=1.67 이라
**두 축이 동시에** 낮았다. 한 축만 올려서는 닿지 않는다.

### 진짜 결함 — 룰 추출기의 체계적 과소검출

hardened42 에서 심판 평균이 있는 24건으로 룰과 대조했다(음수 = 룰이 낮게 봄):

```
S  평균 -0.79 · 중앙 -0.33 · 룰이 낮은 건 14/24 = 58%
V  평균 -0.72 · 중앙 -0.17 · 룰이 낮은 건 12/24 = 50%
M  평균 +0.33 · 중앙 +0.00 · 룰이 낮은 건  1/24 =  4%
```

**S 와 V 만 눌려 있고 M 은 정상이다.** v3 에서 `rule under-detected S/V/M` 이 99.4% 로
뜬 것과 같은 뿌리다. 경계 게이트는 이 증상 위에 검수부담만 얹는다. 고칠 곳은 요소 추출이고
그건 별건이다. 코드를 되돌리고 `pipeline.py` 에 되돌린 이유를 남겼다 — 같은 아이디어를
다시 만들지 않도록.

## 5. 그래도 남는 천장

전부 합성 데이터다. 이 수치들이 보증하는 것은 **표현·길이·장르 변화에 견딘다**까지이며
실문서 일반화가 아니다(자체 실측 교차silver→gold_real F1 0.26). 실 성능의 유일한 레버는
회원사 현장 운영학습이다.

## 6. 배포본 교체는 여전히 별도 판단

v7 이 v3 에서 모든 축을 이기지만 그것만으로 교체 근거가 되지 않는다:
- v3 는 **v7 에게 더 가까운 셋**이다(v7 이 v6 재료를 포함하고, v3 는 같은 저술 프로그램 계열)
- 배포본 v5 는 gold_real 계보로 학습됐고 그 계보의 자(경화42)로 승격됐다
- 두 모델 모두에게 공평한 셋이 아직 없다

교체하려면 최소한 ① 두 모델 모두에게 낯선 셋 ② 서빙 경로 FNR 비교 ③ 검수부담 변화가
있어야 한다. ②는 배포본에 대해서만 쟀다.
