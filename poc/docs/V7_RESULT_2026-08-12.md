## 1. 오늘 드러난 것 — 결박이 두 종류였다

같은 검사를 여러 셋에 돌려 보니 두 계보가 **서로 다른 지름길**을 쓰고 있었다.

| 계보 | 결박 | 증거 |
|---|---|---|
| v5 (배포본) | **장르** — S3 = 판례 | 학습셋 S3 의 24.8% 가 판례, 중앙 1,096자(다른 등급 336~429) |
| v6 (신규) | **길이** — 2,140자 미만을 본 적 없음 | 학습셋 전 등급 2,140~3,625 로 균일 |

증거가 되는 측정(같은 모델, 다른 길이대):

```
v6 → v3 final_800 (2,100~3,600자)   S3 recall 0.858
v6 → mundane_s3   (120~276자)       S3 recall 0.000   ← 500건 전부 S2
v5 → mundane_s3                     S3 recall 0.202
```

**v6 는 장르 결박을 없앴지만 길이 결박이 생겼고, 짧은 문서에서는 v5 보다 나빴다.**
하나만 고치고 끝낼 문제가 아니었다.

## 2. v7 — 두 축을 같이 고친다

v6 + mundane_s3(짧은 비-판례 S3) + patent_proxy(TS/S1) + v5train 에서 재구성.

**설계에서 배운 것**: 등급 *안에서*만 길이를 고르면 부족하다(1차 시도 길이-only 0.692).
등급마다 출처가 달라 주변 분포가 갈린다 — 중앙 길이가 S3 193 vs S2 1,037 로 5배 벌어졌다.
**전역 길이 구간을 잡고 모든 등급이 각 구간에서 같은 수를 가져가야** 길이가 정보를 잃는다.

**판례를 빼지 않았다.** 유일한 실데이터이고 정당한 S3 다. 바꾼 것은 "S3 = 판례"라는
등식이지 판례의 존재가 아니다.

```
학습셋 지표   길이-only 0.378 · Theil's U 0.023 · tell 0종(커버 0.000)
             S3 판례 24.8% → 2.6%
             등급별 500자 미만  TS 154 · S1 145 · S2 148 · S3 260
분할          train 1,936 · val 443 · test 443 (가족 분리 · 겹침 0)
```

## 3. 결과 — 모든 축에서 개선

### 긴 문서 (v3 final_800 · 800건 · 봉인 · 계보 독립 확인)

| | v5 배포본 | v6 | **v7** |
|---|---|---|---|
| F1_macro | 0.2613 | 0.7035 | **0.7436** |
| accuracy | 0.3425 | 0.700 | **0.7525** |
| 고등급 FNR | 0.5472 | 0.4028 | **0.3500** |
| TS recall | 0.0625 | 0.569 | 0.525 |
| S1 recall | 0.720 | 0.615 | 0.715 |
| S3 recall | 0.025 | 0.858 | 0.804 |

### 짧은 문서 (mundane_s3 · 500건 · 120~276자)

| | v5 | v6 | **v7** |
|---|---|---|---|
| S3 recall | 0.202 | **0.000** | **1.000** |

⚠ mundane_s3 는 **전부 S3 단일 등급**이라 "모든 문서를 S3 라고 해도" 1.0 이 나온다.
그래서 v3 의 예측 분포를 함께 봐야 한다 — v7 은 S1 145 · S2 287 · S3 259 · TS 109
(정답 200/200/240/160)로 **네 등급에 고루 분포**한다. S3 로 몰아붙인 것이 아니다.

### 자체 test 가 처음으로 정보를 가졌다

```
v6   F1 1.000 · accuracy 1.000   ← 규칙으로 풀려 아무것도 못 알려줌
v7   F1 0.940 · accuracy 0.941 · fnr_high 0.053
     TS 0.92 · S1 0.92 · S2 0.96 · S3 0.96 (F1)
```

**온도 보정도 같이 정상화됐다:**

```
v6   T 0.05 (퇴화 — val 정확도 100% 라 보정 신호 없음) · 재보정 후 2.4755, ECE 0.138→0.177 악화
v7   T 1.2628 · ECE 0.0328 → 0.0199 개선
```

v6 는 검증셋이 너무 쉬워 온도를 추정할 수 없었고, 재보정해도 ECE 가 나빠졌다.
v7 은 94% 라 여유가 있어 **정상 적합됐고 ECE 도 개선**됐다.
길이·장르 다양성을 넣자 **셋이 측정 가능해진 것**이다.

## 4. 서빙 경로 무음 미탐 0.0% (배포본 · 고등급 360건 전수)

모델 단독 FNR 과 운영 FNR 은 다른 값이다. 서빙 가드를 태우고 다시 쟀다:

```
미달분류(가드 전)   162건 = 45.0%
└ 검수로 라우팅      162건
└ **무음 미탐**        0건 = 0.0%
status: needs_review 360/360
```

**고등급 문서를 하나도 자동확정하지 않았다.** "미탐 최소화는 veto 설계로 충족"이
주장에서 **전수 실측**이 됐다.

⚠ 대가를 같이 적어야 한다: **자동확정률 0%** 다. 미탐은 0 이지만 검수 부담이 100% 이고,
이는 v3 가 v5 에게 분포 밖이라 모델이 계속 룰과 불일치한 결과이기도 하다. 실 운영
분포에서는 다르게 나온다. 이 수치는 **"미탐 0"의 근거로는 쓰되 "운영 효율"의 근거로는
쓸 수 없다.**

## 5. 그래도 남는 천장

전부 합성 데이터다. 이 수치들이 보증하는 것은 **표현·길이·장르 변화에 견딘다**까지이며
실문서 일반화가 아니다(자체 실측 교차silver→gold_real F1 0.26). 실 성능의 유일한 레버는
회원사 현장 운영학습이다.

## 6. 배포본 교체는 여전히 별도 판단

v7 이 v3 에서 모든 축을 이기지만 그것만으로 교체 근거가 되지 않는다:
- v3 는 **v7 에게 더 가까운 셋**이다(v7 이 v6 재료를 포함하고, v3 는 같은 저술 프로그램 계열)
- 배포본 v5 는 gold_real 계보로 학습됐고 그 계보의 자(경화42)로 승격됐다
- 두 모델 모두에게 공평한 셋이 아직 없다

교체하려면 최소한 ① 두 모델 모두에게 낯선 셋 ② 서빙 경로 FNR 비교 ③ 검수부담 변화가
있어야 한다. ②는 배포본에 대해서만 쟀다.
