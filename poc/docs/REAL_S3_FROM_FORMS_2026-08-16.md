# 공개 서식에서 실문서 S3 1,000건을 확보했다 — 우리 학습셋의 첫 실문서

작성 2026-08-16. 사용자 지적에서 시작했다 — "서식모음 문서들이 대부분 회사에서 쓰는
문서인데 활용하면 되지 않나".

---

## 1. 왜 쓸 수 있나 — 이 코퍼스는 정답을 안다

공개 배포되는 빈 서식(신청서·계약서 양식·대장)에는 영업비밀이 없다.

```
누구나 내려받을 수 있다   -> 비공지성 없음
내용이 비어 있다          -> 경제적가치 없음
                          => S3 (영업비밀 아님)
```

**사람 검수 없이 라벨이 보증되는 유일한 실문서다.** 우리 학습셋은 지금까지 전부 합성이었다.

---

## 2. 고치려는 것 — 헛경보 13.0%

`reports/PUBLIC_FORM_SPECIFICITY.json` 실측.

```
빈 서식 161건 중 헛경보 21건 = 13.0%   (공개 양식을 TS/S1 이라고 부름)

  문서양식총람          8.3%
  계약서 모음           9.1%
  각종 법률 서식        10.0%
  100가지 업무용 서식   15.2%
  XLS 엑셀 서식        24.1%
```

우리는 미탐 0 을 유지하는 대신 과분류를 감수하는 설계다. 그런데 **공개 양식 8건 중 1건**
은 운영 부담이 크다.

⚠ '마케팅자료' 폴더(헛경보 69.7%)는 제외했다. 빈 양식이 아니라 실제 기획서·제안서가
  섞여 있어 그 69.7% 가 오류인지 정상인지 판단할 근거가 없다.

---

## 3. 만든 것

`scripts/build_real_s3_from_forms.py`

```
빈 서식 폴더 5개 · 파일 3,870건 훑어 1,467건 처리
  채택 1,000 · 너무 짧음 146 · 중복 본문 22

datasets/real_s3_forms/train_s3.jsonl    600건 · 중앙 496자 · 120~14,545자
datasets/real_s3_forms/sealed_s3.jsonl   400건 · 중앙 497자 · 121~20,000자
```

**분할은 `eval_public_form_specificity.py` 의 해시 분할을 그대로 썼다.** work 절반이
이미 특이도 측정에 쓰인 쪽이라 그것을 학습에 넣고, sealed 로 개선을 잰다. 새로 나누면
봉인이 깨진다.

⚠ 상한을 600 으로 잡았다. S3 를 과하게 넣으면 모델이 S3 로 쏠려 **미탐이 는다** —
  그것이 우리가 가장 피해야 할 방향이다.

---

## 4. 누출 검사 — 두 번 헛다리를 짚었다

### 1차: 봉인셋 단독 검사 → 오탐

```
length_only_1nn 1.000 > 권고 0.55     경고
length_theils_u 0.000                 그런데 연관도는 0
tell_coverage   0.000
```

**봉인셋이 전부 S3 단일 등급**이라 최근접이웃이 무엇을 찍어도 맞는다. 등급이 하나인 셋에
이 지표는 성립하지 않는다.

### 2차: 기존 test 와 섞어 검사 → 또 오탐

```
S3 502건 vs 나머지 154건            길이-only 0.646
```

**내가 섞은 비율이 문제였다.** S3 가 76% 라 "S3 라고 찍으면 맞는다" 가 된다. 길이 누출이
아니라 등급 불균형이다.

### 3차: 등급별 46건으로 균형 → 통과

```
길이-only  0.646 -> 0.304   (무작위 25% 수준)
tell 커버  0.000
문장 공유  6.5% (25종)      <- 남은 경고
```

### 문장 공유의 정체 — 서식이 아니라 기존 합성 셋이다

```
등급별 문장 공유 문서 수
  TS  12/46      <- 기존 합성 test.jsonl
  S1   6/46
  S2   7/46
  S3   1/46      <- 서식

봉인 서식 400건 중 학습셋과 문장 공유:  3건 = 0.8%
```

겹치는 문장이 `"2023년도 결산 초안 (1급 비밀)"`, `"본 문서는 [가상기업A]의 …"` 처럼
**합성 문서의 문구**다. 서식은 실문서라 겹칠 수가 없고 실제로 0.8% 뿐이다.

**결론: 새로 만든 실문서 S3 는 학습에 넣어도 안전하다.**

---

## 5. 이것으로 되는 것과 안 되는 것

```
되는 것    헛경보 감소 (공개 문서를 비밀이라 부르는 것)
           우리 학습셋에 처음으로 실문서가 들어간다

안 되는 것  S1 재현율. 빈 양식에 비밀이 없으므로 TS·S1·S2 는 여기서 안 나온다
           실문서 일반화 주장. S3 한 축만 실문서다
```

⚠ 이 작업이 고치는 것은 **특이도 한 축**이다. 우리의 진짜 약점(S1 이 구조적으로 도달
  불가)은 메타데이터나 실 등급 문서로만 풀린다.

---

## 6. 남은 절차

```
1. 기존 학습셋 + 실문서 S3 600건 병합
2. 누출 검사 (--strict)
3. 생산 학습기로 재학습          <- KL 서버에서 70분
4. 3축 게이트로 판정
5. 봉인 서식 400건으로 헛경보 재측정
6. 개선이 확인되면 교체 검토
```

⚠ 5번이 핵심이다. 학습에 쓴 600건으로 재면 안 된다.
