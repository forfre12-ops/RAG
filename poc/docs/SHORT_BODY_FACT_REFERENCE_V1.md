# 짧은 본문 사실 정답 v1 · 내부 조건부 정책 v0.3

2026-09-15. 기존 원고9종/가상 맥락21사례에 대한 별도 후속 참조다.
새 사실 스키마 `short-body-facts-v1`, 정책 `short-body-content-reference/0.3`.
기존 원장정책v0.1·40건, 문서군v0.2 설계·원고·가정 라벨은 덮어쓰지 않는다.

## 확정의 의미와 범위

**등록한 본문의 어떤 위치에 어떤 값·관계가 쓰여 있는가**를 고정한다.
그 내용의 현실 진위·사업 가치·영업비밀성·최신성·문서/첨부 전체 완전성을 인증하지 않는다.
외부 사람 서명은 이 내부 정답을 제작하는 선행조건이 아니다. 고객 GOLD/법정 등급/운영 승인과 별개다.

표현9종을 처리하는 전체 본문 정규식 파서와, 별도로 직접 작성한 값·원문 앵커 명세를 비교한다.
주 추출기는 예상 등급·고객 맥락·정답값·문서 ID를 입력받지 않는다. 정답 명세는 추출기 출력을 복사해 만들지 않는다.
두 구현은 같은 작성 주체다. 독립 기관/사람 검수 또는 일반 자연어 의미 이해를 증명한 것은 아니다.
규칙의 한계는 분명하다: 문법 밖 문장은 미지원, 미등록 본문은 사실 후보까지만이고 고정 자격을 주지 않는다.
본문 전체가 지원 서식에 맞는지 검사하되, 고정하는 대상은 선정한30개 사실이다. 모든 문장/의미의 완전 추출을 주장하지 않는다.

## 사실 계약

각 사실은 name/state/value/origin/interpretation/evidence를 가진다.
evidence는 Python Unicode 문자 start 포함/end 제외와 그 구간 SHA256이다.
state는 observed 또는 unknown이다. 누락을0/false/공개/무해로 바꾸지 않는다.
해시는 원문-근거 결합이며 진위/작성자 인증 수단이 아니다.

| 구분 | 예 | 의미 |
|---|---|---|
| direct_value | 제시가14,500원, 하한12,800원, 지급 조건→운송비 부담 | 본문에 쓰인 역할·단위·관계를 보존 |
| document_assertion | '계산 순서를 포함하지 않았다', '개별 인명을 기록하지 않는다' | 문서가 그렇게 주장한다는 사실. 현실 부재나 첨부까지의 부재로 승격 금지 |
| not_determined/unknown | 관측값3개만 있는 문서의 program | 완전한 연산 규칙을 알 수 없음. 옆 문서의 수식을 가져와 채우지 않음 |

가격의 제시/하한, 원/개/상자, 오전/오후, 공급자/구매자, 조건의 방향을 구별한다.
30일 내 전액 지급이면 공급자가 운송비를 부담한다는 문장을 필요충분조건/무조건 부담으로 바꾸지 않는다.
서식의 밑줄 placeholder와 작성된 값은 따로 기록한다. 본문에 '빈 서식'이라고 적혀 있어도 값이 있으면 충돌이다.
관측한 placeholder가 실제 원본의 추출 누락이 아닌지까지 판정한 것은 아니다.

## 의미 검산

- 완전한 산술 모형: 입력0~9 전수, 곱셈/덧셈/나머지 실행과 반복 덧셈/뺄셈 구현을 대조한다.
  명세의 시험값도 함께 검산한다. 현실 핵심 기술 재현성/가치 검증은 아니다.
- 관측표: 관측값 모두에 맞지만 예정된 다음 입력의 출력은 서로 다른 두 유한 lookup 함수를 만든다.
  둘 다 정답 프로그램이라는 뜻이 아니라, 주어진 관측만으로 유일 프로그램을 확정할 수 없다는 반례다.
- 거래: 제시/하한 역할과 단방향 조건을 보존하며 하한이 제시가보다 높으면 불일치를 기록한다.
  해당 계약의 효력이나 실제 가격의 진위를 검증하지 않는다.
- 서식: 실제 placeholder와 '비어 있다'는 서술의 일치를 확인한다.
- 배정: 시작/종료 시간과 시간 범위를 검산한다. 요일을 임의의 달력 날짜로 바꾸지 않는다.

사실 정답은 문서가 모순된 주장을 담았다는 사실도 보존해야 한다. 모순을 조용히 수정하지 않는다.
정책 계산에는 등록된 사실 증명서 및 불일치 없는 본문만 허용한다.

## 별도 정책의 채택 기준

가상 맥락은 origin=synthetic_assumption, scope_complete, private_current_revision,
release_authorized_for_this_revision, current_core_asset, other_high_risk_material, world로 명시한다.
본문에서 역산하거나 실제 고객사 확인 사실이라고 기록하지 않는다.
scope_complete=true, other_high_risk_material=false가 아니면 전체 판정은 HOLD다.
공개/비공개 정보가 모순되거나 결정에 필요한 정보가 unknown이면 HOLD다. '공개 허가 없음→비공개'로 추론하지 않는다.

| 규칙 | 충분조건 | 인접 등급 배제 |
|---|---|---|
| R-CORE → TS | 비공개 현행 핵심 자산이며 검산된 완결 프로그램 | 부분/업무 조건보다 우선. 일반 공개/빈 서식 아님 |
| R-DETAIL → S1 | 비공개 실질 프로그램·관측값·거래조건, R-CORE 불충족 | 핵심 완결 조건 제외, 업무 일정 이상의 실제 세부정보 |
| R-OPS → S2 | 비공개 작업·접수·배정·이동 값, 상위 조건 없음 | 핵심/실질 설계·거래 조건 없음, 공개/빈 서식 아님 |
| R-BLANK → S3 | 전체 제공 필드가 placeholder이고 범위/배제 조건 확인 | 미기입 공통 서식. 실제 작성값과 충돌하면 보류 |
| R-RELEASED → S3 | 해당 판본 공개 허가=true, 비공개=false, 범위와 다른 상위 위험 배제 확인 | 이 가상 세계의 안전한 배포본에 한함 |

등록 본문이 아닌 실제 개인정보/인증정보/핵심정보에 공개 표식을 붙여 이 규칙으로 하향할 수 없다.
문서가 미등록이면 공개 맥락과 관계없이 HOLD다. 인터넷 노출을 공개 승인으로 취급하지 않는다.
완결 프로그램의 핵심 여부가 unknown이면 TS/S1 경계가 미정이므로 HOLD.
값 없는 서식은 공개/비공개가 unknown이어도 다른 필수 조건이 확인되고 모순이 없으면 S3가 가능하다.
이는 무관한 unknown 때문에 불필요하게 보류하는 것을 피하는 제한된 규칙이다.

정책은 직접 분기 구현과 별도 SQL CASE를 대조한다. 9본문×5개 맥락 필드의3상태=2,187조합 전수 확인.
이는 같은 유한 정책의 구현 일치 검사이지 모든 고객 정책의 올바름이나 분류 모델 정확도가 아니다.
이전21개 가정 답과는 재계산 후 비교하며, 가정 답을 정책 함수에 전달하지 않는다.

## 사용 제한과 다음 단계

본문 사실9세트/30항목과 맥락 결합 등급18/HOLD3을 별도 버전으로 보존한다.
본문+맥락 변형을 독립 문서 수로 세지 않으며, 다른 정책의 원장40건과 합쳐 고객 정답58건으로 발표하지 않는다.
모두 policy_fixture, training/model_evaluation=false, GOLD/서명/고객 정확도 자격 없음.
기존 운영 FactPacket/API/확정 원장/검수 경로에 연결하지 않는다.
행의 금지 플래그 및 원본 경로의 manifest로 학습 사용을 차단한다. 기존 deny registry는 바꾸지 않았으므로,
플래그/출처를 제거한 복사본까지 전수 차단한다고 주장하지 않는다. 해시는 위변조 서명/권한 통제를 대신하지 않는다.

다음은 미등록된 표현/새 문서군의 사실 추출 검증, 의미 보존/반전/누락 변형과 전체 본문 지름길·중복 검사다.
현재 파서를 일반 문서에 적용해 정답이라고 간주하거나, 이9종의 문체를 복제하여250건씩 채우지 않는다.
데이터/모델/정책 판단요소 중 어떤 부분이 개선됐는지 분리 측정한 뒤 학습 비교를 준비한다.
