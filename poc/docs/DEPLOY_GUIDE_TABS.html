설치 가이드 — 설치 파일 보내고 실행만

개념은 하나다: 설치 파일(패키지)을 서버로 보내고 → 실행하면 한 번에 설치된다. 대상마다 "설치 파일의 형태"와 "보내는 방법"만 다를 뿐, 나머지는 같다. 지금 할 것은 테스트서버 탭(한 대에 지재원+고객사 둘 다), 실서버는 지재원·고객사 탭.

한눈에 — 대상별 "설치 파일"
테스트서버(지금)소스+모델 620MB 패키지scp(인터넷)한 줄 스크립트 → 둘 다
지재원(실서버)소스+모델 패키지scp/rsync(연결망)deploy.sh → 지재원 하나
고객사(실서버)12GB 자립 번들USB 반입(폐쇄망)deploy.sh → 고객사 하나

한 줄 설치테스트서버 1대에 지재원 + 고객사 둘 다

연결망 테스트서버(kip-ai)에 두 프로파일을 동시에 올린다. 설치 파일 만들기 → 전송 → 서버 설치를 스크립트 하나가 자동 처리한다. 포트·DB·컨테이너는 완전 격리, 임베더 캐시만 공유.

이 한 줄이면 끝
Windows Git Bash · 리포 루트(F:\antigravity\rag)에서:
bash poc/scripts/ship_to_testserver.sh

자동으로: ① 소스+모델을 620MB 패키지로 묶고 → ② 서버로 전송 → ③ 서버에서 압축해제 + 이중배포까지 실행. 비밀번호는 두 번 물어본다(전송·설치). 빌드로 10~20분 걸리니 창을 닫지 말 것.

✓끝나면

✓ 완료 — 지재원 :8000 · 고객사 :8001

api 는 서버 내부(127.0.0.1)에만 열리므로, 내 PC 브라우저로 보려면 SSH 터널:

ssh -p 56320 -L 8000:127.0.0.1:8000 -L 8001:127.0.0.1:8001 aisadm@182.212.163.182
# 그 뒤 브라우저:  http://localhost:8000  ·  http://localhost:8001

?미리 알아둘 것 / 옵션

  • 대상 서버 바꾸기: TS_HOST=1.2.3.4 TS_PORT=22 TS_USER=aisadm bash poc/scripts/ship_to_testserver.sh (기본값 = 현재 kip-ai)
  • 전송만/설치는 서버에서 직접: SHIP_ONLY=1 bash poc/scripts/ship_to_testserver.sh → 서버에서 tar xzf ~/koipa-testserver.tar.gz -C ~ && cd ~/poc && bash scripts/deploy_testserver_dual.sh
  • 패키지만 만들기(전송 없이): PACKAGE_ONLY=1 bash poc/scripts/ship_to_testserver.sh
  • 도중 연결이 끊기면 그냥 다시 실행하면 된다(비밀키·이미지 캐시 유지 → 이어서 진행).
사전 1가지
서버(kip-ai)에 Docker가 설치돼 있어야 한다(docker run --rm hello-world 확인). GPU는 불필요(CPU로 동작). RAM은 두 스택이라 ≥16GB(권장 32GB) — 서버에서 free -h 로 확인.

full-train지재원 실서버 (연결망 · 모델공장)

개념은 테스트서버와 동일 — 설치 파일 전송 → 실행. 단 실서버는 지재원 한 스택만 올리고(full-train), 상용 LLM·GPU 학습을 붙인다.

1설치 파일 전송 (소스+모델)

연결망이라 이미지·임베더는 서버가 인터넷으로 받는다. 소스+모델만 보내면 된다.

# 로컬(리포 루트)에서 패키지 전송만
SHIP_ONLY=1 TS_HOST=<지재원IP> TS_PORT=<포트> TS_USER=<계정> bash poc/scripts/ship_to_testserver.sh

2서버에서 설치 (지재원 한 스택)

tar xzf ~/koipa-testserver.tar.gz -C ~
cd ~/poc
cp .env.full-train .env        # DEPLOY_PROFILE=full-train · ANTHROPIC_API_KEY · API_KEY · POSTGRES_PASSWORD
bash scripts/deploy.sh          # 연결망 자동감지 → 마이그레이션+기동+스모크
GPU
GPU 서버라 nvidia-container-toolkit 설치(발주처/인프라 범위). 전체 재학습·합성·골든은 배포와 별개 운영 워크플로.

3확인

API_KEY=$(grep '^API_KEY=' .env | cut -d= -f2)
curl -s http://localhost:8000/api/v1/healthz/ready ; echo        # 200

onprem-local고객사 실서버 (폐쇄망 · 운영)

개념은 같다 — 설치 파일 반입 → 실행. 단 인터넷이 없어 소스만으론 안 된다(서버가 이미지·의존성을 못 받음). 그래서 설치 파일이 이미지·모델·라이브러리를 전부 구운 12GB 자립 번들이고, USB로 반입한다.

1설치 파일 = 12GB 번들 (USB 반입)

dist/koipa-airgap-bundle/(약 12GB — 이미지·모델·wheel·마이그레이션 자립. postgres·redis 포함이라 순수 에어갭 OK)를 승인 매체로 서버에 넣는다.

2서버에서 설치

cd ~/koipa-airgap-bundle
bash verify.sh        # 무결성 → Checksums OK
bash install.sh       # 이미지 적재(docker load)

cp infra-config/.env.template .env
python3 -c "import secrets;print('STORAGE_ENCRYPTION_KEY='+secrets.token_hex(32))"
nano .env             # DEPLOY_PROFILE=onprem-local · API_KEY · POSTGRES_PASSWORD · STORAGE_ENCRYPTION_KEY
                      #   (CPU 서버면 LLM_PROVIDER=none)

bash deploy.sh        # 폐쇄망 자동감지 → 마이그레이션+기동+스모크 (인터넷 0)
CPU 서버면
GPU 없으면 compose 의 nvidia 블록을 주석(grep -n nvidia infra-config/docker-compose.airgap.yml). 분류·검색·OCR 전부 CPU로 동작(추론만 느림).

3확인 + 운영

curl -s http://localhost:8000/api/v1/healthz/ready ; echo        # 200
  • 현장 검수 교정 → tb_corrections → 야간 CPU 증분 재학습(무인) → 후보 등록. 활성화는 관리자 콘솔 + 사람 확인.
  • 임베더(KURE)·대형 LLM은 번들에 없음 — 분류(핵심)는 번들만으로 오프라인 동작, 검색·/answer가 필요하면 별도 반입.
