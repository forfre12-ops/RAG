# 실데이터 재측정 — 수정은 실패했고, 평가셋 하나는 애초에 우리 루브릭과 어긋난다

작성 2026-08-14. `V8_REAL_PROBE_2026-08-14.md` 의 후속. "모르면 unknown 을 배우게 한다"
수정을 넣고 다시 쟀다. **통하지 않았다.** 그리고 그 과정에서 평가셋 하나가 우리 과제와
다른 것을 재고 있었음을 확인했다.

---

## 1. 수정은 실패했다

```
                    이전         현재
secrecy absent     369/400     346/400   거의 안 줄었다
secrecy unknown     22/400       4/400   오히려 줄었다
등급 일치           0.0000      0.0000
고등급 과소분류       100%        100%
게이트 자동확정       4건(미탐 4)  13건(미탐 13)   악화
```

무요소 문서 600건(학습의 17.3%)을 넣었는데 모델이 여전히 `absent` 라고 단언한다.

### 왜 실패했나 — 요소만 뺐지 내용을 넣지 않았다

```
우리 무요소 문서   "본 건의 배경과 검토 사유를 정리한다. 적용 범위와 목적을 아래와 같이
                  정한다. 해당 업무의 대상과 기준 시점을 밝힌다…"
                  -> 내용이 없는 절차 상투어

특허 프록시(실)    "플라즈마를 이용한 반도체소자 제조공정이 진행되는 챔버를 접지시키고,
                  접지를 통해 흐르는 전류를 측정하여 기준값 이상일 때 비정상으로 판단…"
                  -> 구체적 기술 내용
```

수치로도 나온다:

```
                  고유어휘비  숫자밀도
우리 무요소 문서     0.630    0.0202   <- 학습셋에서 가장 빈약하다
우리 일반 학습문서    0.710    0.0185
특허 프록시(실)      0.763    0.0021   <- 가장 실질적이다
```

**모델에게 그것은 "빈 문서" 였고, 빈 문서는 이미 S3(absent) 로 배웠다.** 그래서 unknown 이
늘기는커녕 줄었다. 실문서는 "내용이 가득한데 요소만 없는" 문서인데, 나는 "내용도 없고
요소도 없는" 문서를 만들었다.

교훈: **축을 하나 뺄 때 그 자리를 무엇으로 채우는지가 축을 빼는 것만큼 중요하다.**

---

## 2. 그런데 평가셋 하나는 우리 루브릭과 어긋난다

특허 프록시의 라벨 근거를 열어 봤다:

```
source: 공개특허
grade_basis: nkt:EEBEBB:S1-default
label_source: patent_proxy_nkt
```

**공개특허**다. 그리고 라벨은 "국가핵심기술 도메인이면 S1" 이라는 **도메인 prior 기본값**이지
문서에서 판단한 값이 아니다.

우리 정본 루브릭으로 보면 공개특허는:

```
비공지성 = 공개됨 = proven_absent = 0  ->  곱 0  ->  S3
```

**모델이 S3 라고 한 것이 루브릭상 맞을 수 있다.** 이 셋의 "등급 일치 0.0000" 은 모델
실패가 아니라 **라벨 규약이 다른 것**이다.

특허 프록시는 "이 기술 내용이 국가핵심기술급인가" 를 재는 셋이지 "이 문서가 영업비밀
몇 등급인가" 를 재는 셋이 아니다. 요소 모델의 판정면으로 쓰기에 부적절하다.

---

## 3. 그러나 경화42 는 진짜 미탐이다

경화42 의 고등급 문서를 열어 보니 다르다:

```
[S1] "M&A 실사 보고서 … 유출 시 주가 영향 및 협상 무산 위험"
[S1] "고객 데이터 분석 결과는 경쟁사 대비 핵심 자산"
[S1] "독자 개발 스코어링 모델 (외부 미공개) … 시장 표준 대비 15% 향상"
```

**비공지성과 가치가 본문에 명시돼 있다** — `외부 미공개` · `핵심 자산` · `유출 시 위험`.
요소 진술이 없어서가 아니다. 있는데 못 읽는다.

```
경화42  42건 전부 S3 예측 · 고등급 26건 100% 과소분류
        secrecy  absent 18 · unk 21 · lv1 3
```

이것은 변명의 여지가 없는 실패다. 그리고 우리 학습셋의 요소 문장과 이 문서들의 표현이
다르다는 것이 원인일 가능성이 높다:

```
우리 학습셋   "관련 특허 공보에도 이 범위는 기재돼 있지 않다"   요소를 직접 진술
경화42        "독자 개발 스코어링 모델 (외부 미공개)"          괄호 안 한 마디로 진술
```

같은 사실인데 진술 방식이 다르다. 우리는 한 문장을 통째로 요소 진술에 쓰는데, 실문서는
문장 안에 짧게 끼워 넣는다.

---

## 4. 정리 — 세 셋의 성격이 전부 다르다

```
셋            성격                         모델 S3 예측의 의미
특허 프록시    공개특허 + 도메인 prior 라벨    루브릭상 맞을 수 있음. 판정면으로 부적절
경화42        업무 시나리오 + 요소 진술 있음   **진짜 미탐.** 있는 근거를 못 읽는다
일상 S3       짧은 일상 문서 · 전부 S3       정답이 단일 등급이라 1.0 은 무의미
```

"실문서 성능 0" 이라고 뭉뚱그리면 안 된다. 확실한 것은 **경화42 에서 명시된 요소 진술을
못 읽는다**는 것이고, 그것이 다음 표적이다.

## 5. 다음

```

(나) 무요소 문서를 다시 만든다      내용을 채우되 요소만 없게. 이번 실패의 직접 교정
(다) 특허 프록시를 판정면에서 뺀다   라벨 규약이 다르다. 쓰려면 우리 루브릭으로 재라벨해야
```

(가)가 경화42 실패를 직접 겨냥한다. (나)는 이번 시도의 재작업이다. (다)는 즉시 할 수 있고
잘못된 판정을 막는다.

⚠ 서빙 규칙 수정(`serving_grade` · `has_unknown`)은 유효하다. 모델이 unknown 을 내기만
   하면 안전측으로 올라간다. 문제는 모델이 unknown 을 안 낸다는 것이고 그건 데이터 문제다.
