# 과소분류의 86.5% 는 요소 하나에서 나온다 — secrecy=absent

작성 2026-08-14. business 판정면 136건을 진단한 결과와 그에 따른 두 가지 수정이다.

---

## 1. 원인이 한 요소 · 한 상태로 좁혀졌다

```
business 136건 · 고등급 95건 · 과소분류 52건

  무엇이 곱을 0 으로 만들었나(서빙 규칙)
    secrecy=absent      45건   86.5%   ← 압도적
    management=absent    6건
    value=absent         6건
    0 없음(다른 이유)      1건
```

value 와 management 는 읽고 있다 — value 는 88건을 lv2 로, management 는 72건을 lv2 로
본다. **오직 secrecy 만 47건을 `absent` 로 단언한다.**

실패 문서를 보면 무엇을 단언하고 있는지 분명하다:

```
[TS->S3] S=absent V=lv2 M=lv2   DRAM 1x nm 공정 CVD 핵심 파라미터 변경 검토서 (Rev.3)
[TS->S3] S=absent V=lv2 M=lv2   차세대 HBM 스택 식각 선택비 최적화 실험보고서
[TS->S3] S=absent V=lv2 M=lv2   HSM 마스터키 생성 및 주기적 교체 절차서 (운영 기밀)
```

**"공개되었음이 입증됨" 이라고 말하고 있다.** 근거가 문서 어디에도 없다.

---

## 2. 첫째 원인 — 우리는 비공개 표현의 20% 만 가르쳤다

business 고등급 95건이 실제로 어떤 신호로 비공지성을 드러내는지 셌다.

```
  명시적 부정("공개한 적 없다")   19/95  20.0%   ← 우리 학습셋이 쓰는 **유일한** 형태
  독자성("자체 개발·고유")        51/95  53.7%
  유출 위험("유출 시 …")          40/95  42.1%
  기밀 표시("기밀·대외비·사내")    29/95  30.5%
```

우리 학습셋의 secrecy=lv2 문장은 전부 이런 모양이었다:

```
  «어떤 외부 보고서에도 이 원자료가 인용된 적이 없다.»
  «배포용 부록에 이 기준값을 넣은 적이 없다.»
  «채용 공고를 포함해 어떤 대외 문서에도 넣지 않았다.»
```

전부 **명시적 부정 진술**이다. 실문서는 그렇게 쓰지 않는다. "운영 기밀" 이라고 쓰고
"독자 개발" 이라고 쓴다. 진술이 없으면 모델이 lv2 를 낼 근거를 못 찾는다.

→ 수정: `v8_inline_forms.py` secrecy lv2 에 독자성 · 기밀표시 · 유출위험 12종 추가.
   학습 몫이 절반을 유지하도록 분할을 개수 고정에서 비율로 바꿨다.

## 3. 둘째 원인 — 손실이 "모른다" 를 "공개됐다" 와 똑같이 벌했다

근거를 못 찾았을 때 모델이 갈 곳은 `unknown` 이어야 한다. 그런데 `absent` 로 갔다.
비대칭 손실을 보니 이유가 있었다.

`under_penalty` 가 `cls_to_score` 로 점수를 매기는데 그 표에서 **unknown 도 0** 이다.

```
정답 lv2 일 때 예측별 벌점

  예측        저술규칙   서빙규칙   해석
  absent        2        2      미탐 — 무음 통과
  lv1           1        1      부분 미탐
  lv2           0        0      정답
  unknown       2        0      유보 — 검수로 감
```

저술 규칙으로는 유보와 단언의 벌점이 **같다(둘 다 2)**. 유보해서 얻을 것이 없으니
확신이 없어도 absent 를 고르는 것이 손해가 아니다.

그러나 사람이 보는 등급은 `serving_grade()` 가 만들고, 거기서 unknown 은 최악값으로
채워진다 — **유보는 미탐을 만들지 않는다. 미탐을 만드는 것은 absent 단언뿐이다.**

→ 수정: `--penalty-rule serving|authoring` 도입, 기본 serving.
   손실을 **실제로 사람이 보는 등급을 만드는 규칙**으로 잰다.

## 4. 판정면을 갈랐다 — 진단에 쓴 면은 소비됐다

위 결론은 business 136건을 보고 얻었고, 그 결론으로 학습 데이터를 고쳤다. 그 순간
이 면은 판정면이 아니다. 문서 해시로 고정 분할했다.

```
  business_work    72건 · 고등급 55 (TS 33 · S1 22 · S2 17)   회차마다 본다. 소비됨
  business_sealed  64건 · 고등급 40 (TS 22 · S1 18 · S2 24)   봉인. --unseal 로만 열린다
```

`v8_real_probe.py` 는 기본으로 work 만 본다. sealed 는 개선이 끝났다고 판단할 때
**한 번만** 연다.
