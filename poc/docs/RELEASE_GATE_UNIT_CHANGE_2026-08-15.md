# P1 판정 단위를 원시 모델에서 서빙 경로로 바꿨다 — 막힌 상태에서 한 변경이다

작성 2026-08-15. 사용자 승인 후 실행. **이 문서는 그 변경을 숨기지 않기 위해 쓴다.**

---

## 1. 무슨 일이 있었나

폐쇄망 번들 빌드가 release-gate 에서 중단됐다. 원인을 좁히니 게이트 6개 중 하나였다.

```
P1 classifier            FAIL      <- 이것
P2 retrieval             PASS
classification gold      PASS
human review gold        BLOCKED
retrieval gold size      PASS
model parity             PASS
```

P1 판정식을 열어 보니 `p1.public` 세 조건 중 하나만 걸렸다.

```
f1_macro          0.9547   >= 0.75   통과
fnr_underclass    0.0580   <= 0.05   실패   <-
high_risk_to_s3   0        == 0      통과
```

과소분류 내역은 **한 종류뿐**이었다 — `S1 -> S2` 4건. 모수는 TS+S1 = 69.

```
4 / 69 = 0.0580
임계 0.05 x 69 = 3.45  ->  3건이면 통과, 4건이라 실패
```

**문서 하나 차이다.** 그리고 `high_risk_to_s3 = 0` — 고등급이 S3(비밀 아님)로 샌 것은
한 건도 없다. 놓친 4건은 전부 S1 -> S2 이고 둘 다 보호 등급이다.

⚠ 그 전에 내가 한 번 틀렸다. "llm_pseudo 777건(Qwen 라벨)이 막고 있다" 고 보고했는데
  판정식을 열어 보니 llm_pseudo 는 **판정에 안 쓰인다.** detail 문자열에 같이 찍힐 뿐이다.

## 2. 왜 바꿨나 — 재는 대상이 틀렸다

게이트가 쓰는 숫자는 `eval_p1_model_gold.predict_direct` 의 출력, 즉 **원시 모델**이다.
그 경로는 배포본이 통과하는 게이트를 하나도 안 탄다.

```
FNR-safe 상향(tau=0.30) · 합의 게이트 · metadata floor · 검수 라우팅
```

우리가 출하하는 것은 그 게이트를 다 지난 서빙 경로다. 게이트의 목적이 "출하물이 비밀을
조용히 놓치는가" 라면 **출하하지 않는 부품을 재고 있었던 것**이다.

막고 있던 4건을 서빙 경로로 태우니 갈렸다.

```
fdd5193d  S1   <- 서빙이 등급을 복구했다      needs_review
4543d67c  S2                                needs_review   (사람이 본다)
3bb5fe37  S2                                staging        <- 무음 미탐
df098393  S2                                staging        <- 무음 미탐
```

같은 판정면 160건 전수(`reports/SERVING_VS_RAW.json`):

```
                    원시 모델(종전)   서빙 경로(현행)
  과소분류               4건            3건
  무음 미탐              4건            2건
  fnr_underclass       0.0580 FAIL    0.0290 PASS
  high_risk->S3          0              0
  등급 일치             0.9563         0.9187      <- 서빙이 더 낮다
  자동확정                -             0.8125
  95% 상한                -             0.0997
```

## 3. 이 변경에 대한 정당한 의심과 답

> "막히니까 기준을 옮긴 것 아니냐"

정당한 질문이다. **번들 빌드가 막힌 상태에서 한 변경이 맞다.** 답은 둘이다.

```
(1) 재는 대상이 틀렸다 — 원시 모델은 출하물이 아니다. 우리는 그것을 팔지 않는다.
(2) 서빙이 공짜로 이기지 않는다 — 등급 일치가 0.9563 -> 0.9187 로 내려간다.
    게이트가 경계를 검수로 올리는 대가다. 유리한 쪽만 골랐다면 이 숫자는 안 나온다.
```

그리고 **두 숫자를 모두 리포트에 남긴다.** `p1.public`(원시)은 회귀 탐지용으로 계속
기록되고, `p1.serving` 이 판정 단위다. `decision_unit` 필드가 어느 쪽으로 판정했는지
명시한다.

⚠ 서빙 리포트가 없으면 **원시 모델로 폴백해 판정한다.** 새 측정이 빠졌을 때 조용히
  통과시키지 않는다.

## 4. 변경 후 상태

```
P1 classifier        FAIL -> PASS   (판정단위 serving · FNR 0.0290)
verdict              FAIL -> CONDITIONALLY_READY
남은 차단자           human review gold  0/40
```

`--allow-conditional`(파일럿 waiver)로 열린다. **GA 는 아니다** — 게이트 출력이 그렇게
찍는다.

```
[release-gate] PASS (PILOT WAIVER)
  [!] AUDITED WAIVER - waived for a PILOT release (NOT GA)
  -> GA still requires these to reach PASS (fill human_review)
```

즉 **지금 만들 수 있는 것은 파일럿 번들이고, GA 번들은 사람 검수 없이는 못 만든다.**
검수 40건이 그 조건이다(등급별 구조 게이트 20건과는 별개 수치).

## 5. 남는 진짜 문제

판정 단위를 바꿔도 **무음 미탐 2건은 그대로 있다.**

```
3bb5fe37  전략 고객 맞춤형 가격 협상 내부 지침   S1 -> S2  staging
df098393  해외 현지 유통망 구축 전략 문서        S1 -> S2  staging
```

둘 다 `koipa_case_based` 이고 155~200자다. S1/S2 경계는 비밀관리성으로 갈리는데 그것은
본문에 없다 — ICD 메타데이터가 있어야 확정된다. 이 두 건은 **메타데이터가 오면 자연히
풀릴 후보**이고, 안 오면 남는다.

게이트를 통과했다고 이 2건이 사라진 것이 아니다. 기록해 둔다.
