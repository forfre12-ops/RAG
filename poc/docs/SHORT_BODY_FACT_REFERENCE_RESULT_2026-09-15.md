# 짧은 본문 사실 정답·조건부 정책 검산 결과

2026-09-15. 사용자 '다음 진행'에 따라 이전 입력 적합성 점검의 후속1~3번을 제한된 참조 범위에서 구현했다.

## 결론

**본문9종의 선정 사실30개를 원문 위치·값·관계와 연결해 고정했다.**
같은 본문에 가상 맥락을 결합한21사례는 새 내부 정책에서 등급18건/HOLD3건으로 재계산·고정했다.
기존 v0.2 예상 라벨을 덮어쓰지 않고 별도 `short-body-content-reference/0.3` 결과로 저장했다.

이는 **이 본문·가상 조건·내부 규칙 아래의 정답**이다. 실제 조직의 등급 기준을 객관적으로 증명한 것은 아니다.
본문 사실은 원문 값과 계산으로 검산할 수 있지만, 그 사실을 TS/S1/S2/S3로 매핑하는 규칙은 명시적인 내부 선택이다.
외부 검수자 서명 대기를 선행조건으로 두지 않았다. 고객 정책 승인·고객 GOLD·일반 문서 정확도와는 구별한다.
등급별250개, 총1,000개의 독립 문서 정답지는 아직 완성되지 않았다.

## 검산 방식과 정책 결과

- 전체 본문 정규식 파서와 별도로 직접 작성한 값·원문 앵커 명세가30개 사실에서 일치했다.
  정답 명세는 실행 시 추출기 출력에서 생성하지 않는다. 두 구현의 작성 주체는 같으므로 독립 기관 검수는 아니다.
- 산술 설명은 입력0~9 전수 계산과 반복 덧셈/뺄셈 구현을 대조했다.
  출력은 순서대로3,10,6,2,9,5,1,8,4,0이다. 현실 기술의 사업 가치나 재현 가능성을 증명한 것은 아니다.
- 관측 기록은 세 관측에 모두 맞지만 입력3의 출력은0/1로 다른 두 유한 함수를 제시했다.
  두 함수 중 하나가 정답이라는 뜻이 아니라, 세 관측만으로 프로그램을 유일하게 확정할 수 없다는 증거다.
- 가격 역할·단위·조건 방향, 실제 필드와 빈 서식 서술의 충돌, 시각 범위를 검사했다.
- 숫자/제목이 바뀐 미등록 본문은 추출 가능하더라도 고정 정답 자격을 주지 않는다. 미지원·누락 본문도 HOLD다.

[내부 정책 전체](SHORT_BODY_FACT_REFERENCE_V1.md)와 [조건부 답안](../reports/SHORT_BODY_FACT_REFERENCE_20260915/reference_v1/policy_answers.fixed.jsonl)을 분리했다.
답안에는 적용 규칙, 다른 등급 배제 이유, 본문 사실 증명서 해시, 가상 맥락 위치/값 해시를 포함했다.

| 결과 | 건수 | 제한된 합성 조건 |
|---|---:|---|
| TS | 1 | 검산된 완결 프로그램 + 현행 핵심 자산 + 비공개 |
| S1 | 2 | 비공개 관측 기록/거래 세부조건 |
| S2 | 4 | 비공개 일정·접수·설비 배정·이동 |
| S3 | 11 | 범위/상위 위험 배제가 명시된 빈 서식 또는 해당 판본 공개 허가 |
| HOLD | 3 | 제공 범위가 unknown인 계산/거래/배정 사례 |

독립 본문21개가 아니라 본문9개에 대한 맥락 변형21개다. 동일 본문의 사실 증명서는 맥락을 바꿔도 동일하다.
공개·비공개가 충돌하거나 필요한 값이 unknown이면 HOLD다. 다른 상위 위험이 없다는 가정도 별도 필수 입력이다.
공개 허가 부재를 비공개로, 본문이 내부문서라는 이유를 관리 증거로 역산하지 않았다.

9본문 × 맥락5필드 각각 false/true/unknown = **2,187조합**에서 직접 분기와 SQLite CASE의 등급/HOLD가 일치했다.
이는 같은 유한 규칙의 구현 검산이지 고객 기준의 정당성 검증이나2,187개 독립 평가 문서가 아니다.
이전 예상 라벨과는 재계산 후 비교해21/21 일치했다. 예상 라벨을 바꿔도 계산 결과는 바뀌지 않는 검사를 포함했다.

## 남은 한계와 다음 작업

이번 개선은 **사실 정답의 근거·조건·변조 검증**이다. 실제 분류기 품질 개선을 측정한 것이 아니다.
표현이 달라진 새 문서를 이해하는 일반 추출기, 전체 학습풀 중복/근접중복, 전체 본문 문체 지름길 검사는 아직 남아 있다.
제한 플래그/원본 경로 manifest로 학습·모델 평가를 거절하지만, 메타데이터를 제거한 복사본까지 막는 deny registry 등록은 하지 않았다.

다음 우선순위:

1. 현재 참조의 전체 본문 지름길·정확/근접중복을 검사한다. 본문 사실추출 검사와 등급/정책 검사를 분리하고,
   같은 본문/문서 계열/맥락 변형을 학습과 평가로 갈라 독립 건수로 세지 않는다. 0건은 성공 처리하지 않는다.
2. 기존9개에 맞춘 파서가 없는 새로운 표현·문서군을 별도로 만든다. 사실값·근거와 의미 보존/반전/누락 대조를 먼저 정의한다.
   새 일반 추출기 검증에는 정답표/목표등급/ID를 입력하지 않는다. 기존 참조 수정 대신 새 버전으로 추가한다.
3. 실제로 서로 다른 본문과 판단 경계를 갖고 앞 검사를 통과한 사례만 등급별250건 목표에 채택한다.
   문체/숫자만 바꾼1,000건을 독립 정답1,000건으로 보고하지 않는다. 부족한 근거는 HOLD로 별도 유지한다.

고객사 D01~D08 결정/승인, 일반 문서 모델 평가·재학습·운영 반영·사람 서명은 하지 않았다.
운영 API/모델/DB/라벨/기존 검수 경로 변경 없음. 커밋·푸시·전역 메모리 수정 없음.
워크스페이스 MEMORY와 인계문은 갱신했다. reports는 Git ignore이므로 외부 백업 완료는 아니다.
