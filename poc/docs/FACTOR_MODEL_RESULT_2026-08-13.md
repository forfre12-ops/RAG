# 요소(S/V/M) 예측 모델 — 순환을 끊으니 등급이 따라왔다

작성 2026-08-13. `RULE_EXTRACTOR_DIAGNOSIS_2026-08-12.md` §8 제안의 실행 결과다.
**실험이며 아직 서빙에 붙이지 않았다.**

---

## 1. 왜 했나

룰 추출기의 s_lv/v_lv/m_lv 은 요소 근거가 아니라 content_grade(키워드 argmax)에서 역산된다.
그 S/V/M 이 다시 `grade_from_svm()` 에 들어가 등급이 되니 순환이고, 분포 밖에서는 800건
전부에 S3 라는 상수를 낼 뿐이다. 시드로는 못 고친다는 것을 실측으로 확인했다(누산 점수
분산 0 · semantic 코사인이 음성 대조군과 겹침 · 임계 탐색이 상수 예측기로 수렴).

남은 길은 요소를 학습으로 뽑는 것이고, 라벨이 이미 있었다 — v6 계열이 `expected_factor_scores`
를 전건 보유한다.

## 2. 구조

공유 백본(KF-DeBERTa-base) + 요소별 3-way 헤드 3개. 손실은 합. 등급은 예측한 S/V/M 을
`grade_from_svm()` 에 넣어 얻는다. **요소가 먼저, 등급이 나중이다.**

생산 trainer(`m4_training.trainer`)는 건드리지 않았다. 4등급 단일헤드에 특화돼 있고
(MLflow·base model attestation·chunk 확장·sample weight) 거기에 헤드를 늘리면 배포 학습
경로가 흔들린다. 검증 전까지는 `scripts/train_factor_model.py` 로 분리해 둔다.

셋 분리:

```
학습   labeled_v6_factor_grounded/train.jsonl   1,833건 -> 청크 4,459
검증   labeled_v6_factor_grounded/val.jsonl       455건  (쓸모없었다, §3 참조)
개발   proxy_eval/.../development_200.jsonl       200건  조기종료·집계방식 선택
판정   proxy_eval/.../final_800.locked.jsonl      800건  마지막에 한 번만
```

## 3. 두 번 막혔고 두 번 다 진단이 필요했다

### (a) v6 val 은 검증 신호를 주지 못한다

1 epoch 만에 정확도 1.000 이 나온다. 학습셋과 같은 코퍼스라 규칙으로 풀린다(v6 분류기
학습 때도 F1 1.000 이 나와 아무것도 못 알려줬다). **조기종료 기준이 없는 상태로 학습하고
있었다.** 계보가 다른 development_200 을 붙이고 나서야 꺾이는 지점이 보였다.

### (b) value 만 안 됐다 — 가설 네 개를 반증하고 다섯 번째에서 잡았다

처음 결과가 secrecy MAE 0.16 · management 0.04 인데 **value 만 1.04** 였다. 혼동행렬을
보니 "한 단계 낮음"이 아니라 0 으로 붕괴였다(정답 2 -> 예측 0 이 88/124).

| 가설 | 검증 | 결과 |
|---|---|---|
| 사전(prior) 불일치 | 학습·평가 요소 분포 대조 | 반증 (9/23/69 vs 13/25/62) |
| 표현 풀 분리 | 문장 겹침률 | 반증 (요소 무관 3~4%) |
| 과적합 | epoch 별 dev MAE 추이 | 반증 (1~5 epoch 내내 1.33 평평) |
| 요소 규약 충돌 | 판별문장 교차 대조 | 반증 (불일치 0/9) |
| **입력 창 절단** | 창을 옮겨 재측정 | **확정** |

v3 문서 중앙값이 1,085 토큰인데 창은 512 다. 세 요소 신호가 문서 곳곳에 흩어져 있다:

```
§4 공개 여부와 관리 상태 (secrecy)     시작 426 토큰
§5 업무 가치와 영향 (value)           시작 486 토큰   <- 26 토큰만 보임
§7 자료 보존과 접근 통제 (management)  시작 620 토큰   <- 0% 안 보임
```

창을 옮겨 먹이니 뒤집혔다:

```
앞부분(현행)   secrecy 0.160 · value 1.045 · management 0.040
§4 부터        secrecy 0.180 · value 0.190 · management 0.970
§5 부터        secrecy 0.755 · value 0.190 · management 1.185
```

**모델은 셋 다 배웠는데 평가가 앞부분만 먹이고 있었다.** 반증된 네 가설도 값이 있다 —
"표현 풀이 달라서"나 "과적합이라서"로 결론냈으면 엉뚱한 데를 고쳤다.

추론에만 청크 집계를 붙이면 오히려 나빠진다(평균 MAE 0.478 -> 0.810). 문서 앞부분으로만
학습해서 중간 청크가 분포 밖이기 때문이다. **학습도 청크로** 해야 한다 — 생산 분류기가
이미 그렇게 한다.

## 4. 집계 방식은 요소 MAE 로 고르면 틀린다

development_200 에서:

| 설정 | 등급 일치 | **고등급 미탐** | 과분류 |
|---|---|---|---|
| chunk=0 mean | 69.0% | 38.9% | 1.0% |
| **chunk=1600 mean** | 71.0% | **15.6%** | 16.5% |
| chunk=1600 max | **72.5%** | 24.4% | 10.5% |

`max` 가 등급 일치율은 가장 높은데 미탐은 mean 보다 많다. 게이트 순서가 ①고등급 FNR
②퇴행성 ③검수부담 ④F1 이므로 **mean 채택**. 등급 일치율로 골랐으면 틀렸다.

조기종료도 작동했다 — dev 평균 MAE 가 epoch 2 에서 최소(0.255)고 3·4 에서 올라가
(0.267·0.273) epoch 2 체크포인트가 채택됐다.

## 5. 판정 — final_800 (800건, 잠금, 1회)

```
등급 일치율 67.0%  ·  고등급 미탐 20.0% (360건 중 72)  ·  과분류 15.0%

요소          평균차    MAE    정확     낮게봄    높게봄
secrecy      +0.09    0.29   79.1%    6.4%   14.5%
value        -0.08    0.42   70.1%   16.6%   13.3%
management   -0.05    0.05   95.9%    4.1%    0.0%
```

같은 셋에서의 룰 기준선과 대비:

| | 룰 추출기 | **요소 모델** |
|---|---|---|
| secrecy MAE | 1.44 | **0.29** |
| value MAE | 1.44 | **0.42** |
| management MAE | 0.94 | **0.05** |
| 등급 일치율 | 30.0% | **67.0%** |
| 고등급 미탐 | 100% (전건 S3) | **20.0%** |

룰의 30.0% 는 성능이 아니라 v3 의 S3 기저율이다(800건 전부 S3 라고 답한다). 요소 모델의
67.0% 는 네 등급을 실제로 구분한 값이라 성질이 다르다.

참고로 배포본 등급 분류기(v5)는 같은 셋에서 F1 0.2613 · accuracy 34.25% · 고등급 FNR
0.5472 였다. 요소 경유가 그보다 낫다(67.0% / 20.0%). 다만 v5 는 다른 계보로 학습된
모델이라 이 비교는 참고치이지 공정 비교가 아니다.

## 6. 무엇을 주장할 수 있고 없나

**할 수 있는 주장**: 요소를 직접 예측하면 등급->요소 순환 없이 등급이 나오고, 잠금 평가셋에서
룰 추출기보다 모든 축에서 낫다. 설명도 제대로 된다 — "비공지성 2 · 경제적유용성 2 ·
관리성 0 이라 S1".

**할 수 없는 주장**: 실문서 일반화. 학습·평가가 전부 합성이다(자체 실측 교차silver->gold_real
F1 0.26). v3 는 계보 독립이 확인된 셋이지만 같은 저술 프로그램 계열이고, 무엇보다 회원사
실문서로 잰 값이 이 프로젝트에 **0건**이다.

**고등급 미탐 20.0% 는 그대로 쓸 수 없다.** 이는 모델 단독 값이고 서빙 가드(신뢰도 게이트·
합의 게이트·FNR-safe 상향)를 태우지 않았다. 배포본도 모델 단독 FNR 54.7% 가 서빙 경로에서는
검수 라우팅으로 흡수됐다.

## 7. 채택하려면 남은 것

1. 서빙 경로에 붙여 **가드 포함 미탐**과 자동확정률 측정
2. 합의 게이트 재설계 — 요소 모델이 들어오면 룰과 모델의 "독립성"이 지금과 달라진다
   (지금의 독립성은 이미 허구다. 분포 밖에서 룰은 상수 S3 다)
3. 생산 trainer 통합 여부 판단 — 계약 해시·attestation·MLflow 경로가 걸린다
4. 온도 보정 — 요소 헤드별로 필요한지 미측정
