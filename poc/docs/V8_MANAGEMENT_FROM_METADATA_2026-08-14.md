# 관리성을 문서 밖에서 받는다 — ICD 매핑은 이미 합의돼 있었고 구현만 없었다

작성 2026-08-14.

---

## 1. 왜 필요한가

관리성은 **본문에서 관측되지 않는다.** 실문서 판정면의 업무문서를 세어 보면 이렇다.

```
등급   n    길이 중앙   관리성 어휘 포함
TS    33     236자      9/33
S1    22     187자      2/22
S2    17     167자      1/17
```

200자 문서가 자기 접근통제를 진술할 수는 없다. 비공지성을 본문 대신 **출처**로 판정한
것과 같은 자리이고, 관리성의 증거는 **보관 위치와 접근권한**이다.

그리고 등급에 미치는 영향이 크다. 정본에서 S1 이 나오는 조합은 `(2,2,0)` **하나뿐**이라
M 이 0 으로 확정될 때만 S1 이다. 보수적 완성이 미확인 M 을 2 로 채우므로 M 을 못 받으면
**S1 은 구조적으로 도달 불가**이고, 봉인 판정면의 28%(18/64)가 어떤 모델에서도 TS 가
된다 — 4등급 정확도 상한이 0.719 로 막힌다.

---

## 2. 매핑은 새로 만들 것이 아니었다

`doc/result/감리정본/KL연동_인터페이스_규약서_ICD.html` §3.2·§3.3 에 이미 있다.

```
§3.2 security_marking      top_secret 2 · secret 2 · confidential 1 · none -> 접근범위로
§3.3 access_scope          approved_only 2 · designated 1 · department 1 · all_employees 0
                           null -> 텍스트 폴백(보수적)
```

그런데 배포본은 이 표를 **등급 floor 로만** 썼다(`pipeline.py` metadata-floor). M 값을
만들지 않았고, `access_scope` 는 경고만 냈으며 `all_employees` 는 아예 처리되지 않았다.
즉 표시되던 관리성은 **등급에서 역산한 값**(`svm_levels_for_grade`)이었지 근거가 아니었다.

---

## 3. 구현

```
정본 함수    rule_engine.management_from_metadata(security_marking, access_scope)
             -> (state, level, reason)
             state = present | proven_absent | unknown
```

`proven_absent` 와 `unknown` 을 나누는 것이 핵심이다. 전자는 곱을 0 으로 만들고(S1 또는
S3) 후자는 보수적 완성에서 최악값으로 채워진다. 뭉치면 S1 이 사라지거나 미탐이 열린다.

두 경로가 **같은 함수**를 쓴다 — 재구현하면 배포본과 기준이 갈리고 판정이 무의미해진다
(출처 prior 때 같은 이유로 배포본 함수를 그대로 썼다).

```
배포본   m5_inference/pipeline.py   요소값을 채운다. **등급은 안 바꾼다**
연구     scripts/v8_serving_gate.py  2.5층에서 M 을 대체한다
```

배포본에서 등급을 안 바꾸는 이유: 배포본은 **등급 우선·요소 후행** 구조라(모델이 등급을
내고 요소를 거기 맞춘다) M 을 등급에 바로 물리면 하향 경로가 열린다. `all_employees`
는 등급을 무음으로 내리는 대신 `metadata-management-conflict` 경고로 검수에 보낸다.
요소 우선 경로는 v8 서빙 게이트가 담당한다.

## 4. 무엇이 열리는가 — 커버리지·오류율을 흔들어 실측

실문서 판정면에는 메타데이터가 없다(`gold_real` 어느 파일에도 `security_marking` /
`access_scope` 가 없다). 그래서 합성 2차 판정면에 참 M 에서 역산한 ICD 값을 주입해
잰다(`scripts/v8_icd_sim.py`).

```
커버리지  오류율   4등급     S1재현율   자동확정   무음미탐   미탐상한
   0%     0%     0.7543    0.5458    78.3%       0     0.00133
  50%     0%     0.7889    0.7106    74.6%       0     0.00140
 100%     0%     0.8310    0.8791    71.0%       0     0.00147
 100%     5%     0.8092    0.8352    71.0%      33     0.01768
 100%    20%     0.7345    0.6923    71.5%     140     0.06241
  50%    20%     0.7405    0.6154    74.7%      69     0.03163
```

**전건·무오류면 4등급 0.7543 -> 0.8310, S1 재현율 0.5458 -> 0.8791 이고 미탐은 0 이다.**

그리고 운영 요구사항이 하나 나온다.

```
⚠ 메타데이터 오류율 5% 까지는 미탐 상한 0.0177 로 사전등록 한계(0.02) 이내다.
  20% 면 0.0624 로 깨진다. **오류율 5% 가 계약 경계다.**
```

자동확정이 78.3% -> 71.0% 로 내려가는 것은 정상이다. M=0 인 문서가 TS 가 아니라 S1 이
되고 S1 은 최상단 확정 대상이 아니기 때문이다 — 분류가 더 정확해진 결과다.

⚠ 이 모사는 **이득을 과소평가**한다. 합성 판정면은 관리성이 본문에 진술돼 있어 메타
   데이터 없이도 S1 재현율이 0.5458 이지만 **실문서는 0 이다**(구조적 도달 불가).
