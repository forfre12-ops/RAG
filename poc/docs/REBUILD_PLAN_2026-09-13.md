작성 2026-09-13. 사용자 결정: **"지금까지 의도된 거 없었다. 새로 만드는 게 나을 거야.
아무런 기준도 판단도 없었다."**

선행 문서 `EVAL_CRITERIA_2026-09-13.md`(판정 기준) · `GOLD_ESTABLISHMENT_PLAN_2026-09-13.md`(GOLD 확보).

## 0. 왜 고쳐 쓰지 않고 새로 세우는가 — 실측

| 무엇 | 실측 |

| 사람이 서명한 정답 | **39건 / 448,445행 (0.009%)** · 그중 34건이 한 묶음 |
| 채점에 쓰던 네 평가면 | 전부 BRONZE 이하. golden100 은 출처 기록 자체가 없음 |
| 공개 시황·증권 리포트가 TS/S1 | **고유 16건 · 183행 · train 분할 156행** (연준 FOMC 기사 등) |
| 판례체 문서 | **고유 3,887건 · 57,521행**이 S3 31,436 · S2 11,767 · S1 7,666 · TS 6,233 으로 흩어짐 |

**고칠 수 있는 결함이 아니라 기준이 없던 것이다.** 라벨을 하나씩 고치는 비용이
새로 세우는 비용보다 크고, 고쳐도 "누가 왜 그렇게 정했나" 에 답할 수 없다.

## 1. 버리지 않는다 — 격리하고 역할을 바꾼다

삭제는 되돌릴 수 없다. **격리**한다. 폴더와 이름으로 역할을 강제한다.

| 지금 | 새 역할 | 허용 용도 |
|---|---|---|
| 현행 학습셋 전부 | `quarantine/` | **학습·평가 금지.** 회귀 대조용으로만 읽음 |
| 시황·증권 16건 | `quarantine/contaminated/` | 어디에도 쓰지 않음. 사례로만 보존 |
| 판례체 3,887건 | `public_case_s3_eval/` (라벨 재판정 후) | **공개문서 과분류 시험** ⭐ |
| 공개 실문서 S3 13,260건 | `external_public_s3/` | 같음. URL·기관·해시·수집시각 보유 |
| 777건 LLM 라벨 | `machine_adjudicated_silver/` | 탐색·상대 비교만 |
| 새로 만드는 것 | `reference_locked_eval/` | 공통 제품 합격 기준 |
| 고객사 확정 문서(미래) | `customer_locked_eval/` | 고객사별 실제 성능 |

⭐ **판례는 버릴 자산이 아니다.** 판결문은 공개 문서이므로 **정답이 S3 여야 한다.**
지금 TS/S1 으로 붙은 13,899행을 S3 로 재판정하면, 그 자체가
**공개문서 과분류 시험셋 3,887건**이 된다. 우리가 가장 취약한 축이다
(holdout109 공개문서 43건 중 9~13건 과탐 · golden100 25건 중 16~21건).

⚠ 단 **재판정 전에 확인할 것**: 이 문서들이 판결문 원문인가, 판례를 흉내 낸 합성인가.
   원문이면 S3 확정. 합성이면 그 안에 심어진 영업비밀 내용에 따라 다르다.
   **사람이 표본 100건을 읽고 판정한다.** 자동 분류는 오늘 두 번 틀렸다.

## 2. 실행 순서 — 의존 관계 순

각 항목에 **끝났다고 말할 수 있는 조건**을 붙였다. 없으면 끝난 게 아니다.

### 단계 1. 오염 전수 감사 (2~3일) — 다른 모든 것의 전제

    도구  scripts/audit_label_contamination.py (신규)
    방법  세 축 교차 + 사람 표본 검수
          A) origin/provenance 필드가 public·real
          B) 출처 URL·발행기관·해시가 붙은 행
          C) 본문 문체 — 판례체 · 보도자료체 · 시황체 · 공시체
          D) **사람이 각 축 표본 30건씩 읽고 오탐률을 낸다**
    산출  오염 목록(문서 단위) · 사유 · 제안 조치(격리/재판정/유지)
    완료 조건  각 축의 사람 검수 오탐률이 함께 보고될 것.
               자동 분류만으로 끝내지 않는다 — 오늘 정규식이 두 번 틀렸다

### 단계 2. 등급 역산 차단 (3일) — 우리 손으로 되는 진짜 버그

    지금  rule_engine.py:758-762 가 content_grade 에서 s_lv·v_lv·m_lv 를 만들고,
          777-782 가 최종 등급으로 그것을 **덮어써서** factor_scores 로 내보낸다.
          밖에서 보면 관측값처럼 보이지만 등급에서 나온 값이다.
    할 일  factor_scores 에 등급 파생값을 넣지 않는다.
          관측된 것만 넣고, 없으면 unknown 으로 비운다.
          표시용 값이 필요하면 별도 키(`display_svm`)로 분리해 출처를 명시한다.
    완료 조건  "factor 값이 등급에서 파생되지 않는다" 를 지키는 시험 + 회귀 델타 0

### 단계 3. facts 계약 (1주) — 이미 있는 것을 표준화

    이미 있다  nonpublicity 161,711건이 {basis:'text', spans:[{end,quote}]} 구조.
               새 설계가 아니라 **확장**이다.
    확장할 것  state: observed | proven_absent | unknown   <- 지금 없음
               origin: content_extracted | system_supplied | public_source | dlp
               evidence: span · URL · 시스템 필드 · 수집 시각
    초기 fact  시스템 공급  access_scope · security_marking · source_type
               본문 관측    management_marking_in_text · nonpublicity
               공개 검증    public_disclosed (URL·기관·해시·수집시각)
    ⛔ 제외    document_type — 등급 지름길이다(제거 실험 57.2% -> 32.2%, 찍기 25%)
    ⛔ 금지    등급 · 모델 점수 · rule_factors 를 fact 의 원천으로 쓰지 않는다
    완료 조건  세 상태가 스키마와 시험으로 강제될 것. unknown 을 낮은 등급으로
               자동확정하는 경로가 0 임을 시험이 지킬 것

### 단계 4. 기준 정책 ICD-REF-1.0 (1주 · 3과 병행)

    출력 다섯  TS · S1 · S2 · S3 · **검수 필요**
    규칙       REF-S3-01  공식 공개 URL+발행기관+수집시각+해시 확인 -> S3
               REF-TS-01  법정 보호 근거 + 비공개성 + 관리 근거 -> TS
               REF-S1-01  고가치 설계·소스·가격·입찰 + 비공개성 + 관리 근거 -> S1
               REF-S2-01  내부 운영·사업 정보 + 비공개성·관리 근거 -> S2
               REF-REV-01 필요 값 미수신·충돌 -> 검수 필요
    원칙       internal 경로로 들어왔다고 자동으로 비공개가 아니다.
               표식·ACL·공개 여부가 없으면 낮은 등급으로 확정하지 않는다.
    승인       제품 책임자 + 정책 책임자. 문서 1,000건 검수는 필요 없다.
    ⚠ 먼저 잴 것  이 정책을 지금 데이터에 적용하면 **자동확정률이 얼마가 되나.**
                  ACL 0건이라 TS/S1/S2 는 전부 검수 필요로 떨어질 수 있다.
                  S3 경로는 11,759건에서 작동한다(URL·기관·해시·수집시각 보유).
    완료 조건  자동확정률 실측치가 정책표와 함께 승인될 것.
               **안전 게이트만 0 으로 조이면 "전부 검수 필요" 가 만점을 받는다.**

### 단계 5. 공개문서 과분류 게이트 (3일) — 가장 싸고 효과가 확실

새로 만들지 않는다. 있는 것을 쓴다.

    재료  external_public_s3 13,260건 + 판례 재판정분 3,887건
    게이트  공식 공개 S3 를 TS/S1 으로 자동확정 **0건**
    왜 먼저  우리가 가장 취약한 축이고, 문서 생성 없이 오늘 만들 수 있다
    완료 조건  현행 배포본의 위반 건수가 기준선으로 기록될 것

### 단계 6. 사람 간 일치도 κ (1주 · 병행) — 합격선의 유일한 근거

    표본  30건 (TS·S1·S2·S3 각 7~8건) · 합성이어도 된다
    인원  2~3명 · 독립 blind (서로의 답과 모델 예측을 못 봄)
    산출  Cohen/Fleiss κ · 등급별 일치율 · 가장 많이 갈린 등급 쌍
    읽는 법  κ≥0.80 목표 90% 겨눌 만함 / 0.60~0.79 천장 아래로 조정 /
             <0.60 등급 정의부터 고쳐야 함
    완료 조건  κ 값 없이 합격선을 숫자로 정하지 않는다

    7-2  공개 S3 100건          (2일) 13,260건에서 **선별**. 만들지 않는다.
    7-3  unknown·충돌 100건     (3일) 검수 라우팅 시험. fact 를 비우면 되므로 싸다.
    7-4  경계·반사실 쌍 200건    (1주) 한 사실만 바꿔 등급이 갈리는 쌍
    7-5  구성형 명확 문서 350건  (2주) 가장 비싸다. **마지막에 한다**

    생성 규율  fact card 를 먼저 만들고 문서를 쓴다.
               생성기에 등급명·보안표식·정답 설명을 주지 않는다.

    잠금       expected_result 는 생성 후 다시 계산하지 않고 별도 원장으로 고정한다

## 3. 합격 게이트 (모델 버전이 통과해야 하는 것)

|---|---|
| 정책 엔진 | 정책 벡터 250건 100% 일치 |

⭐ **자동확정률 하한이 없으면 "전부 검수 필요" 모델이 만점을 받는다.**

   S3 과탐이 25/25 = 100% 였다.

F1 목표치는 **첫 기준선과 κ 를 본 뒤** 정책 책임자가 정한다. 근거 없이 먼저 정하지 않는다.
반면 위 안전 게이트는 첫날부터 0 기준으로 운영할 수 있다.

## 4. 실험 규율

한 번에 하나만 바꾼다. 각 단계마다 같은 잠긴 셋으로 재고, 한 지표만 좋아지고
치명적 미탐이 늘면 탈락이다.

    기준 모델 -> 오염 제거 -> facts 다중과제 -> 반사실 쌍 추가 -> 도메인 적응 -> 표·OCR

조건마다 **시드 3판**. 범위가 겹치면 "차이 없음" 이다.

## 6. 이 계획이 지키는 한 줄

**모델 점수가 아니라, 고정된 사실·규칙·잠긴 입력에서 무엇을 놓쳤는지로 합격을 판단한다.**
그리고 **그 정답을 누가 왜 그렇게 정했는지 말할 수 있어야** 한다. 지금은 말할 수 없다.
