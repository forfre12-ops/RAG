# 분류 품질 재발 방지와 재개 조건

상태: 안전장치 구현 / **사업 분류 목적·정책·정답은 미승인**.
이 문서는 운영 산정식·고객사 정책·모델을 변경하거나 승인하지 않는다.

## 방향 정정

내용 기반 보호등급 추천은 사용자가 요청한 내부 실험 범위였다.
이를 사업의 승인된 주 출력과 동일시하면 안 된다. 기존 인계의 ‘확정한 방향’은 그 범위가
빠진 표현이었으며, 분류 목적을 미정으로 둔 승인 초안 A01과 구분한다.
기존 기준·답안·검토 기록은 삭제하지 않는다. 아래 제한이 과거 후속 실행 안내보다 우선한다.

## 정책 판단의 정확한 경계

- 사용자 숫자 입력의 선택 여부와 시스템 판단요소·근거 활용은 다른 결정이다.
- FUN-023은 가이드 기반 라벨 매핑 및 판단요소 연계·활용을 요구한다. 특정 다중헤드 구조나
  신경망 내부 곱셈만을 요구하는 것은 아니다.
- 가이드11쪽은 기업 규모·실정에 따라 비공지성 또는 경제적 유용성만으로 분류할 수 있는
  예외도 설명한다. 따라서 M을 언제나 생략할 수도, 어느 정책에서도 생략 불가라고도 단정하지 않는다.
- 가이드12쪽의 4단계 예시와 프로젝트 라벨 대응은 곱0→S3, 1/2→S2, 4→S1, 8→TS이다.
  `(2,2,0)→S1`은 원 가이드 곱셈이 아닌 내부 보정이다. 현재 기본 모드는 변경하지 않는다.
- 필요한 관리정보가 없으면 `unknown`이다. 본문만으로 실제 ACL이나 관리 상태를 창작하지 않는다.
- PMR-002의 골든셋·블라인드 시험·재현율 목표는 합성 정책 시험의 자기 일치도로 충족하지 못한다.
  문서/청크 단위, macro/micro/등급별 재현율, HOLD 분모는 D06/D07에서 결정해야 한다.

## 사용 제한과 보호 범위

`src/koipa/policy_fixture_registry.json`은 원본을 고치지 않는 **사용 제한 명세**다.
140+40건의 ID·문서 계열·정책 버전·공백 정규화 본문 해시와 원본 파일 지문만 저장한다.
원문·답안·인증정보는 이 레지스트리에 넣지 않는다. 원본 reports 경로는 그대로 유지한다.
규칙 시험·근거 구조 검사·누설 진단에는 사용할 수 있지만, 학습이나 모델 성능 분모에는 넣지 않는다.
`training_allowed=true`나 자칭 서명을 덧붙여도 등록된 시험자료의 금지는 해제되지 않는다.

현재 연결된 경로:

- `m4_training.trainer`: 학습 및 검증/시험 입력 로더.
- `p1_train_classifier`: 오프라인 gold 로더/규칙 평가.
- `train_factor_model`: 학습/검증 공통 로더.
- `ab_tell_train`: 별도 경량 A/B 학습/평가 로더.
- `eval_p1_model_gold`: 평가 로더, 직접 모델 및 API 유사 추론 전 검사.
- `proxy_training_finalization.load_model_document_logits`: 체크포인트 평가 로드 전 검사.
- 2차 보완: `proxy_model_comparison.predict_model`, `collect_document_window_logits`,
  `m6_evaluation.serving_eval.predict_via_serving` 직접 평가 호출에도 검사.
- `eval_serving_path`, `eval_serving_vs_raw`: 원래 행의 계보를 검사한 뒤 평가용 필드 추출.
- `eval_on_clean_candidates`, `score_model_on_eval`: 평가 입력 검사.
- `validate_content_reference --predictions`: 정책 시험자료의 모델 채점 금지.
  예측 없는 구조 검증은 유지한다.

구 `content_reference_contract.measure_predictions`는 기존 정책/계산 단위시험의 저수준 함수로
보존한다. 고객사 모델 평가 진입점이 아니다. 임의 코드가 이 함수나 다른 지표 함수를 직접 호출하여
숫자를 만드는 것까지 보안적으로 봉쇄하지는 않는다. 새 실행 경로는 공통 사용 검사를 거쳐야 한다.
해시 차단은 메타데이터 제거·이름 변경·공백 변경 복사본에는 작동하지만, 본문 재작성/부분 청크에
메타데이터까지 제거하면 모든 변형을 찾지는 못한다. 따라서 원문 ID·계열·계보를 유지해야 한다.
레지스트리는 접근 통제나 승인 인증 시스템이 아니며, 통과했다고 다른 데이터가 GOLD가 되는 것도 아니다.

## 실행 및 종료코드

아래 명령은 `F:\antigravity\rag\poc`에서 실행한다. Python은 `.venv\Scripts\python.exe`를 쓴다.

```powershell
.\.venv\Scripts\python.exe -B scripts/audit_classification_readiness.py
.\.venv\Scripts\python.exe -B scripts/measure_grade_phrase_leak.py --pool reports/CONTENT_REFERENCE_20260914/reference_v1 --min-docs 5 --cv-seeds 5 --strict --top 0
.\.venv\Scripts\python.exe -B -m pytest --confcutdir=tests/data_quality tests/data_quality -q
```

- 준비도: 미결정이면 종료2/HOLD. 기록이 채워져도 담당자 신원/승인 진위를 검증하거나 실행을 허가하지 않는다.
- 누설 검사: 종료0은 진단 완료일 뿐 품질 승인 아님. 입력 불량/등급 후보0건은 종료2,
  `--strict`에서 지름길 경고 또는 문자/계열 CV 미실행은 종료3.
  2차 보완부터 CV 옵션 자체를 생략해도 `INCOMPLETE_CHECKS`로 실패한다.
- 20%p 문장 초과, CV 평균80% 이상 및 permutation 대비30%p 이상은 **개발용 경보 임계**다.
  계약상 합격선이나 누설 확정 판정이 아니다. CV를 생략한 실행은 문자 패턴 안전을 검사하지 않았다.
- `--split` 기본은 development. 봉인 분할은 따로 명시한 경우에만 분석하며, 분석 후에는 순수 미열람
  시험자료라고 주장하지 않는다. 이번 측정은 개발80건만 사용했다.
- v1.1은 `--view body_only`에서40건 전부 검토 사례여서 등급 후보0/종료2가 정상이다.
  `body_plus_synthetic_context`는 가상 맥락을 실제 입력에 포함하는 정책 시험 관점이다.
- 결과 파일은 새 경로에만 쓴다. 기본 출력은 단서 원문 대신 SHA-256이다.
  2차 보완은 파싱한 실제 바이트의 해시와 측정 종료 후 선택 파일의 해시를 대조한다.
  이는 파일 잠금이나 변경 후 원상복귀까지 추적하는 감시 장치는 아니다.

## 재개 순서와 완료 조건

1. [미결정8개](classification_decisions.pending.json)의 D01~D08에 실제 담당자 결정과 근거를 받는다.
   먼저 [D01/D02 권고안](CLASSIFICATION_D01_D02_PROPOSAL_2026-09-15.md)을 검토한다.
   추천 구조는 **근거→요소 후보/unknown→승인된 정책→후보 등급·검토 상태→관리자 최종확정**이다.
   이는 설계 제안이지 사업 목적 승인이나 운영 적용이 아니다.
2. 결정된 정책으로 실제 사용 허가를 받은 문서를 표집하고 독립 정답을 만든다.
   판단 불가 문서는 낮은 등급으로 메우지 않고 별도 보류 정답을 둔다.
3. 문서 계열·학습 계보·블라인드 접근 및 라벨/본문 버전을 고정한다. 본문과 답안 설명을 분리한다.
4. 개발 데이터에서 입력 검사·지름길 진단을 통과해도 독립 검수/정답 진위를 대신하지 않는다.
   검수와 범위 승인이 충족된 후에만 동일 문서·초기 모델·설정으로 라벨 A/B를 진행한다.
5. 추가 데이터 효과는 별도 실험으로 분리한다. 평가 모집단/지표를 바꾸고 점수 향상으로 보고하지 않는다.
   실제 고객사 시험과 운영 반영은 별도 승인이다.

이번 완료의 의미는 재발 방지 장치와 결정 대기 목록의 준비다.
모델 품질 향상·정답 확정·요건 검수 통과·원격 백업 완료를 뜻하지 않는다.
