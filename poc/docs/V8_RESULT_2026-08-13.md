# v8 1차 판정 — (A) 문자열을 외웠다. 원인은 극성이고, 분할 설계가 그것을 조장했다

작성 2026-08-13. `V8_PREREGISTERED_CRITERIA.md` 를 동결한 뒤 학습하고 판정한 결과다.
사전등록한 기준을 그대로 적용했고 기준을 바꾸지 않았다.

사전등록 §6 에 따라 **게이트는 열지 않는다.** 자동확정 조건 근처에도 가지 못했다.

## 2. 어디까지는 됐나 — 형태 결박은 실제로 풀렸다

dev(미관측 형태 · 기관측 표현)에서 **1 epoch 만에 요소 MAE 0.000 · 등급 정확 1.000** 이다.
혼동행렬도 거의 완전 대각이다(unknown -> absent 3~5건뿐).

이것은 실패가 아니라 결과다. **표현을 아는 상태에서 형태만 바뀌는 것은 모델에게 어렵지 않다.**
v8 이 겨냥한 형태 결박은 풀렸고, 남은 것은 표현 전이다.

계보·형태별로도 균일하다 — contract_terms 0.446 · customer_list 0.464 ·
prose 0.441 · terse 0.449 · field 0.473. 특정 형태나 문체의 문제가 아니다.

## 3. 무엇이 무너졌나 — secrecy·value 만, 그리고 한 방향으로

```
요소 정확 (홀드아웃)     secrecy 0.490 · value 0.492 · management 0.820
요소 MAE                secrecy 0.767 · value 0.795 · management 0.245
```

혼동행렬의 지배적 오류가 하나다:

```
secrecy  정답 lv2 1,180건 -> absent 515건 (43.6%)
value    정답 lv2 1,194건 -> absent 612건 (51.3%)
management  정상 (absent 64% · lv1 87% · lv2 98%)
```

**"비공지성이 완전히 존재함"을 "공개되었음이 입증됨"으로 뒤집는다.** 가장 위험한 방향이다 —
등급이 S3 로 떨어져 미탐이 되고(고등급 488건 중 479건이 S3 로 갔다), 동시에 보수적 완성
판정에서 S3-입증형으로 올라가 **자동확정 후보**가 된다(오탐 919건). 미탐과 오탐이 같은
오류에서 동시에 나온다.

## 4. 원인 — 어휘 연상이지 극성 이해가 아니다

가설 두 개를 세우고 하나를 반증했다.

**반증: 어휘 중복 부족** — 학습·홀드아웃 문장 풀의 자카드가 세 요소 모두 0.02~0.13 으로
낮고 management 가 더 높지도 않다(management lv2 0.053 vs secrecy lv2 0.026). 어휘가
갈렸다는 것만으로는 management 가 왜 전이됐는지 설명되지 않는다.

**확정: 극성 신호가 어휘에 눌렸다** — 홀드아웃 lv2 문장의 어휘가 학습셋 **absent** 문장과
얼마나 겹치는지 보면 갈린다:

```
                홀드lv2 ∩ 학습absent   홀드lv2 ∩ 학습lv2   absent 쪽 비율
secrecy                5                    2               0.71
value                  5                    2               0.71
management             4                    4               0.50
```

secrecy·value 는 홀드아웃 lv2 어휘가 학습 absent 쪽으로 71% 쏠려 있고, management 는
50/50 이다. **management 만 균형이고 management 만 전이됐다.**

실제 문장을 보면 명확하다:

```
홀드 lv2     관련 특허 공보에도 이 범위는 기재돼 있지 않다
학습 absent  기재 내용이 특허 공보에 이미 공개돼 있다          <- 같은 '특허 공보'

홀드 lv2     발표 자료에서 해당 절을 의도적으로 제외했다
학습 absent  본문 전체를 공개 세미나 자료로 발표했다            <- 같은 '발표 자료'
```

모델은 "특허 공보 -> 공개됨" 을 외웠고 **부정('않다'·'제외했다')을 읽지 않는다.**
`published` 라는 개념이 아니라 `특허 공보` 라는 문자열에 반응한다.

## 5. 내 분할 설계가 그것을 조장했다

이게 이번 판정에서 가장 중요한 부분이다. 문장 풀을 인덱스 앞 60% / 뒤 40% 로 잘랐는데,
그 결과 **같은 어휘 프레임의 긍정형은 학습에, 부정형은 홀드아웃에** 들어갔다.

```
학습    "특허 공보에 이미 공개돼 있다"        absent
홀드    "특허 공보에도 기재돼 있지 않다"       lv2
```

학습셋 안에서 `특허 공보` 는 **항상 absent 와만 같이 나온다.** 모델이 어휘 연상을 배우는
것이 최적해이고, 극성을 읽을 이유가 없다. 그리고 판정면은 정확히 그 연상이 틀리는 문장으로
채워져 있다. 데이터가 잘못된 것을 가르치고 시험은 그 반대를 물은 셈이다.

management 가 살아남은 것은 우연이다 — 통제 어휘(권한·이력·승인)가 absent/lv1/lv2 에
고루 분포해 어휘 연상만으로는 답이 안 나왔고, 그래서 부정을 읽어야 했다.

---

## 6. 고칠 것 — 극성 최소쌍을 프레임 단위로

문장 풀을 **프레임 단위로 다시 만든다.** 하나의 어휘 프레임이 세 상태를 모두 갖고, 분할은
문장이 아니라 **프레임 단위로** 자른다.

```
프레임 '특허 공보'
    absent   관련 특허 공보에 이 내용이 그대로 공개돼 있다
    lv1      일부 항목은 특허 공보에 있고 나머지는 공개되지 않았다
    lv2      관련 특허 공보에도 이 범위는 기재돼 있지 않다

분할   프레임을 통째로 학습 또는 홀드아웃에 배정
```

이러면 학습셋 안에서 `특허 공보` 가 세 상태에 모두 나타나므로 **어휘 연상으로는 답이
안 나오고 극성을 읽어야 한다.** management 가 우연히 얻었던 성질을 설계로 만드는 것이다.

부수 효과로 풀이 커진다 — 프레임 N개 x 상태 3개이므로 프레임만 늘리면 조합이 늘어난다.
v6 의 교훈("(요인,수준)마다 변형 6~16종뿐이라 문자열을 외운다")에도 대응된다.

### 검증 방법도 같이 정한다

고치고 나서 볼 것은 하나다 — **홀드아웃 lv2 -> absent 오분류율.** 지금 43.6%/51.3% 이고,
이것이 management 수준(2/581 = 0.3%)에 근접해야 극성을 읽는다고 말할 수 있다.

## 7. 사전등록 대비

사전등록 §5 가 예측한 세 가지가 모두 그대로 나왔다.

```
예측: F1 0.60 미만이면 (A) 문자열을 외웠다              -> 0.3865, 적중
예측: 쌍 정합률 0.5 근처면 한 문장을 못 읽는 것          -> 0.1049, 더 나쁨
예측: 입증형이 무신호형보다 낮으면 부재 문장을 못 읽는 것  -> 역전, 적중
```

쌍 정합률이 예측(0.5)보다도 낮은 0.105 인 이유는 쌍 양쪽 정답이 서로 다른데 모델이
한쪽으로 몰아 답하기 때문이다 — 858쌍 중 279쌍(32.5%)에서 **변경된 바로 그 요소를
같은 값으로 봤다.**

사전등록 §6 의 지시대로 임계를 낮추지 않았고 게이트도 열지 않았다. 다음 작업은 §6 에
적힌 "문장 풀 확대" 인데, 이번 진단으로 **확대의 방향이 정해졌다** — 양이 아니라
프레임 단위 극성 최소쌍이다.

실문서 성능이 아니다. 실문서 레버는 여전히 회원사 운영학습뿐이다.
