# `source_type=public` — 헛경보를 완전히 없애지만 위험도 같은 크기다

작성 2026-08-16. 서식 학습이 두 번 FAIL 한 뒤의 대안 측정이다.

---

## 1. 왜 이걸 쟀나

서식을 학습에 넣는 방향은 두 번 다 게이트 FAIL 이었다. 원인은 신호 세기가 아니라
**문서 종류가 두 등급에 걸쳐 있기 때문**이다(`REAL_S3_W025_GATE_FAIL_2026-08-16.md` §7).

대안은 학습이 아니라 **출처를 알려주는 것**이다. 배관은 이미 있는데(`source_type=public`
-> pipeline Gate-1 이 S3 로 cap) **실제로 0% 가 되는지 잰 적이 없었다.**

---

## 2. 효과 — 완전히 해결된다

봉인 서식 400건(정답 전건 S3).

```
지표                   메타 없음    public      변화
헛경보(TS/S1)           13.8%       0.0%      -13.8%
비공개 예측(TS/S1/S2)    31.8%       0.0%      -31.8%
검수 라우팅              59.8%      68.2%       +8.5%

헛경보 95%CI   [0.107, 0.175]  ->  [0.000, 0.009]
등급 분포      {S3 273, S2 72, TS 29, S1 26}  ->  {S3 400}
```

**400건 전부 S3 가 된다.** 학습으로 두 번 못 한 것이 메타데이터 한 줄로 된다.

⚠ 검수 라우팅이 59.8% -> 68.2% 로 **늘어난다.** cap 이 걸린 문서가 검수로 가기 때문이다.
  헛경보는 없어지지만 사람이 볼 양은 조금 는다.

---

## 3. 위험 — 정확히 같은 크기다

진짜 비밀 문서 42건(hardened42)에 **잘못된** public 표시를 붙여 봤다.

```
고등급 -> S3    0건  ->  26건
정답 일치      41/42 ->  7/42
무음 미탐      1건  ->  0건
```

**42건 중 26건이 "비밀 아님" 으로 떨어진다.** 정답 일치가 98% 에서 17% 로 무너진다.

`source_type=public` 은 **내용을 안 보고 무조건 S3 로 cap** 한다. 그것이 서식에는 정확히
맞는 동작이고, 잘못 붙으면 정확히 그만큼 위험하다.

⚠ 한 가지 좋은 신호. **무음 미탐은 1 -> 0 으로 오히려 줄었다.** 26건이 S3 로 갔지만
  대부분 검수로 라우팅됐다는 뜻이다. 게이트가 어느 정도 잡아 준다. 다만 26건이 잘못
  분류된 사실 자체는 남는다.

---

## 4. 그래서 이 대안의 성격

```
표시가 맞으면   헛경보 13.8% -> 0%      완전 해결
표시가 틀리면   고등급 26/42 가 S3 로    치명적
```

**"공개 양식인지 누가 판별하는가" 가 전부다.** 우리가 코드로 보증할 수 없다.

이것은 EDMS 메타데이터 요청과 **정확히 같은 성질의 의존**이다. 그리고 같은 이유로
오류율 경계가 필요하다 - 메타데이터 오류율 5% 를 계약 경계로 합의해야 한다는 것과 같다.

---

## 5. 권고

```
쓸 수 있는 경우    문서관리시스템이 '공개 양식/템플릿' 을 구분해 보관하고 있을 때
                  -> 그 폴더에서 올라온 것만 source_type=public

쓰면 안 되는 경우   사람이 업로드할 때마다 고르게 하는 것
                  -> 실수 한 번이 고등급 문서를 S3 로 만든다
```

**자동으로 붙일 수 있을 때만 쓴다.** 사람 판단에 맡기면 위험이 이득보다 크다.

⚠ 그리고 이 측정의 한계. 부작용 수치는 "표시가 **틀렸을 때**" 의 값이다. 실제 오류율이
  얼마일지는 EDMS 구성에 달렸고 우리는 모른다. 5% 경계 합의가 그래서 필요하다.
