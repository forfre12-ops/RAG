# 대상 보존 작성·교정 후속 명세 v1

2026-09-15. 구현/채택 완료가 아닌 다음 작업 계약 제안이다. 고객 정책 승인이나 GOLD 자격을 만들지 않는다.

## 이번에 배운 점

TS에만 영문 별칭을 넣은 것은 생성 설계의 편향이다. 그러나 이미 본문에서 사용한 이름을 지우는 일은
단순한 글꼴·종결어 교정과 다르다. ‘기질 배치 M에 한정’의 M은 적용 대상 식별값이므로 삭제만으로 고치지 않는다.
현재 삭제뷰는 민감도 실험용이며 원문 정본을 대체하지 않는다. 낮아진 문자 분류 점수도 교정 성공 조건이 아니다.

## 채택할 개발 순서

1. **원문 대상 구조부터 기록한다.** 문서별 대상 ID, 유형, 원문 이름/등장 위치, 같은 대상의 재언급,
   다른 대상과의 대비, 관찰·조건·예외가 연결된 대상을 별도 sidecar로 작성한다.
   동일대상/다른대상/미확인의 세 상태를 쓰고, 자동 추정만으로 미확인을 동일로 바꾸지 않는다.
   원문 이름과 인용은 보존한다. 이 sidecar를 모델 입력에 자동 추가하지 않는다.
2. **원고 작성 요소를 라벨과 독립적으로 사전 배정한다.** 같은 분야·말투·문서형식 안에서 이름 있는
   대상/서술형 대상, 영문/한글/숫자 표기 여부를 네 등급에 교차 배정한다. 등급이 높은 문서만
   제품 코드나 식별값을 갖게 하지 않는다. 본문에 존재하지 않는 자산·관리 사실을 원문에 추가하는 방식은 금지한다.
   합성 새 원고는 대상을 먼저 가상 전제로 선언한 뒤 작성한다. 실제 원문은 원본을 변조하지 않는다.
3. **기존64는 의미를 보존할 수 있는 수정만 별도 판본으로 만든다.** M과 N 두 대상이면 어떤
   표기 변환에서도 둘을 합치지 않는다. M만 있어도 특정 범위를 나타내면 이름 또는 등가 식별을 유지한다.
   등가 표현을 자신 있게 정할 수 없으면 그 문서는 원문 유지/수정 미채택으로 기록한다.
   같은 부모의 수정본을 신규 원고나 독립 시험자료로 세지 않는다.
4. **독립 검산을 두 층으로 한다.** 기계 검산은 숫자·부정·조건·인용·맥락·정책·답안의 불변과
   대상 관계의 1:1 대응을 검사한다. 별도 의미 검토는 해당 조건이 여전히 같은 대상을 가리키는지 확인한다.
   두 구현의 동의는 사람 서명이나 실제 고객 권한 증거가 아니다. 내부 검토 결과로 기록한다.
5. **점수와 안전 조건을 따로 판단한다.** 모델군에 무관한 최소쌍 시험에서 대상 이름만 바꾸면 판정 근거가
   같아야 하고, 공개·접근·투입 사실을 바꾸면 고정 정책의 예상 결과가 나와야 한다.
   별칭 하나 삭제 후 점수가 낮아지는 것만으로 이 조건을 통과했다고 하지 않는다.

## 구현할 데이터 계약과 회귀 항목

- 새 `entity_binding` sidecar: 정책/입력 지문, 엔티티 ID, 표면형 인용(start/end/hash),
  동일·비동일 관계, 관련 주장 ID, 적용 범위·제외 범위 인용, 작성 또는 추출 출처.
- 새 변환 이력: 부모/자식 ID와 해시, 변경 인용, 엔티티 대응, 원문 역추적 가능 여부,
  `adoption_allowed=false` 기본값. 기존 공개 API·학습기의 본문+등급 계약은 바꾸지 않는다.
- 실패 시험: M/N 합침, 이름 삭제로 범위 소실, 인용이 다른 문서를 가리킴, 계열/노출 유실,
  답/정책/맥락 변경, 미확인 관계를 확정으로 승격, 빈 검사 성공, 허용 플래그 임의 승격.
- 통과 시험: 동일 대상을 가리키는 이름의 일관된 치환, 복수 대상 구별 보존,
  모든 비변경 구간·수치·부정·조건 보존, 기존 정책 검산, 최종 평가 제외 유지.

## 수량 확대에 다시 들어가는 조건

64개 원문마다 유지/수정후보/미해결 상태와 이유를 남긴다. 무조건64개 모두 고쳐야 한다고 강제하지 않는다.
안전한 수정본만 내부 원고 채택 대상으로 검토한다. 형식 교차 배정과 대상 보존 검사를 다음 신규 배치에도 적용한다.
현 후보260개를 모두 채택할 수 있다는 가정에서만 추가740개(개발540+새 최종평가200)가 최소량이다.
수정뷰16개는 이 수량을 줄이지 않는다. 현재 자료는 모두 개발 노출됐으므로 최종200에 재사용하지 않는다.
실제800/200 모델 시험, 장문·비산술 문서 다양성, 사실 추출 검증은 여전히 별도 작업이다.
