# 원장 밖 참조 문서군·입력 적합성 설계 v0.2

2026-09-15. 내부 실험 설계이며 고객 정책/운영 승인/GOLD가 아니다.
기존 `internal-fixed-ledger-reference/0.1` 정책과 고정40건을 변경하지 않는다.

## 이번 단계의 선택

원장40건의 숫자를 바꿔1,000건을 만드는 대신, 먼저 짧은 기술·거래·운영 문서의 관찰 가능성을 시험한다.
정답 기준과 모델 입력의 불일치가 있으면 더 많은 학습 라벨로 해결할 수 없다.
새 자료는 **본문9종, 맥락 결합21사례**이며 정책 제안에 따른 예상18/정보부족 예상3을 기록했다.
기술3종/거래3종/운영3종이고, 맥락 변형을 독립 문서21종으로 세지 않는다.
예상 분포는 TS1/S1 2/S2 4/S3 11/HOLD3이다. 일부 문서군에 없는 TS를 수량 때문에 만들지 않는다.

실제 본문 원고는 `poc/scripts/short_reference_probes.py`의 DRAFTS이고, 생성된 입력에는 라벨·이유·규칙·근거 정답이 없다.
`annotations.draft.jsonl`은 정답이 아니라 `design_hypothesis_not_fixed`다.
사람 검수자가 없어서 고정을 보류한 것이 아니라, **자연어 의미와 정책 적용을 검산하는 oracle을 아직 구현하지 않았기 때문**이다.

## 공통 사실과 정책 가정의 분리

| 구분 | 이번에 기록하는 항목 | 직접 증명할 수 없는 것 |
|---|---|---|
| 본문 관찰 | 실제 수치·수식·조건·배정·기입란의 위치와 해시 | 해당 정보의 현실 가치/권리/현행성 |
| 가상 맥락 | 전체 범위, 현행 판본의 비공개 여부, 해당 판본 공개 허가, 핵심 자산 여부, 다른 상위 내용 유무 | 고객 승인/실제 비밀관리/외부 공개 진위 |
| 정책 가정 | 완결된 현행 비공개 핵심 재현TS, 구체 비공개 부분/거래내용S1, 비공개 운영S2, 일반 빈 서식·안전한 공개본S3 | 모든 회사·모든 문서에 통용되는 등급 |

맥락은 전부 `synthetic_assumption`이며 원문에서 추출한 사실로 위장하지 않는다.
S·V·M 숫자는 입력하지 않지만 비공개성·핵심성·공개 승인 등 판단요소를 없애지 않는다.
이 가상 `release_authorized_for_this_revision`은 실제 관리증거 M을 대체하거나 검증한 것이 아니다.
기존 guide/v22/fnr 공식과 D01~D08 결정은 불변이다.

## 문서군별 포함·제외·확대 조건

| 문서군 | 본문에서 추출할 사실 | 제안한 분기 | 고정 전에 필요한 검산 |
|---|---|---|---|
| 기술 설명서 | 입력 정의, 연산 순서, 상수, 출력/시험값, 누락 요소 | 현행 비공개 핵심+완결TS / 실제 부분 내용S1 / 배정만S2 / 안전한 공개S3 | 명세의 모든 입력에 대한 재현·불완전 반례, 핵심성/판본 가정 별도 결합 |
| 거래 검토 메모 | 제시/하한 가격, 수량, 지급 조건, 당사자 연결, 물류 배정 | 거래별 실질 조건S1 / 운영 접수S2 / 안전한 공개·빈 공통서식S3 | 값의 실제 수록 여부·조건 관계·빈 칸/추출 누락 구별. TS 충분조건은 이 원고에 없음 |
| 업무 운영 문서 | 장소, 작업 배정, 시각, 인계 조건, 채워진 칸 | 비공개 운영S2 / 안전한 공개·빈 공통서식S3 | 동일 본문-공개 맥락 반전, 내부 작성 제목만으로 상향하지 않음. 현재 원고에 TS/S1 충분조건 없음 |

기술의 작은 산술 모형이 재현된다고 현실 핵심 제품의 기술 가치가 증명되는 것은 아니다.
예: x=0..9, `(7*x+3)%11`은 유한한 기능 검산 대상일 뿐이다. 실제 고객의 TS 지정 근거는 아니다.
측정값3개만으로 모든 가능한 프로그램을 유일하게 정할 수 없다는 반례가 필요하다.
거래/업무군에 불가능한 등급을 붙여 인위적으로 네 등급 균형을 만들지 않는다.
따라서 이21건 자체는 장르 지름길을 통제한 균형4등급 평가셋도 아니다.

## 가정한 결정 규칙 — 구현 완료로 오인 금지

- R-CORE: 해당 판본이 현행 비공개 핵심 자산이며, 본문에 재현에 필요한 입력/변수/단계/검증이 모두 있고 전체 범위를 확인하면 TS 제안.
- R-DETAIL: TS 조건이 제외되고 비공개 자산의 실질 부분 정보 또는 거래별 협상 내용이 직접 있으면 S1 제안.
- R-OPS: 상위 조건이 제외되고 비공개 실제 업무 배정/일정이 있으면 S2 제안.
- R-BLANK: 전체 범위에 작성된 실질 값이 없고 공통 빈 서식이면 S3 제안. 추출 실패를 빈 서식으로 보지 않는다.
- R-RELEASED: 이 가상 세계에서 해당 판본의 공개 허가와 상위 보호 내용 제거가 확인된 자료만 S3 제안.
  인터넷 노출만으로 개인정보/유효한 비밀을 하향하는 규칙이 아니다.
- R-UNKNOWN: 전체 범위 등 결정 근거가 unknown이면 grade=null/HOLD 제안. 입력에 unknown을 넣었다고 결정 가능으로 보지 않는다.

현재 원고는 다른 상위 위험 없음이라는 **가상 전제**를 명시한다. 이 전제를 실제 원문에 자동으로 붙여서는 안 된다.
충돌/불충분한 정책 범위는 새 oracle이 구현되어도 보류한다. 같은 본문을 포함한 다른 파일의 정보까지 합치는 경우에는
판정 단위가 달라지므로 단일 문서 예상 라벨을 그대로 적용하지 않는다.

## 무엇을 모델에게 맡길 것인가

가장 먼저 만들 결과는 문서군별 **본문 사실추출 정답**이다. 예를 들어 '14,500원은 제시가이며 12,800원은 하한'처럼
본문에서 확인 가능한 관계를 정답으로 삼는다. 등급에서 역산한 S·V·M이나 모델의 확신도를 사실로 저장하지 않는다.
그 다음 별도 정책 계산이 본문 사실+출처 있는 맥락으로 등급/HOLD를 결정하게 한다.

선택지는 아래처럼 구별한다. 이번에 운영 경로를 변경한 것은 아니다.

| 선택 | 얻는 점 | 남는 비용/위험 |
|---|---|---|
| 본문만 직접4등급 | 기존 모델 인터페이스 유지 | 본문이 같고 맥락에 따라 정답이 달라지는 문제를 해결할 수 없음 |
| 본문+맥락을 모델 문자열로 결합 | 필요한 맥락을 제시할 수 있음. 짧은21사례는512토큰 안에 들어감 | 고객 정책 변경 시 학습 의존, 가정 문구에 대한 지름길, 장문 끝 맥락 잘림. 전체 정답 보장은 아님 |
| 본문 사실추출+맥락+결정형 정책 | 사실과 고객 정책/판본을 구별하고 같은 근거를 재검산 가능 | 사실추출 품질 검증, 실제 맥락 공급, 표 전체 집계가 필요 |

**권고는 마지막 구조를 오프라인으로 먼저 검증**하는 것이다. 기존 직접4등급 모델은 비교 기준으로 유지한다.
RAG는 참고 근거 검색이지 승인된 고객 정책/관리증거의 대체물이 아니다.

## 250건씩 채택하기 위한 게이트

1. 각 본문 사실의 양성·음성·누락·모순 사례와 근거 위치를 먼저 고정한다. 사람이 서명해야만 가능하다고 제한하지 않는다.
2. 두 경로의 의미 검산을 구현한다. 수식은 전수 입력/반례, 가격·조건은 값/관계 추출 검증,
   서식은 실제 값/누락 페이지/빈 필드 구분으로 확인한다. 동일 AI 두 번 호출 합의만으로 통과하지 않는다.
3. 정책/맥락을 바꾼 대조쌍에서 사실은 유지되고 등급만 정의대로 바뀌는지 확인한다.
4. 실제로 제시하는 모델 입력의 토큰/정규화/범위/맥락이 정답 근거를 포함하는지 확인한다.
5. 문서군 분리·전체 본문 지름길·정확/근접중복 검사를 수행한다. 지금21건은 장르/문체 일반화 평가로 쓰지 않는다.
6. 통과 사례만 등급별250건 목표에 넣는다. 변형/맥락 대조쌍·HOLD 수는 독립 문서 수와 별도 집계한다.

새21건은 학습·모델 평가용으로 전환하지 않았고 정답 고정 수에0건을 추가했다.
기존40건은 그 좁은 정책에서 계속 고정이지만, 본문만 쓰는 분류 모델의 성능 분모에는 적합하지 않다는 점이 이번에 수치로 확인됐다.
