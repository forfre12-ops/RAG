# 요소 모델 실데이터 탐침 — 합성 0.98, 실문서 0.00

작성 2026-08-14. 1차·2차 판정면을 모두 통과한 7차 모델(`v8_bal`)을 **우리 생성기 밖의
실데이터**로 쟀다. 결과가 명확하고 나쁘다.

---

## 1. 왜 판정면을 더 만들지 않고 실데이터로 갔나

1차·2차를 모두 통과했지만 둘 다 내가 만든 문서다. "형태도 표현도 새롭다" 고 해도 같은
생성기 · 같은 문장 구조 · 같은 조립 방식에서 나온다. **판정면을 열 개 만들어도 그 한계는
바뀌지 않는다.**

---

## 2. 결과

```
셋               n     등급 일치   고등급 과소분류   S3 추락   게이트(tau 0.99)
특허 프록시      400    0.0000     400/400 = 1.0    399     자동 4건 · 미탐 4건
경화42            42    0.1667      26/26 = 1.0      26     자동 0건
일상 S3           50    1.0000        -               0     자동 0건

합성 2차 판정면 3,680    0.9829       1.5%            -     자동 76.1% · 미탐 1건
```

특허 프록시에서 **정답 S1 400건을 399건 S3 로 떨어뜨린다.** 등급 일치율이 0 이다.
경화42 는 42건 **전부** S3 로 예측한다.

일상 S3 의 1.0000 은 의미가 없다 — 정답이 전부 S3 인 셋이라 모든 문서를 S3 라고 해도 1.0 이다.
오히려 이 셋에서 1.0 이 나온 것이 "전부 S3 로 본다" 는 진단과 일치한다.

---

## 3. 원인 — 모델 결함이 아니라 과제 정의의 문제다

요소 예측 분포가 원인을 그대로 보여 준다:

```
특허 프록시   secrecy   absent 369 · lv1 9 · unk 22
             value     absent 313 · lv2 37 · lv1 14 · unk 36
경화42        secrecy   unk 26 · absent 14 · lv1 2
```

`secrecy=absent` 는 "공개되었음이 **입증**됨" 이다. 모델이 특허 명세서를 "공개된 문서" 로
읽는다. 왜 그런지는 문서를 나란히 놓으면 보인다:

```
합성 판정면   "## 관리 목적 / ## 등재 기준 ..."  섹션이 있고 요소 문장이 명시적으로 들어 있다
특허 프록시   "본 발명에 따른 플라즈마 공정챔버 모니터링 방법은, ..."  기술 서술뿐 · 요소 언급 0
경화42        "공용서류등무효·수뢰·알선수뢰 【피 고 인】 ..."  판례 원문 · 업무문서가 아님
```

**실문서에는 우리가 학습시킨 "요소 문장" 이 아예 없다.** 우리 프레임은 전부
"게재했다 / 게재한 적 없다 / 대체 자료가 없다" 같은 **요소를 직접 진술하는 문장**이다.
실제 업무문서는 그런 문장을 쓰지 않는다 — 기술 내용을 쓸 뿐이다.

요소 진술이 없으면 모델은 `absent` 또는 `unknown` 을 낸다. 둘 다 등급 산출에서 0 점이므로
곱이 0 이 되고 전부 S3 가 된다. **구조적으로 그렇게 되게 돼 있다.**

---

## 4. 이것이 뒤집는 것

지금까지 회차마다 올린 수치는 전부 **"요소가 문장으로 적혀 있는 문서"** 안의 성적이었다.

```
1차 판정면  F1 0.8729   요소 문장 있음
2차 판정면  F1 0.9847   요소 문장 있음
특허 프록시  등급일치 0  요소 문장 없음
```

판정면을 아무리 넓혀도 **"요소 문장이 있다" 는 전제는 공유한다.** 그 전제가 깨지는 순간
성능이 0 이 된다. 형태·표현·문체를 아무리 흔들어도 이 축은 안 건드렸다.

기존 결론(합성-only 교차 F1 0.26)과 방향이 같고, 이번에는 **왜** 그런지가 드러났다 —
어휘나 문체 차이가 아니라 **문서에 요소 진술이 존재하지 않는다**는 것이다.

---

## 5. 그래서 무엇을 해야 하나

세 갈래이고 각각 성격이 다르다.

**(가) 요소 진술이 없는 문서를 학습에 넣는다.** 기술 서술만 있고 요소를 유추해야 하는
문서를 만든다. 지금 `unknown` 상태가 그 자리인데, 우리 unknown 문서는 "주제만 언급하고
단언 안 함" 이라 여전히 요소를 **언급은** 한다. 실문서는 언급조차 없다.

**(나) 요소 판단을 유추로 바꾼다.** "이 문서가 기술하는 내용이 공개되었을 법한가" 를
묻는 과제로 재정의한다. 이건 진술 추출이 아니라 추론이고, 훨씬 어렵다.

**(다) 요소 모델의 적용 범위를 좁힌다.** 요소 진술이 있는 문서에만 쓰고, 없으면 요소
모델을 태우지 않는다. 자동확정 후보를 "요소가 진술된 문서" 로 한정하는 것이다. 정직하지만
자동화 대상이 크게 줄어든다.

세 번째가 지금 데이터로 즉시 가능하고 안전하다. 첫 번째가 근본적이지만 데이터를 다시
만들어야 한다. 두 번째는 과제 자체가 달라진다.

---

## 6. 한정

```
특허 프록시가 정말 S1 인가   AI Hub 특허 기반이고 등급은 저술 규칙으로 붙었다.
                          "특허 명세서 = S1" 자체가 검증된 라벨은 아니다.
경화42 는 판례가 섞여 있다   업무문서 셋이 아니다. 문서 종류가 우리 과제와 다르다.
요소 라벨이 없다            등급만 비교했다. 요소 정확도는 못 쟀다.
```

셋 다 라벨의 성격이 다르므로 "실문서 성능 0" 이라고 단정하면 안 된다. 확실한 것은
**요소 진술이 없는 문서에서 이 모델이 전부 S3 를 낸다**는 것이다.
