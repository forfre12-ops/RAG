
읽을 것은 2단계 출력 한 줄이다: `서버 sha=… · profile=… · model=…`

| 나오는 값 | 뜻 | 다음 |
|---|---|---|
| `sha` 가 HEAD 와 같음 | 이미 최신 | 1-4로 건너뜀 |
| `sha` 가 다름 | 미배포 커밋 있음 | 1-2 진행 |
| `sha=unknown` | 이 배포 전에는 빌드 SHA 를 안 구웠다 | 1-2 진행(이번 배포부터 박힌다) |
| `healthz 응답 없음` | 서버가 안 떠 있거나 외부 차단 | **먼저 이것부터 해결.** 못 고치면 시연 방식 재검토 |

이 스크립트는 `--deploy` 를 주지 않으면 **확인만 한다.** 배포는 서버에서 따로 한다.

## 4. 절대 하지 말 것

1. **시연을 위해 임계·게이트를 낮추지 않는다.** `review_confidence_threshold` 0.70,
   `classifier_temperature` 2.03, `agreement_gate_enabled` 는 그대로 둔다. 리허설이 불안정하면
   설정이 아니라 **문서를 교체**한다.
2. **"방금 검수한 1건으로 재학습했다"고 말하지 않는다.** 1~수건 학습은 학습/검증 분리가
   성립하지 않아 감리에서 공격받는다. 재학습을 보여야 하면 **요청·큐 등록까지만 라이브로**
   하고 결과는 이미 끝난 잡의 3축 게이트 판정을 이어서 보여 준다.
3. **"학습셋 지정 완료"라고 말하지 않는다.** 검수 화면의 용도 선택은 아직 **표시만** 한다 —
   서명하면 `train` 을 골라도 `tier=locked_gold_eval` 로 간다([golden_signoff.py:104](../src/koipa/golden_signoff.py#L104)).
   "학습 후보로 표시" 까지가 사실이다.
4. **문서를 손봐 화면 문구에 맞추지 않는다.** 반대로 문구를 사실에 맞춘다.

## 5. 시연에 필요 없는 것 — 오늘 하지 않는다

어제 받은 정적 점검 지적 12건 중 **시연 차단 요인은 없다.** 아래는 시연 후로 미룬다.

| 지적 | 미루는 이유 |
|---|---|
| JWT HttpOnly/Secure 전환 | 지금 `Secure` 를 붙이면 **223은 http 라 로그인이 아예 안 된다.** HTTPS 종단 확보와 함께 처리. 검수 화면은 문서 본문을 전부 이스케이프해 XSS 싱크가 보이지 않고, SameSite=Lax 가 cross-site POST 를 막는다 |
| LLM 비용 build_sha 컬럼 | 요건(FUN/NFR) 매핑을 못 찾았다. 요건 ID 확인이 먼저 |
| LLM JSONL 볼륨 | DB 가 원장이고 JSONL 은 폴백. 시연 경로와 무관 |
| deploy_cloud.sh 빌드 SHA | **223 배포 스크립트는 이미 주입한다**([deploy_kl_223.sh:230](../scripts/deploy_kl_223.sh#L230)) |
| 진단면 인증 | 1-1에서 `healthz/deep` 외부 도달 여부만 확인해 두고 조치는 뒤로 |
| 테스트 63초 · 커버리지 · 복잡도 | 시연 무관 |

## 9. 검수 화면까지 보여줄 때 (2026-08-23 실측 검증)

**로그인은 주소 한 번이면 끝난다.** 서버에 `CONSOLE_LOGIN_PREFILL_TOKEN` 이 켜져 있어
아래 주소를 열면 **토큰 입력 없이 자동 로그인**된다(쿠키 저장 · 주소창에 안 남음).

```
1. http://223.130.156.134:8000/api/v1/golden/candidates/login.html    ← 열기만 하면 됨
2. http://223.130.156.134:8000/api/v1/golden/candidates/manage.html   ← 문서 등록
3. 관리자 콘솔 [검수] 탭 → 3 검증문서 검수 목록 → 「검수 열기 ↗」      ← 검수·서명
```

배포본에서 전 구간을 실제로 태워 확인했다(`682fdd82`):

| 확인 | 결과 |
|---|---|
| 로그인 세션 · 후보 관리 화면 · 후보 목록 · 현황 | 200 |
| 문서 업로드 | **201** · `status=under_review` · 자동 등급 없음 |
| 결정 기록 | 200 · `actor_id=지재원관리자` 로 남음 |

**문서 업로드는 원천 위치·사용 권한 근거를 둘 다 채워야 넘어간다.** 비우고 누르면 오류가
모달 안에 뜨고 빈 칸으로 포커스가 간다 — 2026-08-23 이전에는 그 오류가 모달 뒤에 찍혀
**버튼이 죽은 것처럼 보였다.**

**⚠ 서명 버튼은 누르지 말 것.** 누르면 그 문서가 평가 정답지(locked_gold_eval)로 확정되고
되돌리기 어렵다. 화면과 흐름만 보여준다.

### 시연이 끝나면 — 반드시

```bash
ssh -i ~/.ssh/kipai_testserver kopia@223.130.156.134
# ~/poc/.env.jjw 에서 CONSOLE_LOGIN_PREFILL_TOKEN 줄을 지우고 재기동
```

## 10. 관리자 화면 — 2026-08-23 에 바뀐 것

KL 이 "잘 모르겠다"고 한 화면을 전수로 뜯어 고쳤다. **카드 수(14개)가 문제가 아니라 첫 화면이
자기 일이 아니었다.**

| 바꾼 것 | 왜 |
|---|---|
| 기본 탭 검수 → **운영** · 운영 첫 카드를 **문서 검토 대기**로 | 콘솔을 열면 현장 관리자가 매일 하는 일이 먼저 보여야 한다 |
| 탭을 구분선으로 갈라 좌우 분리 · **설정은 톱니로** | 도입 시 한 번 정하는 설정이 매일 쓰는 탭과 나란히 있었다 |
| **「분류 실행」 샘플 자동 채움·일괄분류 제거** | 열면 **평가 정답지 문서**가 본문에 미리 들어 있었고, 일괄분류는 그 8건을 검수 큐에 적재하며 `기대등급 일치 8/8` 로 채점까지 했다 |
| **검수 목록에서 평가셋·학습셋·승격정본 제외** (60건 → 3건) | 고르면 **평가 정답지가 오염**돼 "모델이 좋아졌다"는 근거가 무너진다 |
| 잡 목록 행에 **「검수 열기 ↗」** | 검수 화면이 2단계 숨어 있었고 메뉴 「검수」로는 검수를 시작할 수 없었다 |
| 판정기 드롭다운을 서버 설정에 맞춰 **잠금** · `noop` 설명 정정 | 폐쇄망 불가·품질 미달 항목이 표시 없이 선택 가능했고, 서버는 noop 인데 화면은 openai 였다 |
| 관제 대시보드 업무 용어 · **0 의 뜻 구분** · 합성 고지를 경고 박스로 | 좋은 0 과 나쁜 0 이 똑같이 보였고, 감리 핵심 문장이 회색 작은 글씨였다 |
| 인증 카드 접기 · 화면 용어 전면 교체 | 첫 화면 맨 위가 API 키·역할 설정이었다 |

**남긴 것**: FUN-xxx 배지. 제출본 「RFP_구현현황」이 `admin.html §N … 화면` 형태로 화면을
요건 증빙에 직접 인용한다 — 지우면 감리 대조 경로가 끊긴다.

### 같은 날 잡은 사고 두 건

1. **배포가 조용히 실패하고 있었다.** 디스크 98% 로 빌드가 죽었는데 스크립트가 exit 0 이었다
   (파이프가 종료코드를 삼키고, 옛 `:latest` 가 남아 이미지 검사도 통과). 이미지에 구운
   `KOIPA_BUILD_SHA` 대조 + 디스크 선확인으로 막았다.
2. **화면 절반이 죽어 있었다.** 지운 요소(#sample-select)를 만지는 초기화가 남아 있어
   `checkHealth()` 가 아예 실행되지 않았다 — 서버 검수 임계가 `—` 로 남았다. init 이 부르는
   함수가 없는 요소를 가드 없이 만지면 깨지는 테스트를 넣었다.
