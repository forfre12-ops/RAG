## 4. 절대 하지 말 것

1. **시연을 위해 임계·게이트를 낮추지 않는다.** `review_confidence_threshold` 0.70,
   `classifier_temperature` 2.03, `agreement_gate_enabled` 는 그대로 둔다. 리허설이 불안정하면
   설정이 아니라 **문서를 교체**한다.
2. **"방금 검수한 1건으로 재학습했다"고 말하지 않는다.** 1~수건 학습은 학습/검증 분리가
   성립하지 않아 감리에서 공격받는다. 재학습을 보여야 하면 **요청·큐 등록까지만 라이브로**
   하고 결과는 이미 끝난 잡의 3축 게이트 판정을 이어서 보여 준다.
3. **"학습셋 지정 완료"라고 말하지 않는다.** 검수 화면의 용도 선택은 아직 **표시만** 한다 —
   서명하면 `train` 을 골라도 `tier=locked_gold_eval` 로 간다([golden_signoff.py:104](../src/koipa/golden_signoff.py#L104)).
   "학습 후보로 표시" 까지가 사실이다.
4. **문서를 손봐 화면 문구에 맞추지 않는다.** 반대로 문구를 사실에 맞춘다.

## 5. 시연에 필요 없는 것 — 오늘 하지 않는다

어제 받은 정적 점검 지적 12건 중 **시연 차단 요인은 없다.** 아래는 시연 후로 미룬다.

| 지적 | 미루는 이유 |
|---|---|
| JWT HttpOnly/Secure 전환 | 지금 `Secure` 를 붙이면 **223은 http 라 로그인이 아예 안 된다.** HTTPS 종단 확보와 함께 처리. 검수 화면은 문서 본문을 전부 이스케이프해 XSS 싱크가 보이지 않고, SameSite=Lax 가 cross-site POST 를 막는다 |
| LLM 비용 build_sha 컬럼 | 요건(FUN/NFR) 매핑을 못 찾았다. 요건 ID 확인이 먼저 |
| LLM JSONL 볼륨 | DB 가 원장이고 JSONL 은 폴백. 시연 경로와 무관 |
| deploy_cloud.sh 빌드 SHA | **223 배포 스크립트는 이미 주입한다**([deploy_kl_223.sh:230](../scripts/deploy_kl_223.sh#L230)) |

## 6. 비상 대비

`git push` 와 **서버 자격증명 읽기**(`grep ^API_KEY= ~/poc/.env.jjw`)는 auto-mode 권한
분류기가 막는다(2026-08-22 각각 2회 확인). 명령 모양을 바꿔 통과시키지 말 것 — 사용자가
`/config` 로 허용하거나 직접 실행해야 한다. 활성 env 파일은 **`.env.jjw`**(배포 로그의
`env=.env.jjw`), compose 프로젝트는 `koipa-jjw`.
