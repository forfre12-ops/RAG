# 실제 문서·고객사 정책용 검수 확장 v2 상세 설계

상태: **설계안만 작성**. 검수 도구/확정 API/골든셋 게이트/DB를 변경하지 않았고 실제 제출0건이다.
기존 합성40건 도구와 결과는 정책 fixture로 보존한다. 현재 고객사 공식 기준은 미정이다.

## 1. 그대로 재사용할 수 없는 부분

`scripts/classification_review_workflow.py`는 SOURCE/SOURCE_SHA를 v1.1 합성40건에 고정한다.
`packet_cases()`는 revision.POLICY_ID와 합성 맥락 view를 사용하고,
`decision_check()`는 내용보호 규칙 매핑/CP-HOLD 코드에 묶여 있다.
이 입력을 실제 고객 문서의 정답 판정/고객 정책 검수라고 부를 수 없다.

재사용할 수 있는 원리: 입력/제출 해시 동결, 근거 위치 검사, 제출 비교, 불일치 원인 코드,
원본 불변, 조정 제안과 최종 확정 분리. 새 기능이 기존40건의 계약을 덮어쓰지 않도록 새 버전 경계로 둔다.

## 2. 검수 실험과 공식 승인 구별

앞서 제안한 R1/R2 독립 검수는 기준 일치성을 확인하기 위한 **품질 실험 설계**다.
현재 `golden_signoff.py`의 계약은 모든 등급에 단일 검수자 서명이다.
R1/R2 실험을 사업의 필수 이중서명 요건으로 주장하거나 기존 단일 서명 게이트를 몰래 바꾸지 않는다.
정답 승인 주체·필요한 검수 수·독립성 조건은 D06 및 업무 책임자의 실제 결정이 필요하다.

`api/confirm.py`는 JWT sub가 있으면 actor를 결합하지만 공유 API key에는 개별 신원이 없어
상위 KL의 actor 전파를 신뢰하는 경로가 있다. 이를 실제 검수자의 독립 인증 완료라고 단정하지 않는다.
실제 로그인·계정 배정·노출 이력·권한을 확인하는 배포 경계는 별도 구현/시험 대상이다.

## 3. 새 입력 manifest 제안

제안 schema_version: `real-document-review-input-v2-draft` (아직 validator/CLI 구현 안 됨).

| 묶음 | 필수 내용 |
|---|---|
| job | job_id, 작업 목적(근거 대조/정책 검수/평가 정답 후보), 작성 시각 |
| organization | 인증된 조직 문맥의 참조·지문, 적용 문서 범위 |
| document | ID·판본·original/extracted hash·문서 계열·source_origin |
| authorization | 사용 허가 참조·지문·허용 목적·기간; 파일에 적힌 제공 선언과 실제 인증 구분 |
| input_view | 본문/맥락/관리 근거 중 검수자에게 실제 제공한 범위와 지문 |
| policy | 정책 ID·버전·해시·적용 시각·규칙 명세 참조, 승인 확인 상태 |
| evidence | FactPacket 및 수집/변환 receipt 참조·지문; 미확인/충돌 항목 |
| assignments | 역할 슬롯과 배정/실제 신원 확인 상태, 사전 답안 노출 여부 |
| use_partition | 근거 대조/개발/held_review/locked_gold_eval 후보 등 용도; 사용 제한 명세 |

정책은 mutable 이름으로 조회하지 않고 해시가 고정된 정책 명세를 입력받는다.
인증/허가/정책 승인이 없으면 초안 검수 입력으로만 다루고 평가/학습 정답으로 확정하지 않는다.
매핑 preview는 관측 FactPacket 대신 사용할 수 없다. 원시→변환 근거 검토 자료로만 연결한다.

## 4. 제출과 상태

제출 구조: case_id, manifest/input/policy hash, 실제 배정 문맥, submitted_at,
decision(status, grade, rule_ids), evidence_refs, rationale, 인접 등급 배제 이유, 추가 확인 요청.

- missing_evidence: grade=null, 무엇이 필요한지 명시.
- policy_conflict 또는 policy_gap: grade=null, 충돌 규칙/쟁점 명시.
- candidate: 고정 정책의 유효 규칙·범위·근거가 연결됨. 최종 등급 아님.
- pending: 미제출. 제출 분모에 포함하지 않되 배정/미완료 건수에는 표시.

새 검증기는 고정된 CP 규칙이 아니라 입력 정책의 rule_id/등급 관계와 해당 정책의 상태 계약을 검사한다.
관측 사실을 정정하려면 정정 근거/판본을 별도 제출한다. grade만 바꿔 근거·정책 불일치를 숨기지 않는다.
본문 근거는 해당 input_view의 문자 offset, 시스템 근거는 source hash+Pointer를 검증한다.
모델의 설명문 자체는 원문 근거가 아니다. 본문만 제공한 검수자에게 숨겨진 ACL 정답을 채점하지 않는다.

## 5. 비교·조정·확정 경계

1. 사용 허가·정책·입력 view를 동결한 뒤 답안 없는 패킷을 역할별로 배정한다.
2. 실제 접근권한/열람 이력으로 사전 노출 여부를 확인한다. 폴더 분리만으로 블라인드 인증하지 않는다.
3. 제출본을 잠그고 결론/규칙/근거의 불일치를 별도 계산한다. 분모0의 비율은 null이다.
4. 조정자는 원문 누락/관리정보 부족/매핑 불일치/정책 공백/해석 차이/라벨 오류를 구분한다.
5. 정책 또는 입력이 바뀌면 새 판본을 만들고 영향 문서를 재배정한다. 구판 제출을 새 정답으로 재사용하지 않는다.
6. 공식 확정은 기존 승인 경로의 권한·판본·저장 성공 계약을 검토한 뒤 별도 연결한다.

공식 확정 연결 전 결과는 final_grade=null, gold_eligible=false, training_allowed=false다.
합의율과 정답 정확도, 검토 불필요 비율과 DB에 저장된 사람 확정을 각각 구분한다.
다수결·상위 등급 채택·AI 답안 복사는 정책 공백을 해결하는 방식이 아니다.

## 6. 구현 단계와 완료 기준

| 순서 | 구현 제안 | 완료 기준 |
|---|---|---|
| R1 | fixture 경로와 무관한 manifest/입력 view 검증기 | 서로 다른 두 가상 정책으로 검산, 기존40건 불변 |
| R2 | 정책 주입형 제출 validator | 미등록 규칙/구판 해시/미제공 근거 거절; HOLD와 등급 혼재 금지 |
| R3 | 비교/조정 제안 확장 | 결론과 근거 불일치 구분, 조정 근거/제출 판본 추적 |
| R4 | 허가된 실제 소수 문서 대조 | 실제 공급 공백과 정책 공백 분리; 고객 정확도로 발표하지 않음 |
| R5 | 인증·기존 승인 경로 통합 | 신원·역할·판본 재확인, 저장 실패 표시, 학습/평가 용도 분리 |

필수 회귀 계획(아직 실행 안 함): 조직 혼합, 두 정책의 같은 rule_id 다른 의미, 문서/정책 교체,
숨은 맥락, 근거 위치 변경, 미제출·중복 제출, 사전 답안 노출, 입력 변경 후 조정 재사용,
인증 없는 공유키 actor의 별도 상태, DB 저장 실패, 평가셋의 학습 편입 차단.

실제 기준·문서·검수자 배정이 없더라도 R1~R3 계약/단위 시험 구현은 가능하다.
R4~R5는 실제 허가/조직·신원 경계와 D01~D08 결정 없이는 완료로 선언하지 않는다.
