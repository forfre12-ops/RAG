# 실문서 판정면을 출처별로 갈랐다 — 경화42 는 낙관적이었다

작성 2026-08-14. 지금까지 실문서 판정을 경화42(n=42)로 했다. 표본이 작고 판례가 섞여
회차 비교가 위태로웠다. gold_real 을 중복 제거하고 출처별로 갈라 다시 쟀다.

---

## 1. 출처별로 성격이 완전히 다르다

```
면          n     고등급   등급 분포                        성격
court     409      13    S3 396 · S1 13                 판례. 공개문서
finance   229       3    S3 178 · S2 48 · S1 3          금융 공시자료
business  136      95    TS 55 · S2 41 · S1 40          업무문서. **주 판정면**
```

**섞으면 안 된다.** 판례는 우리 루브릭으로 비공지성 proven_absent -> S3 이므로 모델이
S3 라 해도 맞다. 그 면에서 나온 정확도는 업무문서 성능의 근거가 아니다.

---

## 2. 면을 가르니 경화42 가 낙관적이었음이 드러난다

```
면                 n   고등급   등급일치   과소분류(서빙)   자동확정
business(주)     136     95    0.2059     0.5474        2.9%
경화42(이전)      42     26    0.3333     0.3462        0.0%
finance         229      3    0.2533     1.0000        0.0%
court           409     13    0.8460     1.0000        0.0%
```

앞서 "과소분류 34.6%" 라 보고한 값은 **n=42 · 고등급 26건 · 판례 7건 혼입** 상태의 값이다.
업무문서 136건(고등급 95건)에서는 **54.7%** 다. 20pp 나 낙관적이었다.

---

## 3. court 0.8460 을 성능으로 읽으면 안 된다

모델이 판례 409건 중 392건을 S3 로 본다. 정답 396건이 S3 이므로 등급 일치가 0.846 이다.

이것은 **루브릭상 맞는 동작**이다 — 공개문서는 비공지성이 proven_absent 이고 곱이 0 이라
S3 다. 그러나 이 수치를 "실문서 정확도 85%" 로 인용하면 거짓이 된다. 판례는 문서 종류가
우리 과제와 다르고, 애초에 전부 같은 등급이라 "전부 S3 라고 답해도" 0.968 이 나온다.

이 면은 성능 지표가 아니라 **"모델이 공개문서를 공개문서로 보는가" 를 확인하는 용도**다.

---

## 4. finance 는 서빙 규칙에서 오히려 나빠진다

```
finance   저술규칙 0.7686  ->  서빙규칙 0.2533
```

정답이 S3 178 · S2 48 인데 서빙 규칙이 unknown 을 최악으로 채워 S2 155 · TS 26 으로
올린다. 공시자료라 실제로는 공개된 문서인데 모델이 "모른다" 고 답하고, 규칙이 그것을
고등급으로 올린다.

**"모르면 안전측" 규칙의 대가가 여기서 보인다.** 미탐은 막지만 과분류가 늘어 검수 부담이
커진다. 공개 출처 문서는 별도 경로(source prior)로 S3 상한을 걸어야 한다 — 배포본에는
이미 그 게이트가 있다(`출처 prior 게이트`). 요소 모델에는 아직 없다.

---

## 5. 정직한 현재 상태

```
합성 판정면        자동확정 48~76% · 미탐 상한 0.012~0.015
실문서 업무문서     자동확정 2.9% · 과소분류 54.7% · 등급일치 20.6%
```

**합성에서 되는 것이 실문서에서 안 된다.** 이 결론은 판정면을 3.7배로 넓히자 오히려
더 분명해졌다.
