IT-2025-3301 / IT운영팀장, 정보보안팀장, 기획팀장 / IT개발팀 김지영 / 2025-12-01  

1. 검토 배경  
- 기존 고객 주문 처리 시스템의 구조가 중앙 집중형으로 구성되어 있어 장애 발생 시 전체 서비스가 마비되는 문제가 반복됨  
- 최근 3개월간 발생한 장애 중 2건에서 주요 서버 응답 지연이 30분 이상 지속되며, 이로 인해 고객 문의가 급증함  
- 이에 따라 IT개발팀은 시스템을 분산형으로 개편하고, 연계된 데이터베이스와 API 엔드포인트를 재설계하는 방안을 검토함  

2. 검토 내용  
- 구성 변경 내용  
  - 기존 단일 DB 인스턴스를 3개의 분리된 마이크로서비스 기반 DB로 전환함  
  - 주문 처리, 재고 관리, 결제 처리를 각각 독립된 서비스로 분리하고, 메시지 큐를 통해 연동함  
  - 각 서비스는 자체 로그 기록과 모니터링 도구를 활용하며 운영됨  
- 연동 범위  
  - 고객 정보 조회, 결제 승인, 배송 상태 갱신 등 핵심 업무에 대한 연동은 유지하되, 보조 시스템은 단계적 통합 예정  
  - 기존 시스템과의 일관성을 위해 3개월 간은 병행 운영하며 데이터 동기화 테스트 실시함  
- 이행 절차  
  - 2026년 1월 중순부터 우선적으로 주문 처리 서비스부터 개편 적용함  
  - 각 단계별로 테스트 환경에서 성능 검증 및 보안 취약점 점검 완료됨  
  - 실제 적용은 2026년 2월 초에 예정되며, 이전까지는 백업 시스템으로의 전환 가능 여부 확인됨  

3. 주요 결과  
- IT운영팀은 새로운 아키텍처에서 병렬 처리가 가능해져 장애 발생 시 일부 서비스만 별도로 유지보수 가능하다고 확인함  
- 정보보안팀은 데이터 암호화 레이어를 서비스 간 통신에 추가하고, 접근 제어 정책을 세분화하여 위험도 감소 가능함을 확인함  
- 업무 협조 부서 담당자들은 연동 부담이 증가할 수 있으나, 운영 안정성 측면에서 긍정적 평가를 내림  

4. 문제점  
- 일부 부서에서는 기존 프로세스와의 차이로 인해 업무 흐름 파악에 어려움을 겪고 있음  
- 개발팀은 복수의 마이크로서비스를 동시에 관리해야 하므로 운영 부담 증가 가능성 있음  

5. 검토 의견  
- 전체 시스템 개편은 기술적으로 타당하며, 장기적 안정성 측면에서 긍정적임  
- 단기적으로는 사용자 교육과 함께 병행 운영을 통해 위험 최소화 필요함  

6. 향후 조치  
- 2025년 12월 말까지 모든 부서에 대해 개편 안내 회의 실시 예정  
- 개선된 시스템 적용 전에 실제 고객 트래픽을 반영한 가상 테스트 환경에서 실험 수행함  
- 롤백 계획은 기존 시스템으로의 복원 절차를 명확히 하고, 모든 조건이 충족될 경우 자동으로 실행되도록 설정함

|------|------|--------|  
| 서버 구성 | 단일 인스턴스 | 마이크로서비스 기반 분산 구성 |  
| 장애 복구 시간 | 평균 45분 | 각 서비스별 별도 운영으로 최대 15분까지 축소 예상 |  
| 데이터 동기화 주기 | 실시간 아님 | 메시지 큐 기반으로 실시간 동기화 가능 |
