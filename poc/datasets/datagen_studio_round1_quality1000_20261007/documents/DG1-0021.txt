IT-2025-1584 / IT개발팀장, IT운영팀장, 정보보안팀장, 업무협조팀장 / IT개발팀 김민수 / 2025-03-13  

1. 연구 배경  
- 기존 시스템의 복잡한 계층 구조로 인해 유지보수 및 확장성에서 한계 발생함  
- 2025년 상반기 중 고객 데이터 처리량 증가에 대응하기 위해 핵심 시스템의 구조 개편 필요 판단됨  
- IT개발팀은 기존 3계층 아키텍처를 단일 서비스 기반으로 재구성하는 방안을 제안함  

2. 수행 내용  
- IT개발팀은 기존 주요 모듈 8개 중 5개를 독립형 서비스로 분리하여 재설계함  
- 연동 범위는 고객 정보 처리, 주문 내역 관리, 결제 처리, 배송 추적, 리뷰 관리 등 5개 영역으로 한정함  
- 각 서비스는 REST API 기반으로 독립화되었으며, 각각의 데이터베이스를 별도로 운영함  
- IT운영팀은 서비스 간 통신 지연 시간을 측정하여 평균 170ms에서 85ms로 개선됨을 확인함  
- 정보보안팀은 인증 처리 방식을 JWT 기반으로 전환하고, 모든 외부 호출에 대해 TLS 1.3 적용 필요 확인됨  
- 업무협조팀은 HRM 시스템과 연계된 근무 시간 기록 업데이트가 지연되지 않도록 연동 로직 재검토함  

3. 결과  
- 시스템 개편 후 테스트 환경에서의 부하 테스트 결과, 동시 접속자 5,000명 기준 응답 지연이 최대 670ms에서 290ms로 감소함  
- 개별 서비스 간 오류 발생 시 전체 시스템 마비로 이어지는 것을 방지하기 위해 장애 격리 기능 도입됨  
- 모든 서비스는 자체 로그 저장 및 모니터링 도구를 통해 실시간 상태 확인 가능함  
- 기존 아키텍처 대비 시스템 안정성 평가에서 4.7점(만점 5점) → 4.9점으로 향상됨  

4. 미해결 과제  
- 고객 정보를 다루는 서비스 중 일부가 여전히 동일한 데이터베이스를 공유하고 있어 완전한 분리 불가능함  
- 롤백 시나리오에 대한 테스트 환경 부족으로 실제 이행 전까지 검증되지 않음  
- 일부 부서에서는 새로운 구조 도입에 따른 업무 흐름 변경에 대한 적응이 지연되고 있음  

5. 후속 계획  
- 다음 주 월요일부터 3일간 테스트 환경에서 전체 이행 절차를 단계별로 검증할 예정임  
- 롤백 계획은 이행 전날까지 완성되어야 하며, 현재는 절차 단위로 실험적 실행 예정임  
- 각 서비스별 이행 순서는 아래와 같음: 고객 정보 → 주문 처리 → 결제 처리 → 배송 추적 → 리뷰 관리  
| 구분 | 현행 | 조정안 |  
|------|------|--------|  
| 데이터베이스 | 공통 DB 사용 | 각 서비스별 독립 DB 운영 |  
| 인증 방식 | 세션 기반 | JWT 기반 인증 적용 |  
| 통신 방식 | SOAP | REST API 기반 통신 |  

- IT운영팀은 이행 중 발생할 수 있는 오류에 대비해 모니터링 시스템을 추가로 강화함  
- 정보보안팀은 모든 서비스의 접근 로그를 중앙 집중화하여 감사용으로 활용할 예정임  
- 업무협조팀은 다음 주 수요일까지 부서별 업무 흐름 변경 사례를 정리하여 교육 자료로 활용함  

이번 개편을 통해 시스템의 유연성과 안정성이 개선될 것으로 판단되며, 이후 정기적인 성능 점검과 함께 지속적인 개선 노력이 필요함
