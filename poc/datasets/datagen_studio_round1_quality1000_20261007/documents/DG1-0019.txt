IT-2025-0633 / IT개발팀장, IT운영팀장, 정보보안팀장, 업무협조부서장 / IT개발팀 김지영 / 2025-02-03  

1. 연구 배경  
- 기존 시스템은 중앙집중형 아키텍처로 구성되어 있어 장애 발생 시 전체 서비스 중단이 발생함  
- 최근 고객 요청 증가와 함께 확장성 문제 및 보안 취약점이 지속적으로 제기됨  
- 이를 해결하기 위해 분산형 구조로의 전환을 검토하며, 이에 따른 시스템 재구성 필요함  

2. 수행 내용  
- IT개발팀은 기존 DB 계층을 마이크로서비스 기반으로 분리하여 4개의 서비스로 재구성함  
- 연동 범위는 사용자 인증, 주문 처리, 재고 관리, 결제 처리로 총 4개 영역으로 설정됨  
- IT운영팀은 각 서비스 간 통신을 위한 API 게이트웨이를 도입하고, 모니터링 도구를 추가 설치함  
- 정보보안팀은 데이터 전송 시 암호화 방식을 TLS 1.3 기준으로 업그레이드하고, 접근 제어 정책을 재설정함  
- 업무협조부서는 고객 문의 처리 시스템과 연계된 내역을 검증하며, 기존 시스템과의 호환성을 확인함  

3. 결과  
- 개발 환경에서의 테스트 결과, 각 서비스 간 응답 시간은 평균 180ms에서 95ms로 개선됨  
- 병렬 처리가 가능해져 동시 접속자 1,500명 기준 안정적인 응답 제공 가능함  
- 연동 테스트 결과, 기존 시스템과의 데이터 일관성은 유지되었으며, 오류 발생률은 0.1% 이하로 감소함  
- 마이그레이션 과정에서 발생할 수 있는 데이터 손실을 방지하기 위해 백업 전략을 병행함  

4. 미해결 과제  
- 특정 서비스에서 발생하는 지연 문제는 여전히 일부 사용자 그룹에서 확인됨 (예: 서울지역 고객 중 일부)  
- 로그 분석 도구의 부족으로 인해 실시간 모니터링이 어려운 부분 존재함  
- 일부 Legacy 시스템과의 연계 시 브릿지 처리가 지연되며, 이에 대한 최적화 필요함  

5. 후속 계획  
- 2025년 3월 10일까지 운영 환경에 대해 단계적 이행 예정이며, 첫 번째 단계에서는 인증 시스템부터 적용함  
- 이행 절차는 '단계적 배포 → 모니터링 → 정상 여부 검증 → 전체 이전' 순으로 진행됨  
- 롤백 계획은 각 단계별로 성공 여부를 확인한 후 불필요한 변경 사항은 즉시 취소 가능하도록 설정함  
- 만약 이행 중 주요 오류가 발생할 경우, 24시간 이내에 기존 시스템으로 복원 가능하도록 백업 포인트를 매일 생성함
