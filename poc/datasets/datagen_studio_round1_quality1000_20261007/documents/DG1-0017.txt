IT-2025-0035 / IT운영팀, 정보보안팀, 업무협조부서 / IT개발팀 김지현 / 2025-10-28  

1. 분석 목적  
- 기존 시스템의 복잡한 구조로 인해 유지보수 난이도가 높아지고 있는 상황에서, 시스템 개선을 위해 핵심 업무 처리 흐름을 재정의하고자 함  
- 특히 고객 주문 처리 및 재고 연동 시스템에서 발생하는 지연 문제를 해결하기 위해 구조적 개편 필요성 확인됨  

2. 분석 방법  
- IT개발팀은 기존 3-tier 아키텍처 기반의 서비스 흐름을 단순화하기 위해 microservices 기반으로 전환하는 방안 검토함  
- IT운영팀은 기존 서버 리소스 분산 상태를 분석하여, 서비스 별로 독립된 컨테이너 배포가 가능한 환경인지 검증함  
- 정보보안팀은 데이터 흐름 중 개인정보 노출 가능성이 있는 지점을 점검하고, 암호화 처리 여부를 확인함  
- 업무협조부서 담당자들은 각 부서별로 연관된 업무 흐름을 정리하여, 이행 시 영향을 받는 업무 영역을 파악함  

3. 분석 결과  
- 기존 시스템은 주문 처리 → 재고 감소 → 배송 발주 순으로 연결되나, 이 과정이 하나의 서비스에 집약되어 있어 장애 발생 시 전체 시스템 마비 위험이 큼  
- 새로운 아키텍처는 주문 처리, 재고 관리, 배송 처리를 각각 독립된 서비스로 분리하여, 각각의 오류가 전체에 영향을 주지 않도록 설계됨  
- 연동 범위는 고객 주문 내역 전달 및 재고 상태 갱신, 배송 상태 반영까지로 제한되며, 이는 기존 대비 25% 축소됨  
- 별도의 통합 인증 서비스 도입으로 인해 로그인 처리 시간이 평균 1.2초에서 0.4초로 개선됨  

| 구분 | 현행 | 조정안 |  
|------|------|--------|  
| 연동 방식 | 싱글 서버 기반 동기 처리 | 독립형 API 기반 비동기 처리 |  
| 장애 전파 범위 | 전체 시스템 마비 가능 | 특정 서비스에 한정됨 |  
| 데이터 저장 방식 | 단일 DB 사용 | 서비스별 DB 분리 (주문용, 재고용) |  

4. 해석  
- 개별 서비스가 독립적으로 운영되므로, 한 서비스에서 오류가 발생하더라도 다른 서비스는 정상 작동함  
- 특히 재고 관리 시스템에서 실시간 동기화가 불가능한 상황이었으나, 이전보다 4배 빠른 주기로 갱신 가능하게 됨  
- 다만, 데이터 일관성 유지를 위해 트랜잭션 처리를 위한 중앙 메시지 큐 도입 필요함  

5. 활용 방안  
- 개편된 시스템은 2026년 1월부터 단계적 이행 예정이며, 첫 번째 단계에서는 주문 처리 시스템부터 적용함  
- 이행 중 발생할 수 있는 오류에 대비해 롤백 계획을 수립하였으며, 현재 상태는 3단계로 구성됨: (1) 백업 생성 (2) 변경 적용 (3) 모니터링 후 정상 여부 확인  
- IT운영팀은 변경 전 후 모두 동일한 부하를 가진 환경에서 테스트를 완료하였으며, 실제 운영 환경에서도 동일한 결과 도출됨  
- 정보보안팀은 모든 데이터 전송 시 TLS 1.3 기준으로 암호화 처리 완료되었으며, 접근 제어 정책도 엄격하게 적용됨  

- 이행 절차는 매주 수요일마다 진행되며, 각 단계별로 담당자와의 검토 회의 실시함  
- 롤백 계획은 변경 적용 후 72시간 내에 문제가 발생할 경우 원복 가능하도록 설정되어 있으며, 이는 이미 테스트 완료됨  
- 업무협조부서 담당자는 변경 후에도 기존 업무 흐름에 문제가 없음을 확인하였으며, 추가적인 교육은 11월 초 예정임  
- IT개발팀은 이번 개편으로 인해 유지보수 주기가 평균 40% 단축될 것으로 예상됨
