# 파일럿 — "공개 의도 명시/암시 + 구체적 사업수치 포함" S3 문서 28건

작성 2026-09-19. golden100 S3 재현율 붕괴(16.0%) 원인 진단 후 만든 첫 번째 성공한 데이터
보강 시도. `poc/datasets/`의 다른 9개 후보 소스(gold_real·oss_v1·v6~v8·bpilot·public_s3_truth
등)는 전부 지름길·중복·라이선스 문제로 실패했으나, 이건 유일하게 검증을 통과했다.

## 왜 만들었나

golden100 S3 정답 25건 중 21건이 배포본(v-fe4b386b)에서 S1/S2로 과대분류됐다. 직접 읽어보니
전부 "외부 공개용"·"전시회 배포용"·"웨비나 참석자 전원 배포" 같은 **명백히 공개 의도가 있는
문서인데, 본문에 구체적 사업수치(매출·ROI%·성능개선율)가 있어서** 모델이 "숫자가 구체적이다
= 기밀스럽다"는 지름길로 오분류한 것으로 진단됐다.

## 생성 시행착오 — 반드시 읽을 것

**1차 시도(28건)는 실패해서 버렸다.** 시스템 프롬프트에 예시로 "매출 120억원, 처리속도 35%
개선, 도입 고객사 40개사"를 넣었더니, LLM(qwen3:14b)이 그 예시를 거의 그대로 베껴 써서
**"40개사"가 28건 중 22회(79%) 반복**됐다(TF-IDF 지름길 검사도 없이 직접 숫자 빈도만 세어도
바로 드러남). 이대로 썼으면 "40개사=S3"라는 새 지름길을 또 만들 뻔했다.

**2차 시도(이 폴더의 `pilot_v2_28docs.jsonl`)가 최종본이다.** 고침: 프롬프트에 예시 숫자를
아예 안 주고, 대신 문서마다 파이썬 `random`으로 **미리 정한 정확한 숫자**(매출·성장률·ROI·
고객사수 등, `assigned_numbers` 필드에 기록됨)를 지정해 "이 숫자를 반드시 그대로 써라"고
요구했다. 결과: 최다 반복 숫자가 22회→6회, 고유 숫자표현 24종→71종. 지정한 숫자가 실제
본문에 그대로 들어갔는지 28/28건 직접 검증했다.

## 설계 — 다양성 축

- 회사명 10종(가상기업A 포함), 업종 10종, 문서종류 10종(제품 브로슈어·웨비나 발표자료·
  제품 카탈로그·보도자료·FAQ·투자자소개자료·컨퍼런스 논문·사회공헌 보고서·홈페이지 소개서·
  전시회 리플렛) — 각 2~3건씩 고르게 분포.
- 공개신호 표현방식 5종을 순환(문서 말미 명시 문구 / 배포경로 암시 / 배포채널 암시 /
  장르 자체로 자명 / 접근성으로 암시) — "외부 공개용"이라는 한 문구만 반복하지 않는다.
- 포함 숫자 종류: 매출·성장률·ROI·성능개선율·가격·시장점유율·생산량 중 문서마다 3개를
  무작위로 골라 지정.

신호도 함께 있다 — 모델이 파일럿에서 배운 "구체적 숫자가 많아도 여전히 S3일 수 있다"는 신호를
이런 진짜 S1 문서에까지 과도하게 일반화한 것으로 보인다.
→ 대조군(다른 등급 negative) 방식이 아니라, **같은 장르(AI/기술 프로젝트 검토서)에 같은 수준의

장르 이름 자체는 golden100의 다른 등급 문서와 겹치지 않아 어제(v3, 84건 확장) 실패를 만든
"문서종류명 충돌" 위험이 구조적으로 없다.
