## 왜 다시 만들었나

기존 `golden100_labeled_v2.jsonl`(100건)을 직접 열어 확인한 결과 세 가지 문제가 있었다:

1. **등급당 25건뿐**이라 문서 1건만 뒤집혀도 재현율이 4%p 흔들렸다(노이즈가 큼). 실제로
   같은 날 golden100 S1 재현율이 문서 2건 때문에 56%→52%로 흔들린 사례가 있었다.
2. **신규 49건의 라벨이 순환논리였다.** `scripts/archive/make_golden100.py`를 직접 열어보면
   `target`을 먼저 정한 뒤 같은 딕셔너리에 `"rule": "TS", "llm": "TS"`까지 작성자가 손으로
   채워 넣고, `agree = (rule_g == llm_g == target)`으로 "일치"를 계산한다 — 진짜 규칙엔진이나
   LLM이 독립적으로 판정해서 우연히 맞은 게 아니라 애초에 세 값이 같게 쓰여 있었다.
3. **등급 간 문서종류/도메인이 우연히 겹칠 위험이 있었다.** 같은 날 학습 데이터 증강
   시도에서 golden100의 TS 문서와 문서종류명(`인수합병 실사 보고서`)·도메인(사기탐지 모델)이
   두 번이나 겹쳐 모델이 지름길을 배우는 사고가 있었다.

## 무엇을 다르게 했나

- **등급당 50건(총 200건)**으로 늘렸다 — 노이즈를 절반으로 줄인다.
- **등급 간 도메인을 설계 단계에서 완전히 분리**했다(TS 25개 산업군·S1 25개·S2 25개·S3 25개,
  서로 안 겹침 — 전수 확인 결과 등급 간 도메인 겹침 0건).
- **라벨을 스크립트에 미리 박아넣지 않았다.** 생성 시에는 목표 등급(`target`)만 정하고,
  생성이 끝난 뒤 **완전히 별도의 프로세스**가:
  1. 실제 `LabelRuleEngine().label(text)`를 그대로 실행해 `rule_grade`를 얻는다.
  2. 문서 본문만(회사명·도메인·의도 등급 등 어떤 힌트도 없이) 별도 LLM 호출에 보여
     블라인드로 재판정시켜 `llm_grade`를 얻는다(생성에 쓴 것과 다른 프롬프트·낮은 temperature).
  3. `agree_llm = (target == llm_grade)`를 **실제로 계산**한다.

## TS 프롬프트 수정 — 반드시 알아둘 것

1차 생성에서 TS 50건 중 **24건(48%)이 블라인드 재판정에서 S1로 내려갔다.** 원인을 직접
대조한 결과: "유출 시 경쟁사가 즉시 복제 가능해 시장 지위가 붕괴할 수 있다" 같은 강한 표현도
블라인드 판정에서는 S1(경쟁우위 상실)로 읽혔고, **본문에 "회사 존립" 또는 "국가 안보"라는
표현이 명시적으로 있는 문서만 TS로 유지됐다.** 이 문구를 TS 생성 프롬프트에 필수 요구사항으로
추가하고 50건을 재생성하자 일치율이 48%→100%로 뒤집혔다(재검증 스크립트로 확인).

**교훈**: TS/S1 경계는 "얼마나 심각한가"의 정도 차이가 아니라 "회사 존립·국가 안보급이냐"는
질적 문턱이다 — 강한 경쟁 피해 표현만으로는 부족하다.

## 여전히 남는 한계 (재구성으로도 안 풀리는 것)

- **여전히 100% 합성이다.** 실문서·고객 서명이 아니다 — `datasets/gold/READONLY.md`의
  "운영 성능 근거 불가" 원칙은 v3에도 그대로 적용된다. 이건 재구성으로 해결되는 문제가 아니라
  애초에 실문서가 없어서 생기는 정책적 한계다.
- `label_source=golden100_v3_generator`는 `scripts/audit_eval_ground_truth.py`에서 SILVER로
  분류했다(목표라벨+독립 블라인드LLM 일치를 실측했다는 근거) — GOLD(사람서명)는 아니다.
- S2/S3의 12~22% 불일치는 "더 민감하게 읽힘"이라는 안전한 방향이지만, 그만큼 그 문서들의
  "의도한 등급"이 완전히 명확하진 않다는 뜻이기도 하다 — 향후 재검토 후보로 남겨둔다.
