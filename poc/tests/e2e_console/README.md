# 관리자 콘솔 e2e 시나리오

화면을 **진짜 DOM 으로 띄우고 사람이 누르는 순서대로 눌러 보는** 시험이다.

```
cd poc/tests/e2e_console
npm install            # 한 번만 (jsdom)
node run.mjs           # 전부 실행
```

pytest 에서도 같은 것이 돈다(`poc/tests/test_e2e_console_scenarios.py`). node 나 jsdom 이
없으면 그 파일은 통째로 skip 한다 — 파이썬 CI 에 node 를 강제하지 않는다.

---

## 왜 만들었나

콘솔 계열 시험이 이미 여러 벌 있었는데도 실제로 열어 보면 안 되는 것이 계속 나왔다.
기존 시험이 보던 것은 세 가지뿐이었다.

| 기존 방식 | 못 잡는 것 |
|---|---|
| HTML 문자열에 특정 주소가 있는지 | 그 버튼을 눌렀을 때 실제로 무슨 일이 나는지 |
| `node --check` 문법 검사 | 실행 시점 오류(없는 함수·없는 요소) |
| 가짜 DOM 스텁으로 실행 | **스텁이 어떤 id 든 가짜 요소를 만들어 준다** — 화면에서 지운 요소를 만져도 안 터진다 |

세 번째가 핵심이다. 종전 하니스의 `document.getElementById` 는 없는 id 에도 객체를
돌려줬다. 그래서 2026-08-23 사고 — 화면에서 뺀 요소를 초기화 코드가 계속 만지다가
TypeError 를 냈고 **그 줄 뒤의 `checkHealth()` 가 아예 실행되지 않은 것** — 이 시험을
그대로 통과했다. jsdom 은 없는 id 에 `null` 을 준다. 그 순간 터지고, 여기서 잡힌다.

---

## 무엇을 보는가 / 무엇을 못 보는가

**본다**
- 스크립트 실행 오류(`window.onerror`·미처리 Promise·jsdom 오류) — 하나라도 나면 실패
- 버튼을 눌렀을 때 나가는 요청의 **메서드·경로·본문·헤더**
- 그 응답으로 화면에 **무엇이 그려졌는가**(등급·수치·경고·빈 목록 안내)
- 안 보이는 요소를 누르려 하면 그 자리에서 실패 (`display:none` 인 탭의 버튼 등)
- 확인창(`confirm`/`alert`/`prompt`)이 실제로 뜨는지, 취소하면 요청이 멈추는지
- 고장 주입 — 401·403·500·연결 끊김·JSON 자리에 HTML·지연·빈 응답

**못 본다**
- 레이아웃·CSS 시각 결과(글자 겹침, 색, 반응형)
- 실제 브라우저 고유 동작(파일 선택 대화상자, 인쇄, 실제 새 탭)
- `type="module"` 의 진짜 모듈 의미 — 시연 화면(index.html)의 `app.js` 는 하니스가
  의존 순서대로 이어 붙여 IIFE 로 감싸 실행한다(지연 실행 + 전역 미오염까지는 재현).

## 구성

```
run.mjs               실행기 (--json · --only · --list · --base)
lib/server.mjs        정적 파일 서빙 + /api/v1 mock + 고장 주입
lib/fixtures.json     API 응답 본보기 (파이썬 계약 시험이 실제 스키마로 검증한다)
lib/page.mjs          jsdom 부팅 + 조작 도구(click/set/attachFile/until/visible …)
lib/expect.mjs        확인 모음 — 실패해도 멈추지 않고 모아서 보고
scenarios/*.mjs       시나리오
```

## 본보기가 실제와 어긋나지 않게 하는 장치

여기 mock 이 실제 서버와 다르면 **화면 시험은 전부 통과하는데 실서버에서는 안 되는**
상태가 된다. 그것을 `poc/tests/test_e2e_console_api_contract.py` 가 막는다.

- 콘솔이 부르는 METHOD·경로가 FastAPI 라우트 표에 실재하는가
- 그 경로가 `fixtures.json` 에 있는가 (없으면 하니스가 404 로 답한다)
- 본보기 본문이 그 엔드포인트의 `response_model` 로 검증되는가

세 번째가 필드명 드리프트를 잡는다. 실제로 이 시험을 붙이자마자
`table_coverage` 를 숫자로 적어 둔 것(실제는 문자열)이 걸렸다.
`response_model` 없이 `dict` 를 돌려주는 엔드포인트는 자동 검증이 안 되므로,
그 목록이 늘어나면 계약 시험이 알려 준다.

## 실서버를 상대로 돌리기

```
KOIPA_E2E_API_KEY=<서버의 API_KEY> node run.mjs --base http://223.130.156.134:8000
```

화면도 API 도 **그 서버에서** 받는다. 하니스는 기록만 하는 프록시로 사이에 서므로,
"어떤 요청이 어떤 본문으로 나갔나" 확인은 실서버 상대로도 그대로 성립한다.
API 키는 `--key` 나 `KOIPA_E2E_API_KEY` 로 준다(콘솔이 `localStorage.koipa_api_key` 를
읽는 그 경로를 그대로 쓴다). 안 주면 콘솔 기본값으로 전부 401 이 난다.

건너뛰는 것 셋:

| 표시 | 뜻 | 왜 건너뛰나 |
|---|---|---|
| `needsMock` | 고장 주입이 필요 | 실서버에 401·500 을 만들어 낼 수 없다 |
| `writes` | 서버 상태를 바꾼다 | 무심코 분류·확정·학습 요청을 날리지 않기 위해. `--allow-writes` 로만 실행 |
| `needsData` | 특정 문서·목록이 있어야 성립 | 실서버 DB 내용은 시험이 정할 수 없다 |

`check.data.*` 로 쓴 확인(본보기 수치에 기대는 것 — "대기 3건", "정확도 91.7%")도 실서버
모드에서는 건너뛴다. 배선·동작을 보는 확인은 `check.*` 로 남겨 실서버에서도 그대로 판정한다.

**실측 2026-08-23** — 223(`http://223.130.156.134:8000`) 상대 읽기 전용 실행:
32 통과 · 2 실패 · 58 건너뜀. 실패 2건은 둘 다 **소스에서는 고쳤으나 223 에 아직 배포되지
않은 것**이다(자동갱신 정지 표시, 시연 화면 프로파일 표시). 재배포하면 통과한다.

## 시나리오 추가

`scenarios/` 에 `.mjs` 를 만들고 `scenarios` 배열을 내보내면 자동으로 잡힌다.

```js
export const scenarios = [{
  id: 'ops.something',
  title: '사람 말로 쓴, 이 시나리오가 확인하는 것',
  why: '이 시험이 존재하는 이유(과거 사고·요건)',
  needsMock: true,          // 고장 주입·응답 덮어쓰기를 쓰면 붙인다
  writes: true,             // 서버 상태를 바꾸는 요청이 나가면 붙인다
  needsData: true,          // 특정 문서·목록이 있어야 성립하면 붙인다
  async run({ server, check, live }) {
    const page = await openPage(server, '/console/admin.html');
    await page.settle();
    page.click('btn-something');
    await page.settle();
    check.ok(server.lastCall('POST', '/x'), '요청이 나갔다');          // 어디서나 참
    check.data.includes(page.text('result'), '3건', '건수가 보인다');  // 본보기 수치에 기댐
    return page;            // 실행기가 닫는다
  },
}];
```

새 엔드포인트를 쓰면 `lib/fixtures.json` 에 본보기를 추가한다 — 안 그러면 계약 시험이
"콘솔이 부르는데 본보기에 없다"로 알려 준다.
