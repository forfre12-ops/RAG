AI 거버넌스 폐곡선 콘솔

분류 → 검수(확정·재라벨) → 재학습 → 모델 핫리로드 → 메트릭. 거버넌스 폐곡선 전 구간을 한 화면에서 밟는 운영·E2E 검증 콘솔입니다. 모든 동작은 기존 /api/v1 엔드포인트를 그대로 호출합니다.

1 분류 → 2 검수 → 3 재학습 → 4 모델 리로드 → 5 메트릭
실시간 관제 정지 켜두면 관제 대시보드·검수 큐를 주기적으로 읽기 전용으로 자동 조회합니다. 확정·재라벨·재학습·활성화 같은 쓰기 작업은 폴링하지 않습니다(Safe Mode 무관). 메트릭·혼동행렬은 재학습 때만 바뀌므로 수동 조회로 둡니다.
0 연결 · 인증 컨텍스트
X-API-Key · X-Actor-Role

기본은 이 페이지를 서빙하는 서버. 다른 호스트면 전체 URL.

settings.api_key (.env API_KEY). 기본 demo-secret-key — 비어 있으면 모든 호출이 401.

X-Actor-Role 헤더 + confirm/relabel actor.role.

Safe Mode 기본값입니다. 체크하지 않으면 확정·재라벨·재학습·모델 활성화·핫리로드 같은 상태 변경 작업은 실행되지 않고, 조회와 분류 시연만 수행합니다.

권한 주의: confirm/relabel은 admin·reviewer, train·model/reload는 admin 역할이 필요합니다. X-Actor-Role 헤더 신뢰는 서버의 api_key_trust_actor_role_header=True(개발 기본)일 때만 적용됩니다. 운영(poc_mode=full)에서는 .env의 API_KEY_ROLE로 고정하세요.

1 분류 실행
POST /classify

샘플은 운영 골든셋(golden100_labeled_v2)에서 등급별 2건 선별 — doc_id로 보고서·메트릭과 추적됩니다. 일괄 분류는 4등급(TS·S1·S2·S3) 8건을 순차 분류해 검수 큐에 적재합니다. ※ body는 합성 텍스트(발주처 실문서 도착 전 기준).

2 검수 큐 · 확정/재라벨
POST /confirm · /relabel

confidence < 0.70 이거나 warnings 존재 시 검수 필요 플래그. 게이트 이상이면 자동 확정 후보.

「DB 검수 큐 불러오기」로 서버의 승인 대기 건을 조회하거나, 분류를 실행하면 결과가 적재됩니다.

DB 검수 큐 불러오기는 GET /review-queue(서버측 needs_review 대기 목록, FIFO)를 불러옵니다 — 브라우저 세션과 무관하게 실제 대기 건을 봅니다. 분류를 실행하면 이 세션 건도 누적됩니다. 확정/재라벨은 /confirm·/relabel로 전송되어 corrections·재학습 큐에 반영됩니다.

R 유사 문서 검색 · 검수 보조
POST /rag/search
검수 중인 문서와 비슷한 과거 문서·가이드를 찾아 검수자 판단을 돕습니다. LLM 답변 생성 없이 검색만 수행합니다.

RAG 검색 전용 — POST /rag/search(KURE 임베딩 + 하이브리드 + reranker)로 유사 문서 Top-K 반환. LLM 답변 합성(/answer)은 요건외라 호출하지 않습니다. 검수자가 유사 사례를 보고 등급을 판단하는 용도.

3 재학습 트리거
POST /train · GET /train/jobs
jobstatusmodel_versiontrigger
목록 없음 — "작업 목록 새로고침"

/train은 enable_training(full-train 프로파일)에서만 등록됩니다. PoC 기본은 stub 잡 — 실제 학습은 scripts/p1_train_classifier.py. 비활성 프로파일이면 404가 정상입니다.

4 모델 서빙 · 배포(G1) · 핫리로드
POST /admin/model/activate · /reload

activate(POST /admin/model/activate)는 현재 활성본 대비 deploy gate(고등급 미탐 FNR·F1 회귀)를 적용해 특정 ModelVersion을 배포하며, gate 미통과는 force로만 우회됩니다(감사 기록). 핫리로드는 활성 ModelVersion을 프로세스 재기동 없이 서빙에 반영합니다. rollback 및 자동 배포는 거버넌스 스케줄러·CLI가 담당합니다.

5 모델 메트릭 · FNR 게이트
GET /metrics/latest · /history · /confusion-matrix
◎ 운영 관제 대시보드
GET /admin/dashboard
“관제 종합 새로고침”으로 보류큐·배포 readiness·재학습 backlog·kill-gate·드리프트를 한 번에 조회합니다 (admin 전용).

이중검토 보류·locked_gold_eval 배포 readiness·재학습 backlog·kill-gate·임베딩 드리프트를 한 화면에 종합합니다(admin 전용·읽기 전용). 각 섹션은 독립 best-effort — 일부 소스 미가용 시 그 섹션만 degraded로 표기됩니다(500 없음). 드리프트는 마지막 게이지 값(주기 refresh 갱신)이라 표본 0이면 “데이터 없음”으로 표시됩니다.
