AI 거버넌스 폐곡선 콘솔

분류 → 검수(확정·재라벨) → 재학습 → 모델 핫리로드 → 메트릭. 거버넌스 폐곡선 전 구간을 한 화면에서 밟는 운영·E2E 검증 콘솔입니다. 모든 동작은 기존 /api/v1 엔드포인트를 그대로 호출합니다.

1 분류 → 2 검수 → 3 재학습 → 4 모델 리로드 → 5 메트릭
0 연결 · 인증 컨텍스트
X-API-Key · X-Actor-Role

기본은 이 페이지를 서빙하는 서버. 다른 호스트면 전체 URL.

settings.api_key (.env API_KEY). 기본 devkey.

X-Actor-Role 헤더 + confirm/relabel actor.role.

권한 주의: confirm/relabel은 admin·reviewer, train·model/reload는 admin 역할이 필요합니다. X-Actor-Role 헤더 신뢰는 서버의 api_key_trust_actor_role_header=True(개발 기본)일 때만 적용됩니다. 운영(poc_mode=full)에서는 .env의 API_KEY_ROLE로 고정하세요.

1 분류 실행
POST /classify

샘플은 운영 골든셋(golden100_labeled_v2)에서 등급별 2건 선별 — doc_id로 보고서·메트릭과 추적됩니다. 일괄 분류는 4등급(TS·S1·S2·S3) 8건을 순차 분류해 검수 큐에 적재합니다. ※ body는 합성 텍스트(발주처 실문서 도착 전 기준).

2 검수 큐 · 확정/재라벨
POST /confirm · /relabel

confidence < 0.70 이거나 warnings 존재 시 검수 필요 플래그. 게이트 이상이면 자동 확정 후보.

분류를 실행하면 결과가 검수 큐에 적재됩니다.

검수 큐 GET API는 PoC에 없어, 이 큐는 이 세션에서 분류한 건만 클라이언트에 누적합니다(DB 영속 큐 아님). 확정/재라벨은 실제 /confirm·/relabel로 전송되어 corrections 테이블·재학습 큐에 반영됩니다.

3 재학습 트리거
POST /train · GET /train/jobs
jobstatusmodel_versiontrigger
목록 없음 — "작업 목록 새로고침"

/train은 enable_training(full-train 프로파일)에서만 등록됩니다. PoC 기본은 stub 잡 — 실제 학습은 scripts/p1_train_classifier.py. 비활성 프로파일이면 404가 정상입니다.

4 모델 서빙 · 핫리로드
POST /admin/model/reload

핫리로드는 활성 ModelVersion(activate/rollback 후)을 프로세스 재기동 없이 서빙에 반영합니다. activate / rollback 자체는 REST가 없고 거버넌스 스케줄러·CLI에서 수행됩니다(자동 롤백 포함) — 콘솔은 그 결과를 리로드로 서빙에 적용하고 메트릭으로 확인합니다.
