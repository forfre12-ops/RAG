본 데모의 수치는 출처가 다음 3 종으로 명시됩니다.

실측 우리가 직접 측정 / 코드에서 카운트한 사실 · 명세 합격선·목표값·법령 등 명문화된 기준 · 참고 V2 통합본 인용 또는 예시 시나리오(미실측)

BERT 추론 1.18s · LLM 25.8s는 Phase 4/5 자체 GPU(RTX 5070 Ti) 실측. 사고 손해액은 예시 시나리오 기반으로 발주처 실문서 도착 후 실측치로 갱신 예정.

이 서버는 학습 분류기 v-fe4b386b가 로드된 상태이고(/api/v1/healthz의 classifier_model_dir로 확인 가능), 판정은 룰 엔진과 분류기의 이중판정으로 나옵니다 — 아래 결과 카드가 두 엔진의 등급을 각각 보여 줍니다. 모델이 로드되지 않은 배포에서는 룰 분류기(rule-fallback-v0) 단독으로 동작합니다. 위 1.18s·25.8s는 별도 GPU 환경 벤치 latency로 이 데모의 실측 응답시간과는 다릅니다.

§1시연 — 30초 안에 4단계가 갈리는 순간

업무 문서를 올리거나(HWP·PDF·DOCX·XLSX 등 — 추출 → 정규화·PII마스킹 → 청킹 → 검수 게이트 → 등급까지 한 번에), 샘플 12종(시드 v4 빌드 + 의도 등급 검증 통과)을 고르거나, 본문을 직접 붙여넣으십시오. 본문 입력은 SSE 7단계 점등으로 분류 과정이 실시간으로 보이고, 파일은 서버가 돌려준 실제 처리 단계가 표시됩니다. 파싱 세부(추출기·품질·청크·PII·검수 게이트)는 아래 §2 결과 안의 「파싱 상세」에 있습니다.

기본 demo-secret-key
📄 파일을 여기로 끌어다 놓거나 클릭해 선택
HWP · HWPX · PDF · DOCX · DOC · XLSX · XLS · PPTX · PPT · TXT — 본문 텍스트가 있는 파일만. 스캔 이미지는 지원하지 않습니다.
이 화면의 분석은 데이터베이스에 저장하지 않습니다. 올린 문서도 판정 결과도 남지 않습니다 — 문서 크기와 무관합니다 (큰 문서는 비동기로 분류하지만, 저장 경로를 타지 않는 것은 같습니다). 아래 「실적재(검수 큐 전송)」를 직접 켰을 때만 적재됩니다.
업무 문서를 직접 끌어다 놓으십시오. 실측(실업무문서 형태 29건): 자동 확정 5건이 전부 정답이었고, 정답보다 낮게 본 것은 1건인데 그 1건도 검수로 격리됐습니다 — 사람 없이 새어나간 미탐 0건입니다. 확신이 기준(0.70)에 못 미치면 등급은 산출하되 자동 확정하지 않고 검수 큐로 보냅니다.
참고 샘플 — 짧은 예시 문서 6종 (실측값은 아래 설명 참조)
참고 샘플
위 5종(TS·S1·S3·S2·S1)은 자동 확정되는 경로입니다(2026-08-24 배포본 실측 · scripts/check_demo_docs.py --set oneclick). 아래 1종은 조용히 오분류하지 않고 검수로 넘기는 안전장치를 보여 줍니다 — 본문이 사실상 없어 추출 게이트가 잡는 경우입니다(확신도 때문이 아닙니다 — 실측 사유 extraction-gate). 이 6종은 본문이 267~448자로 짧습니다 — 확신도는 본문이 길수록 낮아지므로, 실제 업무문서(2,000자 이상)에서는 자동 확정 비율이 이보다 낮습니다.
문서 속성 (ICD) — 출처 · 보안표시 · 접근범위 · 선택. 넣으면 등급 판정에 반영됩니다
보안표시가 있으면 그 등급 아래로는 안 내려갑니다(명시 표기 우선, ICD §4.2). 접근범위는 표시가 없을 때 관리성(M)을 정합니다 — 본문에서 관측되지 않는 축이라 이 값이 유일한 근거입니다. ⚠ 전 직원 열람은 비밀관리성 요건 미충족이라 등급을 내리는 방향입니다 (법리상 영업비밀 아님). 미탐 방향이므로 시스템이 경고를 남기고 사람 검수로 보냅니다.

아래 키워드의 체크를 해제하면 본문에서 해당 단어가 일반어로 치환됩니다. 다시 「분류하기」를 눌러 등급 변화를 확인하세요. 「영업팀 주간 업무 공유 초안」 샘플에서는 체크 해제만으로 S1 → S2 → S3로 등급이 실제로 내려갑니다. (특급·1급 문서는 비밀 신호가 촘촘해 몇 개를 꺼도 등급이 유지되는데, 이는 미탐 0을 지향하는 안전 설계입니다.)

실적재를 켜면 분석과 별개로 문서를 실제 적재(POST /documents → /classify)합니다 — needs_review 건은 거버넌스 콘솔의 DB 검수 큐에 나타나고, 본문은 RAG demo 컬렉션에 색인됩니다. 적재 문서는 created_by=demo-console 로만 태깅되어 admin의 「데모 데이터 초기화」로 한 번에 지웁니다.

§2결과 — 왜 이 등급인가

등급·자동확정 여부와 그 사유·자연어 판단(양성+음성 근거)·3 평가요소(S·V·M)·근거 키워드. 신뢰도 수치는 화면에 띄우지 않습니다 — 자동확정은 이 값 단독이 아니라 다단 게이트로 결정되기 때문입니다(수치는 API 응답·감사기록에 그대로 남습니다). 등급 배지를 클릭하면 §3 법령 카드로 이동합니다. 파일을 올린 경우에는 「파싱 상세」에 추출기·추출 품질·글자수·청크 수·구조화 표·PII 마스킹 건수와 검수 게이트 판정이 함께 표시됩니다.

진행 단계 — SSE 실시간 점등

샘플을 선택하고 "분류하기"를 누르세요.

두 엔진의 판정 — 룰 · 분류기 · 최종 결합

운영과 동일하게 룰 엔진과 학습 분류기(BERT)가 각각 독립 판정하고, 안전 규칙으로 결합해 최종 등급을 냅니다.

분류 후 표시됩니다.

3 평가요소 S·V·M (KOIPA 가이드 v1)

근거 키워드 — 클릭 시 본문 하이라이트

파싱 상세 — 추출 · 정규화 · PII 마스킹 · 청킹 · 검수 게이트
파일을 올리면 추출기·추출 품질·글자수·청크 수·구조화 표·PII 마스킹 건수가 여기에 표시됩니다.

FNR-안전 설계: 표 미추출·저품질·손상은 등급을 바꾸지 않고 검수로 라우팅합니다.

본문 미리보기 (시드 키워드 매칭)

실시간 요청 로그는 화면 하단 고정 콘솔에 표시됩니다(스크롤과 무관하게 항상 보임). 서버 uvicorn 로그와 대조하면 위조가 아님을 확인할 수 있습니다.

§2.5운영 현황 · 검수 반영 DB 실측

아래 수치는 모두 DB 실측 카운트(가공 없음)입니다. "실시간 반영 시연"은 등록→분류→검수 교정→재분류를 실제로 호출하며, 교정 결과가 다음 분류에 반영되는 것을 보여줍니다.

버튼을 누르면 실제 문서를 등록·분류하고, 검수자가 등급을 교정한 뒤 같은 문서를 재분류합니다. 각 단계는 서버 실호출이며 위 카운터가 실시간으로 바뀝니다.

§3법령 근거 — 부정경쟁방지 및 영업비밀보호에 관한 법률 §2조 2호

등급별 법령 출처 + KOIPA 가이드 v1 §번호 + 시드 키워드. 카드의 키워드를 클릭하면 §2 본문에서 해당 단어가 깜빡입니다.
