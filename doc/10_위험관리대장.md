# 위험관리대장 — KOIPA AI 영업비밀관리시스템 (로이드케이 파트)

작성일: 2026-05-27
버전: v0.9 (KL/발주처 회신 시 v1.0 확정)
유지: 로이드케이 사업단
대상: 내부 사업관리 + 발주처/KL 공유본

## 0. 사용법

### 0.1 구조
본 대장은 **2축 구조**입니다.

| 축 | 카테고리 | 특성 |
|---|---|---|
| **회신 의존 (분기형)** | R-Q (발주처) / R-E (KL ES) | 회신 결과로 시나리오가 결정 → 매칭 시 즉시 대응안 발동 |
| **운영 위험 (상시)** | R-T (기술) / R-S (일정) / R-O (조직) | 회신과 무관하게 항상 모니터링 |

### 0.2 영향·확률 평가 기준

| 영향 | 정의 |
|---|---|
| **상(High)** | 일정 지연 ≥ 2주, 또는 합격선 미달, 또는 RFP 미충족 |
| **중(Med)** | 일정 지연 < 2주, 또는 보조 기능 영향 |
| **하(Low)** | 디버깅·튜닝으로 흡수 가능 |

| 확률 | 정의 |
|---|---|
| **상(High)** | 50% 이상 |
| **중(Med)** | 20~50% |
| **하(Low)** | 20% 미만 |

### 0.3 대응 유형
- **회피**: 위험 발생 경로 자체를 제거
- **전가**: 제3자 책임으로 이전 (발주처/KL/외부 클라우드)
- **완화**: 발생 확률·영향 감소
- **수용**: 발생 시 대응안 보유, 사전 행동 없음

### 0.4 트리거
각 위험의 "발동 신호". 트리거 충족 시 1차 대응 즉시 실행.

## 6. 시나리오 매핑 — 회신 도착 즉시 액션

회신이 도착하면 본 절을 보고 즉시 시나리오를 매칭해 1차 대응을 실행합니다.

```
┌─ 발주처 회신 ─────────────────────────────────────────────┐
│ Q1 GPU         → R-Q1 (a/b/c)                              │
│ Q2 합성 활용   → R-Q2 (a/b/c)                              │
│ Q3 실문서      → R-Q3 (a/b/c)                              │
│ Q4 가이드      → R-Q4 (a/b)                                │
│ Q6 EXAONE      → R-Q5 (a/b)                                │
│ Q7 워크숍      → R-Q6 (a/b)                                │
└────────────────────────────────────────────────────────────┘

┌─ KL ES 회신 ──────────────────────────────────────────────┐
│ E1 ES 버전     → R-E1 (a/b/c) — 코드 자동 분기, 추가 작업 0│
│ E2 Nori        → R-E2 (a/b/c)                              │
│ E3 라이선스    → R-E3 (a/b) — R-E4·R-E6와 연결            │
│ E4 격리 정책   → R-E4 (a/b/c)                              │
│ E5 노드 사양   → R-E5 (a/b/c) — (c)는 ES heap 축소 운영   │
│ E6·E7 권한     → R-E6 (a/b)                                │
│ E8 retention   → ILM 정책 확정 (doc/13 §11.4)             │
└────────────────────────────────────────────────────────────┘
```

**조합 위험**: 다음 3개 조합은 합쳐서 발생하면 전체 일정에 영향이 큽니다.

| 조합 | 결과 |
|---|---|
| R-Q1 (c) + R-E5 (c) | GPU·ES 모두 부족 → 클라우드 GPU + ES heap 축소 운영 → 일정 영향 미미 (벡터 백엔드 단일화 유지) |
| R-Q2 (c) + R-Q3 (c) | 합성·실문서 모두 막힘 → 외부 일반화 검증 불가 → 합격선 의미 약화 |
| R-E7 (b) + R-T4 | 폐쇄망 + LLM 비용 → Claude 완전 제거 → Qwen3 자체 호스팅 GPU 상시 점유 필요 → R-Q1 (c) 시나리오 GPU 부담 가중 |

## 7. 거버넌스

### 7.1 갱신 주기
- **회신 도착 시**: 해당 시나리오 행을 "해당 시나리오 확정"으로 갱신, 1차 대응 실행 기록 추가
