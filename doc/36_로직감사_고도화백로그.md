추론·라벨링·능동학습·보정·평가 3차원 병렬 감사 결과와 조치. 보안설계(미탐방지) 골격은

## B. 검토 후 보류 (의도적 미수정)

- **B3 (청크 노이즈 가드)** — *철회*. 짧은 노이즈 청크 스파이크 과분류를 막으려 severe-max에
  최소길이 필터를 시도했으나, 짧은 *비밀* 청크("마스터 키: …")도 배제돼 **미탐(FNR) 유발**
  (test_audit_w2_a가 적발). 영업비밀 시스템은 **과분류가 안전 방향**이므로 전체 청크 severe-max
  유지가 옳음. → 미적용 확정.

## C. 본개발 과제 (데이터·아키텍처 의존 — 블라인드 수정 위험으로 보류)

| ID | 결함 | 왜 보류 | 본개발 조치 |
|---|---|---|---|
| **A2** | 능동학습 3중 단절: ① 교정이 학습에 미반영된 채 `consumed` 마크(데이터 유실) ② 재학습 모델 배포 전 합격선 검증 없음 ③ 재학습 모델 실제 배포 안 됨(디스크 저장만) | 워커·학습·배포 아키텍처 재배선 — 검증 데이터 없이 자동배포 게이트를 추가하면 오히려 위험 | corrections→labeled 재빌드 파이프라인 + 홀드아웃 합격선 게이트(`fnr_high ≤ baseline`) 통과 모델만 `register/activate_model_version`으로 배포 + 동시성 락 |
| **B1** | FNR-override 임계(3.0/2.2/1.6)가 측정근거 없는 잠정값 + 범용 영문약어(EUV·API·patent·M&A)가 단독 TS 트리거 → 과분류 | 임계 튜닝은 **라벨된 검증셋의 PR곡선** 필요. 과분류는 FNR-safe 방향이라 안전 결함이 아님 | **골든셋 500건으로 PR곡선 튜닝** → 임계 확정 + 범용 약어 weight 하향/출처 교차검증 |
| **C-esc** | escalation τ(FNR 레버)가 평가에만 있고 실서빙 `_run_model`은 plain argmax | 운영점 τ는 실데이터 PR곡선으로 확정해야 | 보정 연결(A1 완료) 후 τ를 settings로 노출 + argmax 대체 |
| **C-eval** | eval↔serving 불일치 — 평가가 full 파이프라인(temperature·청크·게이트) 미경유 | 평가 하네스 재작성 | 최소 1개 게이트 평가를 `InferencePipeline` 경유로 측정 |
| **C-cons** | 교정 합의 없음 — 단일 검수자 1건이 곧 정답(편향·오염) | 검수 정책 결정(발주처 협의) | 고등급 변경 2인 검토/시니어 사인오프 + 검수자 신뢰도 추적 |
| **C-ver** | 모델 버전관리·롤백 인프라(`register/activate_model_version`)가 테스트에서만 호출 | A2와 함께 배선 | 배포 단계에서 버전 등록·활성화·롤백 경로 배선 |

## 본개발 우선순위
1. **A2 능동학습 재배선** — 교정 유실 차단 + 배포 합격선 게이트(보안 직결, 최우선)
2. **B1/C-esc 임계 튜닝** — 골든셋 500 + 실데이터 PR곡선으로 override·escalation 운영점 확정
3. **실데이터 확보** — 합성→실 격차(93→76%) 해소, 90% 도달의 본질 레버
4. C-eval/C-cons/C-ver — 평가 정합·검수 거버넌스·버전관리
