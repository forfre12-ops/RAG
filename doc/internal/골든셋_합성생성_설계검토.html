골든셋·평가셋 합성 생성 — 설계 검토

"평가셋(골든셋 1,000개)를 합성으로 만든다"는 방향이 설계로 받쳐지는지를 코드 기준으로 점검한 보고서다. 결론: 라벨·합의·티어 코드는 견고하나, 사람 서명이 양쪽(빌드·운영) 다 막혀 합성은 평가 진실이 될 수 없다. 그래서 산출물을 "골든셋 1,000 생성"이 아니라 → 합성 학습코퍼스 1,000 + 합성 holdout + 외부 앵커 기반 다층 평가 + 메타모픽 최소쌍 회귀 테스트(+ 배포 후 운영 능동감사로 실분포 보완)로 정확히 명명한다.

명명 골든셋 1,000 ❌ → 학습코퍼스+holdout+다층평가+회귀테스트
평가 중심 외부 사실 앵커(legal_floor)
D 1순위 메타모픽 회귀(정답 아님)
실분포 측정 운영 능동감사 A (별도)
검증 Claude 고등급 0건 → 4중일치 강등
ℹ
한눈에 보기. 합성으로 등급분류 골든셋 1,000건을 만들려 한다. 부품(생성·합의·티어·서명)은 이미 코드로 있다. 그런데 두 가지가 발목을 잡는다 — ① "평가셋"이라는 말이 함정: 합성은 절대 "평가 진실(정답)"이 될 수 없고(사람 서명 전용인데 그 사람 서명이 빌드·운영 양쪽 다 막힘), ② 심판도 못 믿는다: 단일 LLM(Claude)으로 591건을 재판정하니 고등급(TS·S1)을 단 한 건도 못 냈다. 그래서 "정답지 하나"는 불가능하다. 대신 등급이 바깥 사실로 박힌 앵커(공개 판례→S3, 국가핵심기술→TS)를 중심으로, 약점이 안 겹치는 여러 측정을 층으로 쌓고 절대 한 숫자로 합치지 않는 것이 사람 없이 가능한 가장 정직한 평가다.

01 결론 — 한눈에 보기

이번 검토가 확정한 것 5가지.

항목확정 내용
설계 품질생성·합의 게이트·티어 계약·빌드 서비스 — 견고하고 적대적 검증까지 마침. 재설계 불필요
산출물 정체합성 1,000건 = silver_train ~700 + 합성 holdout ~250 · 평가 진실 아님("일반화 아님" 스탬프 필수)

검증된 사실단일 LLM 심판으로 고등급 정답 못 만듦(591건: Claude 고등급 0건) → ③ 4중일치 층 보조 강등

02 산출물 정체 — "평가셋"이 아니다

가장 먼저 짚을 개념 충돌. 합성 1,000은 "평가 정답"이 될 수 없다.

티어 계약(golden_tiers.py)과 설계서 §04가 명시한다 — 합성·무검수는 gold_candidate/silver까지만. locked_gold_eval(평가 진실)은 사람 서명 전용이다. 그런데 그 사람 서명이 양쪽 다 막혀 있다:

빌드 시점 (지재원)
검수 0
전문가가 문서에 "정답 등급" 서명 불가 (VP 합성-only 지시)
운영 시점 (고객사)
반출 0
관리자가 확정해도 그 결과가 우리(지재원)에게 영영 안 옴

→ 즉 locked_gold_eval은 현 제약에서 구조적으로 영구히 빈다. golden_signoff.promote_to_locked·사람 서명 기계장치는 호출될 일 없는 휴면 코드다(지우진 말고 "제약 완화 시 전용"으로 표시). 따라서 합성 1,000건의 정체는:

무엇설계상 정체양 (1,000 기준)
silver_train학습 시드 — 평가 금지~700
합성 holdout상대비교용 — "일반화 아님" 명시 필수~250 (25%)
locked_gold_eval진짜 평가 진실 → 합성·LLM 불가, 사람 서명 막힘0 (영구 휴면)
⚠
"1,000"의 의미 정정. 설계서의 1,000은 합성 코퍼스 총량(TS20·S130·S230·S320, ~1,600 과생성 → 순통과 1,000)이지 평가 1,000건이 아니다. 우리가 만드는 1,000은 학습코퍼스(silver ~700) + holdout(~250)으로 확정하고, 이를 "평가셋"이라 부르지 않는다. 평가를 어떻게 신뢰할지는 §03에서 다층 측정으로 푼다.

03 평가 신뢰 — 앵커 중심 다층 평가

사람 정답지가 없으면 "어떤 라벨을 믿느냐"가 전부다. 단일 정답지는 불가능 → 약점이 안 겹치는 층을 쌓는다.

먼저 — 검증된 사실: 단일 LLM 심판으로 고등급 정답을 못 만든다

datasets/gold_real/_rejudge_claude/summary.json 직접 확인 (claude-opus로 591건 재판정):

CLAUDE 분포
TS·S1 = 0건
S3 577 / S2 14 — 고등급 전무
이동
하향 208 / 상향 1
Qwen S1 30·S2 191 → 대거 S3
함의
고등급 정답 0
LLM 합의로 고등급 평가셋 못 채움
ℹ
정직한 해석(과장 금지). 이걸 "Claude가 고장난 채점자"로만 보면 안 된다. 이 591건은 60%가 공개 판례 프록시라, 비공지성 법리상 공개 판례는 S3가 맞다 — Claude의 하향은 "규칙을 올바르게 적용"한 것일 수도 있다. 하지만 어느 해석이든 결론은 같다: 단일 LLM 합의로 "고등급 정답"을 만들 수 없다(편향이든 코퍼스 오염이든). → 고등급 평가는 LLM이 아니라 외부 사실 앵커에 얹어야 한다.

다층 평가 — 빌드 평가(사람 불필요) + 운영 평가(별도)

층무엇역할 · 신뢰도
1 ★외부 사실 앵커 (legal_floor)공개 판례→S3·국가핵심기술→TS·법원 인정 판례→S1/S2. 비순환·고신뢰(릴리스 차단 floor), 단 분포 OOD(판례≠내부문서)
2AI 합의 holdout룰==심판+근거+self-consist 통과분 25%. 양 많아 등급별 수치, 단 순환=천장 한정
3 ↓강등4중일치 (target==룰==주심==섀도)고등급에서 구조적 0건(위 591건) → 평가 backbone에서 내리고 저등급 보조 교차확인으로만
+D ⭐앵커→사내문서체 패러프레이즈
회귀 테스트(정답 아님)		외부확정 고등급 앵커를 Qwen으로 내부문서처럼 재작성. 정답 평가셋이 아니라 1순위 메타모픽 회귀 테스트 — ↓ 전용 블록·강화 사양 참조
+C출처별 분리 카드 + 단일숫자 금지칸마다 N·신뢰구간, 표본 부족 시 PASS 아닌 INCONCLUSIVE(판단보류). 거짓 헤드라인 코드 차단

+E서빙 메타모픽 불변식정답 없이 회귀 잠금. 핵심=고위험 본문에 보도자료 출처 붙여 cap될 때 경고 누락(조용한 미탐) 탐지
운영 A능동 감사 표집 (배포 후·별도)유일하게 실분포 미탐을 비편향 측정. 단 운영 검수(사람)+집계만 반출 합의 필요 — 빌드 평가 아님(§아래 주의)
⚠
A(운영 능동감사)는 결이 다르다. 합성·순환 천장 위에서 진짜 분포의 미탐율을 재는 건 이것뿐이지만 — (a) 고객사 관리자의 노동이 들고(빌드 검수 0과 별개인 "운영 검수 필수" 루프), (b) 반출 0이라 문서가 아닌 집계 수치만 받으며(정기 집계 리포트 합의=KL/부사장 항목), (c) 고등급 미탐이 희소해 분기 수백 건으론 신뢰구간이 [0%,5%]로 넓다. → 지금 만드는 1,000 합성 평가셋에 넣는 게 아니라, 배포 후 4번째 층으로 둔다.
✓
핵심 원칙: 절대 한 숫자로 합치지 않는다. "앵커 FNR / holdout recall / 일치율"을 나란히 보고해야 어디가 약한지(특히 치명적 고등급 미탐) 드러난다. 가중평균 F1 같은 단일 헤드라인은 C가 코드로 금지한다.

D — 1순위: 메타모픽 최소쌍 회귀 테스트 (정답 평가셋 아님)

D는 "정답 평가셋"으로 쓰지 않는다. 회귀 테스트로 1순위 포지셔닝한다 — 불변식: 같은 사실을 내부문서체로 바꿔도 등급이 내려가면 안 된다. 이러면 절대 정답을 완전히 믿을 필요가 줄어든다(검증 불가능한 "이게 TS인가" 대신, 검증 가능한 "내려가면 안 된다"만 본다). anchor=TS · paraphrase=S3면 거의 확실한 위험 신호 — 이게 D의 가장 강한 사용법이다.

⚠
핵심 규율 — 실패만 정보다. 통과는 정보가 아니다. anchor=TS·paraphrase=S3(실패)=강한 위험 신호지만, paraphrase=TS(통과)는 "좋다"는 증거가 아니다 — 모든 걸 TS로 찍는 분류기도 만점 통과한다(공허). 그리고 우리 시스템은 FNR-safe min(rule_engine.py:399)·공개 판례 85% 과분류 실측으로 구조적으로 과분류 쪽으로 기운다. 순방향만 보면 과분류 시스템에서 거짓 안심한다.

→ 그래서 D는 대칭 3종을 같이 보고한다(한쪽만 보면 반대로 무너짐):

검사불변식잡는 것
순방향 ★ (사실 유지·문체 변경)등급 안 내려가야고등급 OOD 미탐(FN) — anchor=TS, paraphrase=S3 = 위험
역방향 (등급 결정 사실 제거/중화)등급 내려가야과분류(FP) — 안 내려가면 사실이 아니라 표면 단서에 패닉
과분류율 (공개→S3)S3 유지과분류 베이스라인 — eval_real_public_fpr.py 기존 활용

D는 합성·순환 holdout과 같은 평가 숫자로 섞지 않는다. 회귀 테스트 PASS/FAIL은 별도 산출이며, 위 §"한 숫자로 안 합침" 원칙의 가장 엄격한 적용이다.

✓
채점 코어 구현 완료. m6_evaluation/metamorphic.py — 사실보존 게이트(check_fact_preservation: 토큰 보존 + 부정 가드, 룰/심판 아님)와 대칭 채점(build_metamorphic_report: 순방향/역방향/과분류 + Wilson CI, quality_score는 NotImplementedError로 "통과=품질 아님" 강제). 테스트 10건. 패러프레이즈 생성(앵커→사내문서체, Qwen)은 앵커 파이프라인 소관으로 분리 — 이 코어는 생성 결과를 받아 채점/검사만 한다.

D 강화 사양 — 라벨 상속 조건 (느슨하면 위험 데이터)

D의 가치는 "앵커의 권위 + 합성의 유연함"을 동시에 얻는 데 있다. 그런데 재작성이 사실을 희석하는 순간, 앵커의 권위(외부 사실로 등급이 박혔다는 신뢰)는 가져오면서 그 근거는 합성으로 깨진 — "합성인데 앵커인 척하는" 데이터가 된다. 이건 품질 저하가 아니라 틀린 라벨에 고신뢰 도장이 찍혀 평가를 반대 방향으로 오염시킨다. 따라서 D는 아래 조건을 모두 통과한 쌍만 채택한다.

#조건내용
1고등급 앵커에만 적용S3 공개 앵커는 패러프레이즈 금지. 공개 판례→S3의 등급 근거는 본문이 아니라 "공개됨"이라는 메타데이터 — 내부문서체로 재작성하면 그 유일한 S3 근거가 사라지고 내용상 고등급으로 보이는 가짜 내부문서가 된다(relabel_public_to_s3.py가 막으려던 바로 그것). → D는 TS/S1/S2 앵커에만.
2소스별 핵심 사실 체크리스트 보존한 종류로 안 됨. NKT 특허(TS)=국가핵심기술 소분류 기술용어; 법원 판례(S1/S2)=법원이 영업비밀로 판시한 그 대상 명사구(mine_trade_secret_cases.py의 verbatim trap). 등급을 만든 사실이 보존돼야 함.
3등급 결정 근거 보존2의 사실이 등급을 정한 논리(왜 TS인가)까지 살아 있어야 함. 키워드만 남고 맥락이 빠지면 탈락.
4부정/방향 가드토큰이 살아도 의미가 뒤집히면 끝. "이 기술은 국가핵심기술이 아니다"는 토큰 보존·사실 반전. 등급 근거 문장이 부정·완화·조건절에 묶이지 않았는지 검사.
5한·영 쌍 둘 다 통과번역/영문 생성은 또 하나의 희석 경로. KO 통과·EN 실패면 그 쌍 폐기(영어 OOD 보완하려다 영어 라벨이 깨지면 본전 손실).
6원본 앵커 id 추적각 쌍에 원 앵커 id + 변환 로그(모델·프롬프트·버전) 스탬프. 감사·재현, 그리고 원 앵커가 오라벨로 밝혀지면 파생 일괄 정정.
7검사 = 룰/심판 아님, 결정적 사실 검사룰·심판으로 거르면 D가 탈출하려던 순환이 복귀(심판 동의 케이스만 남김=쉬운 것만 선택). 하드 게이트는 결정적 체크리스트(1~4). NLI 함의 검사를 쓰려면 학습/라벨/심판 계열이 아닌 별도 모델로 보조 신호만.
8폐기 아니라 격리 + 폐기율 로깅그냥 버리면 "D 잘 됨" 착시. 소스별 폐기율 기록 — 높으면 "그 앵커 종류는 재작성으로 라벨 유지 불가"가 결과 자체(조용한 누락 금지).
9앵커당 패러프레이즈 수 상한 + 가중1 앵커서 10개 뽑으면 정보량 1을 10으로 분장. 앵커당 개수 제한 + 통계 가중.
10원본·패러프레이즈 같은 숫자로 안 섞기같은 소스라 상관됨 → 합치면 N·신뢰구간 거짓 부풀림. 분리 보고(C 원칙).
⚠
정직한 잔여 한계(오버셀 금지). 패러프레이즈도 Qwen, 학습 silver도 Qwen 생성 → D 패러프레이즈는 학습셋과 같은 생성기 문체다. 분류기가 잘 맞춰도 "등급 학습"인지 "Qwen 문체 인식"인지 섞인다. → D는 엄밀히는 진짜 실세계 OOD가 아니라 "Qwen 분포 안에서의 문체 전이 견고성". 안 하는 것보단 훨씬 낫고 고등급을 비순환으로 겨냥하는 유일한 합성법이라 가치는 크나, 모델카드엔 그렇게 정직하게 적는다.

07 완전성 점검 — 놓치기 쉬운 4가지

다각도 적대 검증이 끝에서 잡아낸, 평가가 통째로 빠뜨리기 쉬운 위험(메모리 대조 확인).

놓친 것왜 위험 · 보완
영어 OOD 통째 누락학습셋 영어 0%·S1 약점 절반이 영어인데 모든 안이 한국어 기준. → D 패러프레이즈에 한·영 짝 강제(가장 싼 보완)
고객사 자가재학습이 평가 없이 돎고객사에서 enable_training 미게이트 버그로 재학습 루프가 돎(교정 admission 게이트 0). 빌드 평가가 좋아도 무의미. → A 측정을 재학습 hard gate로
보정(calibration) 평가 부재미보정 서빙 시 OOD 과신(T≈3 필요). FNR만 보고 과신은 안 봄 → 보정 지표를 리포트에 추가

08 다음 단계

코드는 본 보고서 합의 후 착수. 쉬운 정직성 장치(C·B)부터, 그다음 산출·앵커.

  1. [정직성·쉬움] C 분리 리포트 + B 심판 폭로 — ✅ 구현 완료: eval_cards.py(Wilson CI·INCONCLUSIVE·단일숫자 코드차단) + judge_reliability.py(591 층화·proxy 양가). 테스트 17건 통과(실데이터 회귀 락 포함). 데이터 0 추가.
  2. [계측] 파일럿 통과율 — ConsensusJudge 경로로 등급별 ~25건(100건) 통과율 측정 → 과생성 배수 사이징.
  3. [빌드] 1,000 산출 오케스트레이션 — 생성→앵커 적재(+D 한·영 패러프레이즈)→build_golden_set→25% 등급층화 분할→다층 리포트. run-스코프 파일만(정본 보호).
  4. [연결] deploy gate — 합성 test.jsonl 대신 앵커/holdout으로 FNR 재측정(§05 하드닝). 앵커 비면 fail-closed.
  5. [잠금] E 메타모픽 스위트 — 출처 cap 시 경고 누락 회귀 테스트.
  6. [거버넌스] A 운영 능동감사 — 집계 반출·재학습 gate 합의(KL/부사장). 배포 후 4번째 층.

09 한계·전제 (정직)

이 평가가 할 수 있는 것과 없는 것.

  • 합성 천장 — 고등급·영어·실분포는 합성으로 못 채움(실측). 앵커·holdout은 "상대비교 출발선"이지 일반화 보증이 아니다.
  • 평가 진실은 영구 0 — 사람 서명이 빌드·운영 양쪽 다 막혀 locked_gold_eval은 채워지지 않는다. 운영 능동감사(A)도 집계·표본 한계라 진짜 정답지를 대신하진 못한다.
  • 앵커는 비순환이나 OOD — 공개 판례≠내부 비밀문서. D 패러프레이즈로 갭을 줄이되, 재작성이 사실을 희석하면 라벨 상속이 깨진다 → §03 D 강화 사양 10조건(결정적 사실검사·부정가드·격리·최소쌍)으로만 안전. 그래도 패러프레이즈가 Qwen이라 진짜 OOD가 아닌 "Qwen 문체 전이 견고성"임은 잔존.
  • 심판 공통편향은 못 깸 — B는 순환을 "측정"할 뿐 제거하지 못한다(Qwen·Claude 같은 기반·RLHF).
  • 이 보고서는 코드 미변경 — 검토·결정 문서다. 실제 생성·평가는 §08 합의 후 착수한다.
ℹ
종합. 사람 서명이 막힌 세계에서 "완벽한 정답지"는 못 만든다. 대신 외부 사실 앵커를 중심에 두고, 약점이 안 겹치는 측정을 층으로 쌓아 절대 한 숫자로 합치지 않는 것이 가능한 최선이다. 4중일치는 보조로 내리고, 고등급 미탐은 D(앵커→사내문서체)로 비순환 측정하며, 진짜 분포는 운영 능동감사(A)로만 — 그것도 집계·표본 한계 안에서 — 본다. 모든 한계는 모델카드·계약에 정직히 명시한다.
