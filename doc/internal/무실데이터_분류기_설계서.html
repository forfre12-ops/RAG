무실데이터 분류기 설계서

실데이터 0 · 빌드 검수 0 · 반출 0 제약 아래에서 영업비밀 등급 분류기를 어떻게 만들고(합성 부트스트랩) 어떻게 운영에서 개선하며(선례·재학습), 오염이 운영까지 도달하는 "죽음의 나선"을 어떻게 막는가를 코드 기준으로 확정한 설계서다. 모든 코드 주장은 제어흐름 추적 + 적대적 검증으로 확인했다.

제약 실데이터·검수·반출 0
전략 안전배포+운영학습
기둥 합성 부트스트랩 / 운영 선례
죽음의 나선 오늘은 차단(단일 플래그)
하드닝 4건
ℹ
한눈에 보기. 우리는 진짜 문서도, 사람 검수도, 데이터 반출도 못 쓰는 상황에서 비밀등급 분류기를 만들어야 한다. 그래서 ① 합성 데이터 + 여러 AI의 합의로 "출발 모델"을 만들고(검수 대역), ② 배포 후 고객사 관리자가 확정한 등급을 시스템이 즉시 참고·학습한다. 핵심 위험은 정확도가 아니라 — 지친 관리자가 틀린 걸 그냥 승인 → 그 오염이 자동 재학습으로 모델에 박혀 점점 바보가 되는데 똑똑해진 줄 착각하는 "죽음의 나선"이다. 검증 결과 오늘은 단 하나의 설정(retrain_auto_activate=False)이 이걸 막고 있고, 진짜 구멍은 교정→학습 편입에 품질 게이트가 없다는 것이다(§6·§7). 이 설계서는 그 단일 차단점에 기대지 않도록 4곳을 하드닝한다.

01 한눈에 보기 — 무엇을 결정했나

이 설계서가 확정하는 것 5가지.

항목확정 내용
전략 무게중심"검증 후 배포"(불가능) → "안전 배포 + 운영에서 학습"
골든셋 생성생성=Qwen / 심판=Claude+Qwen섀도 · 구성 TS20·S130·S230·S320 · 25% holdout · 과생성 ~1,600→1,000
평가 진실합성은 locked_gold_eval이 될 수 없음(사람 서명 전용) → 운영 관리자 확정으로만 채워짐
운영 개선관리자 확정 → 선례(FNR-safe 상향·검수 라우팅만) + 재학습. kNN/CP는 shadow로만 시험
핵심 방어죽음의 나선을 단일 플래그에 안 기대고 4곳 하드닝(교정 admission·deploy gate·누수가드·per-run 사인오프)

02 제약 — 없는 것 3가지

이 설계의 모든 결정은 이 세 제약에서 나온다. 제약을 바꿀 수 없다고 확정됨.

실데이터
0
실제 비밀문서 제공 불가. 합성·공개프록시만
빌드 검수
0
전문가 사람 검수·서명 불가. 자동 합의로 대역
반출(exfil)
0
고객사 데이터 밖으로 못 나감. 로컬 학습
⚠
제약이 결과 천장을 정한다. 아무리 좋은 방법도 "실데이터 한 줌"을 못 이긴다. 실데이터 50~100건이라도 합성 1,000건보다 평가 가치가 크지만, 그 경로가 닫혔음을 확인했다. 따라서 이 설계는 "좋은 모델 보증"이 아니라 "안전하게 깨지는 부트스트랩 + 운영 학습"을 목표로 한다.

03 전략 전환 — 검증후배포 → 안전배포+운영학습

배포 전에 모델이 좋은지 알 방법이 없다 → 목표를 바꾼다.

❌ 불가능✅ 채택
좋은 모델을 만들어 검증 후 배포안전하게 깨지는 부트스트랩 + 운영에서 빠르게 학습
합성 골든을 "평가 진실"로 사용합성=silver/gold_candidate(학습) · 평가 진실=운영 사람확정(locked)
정확도 KPI 자랑안전(미탐 0) + 검수 절약 + 오염 탐지 KPI

→ 무게중심이 빌드(기둥1)에서 운영 학습 루프로 옮겨간다. 데이터 흐름은 고객사→지재원이 아니라(반출 0), 운영 확정이 고객사 안에서 진짜 데이터를 만든다.

04 두 기둥

같은 문제(데이터·검수·반출 0)를 푸는 2단 전략.

기둥 1 — 지재원(빌드): 합성으로 모델 부트스트랩

합성 생성(Qwen) → 자동 합의 라벨 → 티어링 → 학습
  └ 등급별 상황 프롬프트       └ 룰 == Claude(주심판) + Qwen 섀도
    (등급명 leakage 차단)         = 사람 검수의 "대역"
설계 결정값 / 근거
생성 ↔ 심판 분리생성=Qwen(로컬) / 주심판=Claude / 섀도=Qwen — circularity(자기채점) 차단. 동일모델 생성+판정 시 품질검증 0
등급 구성고등급 과대표집 TS 20 / S1 30 / S2 30 / S3 20 — 자연분포(S3 다수)는 약점인 고등급 부족
학습/평가 분리~700 silver_train / ~250 합성 holdout(상대비교용, "일반화 아님" 명시)
과생성합의 게이트 탈락분 보정 위해 ~1,600 생성→순통과 1,000. 고등급 탈락률↑ → 더 생성. 파일럿 100건으로 통과율 먼저 측정
합의 게이트evaluate_consensus: 근거 span ∧ 룰==심판 ∧ self-consist≥0.67 ∧ ¬ts_downgrade ∧ ¬섀도불일치. conf 안 봄
티어 계약합성·무검수는 gold_candidate/silver까지만. locked_gold_eval(평가 진실)은 사람 서명 전용 — 구조적으로 합성 불가

기둥 2 — 고객사(운영): 관리자 확정을 선례로

관리자 등급 확정 → tb_corrections 적재
        ↓ 다음 유사 문서
유사 선례 검색 → "과거 이 문서는 S1로 확정됨" → FNR-safe 적용 (재학습 0)
⚠
선례 적용의 절대 제약 (안 지키면 위험). 임베딩 유사도 ≠ 등급(등급은 출처·관리수준에 좌우, 임베딩은 내용만 봄). 따라서 ① 선례가 더 높으면 상향 override / 충돌·유사면 검수 라우팅만, ② 자동 하향 override 절대 금지(임베딩 유사도로 무인 미탐 주입), ③ exact-match 재사용(이미 구현)에서 출발 → 고유사 kNN은 shadow mode로 검증 후에만 권한 부여, ④ 신뢰 보정만(사람 서명, 머신 제외) + 메타데이터 교차확인.

의미: 운영 관리자 확정 = 시스템이 처음 만나는 "진짜 사람 검증 데이터"이자, locked_gold_eval을 채울 유일한 경로. 기둥 1의 합성 맹점을 실전이 치료한다.

🔧
코드-설계 불일치 (수정 필요). 고객사는 분류기 재학습을 하지 않는다(비모수만)가 설계인데, 검증 결과 자동 재학습(분류기 가중치) 루프가 고객사 서버에서도 돈다 — enable_training=False가 HTTP 라우트만 막고 celery beat 루프는 안 막기 때문(버그). → 이 루프를 OFF해 설계(고객사=비모수)에 맞춰야 한다. 새 결정이 아니라 코드를 설계에 맞추는 수정(§10 0.5).

06 죽음의 나선 검증 (적대적 테스트)

오염 교정이 운영까지 도달하는 경로를 6단계로 추적 + Opus 스켑틱 공격.

#단계결과막는/뚫는 것
1오염 교정 기록(러버스탬프)🔴 통과교정 작성에 품질 게이트 없음
2학습셋 편입 (최약 고리)🔴 통과WHERE consumed_in_run IS NULL뿐 — 신뢰도·status·이중검수·사람여부 필터 0 (corrections_rebuild.py:122-127)
3누수 가드(merge)🟡 fail-openretrain 경로에서 holdout_paths 미전달(경고만) — 구현 시 확인 권장
4재학습 발화(≥10)🔴 통과30분 beat 자동 enqueue, 사람 없음 (tasks.py:427)
5deploy gate🔴 통과datasets/labeled/test.jsonl(정적·합성)에서 재고 locked_gold_eval 안 봄 → 실분포 오염에 맹목 (trainer.py:170)
6운영 활성화✅ 차단if decision.passed and auto: — auto=retrain_auto_activate=False(기본) → 등록만 (training_service.py:130-134)
7서빙✅ 도달불가활성 안 됨. auto_rollback도 기본 False
🔴
판정 — 오늘은 차단, 단 단일 플래그로. 기본 설정에서 죽음의 나선은 활성화 단계 한 곳에서만 막힌다(retrain_auto_activate=False). 1~5단계는 전부 무방비다. 운영자가 retrain_auto_activate=True 한 줄만 켜면 오염→운영이 그대로 도달한다(auto_rollback도 기본 False라 사후망도 없음). 진짜 약한 고리는 활성화 플래그가 아니라 2단계(교정→학습 편입에 품질 게이트 0)다. 플래그는 운 좋게 꺼진 다운스트림 안전망일 뿐, 구멍은 위에 뚫려 있다. 또한 검증 확정: 이 자동 재학습 루프는 enable_training=False인 고객사 서버에서도 돈다(beat 미게이트) — 즉 죽음의 나선은 고객사에서, 고객사 관리자의 러버스탬프로 일어날 수 있다. 설계상 고객사=비모수만이므로 이 루프를 OFF하면(§10 0.5) 고객사에선 위험 자체가 사라진다.

07 4대 하드닝 — 단일 플래그에 기대지 마라

정확한 코드 위치까지 확정된 수정 4건. 재학습 자동활성(retrain_auto_activate=True) 전에 반드시 박혀야 한다.

08 안전 방어선 (모델 밖)

이런 시스템은 보통 모델이 아니라 UX·프로세스에서 무너진다.

8.1 자동화 편향 3중 방어 (죽음의 나선 #1 방어)

러버스탬프는 랜덤 노이즈가 아니라 모델의 체계적 약점(S1 과소분류)을 그대로 승인 → 오염이 FNR 방향과 정렬(최악). UI 마찰만으론 부족:

  1. UI 마찰 — 저신뢰 건 승인 3초 지연 · 원문 하이라이트 대조 · 판단 근거 시각화로 능동 사고 유도
  2. reviewer_trust 가중(이미 코드 존재) — 확정을 무조건 진실로 안 받고 검수자 신뢰도로 가중. 자주 번복되는 확정은 골든 승급 제외
  3. 행동 텔레메트리 + 표본 재검수 — "2초 만에 99% 동의"=러버스탬프 시그니처 자동 플래그 + TS/S1 확정 무작위 표본 2차 확인

8.2 kill-gate — fatigue ∧ error-rate ∧ overturn (셋 다)

지표기준왜
TS/S1 미탐≥ 1건 → 즉시 중단 (절대 floor)가장 위험한 오류. fnr_underclass로 측정 가능
관리자 처리 부담≥ 일 처리능력 150%fatigue → 러버스탬프 나선 트리거

✅

8.3 보류·정정

  • Conformal Prediction 보류 — 합성 보정은 exchangeability 깨져 "95% 보장" 무효 + 합성은 쉬워서 집합이 과도하게 좁아져(과신) 정작 하드케이스에 기권 안 함. phase 1엔 빼고, 실라벨 N 쌓인 뒤 도입(그때도 휴리스틱 지표로만, "수학적 보장" 프레이밍 금지)
  • 룰은 "대체"가 아니라 "합집합" — FNR-safe override는 most-severe로 더하는 구조라 룰 비중↑가 recall을 깎지 않음. 진짜 위험은 룰·모델 둘 다 모르는 합동 침묵(joint silent miss) → "룰방어/모델적중/둘다놓침" 분리 모니터링

11 한계·전제 (정직)

이 설계가 할 수 있는 것과 없는 것.

  • 운영 정확도 보증 불가 — 합성·OOD 기준이라 실분포 정확도는 운영 후 재측정해야 확정. 모델 카드에 명시(계약 방어).
  • 합성 천장 — 고등급·영어·실분포는 합성으로 못 채움(실측). 합성 골든은 "출발선".
  • 운영 첫 교정이 첫 진실 신호 — 그 전까진 깜깜이. 안전망(게이트·표본감사·미탐 0 floor)은 협상 불가.
  • 콜드스타트 부담 — 초기엔 모델이 OOD라 오류·검수 많음. 보수적 게이트(검수 라우팅)가 그걸 안전하게 흡수.
  • 선례 일반화 한계 — kNN 선례는 유사 케이스만 패치, 새 유형 일반화는 재학습 영역.
  • 분류기는 합성 천장에 영구 고정(수용) — 무반출 + 무실데이터라 분류기 가중치가 실데이터로 개선될 경로가 없다. 고객사 로컬 재학습은 원래 설계에 없음(추론 전용). 분류기 갱신=지재원의 새 합성 재번들로만, 실세계 개선=고객사 비모수(선례·게이트·보정)로만. 이 천장은 설계의 수용된 귀결이며 열린 결정이 아니다.
ℹ
종합. 실데이터·검수·반출이 모두 0인 세계에서 — 합성 LLM합의 골든으로 부트스트랩하고, 보수적 안전망으로 미탐을 막은 채 운영하며, 관리자 확정으로 고객사 비모수(선례·게이트·보정) 개선을 쌓는 것이 가능한 최선이다. 분류기 가중치 자체는 합성 천장에 고정되고(실데이터 경로 없음·수용), 실세계 신호는 비모수 메모리에만 남는다. 한편 지재원의 (합성 기반) 재학습 경로는 오염으로 자기파괴(죽음의 나선)하지 않도록 §7의 4대 하드닝이 필요하고, 고객사에서는 그 재학습 루프 자체를 OFF해 위험을 제거한다(§10 0.5). 이 설계서의 모든 코드 주장은 제어흐름 추적 + 적대적 검증으로 확인됐다.
