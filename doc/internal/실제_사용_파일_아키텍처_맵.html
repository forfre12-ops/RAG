실제 사용 파일 아키텍처 맵

이 프로젝트에서 실제로 실행·사용되는 파일이 무엇이고 어떤 역할을 하는지, 그리고 배포 시 어떤 모델·DB를 어디에 설치해야 하는지를 경로·모듈 단위로 정리한다. 앱 코드는 전부 단일 패키지 poc/src/koipa/ 안에 있고, 실제 기동되는 것은 3개 프로세스뿐이다. 나머지 파이썬 파일은 이 3개를 구성하는 라이브러리·오프라인 도구·테스트다.

앱 코드 178 (src)

가장 중요한 한 가지

558개 파이썬 파일이 있지만 실제로 돌아가는 것은 API 서버 · Celery 워커 · Celery beat 3개 프로세스뿐이다. 이 3개가 로드하는 앱 코드는 poc/src/koipa/(178개)이고, poc/scripts/(151)는 손으로 돌리는 빌드·평가·릴리스 도구, poc/tests/(207)는 테스트다. 아래 표에는 각 파일에 🟢 LIVE(런타임 서빙 경로) · 🔵 BATCH(오프라인 빌드·평가 배선) · ⚪ DORMANT(미배선) 태그를 붙였다.

00 한눈에 — 실행되는 건 3개 프로세스

이 세 줄이 시스템 전체의 실행 표면이다. 나머지 파일은 이 셋을 구성하는 부품이다.

① API 서버    uvicorn koipa.api.app:app                          (포트 8000)
② Celery 워커  celery -A koipa.workers.celery_app worker
                 -Q classify,index,synthesis,learning,celery
③ Celery beat  celery -A koipa.workers.celery_app beat            (주기 잡)
① API
동기 요청 처리
분류·확정·설명·관리 엔드포인트. 실서빙 추론(M5)과 전처리(M2)를 직접 호출하는 핫패스. 진입점 api/app.py 하나(별도 main.py 없음).
② 워커
무거운 배치 잡
비동기 분류·합성·재학습(M4)·골든빌드·드리프트. 큐 5종 구독. 진입점 workers/celery_app.py.
③ beat
스케줄 트리거
active-learning(30분/일1회)·드리프트·auto-rollback·outbox·partitions 주기 잡. 단일 인스턴스.
