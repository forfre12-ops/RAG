#항목기준

4. 배포 실행

scp -i ~/.ssh/kipai_testserver poc_src.tar poc_src.tar.sha kopia@223.130.156.134:~/
ssh -i ~/.ssh/kipai_testserver kopia@223.130.156.134 \
  'cd ~/poc && DIRECT_SRC_TAR=$HOME/poc_src.tar bash ~/poc/scripts/deploy_kl_223.sh'
DIRECT_SRC_TAR 를 빼고 부르면 안 된다. 그러면 스크립트가 GitHub 원격 tip 을 받아 현재 판보다 뒤로 롤백된다. 이 환경은 push 가 막혀 있어 원격이 로컬보다 뒤에 있다.

스크립트가 자동으로 처리하는 것 — uv.lock 정합 · 외부 볼륨 이름 · .env 접두 · 워커 메모리 한도 · 학습 산출물 소유권 · 6개 이미지 태그 · 되돌림 태그 생성 · 기동 후 SHA 대조.

5. 스키마 마이그레이션 (별도 · 수동)

배포 스크립트는 alembic 을 돌리지 않는다. 소스 반영과 스키마 변경을 분리해 두었다.

docker exec koipa-jjw-api-1 alembic upgrade head   # -> a1b2c3d4e5f6

대상과 검증 결과는 「DB 대리키 표준화 전환계획」에 있다. 요지 — 정수 대리키 9개를 SERIAL 에서 표준 GENERATED ALWAYS AS IDENTITY 로 바꾼다. 223 실데이터에 트랜잭션으로 걸어 보고 롤백해 검증했다(tb_audit_log 38,502행 포함).

7. 롤백과 실행 기록

스크립트가 배포 전 이미지에 :rollback-YYYYMMDDHHMM 태그를 남긴다. 소스는 그 태그로 되돌리고, 스키마는 alembic downgrade -1 로 되돌린다. 순서는 스키마 먼저, 그다음 이미지다.
