2. 켜지 않은 기능과 이유

모두 만들어져 있고 켜지 않은 것입니다. 요건은 “~할 수 있어야 한다”이므로 기능을 갖춘 것으로 충족되며, 켜고 끄는 것은 운영 판단입니다.

기능현재켜지 않는 이유 — 한 줄
RAG 검색
④-②		꺼짐 요건이 “선택 옵션”으로 규정. 켜면 판정이 0.4초 → 1.4초가 되어 성능 요건(0.5초)을 넘습니다
불용어 제거
㉒-③		꺼짐 지우면 금액·수량이 함께 사라져 놓치는 문서가 생깁니다. 분류 모델은 조사·어미로 문맥을 읽어 단어를 지우면 손해입니다
Chunk 학습
④-③		꺼짐 한 문서의 조각이 학습과 평가에 갈라져 들어가 점수가 부풀려집니다

2-1. RAG — 켤 때 확인할 것

검색을 켜도 등급은 바뀌지 않습니다. 검색 결과는 참고 맥락으로만 쓰이고 판정에는 넘어가지 않습니다. 이 경계를 넘으면 모델이 매긴 옛 등급이 새 판정의 근거가 되는 순환 구조가 되므로 그대로 둡니다.

확인할 것내용
넣을 선례가
아직 없음		사람이 등급을 확정한 문서가 4건뿐(전부 테스트 계정)입니다. 검수가 쌓인 뒤에 그 확정분을 색인하면 됩니다. 현재 색인에 든 3,754문서는 검색 성능 측정용 시험 데이터이며 선례용이 아닙니다
검색 범위엔진 하나가 고객사 한 곳만 담당하는 구조라 범위 제한을 두지 않는 설계입니다(격리는 포털 담당). 화면 표시 용도로는 그대로 문제없습니다. 검색 결과를 상용 LLM 에 보내는 경우에만 출처 확인이 필요합니다 — 허용 범위 밖 문서가 섞이면 실행분 전체가 외부 전송 차단됩니다
유지 비용등급이 바뀌거나 문서가 늘면 색인을 다시 만들어야 합니다. CPU 서버에 임베딩 모델이 상주해야 합니다

3. 결정이 필요한 항목

#항목쟁점권고
1RAG 옵션 처리 GPU 보유 고객사에 한해 켤 수 있게 남길지, 전면 OFF 로 못박을지 옵션으로 남긴다. 요건이 선택 옵션으로 규정했으므로 제거하면 오히려 요건에서 멀어진다
2등급 추가 시 동작 정책 화면에서 새 등급을 만들 수 있다. 그런데 현행 모델은 학습된 4개 등급만 출력하므로 새 등급을 절대 내놓지 못한다. 지금은 “재학습 필요” 신호만 띄우고 그 다음 동작이 정해져 있지 않아, 모델이 옛 등급으로 답한 것을 그대로 확정해 버린다 재학습 전까지는 자동 확정을 막고 검수로 보낸다. 새 등급이 걸린 문서는 사람이 판단하게 한다
3판단요소 점수 테이블 문서별 판단 점수(비공지성·경제가치·관리수준 각 0~2점)를 저장하려고 만든 표가 한 줄도 없이 비어 있다. 점수는 계산해서 화면에 보여주고 저장은 하지 않는다. 감리가 DB 설계를 열면 빈 표가 보인다 표는 그대로 두고 설명만 준비한다. 요건은 “요소를 정의할 수 있어야”이지 “문서마다 점수를 저장하라”가 아니다. 감리 직전 스키마 변경은 위험 대비 이득이 없다
4검수 승인 → 학습 자동 호출 자동 호출이 없다. 승인분을 학습행으로 만드는 기능은 있고 명령(build_synth_training_set.py)으로 실행한다. 학습을 돌릴 때 이것이 자동으로 불리지는 않는다. 별개로 검증문서 후보를 학습행으로 바꾸는 코드는 존재하지 않는다(요건에도 없음) 붙일지 결정 필요. 함수·스크립트가 이미 있어 작업은 작다. 다만 현재 승인 건수가 0이라 붙여도 도는 것은 없다
5검수 화면 유사 선례 표시 참고 정보로 유용하나, 지금 켜면 보여줄 선례가 사람 확정 0건이라 모델의 옛 출력을 선례로 제시하게 되고 앵커링으로 사람 서명의 독립성이 깨진다 지금은 켜지 않는다. 켤 조건 셋 — ① 등급을 가린 채 본문만 먼저 보여준다 ② 사람이 확정한 선례만 후보로 쓴다 ③ 검수자가 자기 결정을 저장한 뒤에 이웃 등급을 공개한다
6LangChain 미사용 사유 기재 제출본에 미사용 사유 박스가 들어가 있다. 「안 쓰는 것을 나열하지 않는다」는 원칙과 충돌해 보인다 존치. 요건이 제품명을 지목한 유일한 항목이라, 설명을 빼면 “미구현”으로 읽힐 위험이 더 크다
7요소 어휘 두 벌 등급 계산은 신 3요건(S·V·M)으로 하는데, 키워드 404개 중 41개가 구 요소 LEAK_IMPACT(유출 시 영향도)를 가리킨다. 신 3요건에는 없는 요소라 설명 화면에서 어디에도 매칭되지 않는다 41개를 VALUE 로 재매핑하거나 구 요소를 비활성 처리. 동작에 지장은 없어 급하지 않음
