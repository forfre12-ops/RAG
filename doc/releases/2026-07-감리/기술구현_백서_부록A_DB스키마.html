DB 스키마

2026-06-29 운영 전제 업데이트: 실데이터 0 · 빌드 검수 0 · 반출 0 제약에서는 배포 전 정확도 검증을 주장하지 않는다. 합성/LLM 라벨은 학습 시드·상대비교·회귀 테스트용이며, locked_gold_eval은 사람 서명 전용이다. 현재 목표는 "검증된 분류기 배포"가 아니라 룰 우선 안전 부트스트랩 + 보수적 검수 라우팅 + 운영 관리자 확정에서 배우는 루프다. 이 문서의 기존 F1/FNR/PASS 수치는 합성·OOD·프록시 또는 메커니즘 검증으로만 해석한다.

현재 ORM 기준 19개 테이블과 Alembic SQL의 RAG 2테이블(tb_rag_vectors 임베딩 · tb_rag_aliases 무중단 재색인 alias)을 운영한다. tb_chunks·tb_llm_usage·tb_audit_log는 월별 RANGE PARTITION 부모 테이블이다. 채점은 3요건(S·V·M) 곱셈식(B안)으로 정합되어 있다.

본 부록은 현재 소스가 생성·매핑하는 Koipa 애플리케이션 테이블을 다룬다 — AI 코어 6모듈(M1 합성·M2 청킹·M3 라벨링·M4 학습·M5 추론·M6 보정), 등급체계, 문서/감사/비용/가이드 운영 테이블. 현 ORM에는 tb_documents, tb_audit_log, tb_llm_usage, tb_guides도 Koipa 모델로 포함된다. KL 원천 문서·EDMS·회원/권한·자가진단(tb_self_assessments)은 외부 시스템이며, 연동 키는 external_ref와 메타데이터로 다룬다.

tb_evaluation_factors평가 요건

정본 3요건 체계. 등급 = 비공지성(S) × 경제적 유용성(V) × 비밀관리성(M), 각 요건 0·1·2점의 곱셈식(B안, 2026-06-18 전환). 곱 매핑 8→TS · 4→S1 · 1·2→S2 · 0→S3. 곱셈식이라 weight 컬럼은 미사용(하위호환 1.0). 레거시 4요소는 is_active=FALSE로 보존(키워드 시드 태그 및 FK 정합 유지, migration c7d8e9f0a1b2). 정본/레거시 매핑은 LEGACY_FACTOR_ALIAS로 3요건에 폴딩(LEAK_IMPACT→VALUE).

컬럼타입NOT NULL설명
factor_idINTEGER PK AUTOINCREMENT●
factor_codeVARCHAR(30) UNIQUE●정본: SECRECY · VALUE · MANAGEMENT (is_active=TRUE) / 레거시(is_active=FALSE): NON_PUBLICITY · ECONOMIC_VALUE · MANAGEMENT_LEVEL · LEAK_IMPACT
factor_nameVARCHAR(100)●비공지성(S) / 경제적 유용성(V) / 비밀관리성(M)
weightNUMERIC(3,2)●미사용 (곱셈식 등급 = S×V×M, 가중치 가산 안 함). 하위호환 기본 1.0. weight 합계=1.0 트리거 제거됨
is_activeBOOLEAN●정본 3요건 TRUE · 레거시 4요소 FALSE
요건별 점수 기준(LLM 라벨러 정본 룰브릭) — S: 0=이미 공개·1=통상적 입수 곤란·2=보유자 통하지 않곤 모름 / V: 0=가치 없음·1=비용·노력 투입·2=상당한 비용·노력 / M: 0=공개·관리 안됨·1=임직원 일부 공유·2=승인된 자만. 한 요건이라도 0이면 곱=0 → S3.

벡터 검색 — PostgreSQL pgvector 통합

벡터 임베딩(KURE-v1 1024차원)은 Alembic 마이그레이션이 생성하는 tb_rag_vectors.embedding 컬럼에 저장하고 HNSW 인덱스로 검색한다. tb_chunks는 원문 청크·페이지·섹션 메타의 운영 원장이고, RAG 검색용 벡터/렉시컬 색인은 tb_rag_vectors가 담당한다. 한국어 렉시컬은 앱이 만든 bigram 토큰 tsvector를 ts_rank로 채점(코어 FTS)하고, pg_bigm GIN은 설치 시 후보생성 가속으로만 보완한다.

-- 확장 (1회)
CREATE EXTENSION IF NOT EXISTS vector;     -- 벡터 검색 (pgvector)
CREATE EXTENSION IF NOT EXISTS pg_bigm;    -- (선택) 한국어 bigram GIN 후보가속 — 랭킹은 코어 ts_rank

-- RAG 벡터 테이블 (KURE-v1 = 1024차원)
CREATE TABLE tb_rag_vectors (
  collection  TEXT NOT NULL,        -- 논리 네임스페이스(ES index 대체). PK 1번째
  id          TEXT NOT NULL,        -- 항목 고유 ID(컬렉션 내 유일, 보통 doc_id#chunk_idx). PK 2번째
  doc_id      TEXT,                 -- 원문 문서 식별자(느슨한 참조·FK 아님). 문서 단위 삭제·필터
  chunk_idx   INTEGER,              -- 문서 내 청크 순번(0-base). 원문 재구성·인접 청크 조회
  content     TEXT NOT NULL,        -- 청크 원문 텍스트. 결과 반환 + pg_bigm 후보생성 대상
  bigram_text TEXT,                 -- content의 bigram 토큰(앱이 채움). 한국어 ts_rank 채점 소스(조사·굴절에 강함)
  embedding   vector(1024),         -- dense 임베딩(KURE-v1/BGE-M3, 차원 고정·가변불가). HNSW 코사인 kNN 대상
  tsv         tsvector GENERATED ALWAYS AS (to_tsvector('simple', coalesce(bigram_text, ''))) STORED,  -- 어휘 인덱스원(bigram서 DB 자동파생). 어절 NL R@5 47%→bigram 87%
  payload     JSONB NOT NULL DEFAULT '{}'::jsonb,  -- 임의 메타데이터(heading_path·source·등급 등)
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),  -- 적재 시각(재색인·감사)
  PRIMARY KEY (collection, id)      -- 복합 PK — 같은 id 다른 컬렉션 공존(재색인 blue/green)
);

-- 의미 검색용 HNSW 인덱스 (코사인 거리)
CREATE INDEX idx_ragvec_embedding
  ON tb_rag_vectors USING hnsw (embedding vector_cosine_ops);

-- 한국어 렉시컬 랭커 — 앱이 만든 bigram 텍스트의 tsvector + ts_rank (코어 FTS)
CREATE INDEX idx_ragvec_tsv ON tb_rag_vectors USING gin (tsv);

-- (선택) 후보생성 가속 — pg_bigm GIN. 랭킹 아님(위 ts_rank).
CREATE INDEX idx_ragvec_content_bigm
  ON tb_rag_vectors USING gin (content gin_bigm_ops);

-- Blue/Green 무중단 재색인 alias
CREATE TABLE tb_rag_aliases (
  alias       TEXT PRIMARY KEY,     -- 논리 이름(예: uploads). 앱이 참조하는 안정적 이름
  collection  TEXT NOT NULL,        -- 실제 물리 collection(예: uploads_v3). 재색인 시 이 값만 교체
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now()  -- alias→collection 갱신 시각
);

-- 최근접 이웃 (상위 5건)
SELECT id, doc_id, content
FROM   tb_rag_vectors
WHERE  collection = :collection
ORDER  BY embedding <=> :q
LIMIT  5;

※ 골든셋 수천~수십만 건은 HNSW로 sub-100ms 응답이며 수백만 건까지 여유가 있다. 임베딩 컬럼은 고객사 agent의 Postgres+pgvector에 오프라인 골든 번들로 적재된다.
