합성 코퍼스와 locked 평가는
왜 나누나

2026-06-29 운영 전제 업데이트: 실데이터 0 · 빌드 검수 0 · 반출 0 제약에서는 배포 전 정확도 검증을 주장하지 않는다. 합성/LLM 라벨은 학습 시드·상대비교·회귀 테스트용이며, locked_gold_eval은 사람 서명 전용이다. 현재 목표는 "검증된 분류기 배포"가 아니라 룰 우선 안전 부트스트랩 + 보수적 검수 라우팅 + 운영 관리자 확정에서 배우는 루프다. 이 문서의 기존 F1/FNR/PASS 수치는 합성·OOD·프록시 또는 메커니즘 검증으로만 해석한다.

AI가 문서 등급을 배우려면 라벨이 필요하지만, 합성·LLM 라벨은 믿을 수 있는 평가 정답이 아닙니다. 이 문서는 ① 골든셋이 무엇인지, ② 어디서 모으고 어떤 모델로 만드는지, ③ 합성 산출물을 왜 학습셋과 상대비교 holdout으로만 쓰는지를, 파일의 실제 구성항목과 예시로 비전문가도 한 번에 이해하도록 풀어 씁니다.

한눈에 보기

골든셋 = "이 문서는 TS(특급기밀)다, 저건 S3(공개)다"라고 정답이 확정된 문서 모음. 이것을 둘로 나눕니다 — 학습셋(AI가 보고 배우는 연습문제)과 홀드아웃(절대 안 보여주고 시험만 보는 모의고사).

비유하면 — 합성 코퍼스는 연습문제입니다. 그 일부를 학생(AI)에게 풀게 하고, 나머지는 숨겨뒀다가 시험문제로 냅니다. 연습한 문제로 시험 보면 다 맞히는 게 당연하니까(=암기), 진짜 실력은 숨겨둔 문제로만 잴 수 있습니다.

01골든셋이란

합성 코퍼스 ≠ locked 평가 정답

골든셋(gold set)의 "gold(금)"은 정답의 순도가 높다는 뜻입니다. 즉 골든셋은 용도(학습용·시험용)로 정의되는 게 아니라 "정답이 얼마나 믿을 만한가"로 정의됩니다. 사람이 검수해 도장을 찍은, 신뢰할 수 있는 라벨 모음이죠.

그래서 골든셋은 학습셋도 홀드아웃도 그 자체는 아닙니다. 골든셋을 쪼개서 둘을 만듭니다 — 골든셋은 둘의 부모(공통 출처)입니다.

숨겨두고 채점만 (시험문제)

현재 classification_gold.jsonl 계열은 합성·공개·LLM 라벨이 섞인 프록시/후보 데이터이며, 등급 분포는 TS 55 S1 56 S2 89 S3 577 입니다(2026-07-22 판례-프록시 디오염 반영).

02수집 출처

골든셋은 어디서 모으나?

라벨의 신뢰도는 출처에서 옵니다. 우리는 한 곳이 아니라 법적 근거가 분명한 공개 출처와 AI·룰의 판정, 그리고 운영에서 쌓이는 관리자 확정 라벨를 층층이 쌓습니다. 출처마다 신뢰 등급(tier)이 다릅니다.

출처 (label_source)무엇건수신뢰 tier
public_definitive공개 확정 — 판례·공시·보도자료처럼 실제로 공표된 문서(공개 = S3 근거)50법적근거

학습시드 = LLM이 단독으로 단 라벨. 학습 재료로만 쓰고 채점엔 안 씁니다.  법적근거 = 판례·공시·국가핵심기술 등 법으로 뒷받침되는 라벨. 릴리스 바닥(floor)으로 씁니다.  평가정답 = 사람이 서명한 최고 신뢰 라벨. 오직 이것만 진짜 채점 정답입니다.

03제작 모델

어떤 모델로 라벨을 다나? (오픈소스 vs 상용 LLM)

라벨은 한 모델이 혼자 찍지 않습니다. 3단 합의로 만듭니다 — 규칙(룰) → LLM 판정 → 사람 검수. 틀린 라벨 하나가 정답지를 오염시키면 모델 전체가 잘못 배우기 때문에, 일부러 여러 눈을 거칩니다.

1단
룰 엔진
S×V×M 규칙으로 1차 등급
→
2단
LLM 판정자
한국어 등급 판정 (k회 합의)
→
3단
사람 검수
최종 서명 → 평가 정답 승급

등급 판정 공식 — S × V × M

LLM과 룰은 같은 기준으로 점수를 매깁니다. 세 요소를 0·1·2점으로 채점한 뒤 곱합니다.

요소뜻0점2점
S 비공지성얼마나 안 알려졌나이미 공개됨보유자 통하지 않곤 알 수 없음
V 경제적 유용성경제적 가치가치 없음상당한 비용·노력 투입
M 비밀관리성관리 수준공개·관리 안 됨승인된 자에 한해 공개

결과: 곱이 8 → TS · 4 → S1 · 1~2 → S2 · 0 → S3. 원칙은 "모호하면 한 단계 위"(미탐 금지).

LLM 판정자 — 오픈소스와 상용을 데이터 민감도로 갈라 씁니다

"어떤 모델을 쓰나"의 핵심은 보낼 데이터가 비밀이냐 아니냐입니다. 비밀을 외부 클라우드로 보내면 안 되니까요.

역할모델언제
주 판정자 (상용)Claude / GPT / Gemini 중 택일비민감(공개 준비 데이터)일 때만
주 판정자 (오픈소스)Qwen3-14B (온프렘 GPU)민감(실고객 비밀) → airgap 단독
섀도 교차검증Qwen3-14B (온프렘)상용이 주판정일 때 의심 탐지용
자가일관성위 LLM을 3~5회 반복표가 갈리면 추가 샘플(다수결)
데이터 거버넌스 — 비밀은 클라우드로 안 나갑니다

문서가 실고객 비밀(sensitive)이면 시스템이 자동으로 airgap 모드로 라우팅합니다: 온프렘 오픈소스 Qwen 단독으로 판정하고, 상용(공개 클라우드) 호출은 0건입니다. 상용 LLM은 공개 데이터 준비 단계에서만 보조로 쓰입니다. 운영 추론과 실비밀 라벨링은 폐쇄망 온프렘 GPU 전제입니다.

(참고) 운영 분류기 본체는 한국어 PLM kf-deberta-base 파인튜닝, 검색 임베더는 KURE-v1입니다. 즉 라벨을 만드는 LLM과 실제로 등급을 분류하는 분류기는 별개입니다.

04둘로 나누기

골든셋 → 학습셋 + 홀드아웃

정답지가 완성되면 둘로 가릅니다. 나누는 1순위 규칙은 "같은 내용은 양쪽에 걸치지 않게"(누출 차단)입니다.

  • 같은 텍스트는 같은 쪽으로 — 내용이 같은 문서(중복·재탕)는 한 덩어리로 묶어 한쪽에만. 양쪽에 걸리면 시험이 부정행위가 됩니다.
  • 등급 비율 유지 — TS·S1·S2·S3가 홀드아웃에도 골고루 들어가게 떼어냄(안 그러면 S1을 못 잼).
  • 한 번 정하면 고정 — 모델 버전을 비교하려면 시험지가 매번 같아야 함.
  • 평가정답(locked)은 학습 금지 — 사람이 서명한 채점 정답은 절대 학습에 넣지 않음(외운 걸 채점하는 부정 차단).
05학습셋 파일

학습셋 파일의 구성항목

학습셋은 AI가 보고 배우는 파일이라 꼭 필요한 것만 담습니다 — 본문(입력)과 정답 등급(목표). 군더더기 필드는 없습니다.

필드뜻역할예시
doc_id문서 고유 ID(내용 해시 기반)식별a1b2c3d4…
text본문입력 (X)"2027년 신제품 양산 원가표 …"
label정답 등급목표 (y)S1
source데이터 출처관리gold_real / rag_corpus / oss

실제 학습 파일 한 줄(예시·가상):

// labeled_p1_retrain_v4_clean/train.jsonl — 한 줄(예시)
{ "doc_id": "a1b2c3d4e5f6a7b8",
  "text": "2027년 신제품 양산 원가표 — 셀 단가, 수율 목표 …",
  "label": "S1",
  "source": "gold_real" }
학습셋의 특징

① 핵심만(text+label) 추림  ② 골든 문서는 ×3 반복해 오버샘플(귀한 데이터 학습 강화)  ③ 공개 학습데이터(oss·rag)와 섞음 → 그래서 학습셋은 골든셋보다 큽니다.

06홀드아웃 파일

홀드아웃 파일의 구성항목

홀드아웃은 채점 정답지입니다. 그래서 "왜 이 등급인지"까지 보존합니다 — 법적 근거, 등급 판단의 실제 근거 구절, 검수 메모, 검수자까지. 학습셋보다 훨씬 풍부합니다.

필드뜻예시
doc_id문서 고유 IDf9e8d7c6…
text본문(채점 입력)"○○ 공정 레시피 — 소성 온도 …"
label정답 등급(채점 기준)TS
label_source라벨 근거 종류nkt_designated
review_status검수 상태locked (잠금)
reviewer_id검수자(실계정)reviewer_kim
source / domain출처 / 도메인nkt / manufacturing
legal_reference법적 근거산업기술보호법 국가핵심기술 §9
evidence_spans등급 판단의 실제 근거 구절["소성 온도 …", "촉매 배합비 …"]
notes검수 메모"사람 확정 — 평가 정답"

실제 홀드아웃 파일 한 줄(예시·가상):

// holdout_eval.clean.jsonl — 한 줄(예시)
{ "doc_id": "f9e8d7c6b5a4f3e2",
  "text": "○○ 공정 레시피 — 소성 온도/촉매 배합비 …",
  "label": "TS",
  "label_source": "nkt_designated",
  "review_status": "locked",
  "reviewer_id": "reviewer_kim",
  "legal_reference": "산업기술보호법 국가핵심기술 §9",
  "evidence_spans": ["소성 온도 …", "촉매 배합비 …"],
  "notes": "사람 확정 — 평가 정답" }

학습셋 vs 홀드아웃 — 같은 점과 다른 점

항목학습셋홀드아웃
핵심 필드 (text·label)✅ 동일✅ 동일
부가 필드최소(추림)풍부(근거·검수·법적)
구성골든 일부 + 외부데이터 섞음정화된 정답만

분포증강·보강자연 분포 그대로

핵심: 모델이 보는 입출력 계약(text→label)은 같아야 채점이 가능합니다. 그 외 가공은 의도적으로 다릅니다 — 학습은 "잘 배우게" 보강하고, 홀드아웃은 "정직하게 재려고" 현실 그대로 둡니다.

07왜 둘로?

왜 학습셋만으론 안 되고 홀드아웃이 필요한가

가장 흔한 오해: "학습셋으로 채점하면 되지 않나?" · "새 문서는 학습셋과 비교해 분류하면 되지 않나?" — 둘 다 위험합니다. 예시로 봅니다.

예시 1 — 학습셋으로 채점하면 "외운 걸 채점"

학습셋에 "○○ 원가표" 문서가 있고 AI가 이걸 보고 배웠습니다. 이제 같은 "○○ 원가표"로 시험을 보면? AI는 답을 외웠으니 S1 정답. "정확도 99%!"처럼 보입니다. 하지만 이건 실력이 아니라 암기입니다. 운영에서 들어온 처음 보는 "△△ 원가표"(다르게 쓰인 문서)는 외운 게 없으니 틀립니다. → 숨겨둔 문제로 채점해야 진짜 실력이 보입니다.

예시 2 — "학습셋과 비교해 분류"는 외운 걸 베끼는 것 (이미 실측 실패)

새 문서를 학습셋에서 닮은 걸 찾아 그 등급을 베끼는 방식(검색·kNN)은, 새 문서가 글자가 닮았을 때만 맞습니다. 실측 결과 이 방식은 S1(영업비밀)을 9%만 잡았습니다(=사실상 무검출). 제약 완화 시 실문서는 모두 "처음 보는 문제"라 닮은 이웃이 없으면 무너지기 때문입니다. 반면 규칙을 배운 분류기는 처음 보는 표현도 추론합니다. → 자세한 수치는 검색 단독 vs 검색+분류기 비교 참고.

자(尺)의 비유

길이를 재는 자로 물건을 만들면 안 됩니다 — 그 자로 재면 항상 딱 맞으니까요(의미 없는 측정). 홀드아웃은 "재는 자" 전용이라 학습에 쓰는 순간 자격을 잃습니다. 그래서 학습셋과 홀드아웃을 반드시 분리하고, 텍스트 해시로 겹침이 0건인지 검증합니다.

08한계·요약

정직한 한계 + 한눈 요약

지금의 한계 (투명 공개)

① 사람 서명 평가정답(locked)은 0건입니다 — 현 제약에서는 비어 있는 것이 정상이며, 운영 관리자 확정 또는 제약 완화가 있어야 채워집니다. 그 전까지는 법적근거 라벨을 임시 평가 바닥으로만 씁니다(릴리스 차단용, 일반화 진실 아님).

② 현재 정화 홀드아웃은 holdout_eval 42건 · holdout_business 35건입니다. 원래 109건 중 67건이 학습 누출(같은 내용이 학습셋에 존재)이라 제거한 결과로, 그래서 숫자가 작아도 믿을 수 있습니다.

어떤 모델로 만드나?룰 → LLM 판정(비밀=오픈소스 Qwen / 공개=상용 택일) → 사람 검수 3단.
학습셋 파일 구성?doc_id · text · label · source — 최소(배움용).
홀드아웃 파일 구성?위 + legal_reference · evidence_spans · notes · reviewer_id — 풍부(채점용).
왜 둘로 나누나?학습셋으로 채점하면 외운 걸 채점(가짜 점수). 숨겨둔 홀드아웃으로만 진짜 실력 측정.
