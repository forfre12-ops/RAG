데이터 거버넌스 계획

2026-06-29 운영 전제 업데이트: 실데이터 0 · 빌드 검수 0 · 반출 0 제약에서는 배포 전 정확도 검증을 주장하지 않는다. 합성/LLM 라벨은 학습 시드·상대비교·회귀 테스트용이며, locked_gold_eval은 사람 서명 전용이다. 현재 목표는 "검증된 분류기 배포"가 아니라 룰 우선 안전 부트스트랩 + 보수적 검수 라우팅 + 운영 관리자 확정에서 배우는 루프다. 이 문서의 기존 F1/FNR/PASS 수치는 합성·OOD·프록시 또는 메커니즘 검증으로만 해석한다.

KOIPA 영업비밀관리시스템의 데이터 자산·라벨 품질·재현성 관리 계획 — 합성 코퍼스 계층, 라벨 출처와 품질 현황, locked 평가 진실의 부재를 전제로 한 안전 부트스트랩, 운영 관리자 확정 루프를 다룬다. 목표는 배포 전 정확도 보증이 아니라 오염을 막고 운영에서 배울 수 있는 토대를 만드는 것이다.

핵심 메시지

현재 정확도 지표는 대부분 합성·LLM·공개 프록시 라벨에 기반한다(라벨 순환성). 따라서 본개발의 1순위는 이를 평가 진실로 포장하지 않고, 운영 관리자 확정이 들어오는 경로와 품질 게이트를 깨끗하게 만드는 것이다.

01개요 · 원칙

데이터 거버넌스 원칙

  • 출처 추적 — 모든 라벨은 출처(합성·LLM판정·인간검증)를 기록한다.
  • 학습/평가 분리 — 평가 정답지는 학습에 쓰지 않으며, 가능한 한 독립 출처로 구성한다.
  • 재현성 — 데이터셋·모델은 버전으로 고정해 결과를 재현한다.

03라벨 출처 · 품질 현황

현재 라벨 구성과 측정 한계

현 학습·평가 라벨은 대부분 합성 데이터와 LLM 판정으로 만들어졌고, 사람이 직접 검증한 라벨은 매우 적다. 그 결과 3-tier 평가에서 데이터 출처에 따라 정확도가 크게 갈린다.

평가셋 종류F1(예시)해석

04라벨 순환성 · 골든셋 구축 (P0)

왜 locked 부재를 정직하게 관리해야 하는가

라벨 순환성 — 학습 라벨과 평가 라벨이 모두 모델이 모방할 동일한 룰 + LLM에서 파생되면, 모델과 정답지가 같은 맹점을 공유해 "끼리끼리 채점"이 된다. 합성 F1=1.0과 실측 0.37의 격차가 이 순환성의 증거다. 게다가 모든 배포·롤백 임계값이 이 미검증 라벨 기준이므로, 토대가 흔들린다.

본개발 골든셋 구축 계획 (P0)

① 영업비밀 도메인 전문가가 직접 라벨링 500건 이상(희소한 TS·S1 경계 사례 가중) ② 학습에 쓰인 룰·LLM과 독립된 holdout으로 구성 ③ 이 골든셋 위에서 모든 품질 게이트(배포·롤백 임계) 재보정 ④ 2인 검토·검수자 신뢰도 추적으로 라벨 품질 보증. 이것이 없으면 다른 모든 품질 지표가 그림자 측정이다.

05합성 부트스트랩 → 운영 확정 루프

운영에서 배우는 검증 루프

프로토타입 수치는 타당성 확인·모델 선정용이다. 실제 운영 정확도는 운영 관리자 확정 라벨이 충분히 쌓인 뒤에야 확인한다. 현 제약에서는 분류기 가중치가 실데이터로 개선될 경로가 없으므로, 고객사에서는 exact-match 선례·상향 override·검수 라우팅 같은 비모수 메모리부터 안전하게 쌓는다.

06재현성 · 버전 관리

버전 고정

  • 데이터셋 버전 — 골든셋·학습셋을 버전으로 고정하고 변경 이력을 관리.
  • 모델 버전 — 활성 분류기 버전(v-dd3abab9, v4_clean 정제본 · .env 배포 포인터)을 tb_model_versions로 추적, 학습 설정·지표를 MLflow에 기록. (step3/v-f9b5cedb는 정제 전 비교 baseline)
  • 인코딩 정합 — 일부 gold 파일의 source 필드 인코딩(모지바케)을 점검·정정.
07이번 차수 적용 거버넌스 통제

이번 차수 적용된 거버넌스 강화

골든셋·재현성 토대 위에, 데이터 보존·평가 무결성·라벨 품질을 코드/스키마 수준에서 강제하는 통제를 이번 차수에 반영했다. 정책 수치(보존기간·신뢰도 임계·검토자 자격)는 발주처 협의 사항으로 두고, 메커니즘만 선반영한다.

통제적용 내용거버넌스 효과
논리 삭제 · 보존정책
적용		 tb_documents.deleted_at 도입 — 문서 삭제 시 물리 삭제 대신 삭제 시각을 기록(논리 삭제). 청크·감사 행은 보존하고, 일반 조회는 활성행(deleted_at IS NULL)만 노출한다. 감사·복구 경로만 include_deleted로 명시 opt-in. 삭제 이력·증빙을 잃지 않으면서 운영 화면에서는 삭제 문서를 숨긴다. 기본값은 NULL이라 기존 데이터·동작 비파괴. 보존기간 만료 후 물리 회수(purge)는 별도 운영 잡이 담당(본 차수 범위 밖).
평가 데이터 누수 차단
적용		 보정(corrections) 기반 학습셋 재구축 시, holdout(val/test)의 doc_id 및 정규화 텍스트와 교집합인 보정 문서를 train 추가에서 강제 제외(enforce). 같은 문서가 다른 공백·대소문자로 적혀도 동일 본문으로 잡아 막고, 제외 건수를 로깅한다. 등급별 상한(cap)은 opt-in으로 제공. “파일 불변”만으로는 같은 doc_id가 학습·평가 양쪽에 존재할 수 있어 누수가 가능했던 경로를 차단. 보정이 특정 등급에 몰릴 때의 분포 왜곡도 cap으로 완화. 배포·롤백 게이트가 누출 없는 holdout에서 측정되도록 보장한다.
검수자 신뢰도 거버넌스
적용		 검수자 신뢰도를 본인 최신보정 자동동의(self-reference) 대신 동료 합의(peer corroboration) 기준으로 산정 — 분류의 최종 등급을 본인 외 검수자도 선택한 표본만 신뢰도 분모로 인정. 이 점수는 고등급 변경 2인검토 정족수 게이트의 신뢰도 입력으로 전파된다. “마지막에 손댄” 검수자의 신뢰도가 무조건 오르던 recency 편향·게이밍을 제거. 신뢰도 임계(high_grade_review_min_reliability)와 검토자 자격은 발주처 협의 사항이며 기본값은 동작 보존(임계 0=비활성)으로 둔다.
보정 멱등성
적용		 tb_corrections에 (classification_id, corrected_level_id, corrected_by) UNIQUE 제약 추가 — 같은 분류·등급·검수자 조합의 중복 보정 행을 DB 수준에서 차단(최종 방어선). 보정 경로의 동시성(race)으로 중복 행이 생겨 능동학습 큐·재학습 임계가 같은 라벨로 중복 가중·오염되는 것을 방지한다.
자동확정 안전 게이트
적용		 자동확정·검수 라우팅을 confidence 임계(기본 0.7) 단독이 아니라 다단 게이트로 결정. confidence는 분류기가 학습한 신뢰도가 아니라 softmax 파생값이라 OOD에서 과신하고 정답/오답 판별력이 낮다(골든500 AUROC 0.58). 현재 소스 기준 ① 희소근거 게이트(rule_fallback_min_evidence=0.9)는 룰-폴백 경로 기본 ON으로 단일 약한 키워드만으로 conf=1.0이 되는 자동확정을 차단한다. ② 합의 게이트(agreement_gate_enabled)는 base 기본 OFF(운영 프로파일 별도)이며, 자동확정은 예측이 공개등급(S3)이거나 룰등급==모델등급일 때만 허용하고 그 외 불일치는 사람 검수로 보낸다. confidence 과신으로 약한 근거가 자동확정되던 경로를 막는다. 측정효과(합성 골든셋·OOD 기준): 희소근거 게이트로 golden100 무성 TS 미탐 5→0, 합의 게이트로 자동확정 정밀도 63→81%·고등급 TS/S1 미탐 46→8. TS/S1 자동확정분은 표본감사한다. 운영 human_review/locked 확정 전에는 운영 확정 수치가 아니다.
보정 환류 · 재학습 경계

위 보정(corrections) 기반 재학습은 학습 사이트(지재원)의 활동이다. 고객사는 추론 전용이라 자체 학습하지 않으며, 고객사 검수교정을 지재원으로 반출할지는 미확정 결정이다(확인 5 A/B/C — 기본 권고: 문서 무반출·집계 진단만). 또한 모델은 상시 재학습되지 않는다 — 하드 요건은 제약 완화 시 별도 학습(제약 완화 시 실문서 반입)이며, 이후 일상 적응은 룰·키워드·임계·보정·LLM 2차·사람 게이트(비-모델 레버)가 담당하고, 모델 재학습은 드리프트·이벤트 트리거 시 단발로 수행한다.

정책 경계

위 통제는 메커니즘을 코드·스키마에 반영한 것이며, 기본값은 기존 동작을 보존한다. 보존기간·신뢰도 임계·검토자 자격 등 운영 정책 수치는 발주처 협의로 확정한다.
