# 제출 동결본(release) 목록

동결본은 **덮어쓰지 않는다**(`build_supervision_bundle.py`가 동일 `release_id` 재생성을 거부한다).
정본(`doc/result/open/`)이 갱신되면 **새 `release_id`로 재동결**하고, 이전 동결본은 이력으로 남긴다.

발송 시 **아래 표의 '현행'만** 사용한다. 이전 동결본은 감사 추적용이며 발송 대상이 아니다.

| release_id | 상태 | source_commit | 비고 |
|---|---|---|---|
| `2026-08-사전진단-r2` | **현행 — 발송 대상** | `0af6e75` | 정식 34종 · 참고 8 · 사업관리보고 4 · 검증증적 2 |
| `2026-08-사전진단` | 대체됨(superseded) | `9223f2c` | ⚠ **발송 금지** — OCR 바이너리 번들 동봉 서술 등 정합 오류 6건(DEF-2026-34~39) 미반영 |
| `2026-07-감리` | 이력 | — | 2026-07 감리 대응 동결본 |

## 무결성 확인

```bash
python scripts/build_supervision_bundle.py --check 2026-08-사전진단-r2
```

`INTEGRITY.sha256`은 번들 **내부** 파일 해시만 검증한다. 정본 대비 신선도(stale 여부)는 별도로
확인해야 한다 — 정본을 고친 뒤 재동결하지 않으면 `--check`는 통과하면서 내용은 낡아 있을 수 있다.
