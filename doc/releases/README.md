## 발송 전 확인 — 두 축을 모두 본다

내용이 정합해도 열람 환경에서 깨지면 소용없다. 실제로 그런 결함이 두 번 나왔으므로
**내용 축**과 **전달 축**을 따로 확인한다.

```bash
# ① 무결성 — 번들 내부 파일 해시 · 문서 ID · 소스 커밋
python scripts/build_supervision_bundle.py --check 2026-08-사전진단-r5

# ② 전달 — 외부 리소스 · JS-off 판독 · 납품본과 동명인 미하드닝 사본
python scripts/harden_bundle_offline.py --check

# ③ KL 제출묶음 — 인용 문서 누락 · 깨진 링크 · 고아 · 전달 결함(②를 호출)
python scripts/sync_kl_bundle.py --check
```

### 검사가 못 보는 것

- `INTEGRITY.sha256`은 번들 **내부** 해시만 본다. **정본 대비 신선도는 안 본다** — 정본을
  고친 뒤 재동결하지 않으면 `--check`는 통과하면서 내용은 낡아 있다(실제로 그렇게 8종이 낡았다).
  정본을 고쳤으면 반드시 새 `release_id`로 재동결한다.
- 동결본(`releases/`·`archive/`)은 하드닝 대상이 아니다. "그때 보낸 것이 그것"이라는 기록이므로
  소급 수정하지 않는다. 결함이 있으면 고치는 게 아니라 위 표에 **발송 금지**로 적는다.
