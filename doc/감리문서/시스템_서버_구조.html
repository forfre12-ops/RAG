본 문서는 시스템의 배포 형태와 서버 구성을 기술한다. 값의 출처를 실측과 선언으로 구분해 표기했다. 실측은 서버에서 직접 확인한 값이고, 선언은 발주처 사양서 또는 설계 문서가 정한 값이다.

1. 배포 형태

배포 모드는 환경변수 KOIPA_DEPLOY_PROFILE 로 전환한다. 프로파일이 안전 게이트, 기능 노출 범위, 저장소 백엔드의 기본값을 결정한다.

프로파일용도학습 기능특징
lite-noapi로컬 개발 · 기본값없음외부 의존 없이 기동한다(해시 임베딩, 메모리 내 벡터 저장)
lite-cloud오픈망 파일럿없음관계형 DB 와 로컬 파일시스템 저장
onprem-local고객사 폐쇄망 운영없음 (야간 증분 재학습은 별도 설정)안전 게이트 적용을 강제한다. 원본 저장 시 암호화가 필수이며, 게이트가 비활성이면 기동을 차단한다
full-train지재원 학습 노드 · 시험 서버있음학습·합성 라우터가 추가로 노출된다. 안전 게이트 설정은 onprem-local 과 같다

시험 서버에 GPU 가 있으나 배포 이미지에서는 인식되지 않는다. 이미지에 설치된 torch 가 CPU 빌드이기 때문이다(TORCH_INDEX 가 CPU 인덱스를 가리킨다). 운영 추론을 CPU 전용으로 하는 설계와 일치하며, GPU 성능 측정이 필요한 경우 CUDA 인덱스로 별도 이미지를 빌드한다. 가동 컨테이너 목록의 MinIO 는 시험 구성에서만 사용하며 폐쇄망 구성에는 포함하지 않는다(§4).

4. 폐쇄망 구성

항목구성
이미지 공급빌드 컨텍스트 없이 docker load 로 복원한 이미지 태그를 직접 참조한다. 소스와 인터넷 연결이 필요 없다
객체 저장소객체 저장소를 사용하지 않는다. 로컬 파일시스템에 저장하며 원본은 AES-256-GCM 으로 암호화한다
검색 엔진두지 않는다. 유사문서 조회를 2026-09-05 미채택으로 걷어 벡터 검색 자체가 없다
전송 보안nginx-mtls 상호 TLS
LLM기본 미사용. 등급 결정 경로는 LLM 없이 동작한다
안전 게이트적용을 강제하며, 게이트가 비활성이면 기동하지 않는다

5. 저장 계층

대상저장소비고
구조화 데이터PostgreSQL테이블 19 개이며 상세는 테이블_정의서 에 있다. 납품 정본(MariaDB)은 파티션을 두지 않는다 — 시간축 인덱스와 보존기간 삭제로 대신한다. 현행 시험서버(PostgreSQL)에는 옛 마이그레이션이 만든 월별 파티션이 남아 있다(실측: tb_audit_log·tb_chunks·tb_llm_usage 각 15개)
임베딩KURE-v1 (CPU)룰 시드 유사도·학습 분포 감시에 쓴다. 저장하지 않는다
문서 원본 · 정규화 텍스트로컬 파일시스템DB 에는 접근 경로만 저장한다. 운영 프로파일에서는 저장 시 암호화가 필수다
작업 큐Redis배치 분류·학습 작업의 큐와 멱등 키 저장에 사용한다
모델 아티팩트파일시스템 볼륨학습 노드는 MLflow 로 실행을 추적한다

고객사 노드에서는 야간 증분 재학습만 별도 설정으로 동작하며, 재학습 결과는 후보 등록까지만 수행한다. 서빙 모델로의 자동 전환은 하지 않는다.

7. 운영 호스트 운영체제

운영 서버는 Rocky Linux 로 설치한다(2026-08-26 발주처 통보). 시험 서버(Ubuntu 22.04.3)와 다르므로 구분해 기술한다.

판단근거
배포판 종속 없음애플리케이션은 전부 컨테이너에서 동작하고 이미지 내부는 Debian 계열(python:3.11-slim)이다. 호스트가 바뀌어도 컨테이너 내부는 동일하다
패키지 관리자 비의존install.sh 는 docker load 만 수행한다. apt·dnf 를 호출하지 않는다
호스트 런타임 불요파이썬을 포함한 의존성은 이미지에 포함되어 있다. 호스트에 파이썬이 없어도 된다

7-1. RHEL 계열에서 달라지는 것

항목무엇이 다른가적용한 조치
SELinux기본 enforcing. 라벨 없는 bind mount 는 컨테이너가 읽지 못해 모델 적재가 실패한다 폐쇄망 compose 의 bind mount 3 곳(../models × 2, mtls 설정·인증서)에 :z 공유 라벨을 적용했다. SELinux 가 없는 호스트에서는 무시되므로 양쪽 모두 안전하다
컨테이너 런타임RHEL 계열 기본은 podman 이다 설치·기동 스크립트를 런타임 중립으로 바꿨다. docker 를 우선 찾고 없으면 podman 으로 진행하며, compose 는 compose 하위명령 → podman-compose → docker-compose 순으로 판별한다. 어느 쪽이 설치되어 있든 동작한다
firewalld기본 활성. API 포트와 컨테이너 간 통신 규칙이 필요하다 사전 점검 스크립트가 활성 여부와 포트 점유를 확인하고 개방 명령을 안내한다
uid · gid운영 이미지는 비-root(uid 1000)로 동작한다. 호스트 계정 uid 가 다르면 호스트가 만든 디렉터리를 컨테이너가 쓰지 못한다 사전 점검 스크립트가 설치 사용자 uid 를 컨테이너 uid 와 대조한다

7-2. 설치 전 점검

설치는 발주처가 수행하므로, 현장에서 처음 만나는 실패를 줄이기 위해 읽기 전용 점검 스크립트를 번들에 동봉한다.

bash preflight_host.sh # 아무것도 설치·변경하지 않는다 1 운영체제 2 컨테이너 런타임 3 SELinux 4 방화벽 · 포트 5 사용자 uid · gid 6 cgroup 7 자원(CPU · 메모리 · 디스크) 8 필수 명령 9 시간 동기 종료 코드 0 = 진행 가능 · 1 = 차단 항목 있음

스크립트 poc/scripts/preflight_host.sh · 절차서 docs/INSTALL.md §0-1

미검증 고지. 본 구성은 Rocky Linux 에서 설치 시험을 수행한 이력이 없다. 위 조치는 코드·구성 검토와 RHEL 계열의 알려진 동작에 근거한 것이며, 실제 설치 전에 동일 버전의 Rocky 에서 리허설을 한 번 수행할 것을 권한다. 저장소 전체를 검색한 결과 selinux·podman·dnf 를 다루는 코드는 본 조치 이전까지 한 줄도 없었다.

8. 미확인 항목

항목상태
운영 서버 하드웨어 사양설계 문서가 발주처 사양 선언값을 인용한 것으로 실측값이 아니다. 운영 환경이 확정되면 실측값으로 대체해야 한다
운영 서버 운영체제운영 서버는 Rocky Linux 로 확정되었다(§7). 본 문서 §3 의 Ubuntu 22.04.3 은 시험 서버 실측값이다. 다만 Rocky 버전과 컨테이너 런타임 종류는 아직 확인하지 않았다
이중화고가용성 구성은 하지 않으며 복구 목표 시간(RTO)을 정한 재해복구 절차로 대응한다. 상세 절차는 운영_런북 에 있다
