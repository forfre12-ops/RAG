본 명세의 대상은 AI 엔진이 제공하는 HTTP API 전체이며 경로 접두는 모두 /api/v1 이다. 정본은 구동 중인 서버가 반환하는 /api/v1/openapi.json 이고, 본 문서는 그 스펙에서 생성했다. 제안요청서 요건에 해당하지 않는 부가 기능(RAG 질의응답)은 본 명세의 범위에서 제외한다.

1. 인증

모드자격 전달설명
api_key (기본)X-API-Key 요청 헤더단일 공유 자격을 사용한다. 호출자 역할은 서버 설정으로 고정되며 요청 헤더로 역할을 상향할 수 없다
jwtAuthorization: Bearer 또는 동일 오리진 HttpOnly 쿠키RS256 서명을 검증한다. 토큰의 주체(sub)가 감사 로그의 행위자로 기록된다
both둘 다 허용전환기 전용

인증 주체는 tb_audit_log 에 기록된다. 인증 정보가 없으면 X-Actor-Id 헤더 값을 대신 사용하는데, 이 값은 호출자가 스스로 적은 것이므로 서명·확정 경로에서는 허용하지 않는다.

2. 공통 규약

항목규약
오류 계약오류는 HTTP 상태 코드로 구분한다. 별도의 애플리케이션 오류 코드 체계는 두지 않았다. 소스 전체에서 code 필드를 반환하는 응답은 KOIPA_BODY_TOO_LARGE(413)와 KOIPA_RATE_LIMIT(429) 둘뿐이므로, 연동 시스템은 상태 코드를 기준으로 분기해야 한다
본문 형식요청·응답 모두 application/json. 파일 업로드는 multipart/form-data
멱등성요청에 Idempotency-Key 헤더가 있는 변경 요청(POST·PUT·PATCH·DELETE)에 한해 중복 실행을 차단하고 최초 응답을 재현한다. 헤더가 없으면 적용되지 않으며, 저장소 장애 시에도 요청은 정상 처리된다
요청 크기상한 초과 시 413 + KOIPA_BODY_TOO_LARGE
속도 제한초과 시 429 + KOIPA_RATE_LIMIT
비동기장시간 작업(분류 배치, 골든셋 생성, 학습)은 202 와 작업 식별자를 반환하고 별도 조회 경로에서 상태를 확인한다

5. 연동 시 유의

항목내용
등급 결과의 두 축응답은 등급과 상태값을 함께 반환한다. 상태값이 needs_review 이면 사람 검수 대기이며 자동확정이 아니다. 연동 시스템은 등급만으로 확정 처리해서는 안 된다
“판단 불가”는 없다분류는 항상 등급을 산출한다. 불확실성은 상태값과 신뢰도로 표현한다
예측 등급과 확정 등급GET /classify/{doc_id} 의 label 은 모델 예측이며 사람이 확정해도 바뀌지 않는다(감사 증적 보존). 사람이 확정한 등급은 같은 응답의 confirmed_label · confirmed_by · confirmed_at 로 내려간다. 확정 전에는 세 필드가 null 이다
메타데이터출처·보안표시·접근범위 3 개 필드를 함께 전송하면 등급 보정과 검수 라우팅에 사용한다. 상세 규약은 KL연동_인터페이스_규약서_ICD 에 있다
스펙 동기화본 문서는 스펙에서 생성한 것이므로, 코드 변경 시 /api/v1/openapi.json 을 다시 받아 갱신한다
