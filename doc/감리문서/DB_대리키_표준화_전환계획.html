1. 왜 바꾸는가

SERIAL 은 표준 SQL 이 아니다. PostgreSQL 10 부터 표준은 GENERATED ... AS IDENTITY 이고 SERIAL 은 남겨둔 옛 표기다. 표기 문제로 그치지 않고 동작이 다르다.

항목SERIAL (현행)IDENTITY ALWAYS (전환 후)
임의 값 삽입 INSERT INTO t (id) VALUES (999) 를 막지 못한다. 시퀀스는 그대로 1 부터 올라가다 999 에 부딪혀 중복키로 실패한다. 언제 터질지가 적재량에 달려 있어 운영 중에 드러난다 그 INSERT 자체를 거부한다
표준 여부PostgreSQL 고유 표기. 표준 SQL 아님SQL 표준
권한 관리시퀀스에 별도 USAGE 권한이 필요해 표와 갈라진다 칼럼에 속하므로 표 권한만 보면 된다

3. 이미 마친 검증

계획만 세운 것이 아니라 시험서버 실데이터에 걸어 보고 되돌렸다(2026-08-29 · PostgreSQL 16.14). DDL 이 트랜잭션 안에서 동작하므로 커밋하지 않으면 흔적이 남지 않는다. 롤백 여부는 새 연결로 재확인했다.

3-1. 파티션 표에 IDENTITY 가 되는가

대상 9개 중 둘이 월별 파티션이라 추측하지 않고 먼저 확인했다.

1) 파티션 부모에 IDENTITY 생성 : OK
2) 자식 파티션 생성          : OK
3) 자동 채번 INSERT          : OK
4) 명시 id INSERT            : 거부
5) SERIAL -> IDENTITY 전환    : OK

3-2. 실데이터 전환 (트랜잭션 적용 후 롤백)

표                          칼럼            전 -> 후      행수
tb_classification_levels   level_id       SERIAL -> a   4행 · 다음 id 5
tb_evaluation_factors      factor_id      SERIAL -> a   7행 · 다음 id 8
tb_level_keywords          keyword_id     SERIAL -> a   0행 · 다음 id 1
tb_classification_evidence evidence_id    SERIAL -> a   14행 · 다음 id 15
tb_corrections             correction_id  SERIAL -> a   12행 · 다음 id 14
tb_llm_usage               usage_id       SERIAL -> a   214행 · 다음 id 215
tb_audit_log               audit_id       SERIAL -> a   38,502행 · 다음 id 38,503
tb_training_datasets       id             SERIAL -> a   0행 · 다음 id 1
tb_guides                  id             SERIAL -> a   0행 · 다음 id 1

전환 후 INSERT 자동채번 : OK · audit_id = 38503
명시 id INSERT          : 거부 -> ProgrammingError
롤백 후 재확인          : identity='' (원상)

a = always. pg_attribute.attidentity 값이다.

시퀀스 현재값 이관을 확인한 것이 핵심이다. 전환 절차의 마지막 단계 (ALTER ... RESTART WITH max+1)를 빼먹으면 새 시퀀스가 1 부터 시작해 기존 행과 중복키로 충돌한다. 위 표의 "다음 id" 가 그 확인이다.

6. 영향 범위

이 변경은 API 계약과 업무 데이터의 의미를 바꾸지 않는다. 칼럼 타입 · 값 · 외래키 관계가 모두 그대로이고, 바뀌는 것은 값을 누가 어떻게 채우느냐뿐이다.

영역영향
API 응답 필드없음. 대상 9개는 외부로 나가지 않는 내부 키다
외래키 관계없음. 타입 · 값 불변
기존 데이터없음. 행을 건드리지 않는다
애플리케이션 코드 없음. 이 9개 칼럼에 값을 직접 넣는 코드가 없다 — 서비스의 ORM 생성자는 외래키만 채우고 씨딩 INSERT 도 칼럼 목록에서 빠져 있다. 그래서 BY DEFAULT 가 아니라 ALWAYS 를 선택했다
