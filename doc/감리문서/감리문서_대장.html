감리 산출물은 어느 요구사항이 어떤 문서를 요구했고 그 문서가 현재 어디에 있는지로 관리한다. 아래 표의 RFP 근거 열이 요구사항과의 연결이고, 상태 열은 현재 제출 가능 여부를 나타낸다. 상태는 보유, 보완(문서는 있으나 독립 산출물이 아니거나 감리 트랙 밖에 있음), 부재 세 가지다.

4. 이 폴더의 문서

doc/감리문서/ 를 작업 정본으로 둔다. 신규 문서와 정비 대상 문서를 이 폴더에서 작성하고, 기존 문서는 내용을 수정할 때 함께 이관한다. 이관이 완료되면 docs_registry.yaml 의 active_public_root 를 이 폴더로 변경한다.

5. 우선 작성 대상 6 종의 처리 결과

요청 문서상태지금 무엇이 문제인가처리 결과
API 정의서보완백서 부록B(내부 API)와 ICD(KL 연동)로 갈려 있고, 둘 다 독립 산출물이 아니다완료. API_정의서.html 에 엔드포인트 64 건을 분류별 표로 정리하고 인증 3 개 모드, 오류 구분 방식, 프로파일별 노출 차이를 수록했다. ICD 는 대외 연동 규약으로 분리해 유지한다
