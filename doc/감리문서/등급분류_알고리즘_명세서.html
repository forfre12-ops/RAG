2. 정본 매핑 — 곱셈식과 v2.2 보정

발주처 정본 가이드(11~12p)의 곱셈 매핑을 코드화한 함수가 grade_from_svm(s, v, m) 이다.

이 매핑은 정본 기준이며, 서빙에서 등급을 정하는 판정자가 아니다. 서빙 등급은 §3·§4 의 키워드 등급이 정하고, S·V·M 레벨은 그 등급에서 파생되어 화면·API 로 나가는 요소 표시값을 등급에 정합시킨다. 곱셈 매핑은 그 위에서 상향 방향의 교차 확인으로만 작동한다 — 평가셋 4 종 993 건에서 곱셈 단계가 최종 등급을 바꾼 사례는 0 건이다(poc/scripts/audit_rule_formula.py). business35 를 더한 5 종 1,028 건으로 넓혀도 같다(audit_rule_alternatives.py).

조건곱 (S×V×M)등급근거
s==2 AND v==2 · m≥1≥ 4TS세 요건 모두 충족
s==2 AND v==2 · m==00S1v2.2 보정. 관리체계가 공식화되지 않은 고가치 영업비밀이며, 곱만 적용하면 S3 로 떨어지는 경계 사례다

요소값 0 은 “근거 없음”이 아니라 공개·무가치·무관리가 입증된 경우에만 부여한다. 본문에 언급이 없을 뿐이면 하한을 1 로 둔다(grade_from_svm_floored). 이 구분이 없으면 곱이 0 이 되어 S2 문서가 S3 로 과소분류된다.

3. 실제 연산 순서 — 서빙 경로

등급은 아래 순서로 결정된다. 2·4 단계만 등급을 산출하거나 변경하고 3·5 단계는 등급을 바꾸지 않는다. 3 단계의 룰 등급은 5 단계 합의 판정의 입력으로 쓰이며, 분류기 가중치가 적재되지 않은 경우에 한해 등급 산출을 대신한다.

입력 (문서 또는 텍스트 + ICD 메타데이터) │ ├─ 1 전처리 텍스트 추출 → 정규화 → 개인정보(PII) 마스킹 → 청크 분할 │ ├─ 2 분류기 추론 KF-DeBERTa 청크별 softmax [등급 산출] │ · 온도 보정(temperature scaling), 배포 모델 동봉값 적용 │ · 청크 집계: TS·S1 은 최댓값 선택, 그 외 등급은 길이 가중 평균 │ · 승격 임계값 τ 로 위험도 순 선택(τ 미설정 시 argmax) │ ├─ 3 룰 등급 산출 키워드 argmax → 요소 정합 → 상위 등급 채택 (§4) │ [등급 변경 없음. 5 단계 합의 판정의 입력] │ ├─ 4 등급 보정 [등급 변경] │ · 보안표시 하한: ICD 보안표시가 예측보다 높으면 상향(하향 없음) │ · 출처 상한: 출처가 공개 문서이면 S3 로 상한 │ · 동점 시 상위 등급 채택, 미탐 방지 보정 │ ├─ 5 검수 라우팅 §5 게이트 중 하나라도 해당하면 needs_review │ └─ 출력 등급 · 신뢰도(confidence) · 근거 · 상태값 staging = 자동확정 / needs_review = 사람 검수 대기

4. 룰 등급 산출 — 3단계

단계하는 일계산최종 등급에 미치는 영향
4-1키워드 argmax키워드마다 본문 출현횟수 × 가중치 를 등급별로 누산한 뒤 최고점 등급을 택한다(argmax). 동점이면 상위 등급을 택한다. 매칭이 0 건이면 기본값 S3 이며 이때 신뢰도는 0 이다여기서 결정된다
4-2요소 정합S/V/M 레벨을 4-1 결과에서 산출 → grade_from_svm()요소를 독립 관측하지 않는다
4-3상위 등급 채택곱셈 등급과 키워드 등급 중 더 높은(민감한) 등급을 채택한다곱셈 결과가 더 낮으면 채택하지 않는다
4-2 의 입력은 키워드 등급, 공개 신호 유무, 관리 키워드 매치 유무 세 가지이므로 조합이 16 개로 닫힌다. 전수 열거 결과 최종 등급이 바뀌는 조합은 “키워드 등급 S1 · 공개 신호 없음 · 관리 키워드 매치” 하나이며, 나머지 15 개에서는 4-3 이 키워드 등급을 그대로 유지한다. 평가셋 993 건 실측에서 해당 조합의 발동은 0 건이었다. 재현 명령은 문서정보의 검증 항목에 있다.
공개 신호의 역할은 등급을 내리는 것이 아니라 위 상향을 막는 것이다. 같은 16 조합에서 공개 신호 유무로 최종 등급이 갈리는 것은 “키워드 등급 S1 · 관리 키워드 매치” 한 자리뿐이며, 공개 신호가 있으면 TS 로 오르지 않고 S1 에 머문다. 본문에서 검출한 공개 신호만으로 등급을 낮추지는 않는다 — 하향은 미탐 방향이므로 출처 상한(§3 4 단계 · ICD 메타데이터)과 검수 라우팅(§5 3 번)이 담당한다. 이 성질은 회귀 테스트로 고정돼 있다(test_public_signal_never_lowers_the_grade).

따라서 룰 경로를 “3요건을 독립 판독하여 곱한다”로 기술하면 실제 동작과 맞지 않는다. 정확한 기술은 “키워드 등급을 먼저 판정하고, 3요건 레벨을 그 등급에 정합시킨 뒤, 곱셈 매핑이 더 높은 등급을 가리킬 때에만 상향한다”이다.

5. 검수 라우팅 게이트

검수 게이트는 등급을 바꾸지 않고 자동확정 여부만 결정한다. 위에서부터 순서대로 평가하며, 하나라도 해당하면 상태값이 needs_review 가 된다.

게이트는 예외가 발생해도 분류를 중단하지 않고 기존 동작을 유지하며, 미적용 사실을 경고와 지표 카운터로 남긴다. 미탐 방향 게이트가 이렇게 미적용된 경우는 11 번 게이트가 다시 검수로 보낸다.

관리 화면에서 등록한 태깅 규칙 하나가 게이트 전체를 멈추던 경로를 차단했다(02b660ef). 정규식 규칙이 컴파일되지 않으면 룰 라벨링이 문서마다 예외로 중단됐고, 호출부가 그것을 위 fail-open 으로 흡수해 미탐 방지 상향과 룰·모델 합의(12 번)가 함께 정지했다. 현재는 등록 시점에 정규식을 검사해 거부(400)하고, 이미 저장된 규칙이 깨져 있으면 해당 규칙만 미매치로 처리하고 나머지 판정은 유지한다.
