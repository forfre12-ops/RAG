스캔 문서는 다릅니다. 반드시 확인이 필요합니다. 글자가 이미지로만 들어 있는 문서(스캔본)는 본문을 뽑는 데 OCR 이 필요합니다. 측정해 보면 비용 구조가 뒤집힌다 — 16쪽 스캔 PDF 에서 파싱 28.5초 · 판정 3.9초로 파싱이 7배였습니다.

그런데 납품 번들에는 OCR 이 들어 있지 않습니다. OCR 은 요건에 없고(FUN-022 는 전자문서 텍스트 추출까지), 관련 오픈소스가 GPL 이라 반출 번들에서 제외했습니다. 따라서 스캔 문서는 느린 것이 아니라 처리되지 않습니다 — 본문 0자로 failed 상태로 격리되어 무음 통과하지 않습니다.

회원사가 올리는 문서에 스캔본이 포함될 예정이면 OCR 을 요건으로 확정해 주시기 바랍니다. 요건화되면 라이선스가 맞는 엔진으로 번들을 다시 구성합니다.

6. 가-3-1 — SVM 점수 산정 방식 [정정]

등급 판정 결과의 SVM 점수 산정 방식
정정. 당사 기존 제출문서는 “3요건을 독립 판독한 점수의 곱”으로 기술해 왔습니다. 코드를 재확인한 결과 그 서술이 정확하지 않습니다. 제출본을 정정했고 (2026-08-28), 실제 동작을 아래에 적습니다.

6-1. 실제 순서

① 키워드 룰이 등급을 정한다        content_grade = 가중합 argmax
② 그 등급에서 S·V·M 레벨을 파생한다
     s = 0 if (공개출처 매칭 or content=S3) else (2 if content in (TS,S1) else 1)
     v = 2 if content in (TS,S1) else (0 if content=S3 else 1)
     m = 2 if 관리성 키워드 매칭 else (0 if content in (S3,S1) else 1)
③ 곱셈 매핑으로 교차 확인한다        svm_grade = grade_from_svm(s, v, m)
④ 더 높은 보안등급을 취한다          final = min-rank(svm_grade, content_grade)

즉 S·V·M 은 서로 독립하게 판독되지 않습니다. 세 값 모두 ①의 등급과 두 신호 (공개 출처 키워드 매칭 여부 · 관리성 키워드 매칭 여부)에서 계산됩니다. 곱셈은 독립된 세 번째 판독이 아니라 키워드 등급에 대한 교차 확인이며, ④가 min-rank 이므로 등급을 올리기만 하고 내리지 않습니다(미탐 방지).

6-2. 실측

측정값비고
곱셈이 최종 등급을 바꾸는 조합1 / 16content=S1 · 공개 미매칭 · 관리성 매칭 → TS
평가셋 4종에서 실제 등급 변경0 / 993경화42 · clean42 · holdout109 · v3_final800

현행 데이터에서 등급을 정하는 것은 키워드 가중합 argmax 이며, 곱셈 단계는 안전 방향 가드로만 작동합니다. 곱셈 매핑 자체(8→TS · 4→S1 · 1·2→S2 · 0→S3)는 발주처 정본 가이드 p12 를 그대로 옮긴 것이며 변경하지 않았습니다.

7. 가-3-2 — 판단 근거 제시 방법 [정정]

Attention Weight · Gradient Saliency 기반 XAI 를 사용하는가
사용하지 않습니다. 귀사가 이전 PoC 에서 쓰신 모델 내부 신호(Attention Weight · Gradient Saliency) 기반 기법은 현행 분류 엔진에 구현되어 있지 않습니다.

대신 다음 네 가지로 판단 근거를 제시합니다.

수단내용
evidence본문에서 실제로 매칭된 구간(시작·끝 위치)과 그 문자열 · 요인 태그(S/V/M) · 가중치
decision_path어느 경로로 등급이 정해졌는지(모델 argmax · 에스컬레이션 · 룰 상향 등)
rule_grade · model_grade룰과 모델의 판정을 나란히 제시 — 불일치 자체가 근거가 됩니다
warnings발동한 게이트 내역 — 왜 자동확정하지 않았는지

7-1. 이 방식을 택한 이유

근거 문장을 본문에서 그대로 인용하는 방식은 한 번 시행했다가 철회했습니다. 인용된 8,100건 중 88.3%가 “본 문서는 2급 대외비로 분류한다”와 같은 등급 자체를 적어 놓은 결론 문장이었다. 근거가 아니라 정답을 베낀 것이어서, 검수자가 그것만 보고 확인하면 검수가 형해화됩니다. 근거를 요인 수준으로 다시 쓴 뒤 해당 비율은 2.6%로 떨어졌다.

모델 내부 신호 기반 기법 도입이 필요하시면 별도 협의 항목으로 올려 주시면 검토하겠다. 다만 현행 요건(FUN-023)에는 포함되어 있지 않습니다.

약 400개 키워드가 출현 빈도에 따라 등급 판정 · 개선 예정 · 관리자 관리 가능 여부
귀사 파악판정실제

시드는 전부 정확 일치(exact substring) 방식입니다. 정규식 시드와 의미 유사도 시드는 코드에 자리는 있으나 현재 등록된 것이 0건입니다.

8-1. 개선 예정 여부

있습니다. §6 에 적은 곱셈 단계 무동작(993건 중 0건 변경)이 확인되어, 룰 경로의 실질 판정 로직을 재정비할 필요가 있다고 보고 있습니다. 개선 범위와 일정은 별도 협의 대상입니다.

8-2. 관리자 관리 가능 여부

가능합니다. 키워드는 tb_level_keywords 테이블을 우선 읽고, 비어 있을 때만 코드 내장 시드로 폴백합니다. 즉 코드 변경·재배포 없이 관리자가 키워드를 추가·수정·삭제할 수 있습니다. 등급 체계(등급 코드·순서) 자체도 같은 방식으로 DB 에서 관리됩니다.

13-1. 보안 가이드라인 기반 라벨링 매핑 방법

질의에 포함된 항목이라 함께 답합니다. 매핑은 발주처 정본 가이드(11~12쪽)의 4단계 곱셈표를 그대로 옮긴 것이며 당사가 새로 만든 기준이 아닙니다.

단계내용
① 요건 정의 가이드의 3요건(비공지성 S · 경제적 유용성 V · 비밀관리성 M)을 각 0·1·2 레벨로 둔다
② 곱셈 매핑 곱(S×V×M) → 등급. 8→TS · 4→S1 · 1·2→S2 · 0→S3. 가이드 원본 표와 동일하며, 골든셋 실증으로 2곳을 보정했다(적용서 v2.2)
③ 키워드 시드 가이드의 등급별 예시·설명에서 404개 키워드를 뽑아 등급·요인별로 태깅했다 (TS 114 · S1 107 · S2 87 · S3 96). 전부 정확 일치 방식입니다
④ 관리자 수정 키워드·등급 체계는 tb_level_keywords 로 관리하며 코드 변경·재배포 없이 추가·수정·삭제할 수 있다(§8-2)

실제 판정에서 곱셈 단계가 어떻게 작동하는지는 §6 을 참조하시기 바란다 — 매핑 자체는 가이드 그대로이나, 구현에서 S·V·M 은 독립 판독되지 않습니다.

13-2. 샘플 문서 검수 방안 — 상태·기준·이력

항목내용
검수 상태 pending_review(대기) → approved(승인) 또는 rejected(반려). 세 값만 허용하며 임의 상태로 넘어가지 않습니다

보류·재검수 승인·반려 전까지는 pending_review 로 남아 큐에 계속 표시됩니다. 별도 “보류” 상태를 두지 않은 것은 상태가 늘수록 큐에서 누락되는 건이 생기기 때문입니다. 재검수는 같은 건을 다시 판정하는 것으로 처리합니다
이력 검수 시각·검수자·결정·사유가 레코드에 남습니다. 승인분에서 학습행을 만들 때 교정 건수(grade_corrected)를 함께 산출해, 학습셋을 열어 보지 않고도 교정이 몇 건 반영됐는지 확인할 수 있습니다
위생 게이트 승인됐더라도 생성 실패 산출물(자리표시 본문 · 비정형 응답 · 빈 본문)은 학습에 넣지 않습니다. 제외 건수를 사유별로 계수해 함께 반환합니다

지표 해석의 한계를 함께 고지합니다. 현행 평가셋에는 사람이 서명한 정답이 0건이며, 라벨은 전부 기계가 붙인 것입니다. 따라서 위 수치는 모델 간 상대 비교와 회귀 여부 확인에 쓰는 값이며, 운영 정확도를 보증하는 값이 아닙니다. 실문서 기반 평가정답 확보가 남은 과제이며, 이는 발주처 실데이터 제공 여부에 달려 있습니다.

참고 — 계약상 정확도 수치 목표는 설정되어 있지 않다(성능요건 PER-002 는 속도·자원 기준). 핵심 목표는 미탐 최소화이며, 본 시스템의 게이트 설계가 그 목표에 맞춰져 있습니다.

제시하지 않은 지표를 밝힙니다. 등급별 Precision·Recall·혼동행렬은 산출 가능하나 본 회신에는 대표값(F1 macro)만 실었습니다. 필요하시면 등급별 상세를 별도 제공드립니다.

질의에 함께 적으신 유사 문서 검색 기반 분류는 등급 결정 경로에 포함되지 않아 분류 성능 지표의 대상이 아닙니다. 등급을 정하는 것은 §1 의 모델·룰 둘입니다.

미탐(FNR)은 배포 게이트가 등급별로 감시하며, 고등급 미탐률이 기준선보다 악화되면 승격을 차단합니다. 게이트 기준값과 최근 판정 결과는 요청하시면 제공드립니다.
