## 안건 1. 등급 산정법 채택 — A안(가산) vs **B안(곱셈)** ★핵심

| | A안 (가이드 5p) | **B안 (가이드 11~12p) — 권장** |
|---|---|---|
| 방식 | 5요소 100점 **가산** | 3요건 **곱셈** 등급=S×V×M |
| 임계 | 1급≥75·2급≥50·3급<50, 특급=자체분류 | 8→특급·4→1급·1·2→2급·0→3급 |
| 장점 | 정량 자가진단 적합 | **4등급 1:1 매핑 · 법적 3요건 정합 · "한 요소라도 0이면 공개"로 과분류 차단** |

- **우리 권장: B안 채택.** 근거 — 영업비밀 법적 3요건과 정합, 과분류 근본 해결(doc/32 실측 93%→0%), **그리고 A안 5요소(창출비용·내부활용효과·외부유출위험)는 문서 본문에 없는 외부 경영정보라 텍스트 AI로 산출 불가** = A안은 사람 수기용, B안은 AI용.
- **수행사 설계 확정(근거 통보)**: B안을 AI 정본 산정법으로 **확정**. A안은 회원사 수기 자가진단 보조로 병행. → 기술·법리 근거가 명확해 승인 대기 아님, **발주처 이견 시 협의**.

## 안건 2. 특급기밀(TS) 처리 방식

- 가이드상 특급 = *자체분류*(A안) 또는 *S=V=M=2 극비*(B안). 본질적으로 판단·자체분류 영역.
- **우리 권장**: 자동분류(S×V×M=8) + 명시표기 + **관리자 수동지정 병행**, 특급은 **항상 사람 확정**. 특급 **미탐율(FNR)** 을 보안상 최우선 지표로 관리.
- **수행사 설계 확정(근거 통보)**: 자동(S=V=M=2)+명시표기+수동 병행 **채택** — 가이드 A(자체분류)·B(극비) 모두 만족. AI 특급-FNR 평가는 *텍스트로 산출 가능한 특급*에 한정(순수 자체분류 특급은 AI 범위 밖). → 발주처 이견 시 협의.

## 안건 3. 목표 정확도 90% 와 QA 버퍼 (PMR-002)

- RFP: **1,000건 이상 블라인드 골든셋 + 목표 정확도 90% + 미달 시 보완·재학습 QA버퍼 최소 2주**.
- **현실성 의견**: 4등급 영업비밀 분류에서 90%는 도전적. **보안축(고등급 FNR≈0)** 과 **정확도축**을 분리 평가하고, QA버퍼 2주를 WBS에 명시(RFP 요건) 권장.
- **발주처 확정 필요**: ① 90% 측정 기준(전체 정확도 vs 등급별)? ② 측정용 **실데이터 제공 여부**(미제공 시 합성·공개 데이터로 검증).
- **KL §3 지표 정렬**: KL 요약(Acc/Prec/Rec/F1)에 FNR 미명시 → 보안 특성상 **FNR(고등급 미탐)을 핵심 지표로 추가** 명시 권장(RFP FUN-024 근거; Recall이 이를 함의).
- **최신 실측(2026-06-19, doc/34)**: 현 PoC 운영모델 — 실 비즈니스 **76%**·정형문서 95%·TS recall 81%·고등급 FNR 8~20%. 학습데이터 **법률코퍼스 56% 오염(2,210건 비밀등급 오라벨)을 발견·제외**해 비즈니스 67→76%↑. 90%는 실데이터(운영) 과제 — "PoC baseline → 본개발 90% 확정" 단계 메시지로 설명.

## 안건 4. 골든셋 1,000건 구성 방안 (PMR-002 / 8월 일정)

- **현황(완료)**: 가이드 예시표 기반 **골든셋 시드 v2** + **50건 파일럿 구축 완료**(회사 내부형 4등급×다도메인, 본문 믿음성 확인, DOCX/PDF 변환·재추출 검증). 상세 `doc/34`·`GOLDEN50_FINDINGS.md`.
- **방안(고객 검토형 단계 구축)**: 가이드 예시표 + LLM 합성 + **사람 검수**로 **1,000건 이상**, train과 **완전 격리(블라인드)**. 발주처 비밀 실데이터 없이도 구성 가능 → **개인정보·제3자 저작권 사전검토(PMR-001) 리스크 회피**.
  - **1단계 — 검토본 100건(HTML)**: 판단근거(문구→S/V/M→등급)를 함께 담은 **100건을 HTML로 큐레이션해 고객사가 등급·근거를 직접 검토·확인**. (현재 룰+LLM 이중라벨 **후보 500건** 생성 완료 → 이를 토대로 100건 큐레이션)
  - **2단계 — 900건 확장**: 고객 확인(등급기준·근거품질 합의) 후 동일 기준으로 **나머지 900건 생성 → 총 1,000건 이상** 완성.
  - → 고객이 **소량 100건으로 라벨 기준을 먼저 확정**하므로, 900건 대량 생성 후 재작업 리스크를 차단.
- **객관성(파일럿 입증)**: **판단근거 대장**(문구→S/V/M→등급, 곱↔등급 100% 정합)을 문서별 첨부 → 가이드 추적성 확보. 단 자동라벨만으론 불가 — 파일럿 **검수필요 35/52(≈67%)**, 전문가 검수로 확정(검수시트 `golden50_review_sheet.csv`). → **검수 공수 산정 + 발주처 전문가 참여**가 객관성의 핵심.
- **발주처 확정 필요**: ① 검수 주체 — KL 참고자료 §2가 "**문서 전문가 검수 예정**"으로 명시 → 발주처/수행사 검수자 구성·참여 범위 확정(우리 Q7=검수자 2명+AI팀 셀프검수와 정합). ② 희소한 **특급 표본** 확보 방법(합성/수동 시드).

## 안건 5. 가이드 내부 변이 — 정본 판정 ★주의

가이드의 **예시표(p6~9)** 와 **S×V×M 워크드 예시(p12)** 가 일부 불일치(가이드 p2: "각 기업 현실에 맞게 수정 활용" 특성).

| 문서 | 예시표(p6~9) | S×V×M(p12) |
|---|---|---|
| 중장기 경영계획 | 1급(S1) | S=V=M=2 → **특급(TS)** |

- **추가 검토(고해상도 재판독서 확인)**: 가이드 예시표는 **산업재산권 관리정보(특허·실용신안·디자인)를 2급 대외비(S2)** 로 두나, *등록·공개된* 특허·실용신안은 비공지성상 **3급 공개(S3)** 가 타당 — 출처 게이트(공개특허→S3)와 충돌. → "**등록/공개 IP의 등급**" 정책을 함께 확정 필요.
- **우리 권장**: **S×V×M(p11·p12)을 정본**으로 → `svm_anchor` 권위, 예시표는 검수 대상. 공개 IP는 비공지성 게이트(S=0)로 S3 처리.
- **5① 수행사 확정**: 중장기 경영계획 등 예시표↔S×V×M 변이는 **S×V×M 계산을 정본**으로(B안 채택의 귀결). 예시표는 전형값 참고. → 통보.
- **5② 발주처 확인 필요**: 공개·등록 특허·실용신안 = **3급 공개(S3)** 판정은 *발주처 자체 가이드 예시표(2급)를 정정*하는 것 → 근거 제시 후 확인. (출원 전·미공개 IP는 별도)
- **5③ 판례·공개 법률문서 제외(2026-06-19 신규)**: 법원 판례·특허심결은 *공개 문서*라 영업비밀 분류 대상 아님 → **학습셋·골든셋·홀드아웃에서 제외** 권장. 근거: 학습셋 56%가 판례·심결이었고 비밀등급 오라벨 다수, 제외 시 비즈니스 정확도 67→76%↑(ablation). → 발주처 동의 요청.

## 안건 6. S/V/M 산정에 필요한 메타데이터 — KL 인터페이스 (R6) — ✅ KL 흐름에 이미 포함

- **비밀관리성(M)** 과 사실적 **비공지성(S)** 은 *문서 본문만으로 판정 곤란* — 보안표시·접근권한·출처는 문서 외부 정보.
- **정합 확인**: KL 참고자료 §1-2가 이미 *"파싱 → **메타정보 결합** → BERT 판정"* 으로 명시 → R6 방향이 KL 흐름과 일치(개념 합의 완료).
- **우리 권장**: KL 웹계층이 **출처·보안표시·접근범위 메타데이터**를 분류 API로 전달(비공지성 게이트는 `source_prior`가 일부 담당).
- **확정 필요(KL)**: 개념이 아니라 전달할 **메타 필드 스펙**만 합의 — §6 API 연계 별도협의와 묶음.

## 안건 7. 성능·측정 환경 (PER-002 / ECR-001)

- RFP: 등록 **3초** · 문서 등록/분류 **30초** · 메모리 **90% 미만** · CPU **70% 이하**.
- **GPU/서버 사양 — 확정됨**(KL 참고자료 2026-06-18 §4): 개발 서버 **A100 80GB×2 · 32C+ · 192GB · SSD 4TB · Ubuntu 22.04 LTS** 제공 예정 → 안건 7의 서버 사양 항목 해소(80GB×2면 KF-DeBERTa+KURE+Qwen3 동시 가동·로컬 합성 풀가동).
- **잔여 확정 필요(발주처)**: CUDA/Driver 버전·컨테이너 GPU 런타임, **운영(기업 배포) 환경 사양**(개발 서버와 별개), 부하 측정 환경(부하시험 미실시).
