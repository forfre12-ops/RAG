## 2. 자격증명 관리

### 2.1 환경 변수 (.env / Vault)
**필수 자격증명** (절대 git 커밋 금지):
- `DATABASE_URL` — PG 접속
- `ES_BASIC_AUTH_PASSWORD` — ES 인증 (운영 권장)
- `REDIS_PASSWORD` — Redis ACL
- `MINIO_ROOT_PASSWORD` — 객체 스토리지
- `JWT_PRIVATE_KEY` — JWT 서명용 (P1-C3 도입 시)
- `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` — LLM 원격 (선택)

### 2.2 fail-fast (실재 코드: W12 J 작업)
- `config.py` 가 부팅 시 필수 자격증명 부재 감지하면 즉시 startup 실패
- "동작은 되는데 인증이 빠진" 상태 차단

### 2.3 키 로테이션 정책
| 자격증명 | 주기 | 절차 |
|---|---|---|
| API Key (X-API-Key) | 90일 | `scripts/issue_api_key.py --rotate` (grace 7일) |
| JWT 서명키 | 365일 | `scripts/rotate_jwt_keys.py` (kid 변경, JWKS 게시) |
| DB 비밀번호 | 180일 | maintenance window + connection drain |
| MinIO 루트키 | 365일 | rotate + 클라이언트 일괄 업데이트 |
| TLS 인증서 | 갱신 30일 전 | Let's Encrypt 자동 또는 사내 PKI |

### 2.4 secrets manager 통합 (P2-C5 도입 후)
- 운영 모드: env 직접 read 금지, 모두 secrets manager(Vault/AWS SM) 통해 read
- 로컬 dev: .env 허용, .env.example만 git 커밋

## 3. 인증 (Authentication)

### 3.1 X-API-Key (기본)
- HTTP 헤더 `X-API-Key: <key>` 필수
- 키 부재/오류 → 401 + 표준 에러 응답
- 운영시 라우터 `/health` `/metrics` 만 익명 허용

### 3.2 JWT RS256 (P1-C3 도입 후)
- Authorization: Bearer <jwt>
- 서명 알고리즘: RS256 (대칭키 HS256 금지)
- claims:
  - `sub` (user_id)
  - `tenant` (테넌트)
  - `roles` (배열)
  - `exp` (만료, 권장 ≤ 1시간)
  - `kid` (서명키 식별)
- JWKS endpoint: `/.well-known/jwks.json` (공개)
- refresh token은 별도 endpoint `/auth/refresh`로 발급

### 3.3 Rate Limit (J4 — 실재)
- slowapi 기반, 기본 1분당 60req / 시간당 1,000req
- 초과 시 429 + Retry-After 헤더 (R5에 OpenAPI 명시 완료)
- per-tenant 분리 (key prefix `tenant:<id>`)

## 4. 인가 (Authorization)

### 4.1 RBAC
| Role | 권한 |
|---|---|
| ADMIN | 모든 API + 사용자/키 관리 |
| REVIEWER | confirm/relabel + 자기 tenant 문서 read |
| VIEWER | read-only, 자기 tenant 한정 |

### 4.2 tenant_id 강제 (K5 — 실재)
- 모든 DB 쿼리에서 `WHERE tenant_id = :current_tenant` 적용
- ORM 레벨에서 자동 주입 (`repositories/` 모든 쿼리)
- audit_middleware가 cross-tenant 접근 시 즉시 차단 + 알람

## 5. 데이터 보안

### 5.1 전송
- 외부 노출 API: TLS 1.3 only (TLS 1.2 이하 disable)
- 내부 통신(KL ↔ Lloydk): mTLS 권장(P2-C7)

### 5.2 저장
- DB: PG TDE 또는 디스크 LUKS 암호화
- MinIO: SSE-S3 / SSE-KMS
- 백업: dump 자체를 추가 암호화 (GPG)

### 5.3 PII 마스킹 (P1-A8 도입 후)
- m2_preprocess에서 NER로 PII 토큰 자동 마스킹
- 마스킹 룰:
  - 주민번호 `\d{6}-[1-4]\d{6}` → `***`
  - 이메일 → `***@domain`
  - 사번/계좌 → `***`
- 마스킹 전 원문은 audit 외 어떤 로그에도 남기지 않음

### 5.4 로그 PII 자동 마스킹 (P1-F4)
- Loki promtail pipeline_stages로 ingest 시 마스킹
- 이미 노출된 로그는 grafana annotations + 보존 정책 단축

## 6. 감사 로깅 (audit_log)

### 6.1 기록 대상
- 모든 인증 시도(성공/실패)
- 모든 분류 결과(/classify 응답)
- 모든 검수자 confirm/relabel
- 모든 ADMIN 작업

### 6.2 hash chain (P1-C4 — 변조 방지)
- 각 audit row에 `prev_hash` + `row_hash = sha256(prev_hash || payload)` 컬럼
- 단일 row 변경 시 이후 모든 row hash가 깨짐 → 변조 즉시 검출
- 일별 마지막 hash를 외부 timestamping 서비스에 송부(선택)

### 6.3 보존
- 영구 보존 (영업비밀법 6조 입증력 요건)
- 5년 이상 된 row는 cold storage(MinIO archive bucket)로 이관 가능

## 7. 공급망 보안

### 7.1 정적 분석 CI (C8 — 신설)
- `bandit` Python SAST — HIGH 발견 시 build fail
- `semgrep` OWASP top10 + Python rules — ERROR 발견 시 build fail
- `gitleaks` — full history 누출 검사
- `ruff` — 정적 lint

### 7.2 의존성 보안
- `pip-licenses` direct deps 라이선스 매트릭스 (CI licenses-check)
- AGPL 등 strong copyleft 신규 추가 차단 (allowlist)
- SBOM CycloneDX 산출 (`scripts/dump_licenses.py --format=cyclonedx`)

### 7.3 컨테이너 보안
- 베이스 이미지: alpine 또는 distroless 권장
- 비root 실행 (`USER 1000:1000`)
- read-only filesystem + writable tmpfs 최소
- 이미지 스캔: trivy CI 잡 (운영 진입 직전 추가 권장)

## 8. 모델·AI 보안

### 8.1 모델 격리
- 학습 데이터셋(라벨된 영업비밀)은 별도 보안 볼륨에 저장
- model artifacts는 tenant 간 공유 금지

### 8.2 Adversarial 입력 탐지
- adversarial 골든셋(P1-B3) 100건으로 정기 회귀 테스트
- confidence < 0.5 또는 모든 라벨 균일 → "검수 우선" 큐

### 8.3 모델 회귀(drift) 감지 (P1-B4)
- production embedding 분포 vs 학습 시 분포 KL divergence
- 임계 초과 시 알람 → 재학습 트리거

## 9. 사고 대응 (Incident Response)

### 9.1 사고 등급
- **Critical**: 영업비밀 유출 의심, 인증 우회, audit 변조
- **High**: 인가 실패, PII 노출 가능성
- **Medium**: SAST HIGH 발견, drift 알람
- **Low**: 정보 수집 / 가벼운 설정 미스

### 9.2 표준 절차
1. **격리**: 영향 받은 컴포넌트 즉시 차단 (`docker compose stop <svc>`)
2. **보존**: 로그·메모리 덤프·DB 스냅샷 보존
3. **알림**: 보안팀 + 발주처 KOIPA 측 담당자 (등급별 시간 내)
4. **분석**: audit_log hash chain로 침해 범위 확정
5. **복구**: 검증된 직전 백업으로 복원
6. **사후**: post-mortem 문서화 + 재발 방지 코드/설정 patch

### 9.3 신고 의무 (법적)
- 개인정보 유출: 72시간 내 개인정보보호위원회 (개정 PIPA)
- 영업비밀 유출: 즉시 KOIPA + 사내 법무
