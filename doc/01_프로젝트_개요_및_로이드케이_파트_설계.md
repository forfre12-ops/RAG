## 1. 프로젝트 전체 개요

### 1.1 사업 개요
| 항목 | 내용 |
|---|---|
| 발주처 | 한국지식재산보호원 (영업비밀보호센터) |
| 사업명 | AI 영업비밀(관리)시스템 구축 |
| 핵심 목표 | 기업 영업비밀 문서를 **AI가 자동으로 등급 분류**하고, 전체 생애주기(등록·열람·반출·파기)를 통제·기록·감사할 수 있는 영업비밀 관리 플랫폼 구축 |
| 등급 체계 | **특급기밀 / 1급 비밀 / 2급 대외비 / 3급 공개** (관리자 수정 가능) |
| 배포 방식 | Docker 이미지 + `docker-compose` 일괄 구동, 기업 환경에 온프레미스 설치 |
| GPU | 발주기관 제공 환경에서 학습/추론 수행 |

## 2. 로이드케이(Lloydk) 담당 파트 상세 설계

### 2.1 책임 범위 한 줄 정의
> **"문서가 들어오면 등급(특급/1급/2급/3급)을 근거와 함께 출력하는 AI 엔진"의 전체 라이프사이클** — 학습 데이터 생성 → 전처리 → 라벨링 → 모델 학습 → 추론 → 성능 평가 → 능동 학습 루프.

### 2.3 모듈별 상세 설계

#### 모듈 1. 샘플 문서 생성기 (FUN-003) — `synth-gen/`
| 항목 | 설계 |
|---|---|
| 목적 | 학습 데이터 부족 문제 해결. LLM으로 등급별 모의 문서를 생성 |
| 입력 | 등급체계, 도메인(기술/경영), 가이드 문서 발췌, AI Hub/공공데이터 시드 |
| 출력 | 등급 라벨이 자동 부여된 합성 문서 (검수 큐로 전달) |
| 핵심 기술 | LangChain (PromptTemplate + Chain + Output Parser), LLM Provider 추상화 레이어 |
| LLM 지원 | OpenAI GPT, Anthropic Claude, Google Gemini, OSS(Llama/Qwen 등 vLLM/Ollama) — **Adapter 패턴**으로 교체 가능 |
| 운영 | 개발기간 API 비용은 수행사 부담 → 운영 시 발주처 키로 교체 가능한 설정 분리 |
| 검수 | 관리자 검수 UI(KL) → 승인된 문서만 학습셋에 편입 |

#### 모듈 2. 전처리 파이프라인 (FUN-022) — `preprocess/`
| 단계 | 처리 | 라이브러리 후보 |
|---|---|---|
| 포맷 추출 | HWP → `pyhwp`/`hwp5txt`, DOCX → `python-docx`, PDF → `PyMuPDF`/`pdfplumber`, OCR → `PaddleOCR`/Tesseract/LLM-Vision | |
| 구조 인식 | 머리글/바닥글/표/본문 분리, 표는 별도 토큰화 | `unstructured`, `layoutparser` |
| 정규화 | 불용어, 공백·줄바꿈, 특수문자, 띄어쓰기/맞춤법 | `soynlp`, `KoNLPy`, `hanspell` |
| 노이즈 제거 | 광고/헤더/푸터/반복 문구 제거 | 규칙 + 패턴 |
| 구조화 출력 | JSON / Markdown 형태로 재사용 가능하게 저장 | |
| 청크 분할 | 모델 최대 길이(예 512) 단위 슬라이딩 윈도우 + 오버랩 | LangChain TextSplitter |

#### 모듈 3. 라벨링·태깅 (FUN-023) — `labeling/`
- **4단계 등급 매핑**: 가이드 → 라벨 ID
- **판단 근거 속성**: 경제적 가치 / 비공지성 / 관리수준 / 유출 시 영향도 (각 항목 점수화)
- **태깅 대상**: 키워드, 표현 패턴, 메타데이터(작성 부서, 문서 유형)
- **규칙 관리**: 정책 변경 시 라벨/태깅 규칙을 YAML/DB로 외부화 → 재학습 트리거
- **출력 스키마**:
  ```json
  {
    "doc_id": "...",
    "label": "1급 비밀",
    "scores": {"economic_value": 4.2, "non_publicity": 4.5, "mgmt_level": 3.8, "leak_impact": 4.7},
    "tags": ["기술도면", "R&D부서", "..."],
    "evidence_spans": [{"start": 123, "end": 178, "text": "..."}]
  }
  ```

#### 모듈 4. 학습 파이프라인 (FUN-004) — `training/`
| 항목 | 설계 |
|---|---|
| 모델 후보 | **한국어 PLM 인코더 중심**: KLUE-BERT, KoELECTRA, KF-DeBERTa, KoBigBird(긴 문서) |
| Task | Multi-class Sequence Classification (4-class) + 보조 헤드(평가요소 회귀) |
| Chunk 학습 | 문서를 청크로 분할 후 청크별 예측 → 문서 단위 어그리게이션(max/voting/attention) |
| 데이터 분리 | Train/Val/Test 자동 분리 (Stratified, 기본 70/15/15, 설정 가능) |
| RAG 옵션 | 기업별 사내규정/지침을 임베딩(예: BGE-M3, ko-sbert) → FAISS/Vespa/Elasticsearch에 저장 → 추론 시 Top-K 컨텍스트 결합. **기업 자원 상황 고려해 ON/OFF 토글** |
| 학습 환경 | PyTorch + HuggingFace Trainer, GPU(발주처 제공), MLflow로 실험 추적 |
| 리포트 | Accuracy/Precision/Recall/F1 + 등급별 분포 + 학습 곡선 (PDF/HTML 출력) |

#### 모듈 5. 추론 서비스 (FUN-005) — `inference/`
- **API 설계** (KL이 호출):
  ```
  POST /api/v1/classify
  body: { "doc_id": "...", "text": "...", "use_rag": true, "tenant_id": "..." }
  resp: { "label": "1급 비밀", "confidence": 0.87, "scores": {...},
          "evidence": [...], "model_version": "v1.3.0" }
  ```
- **등급체계 관리**: 4단계는 기본값이며 관리자가 추가/변경/삭제 가능 → 모델 재학습 트리거 인터페이스 제공
- **임시 저장소 → 확정** 흐름: 추론 결과는 staging 상태로 저장 → 관리자 확정 API(`POST /api/v1/confirm`) 호출 시 최종 라벨 확정
- **표시 정보**: 등급 + 신뢰도 + 근거(키워드/문맥) + 적용 정책 매핑

#### 모듈 6. 성능 평가 및 능동 학습 (FUN-024) — `evaluation/`
- **지표**: Accuracy, Precision, Recall, F1, **FNR(미탐율) — 핵심 KPI**
- **Confusion Matrix**: 등급별 오분류 패턴 시각화 (특히 "고등급 → 저등급" 미탐을 별도 알람)
- **능동 학습 루프**:
  1. 추론 결과를 KL UI에 노출
  2. 관리자가 오분류 수정 라벨 부여
  3. 수정 라벨이 누적되면 재학습 큐로 자동 전송
  4. 재학습 후 모델 버전업 + 성능 비교 리포트
- **이력 관리**: 모델 버전·데이터셋 스냅샷·하이퍼파라미터·평가지표를 DB에 보관, 조회 API 제공

### 2.4 인터페이스 경계 (Lloydk ↔ KL)

| 인터페이스 | 방향 | 형식 | 비고 |
|---|---|---|---|
| 문서 분류 요청 | KL → Lloydk | REST `POST /classify` | 동기/비동기 양쪽 지원 |
| 분류 결과 확정 | KL → Lloydk | REST `POST /confirm` | 관리자 확정 시 |
| 오분류 수정 | KL → Lloydk | REST `POST /relabel` | 능동 학습 입력 |
| 모델 학습 트리거 | KL → Lloydk | REST `POST /train` | 또는 스케줄 |
| 학습 진행 상태 | KL ← Lloydk | WebSocket/Polling | 진행률 |
| 학습 가이드 문서 | KL → Lloydk | 파일 + 버전 메타 | FUN-002와 연계 |
| 등급체계 변경 알림 | KL → Lloydk | REST `POST /schema` | 재학습 필요성 응답 |
| 합성문서 검수 큐 | Lloydk → KL | REST `GET /synth/queue` | FUN-003 |
| 성능 리포트 | KL ← Lloydk | PDF/HTML/JSON | 대시보드 표출용 |

### 2.5 배포 패키징 (FUN-010 협조)
- 각 모듈을 별도 Docker 이미지로 빌드 → KL이 통합 `docker-compose.yml`에 편입
  - `lloydk/synth-gen`, `lloydk/preprocess`, `lloydk/inference`, `lloydk/training`, `lloydk/evaluation`
- 모델 가중치는 별도 볼륨/오브젝트 스토리지로 분리, 이미지 재빌드 없이 교체 가능
- `Dockerfile`에 의존성 버전 고정, 보안 취약점 점검(Trivy 등) 단계 포함
