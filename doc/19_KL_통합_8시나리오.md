## 0. 통합 환경 전제

| 항목 | 값 (자체결정 v2) | KL 회신 시 패치 |
|---|---|---|
| 인증 | `X-API-Key` 헤더 | SSO/JWT면 미들웨어 교체 (수 시간) |
| 인프라 | docker-compose 단일 스택 (PG·ES·MinIO·Redis·MLflow) | KL 측 인프라면 endpoint만 변경 |
| 멀티테넌트 | `tenant_id` 컬럼 + 인덱스 분리 | 그대로 운영 |
| 벡터 백엔드 | ES 8.15.3 단일 | 그대로 운영 |

**액터 컨벤션**:
- `kl_backend` — KL 시스템 자동 호출 (기계 호출, role=kl_backend)
- `admin` — 영업비밀 관리자 (사람, role=admin)
- `reviewer` — 합성 문서·라벨 검수자 (role=reviewer)
- `system` — Lloydk 자체 시스템 (재학습 트리거 등, role=system)

## 1. 시나리오 매트릭스

| # | 시나리오 | 호출 라우터 | 주요 검증 | 자동화 | 의존 자원 |
|---|---|---|---|:-:|---|
| **S1** | 단일 문서 분류 동기 | `POST /classify` | 200 + label·confidence·evidence | ✅ | 없음 |
| **S2** | 대용량 비동기 분류 | `POST /classify/async` + `GET /classify/jobs/{id}` | 202 → 폴링 → done | ✅ | 없음 |
| **S3** | 관리자 확정·재라벨 | `POST /confirm` + `POST /relabel` | corrections 누적 + status=corrected | ✅ | PG |
| **S4** | 등급체계 변경 + 재학습 필요성 | `PUT /schema/grades` | requires_retraining=true | ✅ | PG |
| **S5** | 가이드 문서 업로드 → RAG 인덱싱 | `POST /guide/documents` | indexed=true + vector_count > 0 | ✅ | ES + 임베딩 |
| **S6** | 합성 문서 생성 → 검수 → 학습 데이터 편입 | `POST /synth/generate` + `GET /synth/queue` + `POST /synth/{id}/review` | approved → dataset 연결 | ✅ | LLM API (또는 noop) |
| **S7** | 능동학습 트리거 (URGENT_RETRAIN) | corrections × 10건 → `POST /train` | TrainingRun.queued | ✅ | PG |
| **S8** | 운영 지표·CM 조회 | `GET /metrics/latest` + `/history` + `/confusion-matrix/{ver}` | M6 라이브 평가 | ✅ | PG |

→ 8개 모두 **TestClient로 자동화 가능**. PoC 환경에서 LLM API 없이도 noop provider로 S6 시뮬레이션 가능.

## 2. 시나리오별 상세 단계

### S1. 단일 문서 분류 동기

```
1. KL → Lloydk: POST /api/v1/classify
     headers: X-API-Key, X-Actor-Id=kl-user-1, X-Actor-Role=kl_backend, X-Tenant-Id=koipa
     body: { doc_id, tenant_id, content, use_rag=true, return_evidence=true }
2. Lloydk:
   - PreprocessPipeline → cleaned text
   - InferencePipeline → label, confidence, scores, evidence
   - ClassifyService._try_persist (best-effort, tenant/doc 존재 시)
   - audit_log 1건 기록
   - Prometheus: lloydk_requests_total{route='/api/v1/classify', status='200'}
3. Lloydk → KL: 200 ClassifyResponse
4. 검증:
   - status_code == 200
   - body.label ∈ {TS, S1, S2, S3}
   - 0 ≤ body.confidence ≤ 1
   - body.evidence 존재 (return_evidence=true 시)
   - body.elapsed_ms < 5000 (PoC 합격선)
```

### S2. 대용량 비동기 분류

```
1. KL → Lloydk: POST /classify/async (또는 /classify/batch, 1000건 이하)
2. Lloydk: 202 { job_id, status_url }
3. KL: 폴링 GET /classify/jobs/{job_id} (interval 2s)
4. Lloydk: status=queued → running → done, completed=total
5. 검증:
   - 최종 status == 'done'
   - results 배열 길이 == total
   - 각 result.label 유효
```

### S3. 관리자 확정·재라벨 흐름

```
1. KL → Lloydk: POST /classify (S1과 동일) → classification_id 받음
2. (관리자 검토 후) KL → Lloydk: POST /confirm { doc_id, confirmed_label, actor }
   - 같은 등급 확정 → corrections.direction='confirm' 1건
   - 다른 등급 확정 → corrections.direction='underclass|overclass' 1건
3. (오분류 발견) KL → Lloydk: POST /relabel { doc_id, original_label, corrected_label, actor }
   - corrections 추가 + classifications.status='corrected'
4. 검증:
   - confirm 응답: confirmation_id + confirmed_at
   - relabel 응답: relabel_id + queue_size + retrain_threshold
   - DB: SELECT FROM corrections WHERE classification_id=... → 2건
```

### S4. 등급체계 변경 + 재학습 필요성

```
1. KL → Lloydk: GET /schema/grades → 현재 4등급 조회
2. KL → Lloydk: PUT /schema/grades { grades: [...new...], actor }
   - 새 코드 추가 / 순서 변경 / 코드 제거 시 requires_retraining=true
3. 검증:
   - 응답에 requires_retraining boolean + reason 텍스트
   - DB: classification_levels.is_active=true row가 새 목록과 일치
   - 빠진 코드는 is_active=false로 deactivate
```

### S5. 가이드 문서 업로드 → RAG 인덱싱

```
1. KL → Lloydk: POST /guide/documents (multipart)
     form: guide_id, version, effective_date, change_summary, actor (JSON), doc_type
     file: HWP/DOCX/PDF/TXT
2. Lloydk:
   - GuideService.upload(content_bytes)
   - text = _decode_best_effort(bytes)  # UTF-8 → CP949 → ...
   - RagIndexer.index_guide(...)
     · chunks = split(text, 512, overlap=64)
     · embeddings = KURE-v1 (or Hash 폴백)
     · ES.ensure_collection(secrets-guides-{tenant}-{model}-{version})
     · ES.upsert(ids, vectors, payloads)
     · ES.swap_alias(secrets-guides-{tenant}, new_index, old_index)
3. Lloydk → KL: 201 { guide_id, version, indexed, embedding_vector_count, triggers_retraining }
4. 검증:
   - status_code == 201
   - body.indexed == true (ES 가용 시)
   - body.embedding_vector_count > 0
   - ES: GET _alias/secrets-guides-{tenant} → 새 인덱스
   - ES: count secrets-guides-{tenant}-{model}-{version} > 0
5. 후속 GET /guide/documents/{guide_id} → 버전 목록에 본 업로드 포함
```

### S6. 합성 문서 생성 → 검수 → 데이터셋 편입

```
1. (스케줄 또는 admin) KL → Lloydk: POST /synth/generate
     body: { target_grade=S2, domain=tech, count=10, llm_provider=noop, actor }
2. Lloydk: 202 { synth_job_id, expected_count=10, estimated_cost_usd=0.0 (noop) }
3. (워커 백그라운드 실행) — 10건이 sample_documents 테이블에 review_status='pending_review'로 적재
4. (검수자 큐 조회) KL → Lloydk: GET /synth/queue?status=pending&limit=50
5. (각 샘플 검수) KL → Lloydk: POST /synth/{synth_id}/review
     body: { decision=approve, actor }
6. (W6 학습 데이터셋 빌드 시) 승인된 sample은 documents 테이블로 promote + training_datasets에 등록
7. 검증:
   - generate 응답: synth_job_id + expected_count
   - queue 응답: items[].review_status='pending_review'
   - review 응답: synth_id + final_status='approved'
```

### S7. 능동학습 URGENT_RETRAIN 트리거

```
1. (운영 중) S3 시나리오 반복 → corrections.direction='underclass' 10건 누적
2. (스케줄 or admin) Lloydk: evaluate_retraining_need() → retrain_status='URGENT_RETRAIN'
3. (자동 or admin) KL → Lloydk: POST /train { training_type='incremental', actor }
4. Lloydk: 202 { train_job_id, status_url }
5. (Celery 워커) train_classifier_task.delay(...) 또는 PoC는 queued만
6. (모니터링) KL → Lloydk: GET /train/jobs/{train_job_id} → status='queued' → 'running' → 'completed'
7. (학습 완료) Lloydk: ModelVersion 등록 + consume_corrections_for_run(run_id) → corrections.consumed_in_run=run_id
8. 검증:
   - active_learning gauge: lloydk_active_learning_pending_underclass >= 10
   - Prometheus 알람: ActiveLearningUrgent 발화
   - DB: training_runs 1건 생성
   - corrections.consumed_in_run = run_id (학습 후)
```

### S8. 운영 지표 조회

```
1. KL → Lloydk: GET /metrics/latest → 현재 활성 모델의 메트릭
2. KL → Lloydk: GET /metrics/history?limit=20 → 모델 버전별 메트릭 추이
3. KL → Lloydk: GET /metrics/confusion-matrix/{model_version} → CM + fnr_by_grade
4. 검증:
   - latest 응답: model_version, accuracy, f1_macro, fnr_overall, fnr_by_grade
   - history 응답: items 배열 (최대 limit개)
   - cm 응답: labels (4), matrix (4×4), fnr_by_grade
   - 활성 모델 없으면 latest는 404
```

## 3. 통합 테스트 자동화 (tests/test_kl_integration.py)

본 8 시나리오를 TestClient로 자동화한 스켈레톤. PoC 환경(noop LLM, hash embedding, in-memory ES 폴백)에서 실행 가능. 운영 환경에선 실 LLM·실 ES로 자동 전환.

**핵심 픽스처**: `kl_actor`, `admin_actor`, `tenant_seed` (S3 등에서 PG 필요 시 skipif)

**검증 가드**:
- PG 미가용 시: corrections·classifications 영속화 검증은 skip
- LLM API 키 없을 시: S6는 `llm_provider=noop`로 강제 (estimated_cost_usd=0.0)
- ES 미가용 시: S5의 indexed=false도 OK (best-effort 응답)

테스트 스켈레톤은 `tests/test_kl_integration.py`로 신규 작성.

## 4. 일관성·신뢰성 점검 항목

KL 통합 테스트 통과 후 운영 전환 직전 확인:

- [ ] 모든 시나리오 200/201/202/404 응답 코드 OpenAPI와 1:1 일치
- [ ] audit_log에 8 시나리오 전부 기록 (action·actor·target·success)
- [ ] Prometheus 지표 8 시나리오 모두 lloydk_requests_total에 카운트
- [ ] 분류 → 보정 → 재학습 사이클이 corrections.consumed_in_run으로 닫힘
- [ ] /guide/documents 업로드 시 ES alias가 새 인덱스로 스왑됨
- [ ] /schema/grades PUT 시 빠진 등급은 is_active=false (cascade 안전)
- [ ] /metrics/latest는 stored → 라이브 폴백 정상

## 5. 회신·일정 의존성

| 항목 | 자체결정 | KL 회신 필요 |
|---|---|---|
| 인증 방식 (X-API-Key vs JWT) | API Key 동결 | K3 회신 시 차이만 패치 |
| 인터페이스 명세 (20 path) | 자체 작성 doc/03 | K2 회신 시 yaml 검토 의견 반영 |
| 통합 테스트 일정 | W8 이후 즉시 가능 | K4 — KL 측 일정 합의 |
| KL 담당자 | 미정 | K4 — 통합 PM·개발 담당 지정 |

→ K2·K3·K4 회신이 늦어도 본 8 시나리오는 **자체 환경에서 사전 검증 완료** 가능. 실 KL 통합은 회신 후 1주 내 시작 가능.
