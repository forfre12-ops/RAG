## 2. 데이터 출처

### 2.1 공개 데이터 (즉시 확보, 라벨 외부)

| # | 출처 | 활용 데이터 | 라이선스 | 용도 |
|---|---|---|---|---|
| D1 | **AI Hub** (aihub.or.kr) | 한국어 행정문서 OCR, 법률·계약서 코퍼스, 행정문서 데이터 | AI Hub 이용약관 (비영리 연구 가능, 공공사업 활용 사전 신청) | M2 추출 PoC, 도메인 어휘 학습 |
| D2 | **공공데이터 포털** (data.go.kr) | 정부공문서 샘플, 행정용어 사전 | 공공누리 1유형(자유이용) | S3 라벨 후보 |
| D3 | **모두의 말뭉치** (corpus.korean.go.kr) | 신문/일반 코퍼스 | 신청 후 학술/공공 가능 | 도메인 어휘·정규화 학습 |
| D4 | **국가법령정보센터** | 영업비밀보호법, 부정경쟁방지법, 가이드라인 | 공공누리 | RAG 인덱스 시드 |
| D5 | **KIPRA 영업비밀보호센터 공개자료** | 영업비밀 등급분류 가이드, FAQ | 발주처 공식 자료 | **라벨링 규칙(M3 YAML) 산정 기준** |
| D6 | **금융감독원 DART** | 기업 공시 (사업보고서, 분기보고서) | 공개 자료 (재배포 제한 유의) | S3 공개 자료 라벨 |

**확인 필요**: D1·D3은 사전 신청·승인 필요 (각 1~2주 소요). **PoC 시작 전 즉시 신청** 권장.

### 2.2 LLM 합성 데이터 (FUN-003 사전 실행)

| 항목 | 내용 |
|---|---|
| 생성 LLM | Claude Sonnet 4.6 (PoC 단계 기본값) |
| 시드 컨텍스트 | D4·D5 가이드 문서 발췌 + 등급 정의 + 도메인별 템플릿 |
| 등급별 생성 수량 | TS 400 / S1 500 / S2 400 / S3 200 = **1,500건** |
| 평균 길이 | 1,000~3,000자 |
| 예상 비용 | 1,500건 × $0.025 ≈ **$37.5** (수행사 부담) |
| 생성 절차 | M1 SyntheticDocGenerator 활용 (사전 PoC 코드) |
| 안전장치 | PII(주민번호/실인명) 정규식 필터, 실재 기업명 사전 차단, 합성 표기(`[가상기업A]`) 강제 |

#### 합성 프롬프트 골격
```
[시스템]
당신은 한국의 영업비밀 등급분류 가이드 전문가다. 다음 가이드를 근거로
등급 {GRADE}({GRADE_KR})에 해당하는 가상의 사내 문서를 작성한다.

[가이드 컨텍스트]
{GUIDE_CHUNKS}

[등급 기준]
경제적 가치: {V_THRESHOLD}
비공지성: {NP_THRESHOLD}
관리수준: {ML_THRESHOLD}
유출 시 영향도: {LI_THRESHOLD}

[제약]
- 실재 기업/인명/주민번호/연락처 금지
- 문서 유형: {DOC_TYPE} (사업계획서/연구노트/...)
- 길이: 한국어 {LEN_MIN}~{LEN_MAX}자
- 출력은 JSON: {title, body, document_type, dept_hint, rationale_tags}

[작성]
```

### 2.3 발주처 협조 데이터 (가능 시)

| 시나리오 | 가능성 | 활용 |
|---|---|---|
| 비밀해제(declassified) 실문서 제공 | 보통 | Test set 강화 |
| 익명화(개인정보·기업명 마스킹) 샘플 | 낮음~보통 | Validation 강화 |
| 가이드라인·정책문서만 제공 | **높음** | RAG 시드 + 라벨링 규칙 |

→ 본 계획은 **2.3 없이도 진행 가능**하도록 2.1+2.2만으로 4,000건 확보 가능하게 설계. 제공 시 Test셋에 50~300건 추가하여 외부 일반화 검증.

## 4. 검수·라벨링 절차

### 4.1 합성 데이터 검수 (필수)
- **전수 검수**: 1,500건 모두 검수자 2명이 검토 (1차)
- **이중 검수**: 등급 일치 시 채택, 불일치 시 시니어 검수자가 조정 (2차)
- **합격 기준**:
  - 등급 적정성 (검수자 등급 = 합성 라벨 일치율 ≥ 90%)
  - 자연스러움 (4점 만점 3점 이상)
  - PII 없음
- **반려 데이터**: 별도 보관하여 프롬프트 개선 데이터로 재활용
- **인력·시간**: 검수자 2명 × 일 100건 × 8일 = 1,600건 처리 (10% 여유)

### 4.2 공개 데이터 라벨링
- D2/D6 일반 공개 자료: **자동 라벨 S3** (1차)
- D1 행정문서: 도메인·민감도 기준으로 **수동 라벨링 후보** → S2/S3 후보로 분류
- D5 가이드 문서: 라벨링 대상 아님(라벨링 *기준*으로 사용, RAG 시드)
- 검수자 가이드라인: KIPRA 가이드 + 라벨링 규칙 YAML 동시 참조

### 4.3 검수 UI 도구
- 임시: **doccano** (오픈소스 라벨링 도구, Docker 1컨테이너)
- 입력: `synthetic/*.jsonl` 또는 `labeled/draft.jsonl`
- 출력: 검수자 결정(등급, 점수, 코멘트) + 합의 결과
- 본 PoC 단계에서는 doccano로 충분. 운영 단계는 KL UI(`/synth/queue`) 사용.

## 6. 데이터 품질·편향 점검

### 6.1 품질 지표 (PoC 데이터셋 자체 평가)
| 지표 | 목표 |
|---|---|
| 검수자 간 일치도(Cohen's Kappa) | ≥ 0.75 |
| 합성 데이터 검수 합격률 | ≥ 85% |
| 등급별 평균 문서 길이 편차 | CoV ≤ 0.3 (등급간 길이 편향 방지) |
| 도메인별 등급 분포 균형 | 카이제곱 검정 p ≥ 0.05 (특정 도메인↔등급 강결합 방지) |

### 6.2 잠재 편향과 대응
| 편향 | 대응 |
|---|---|
| 합성 데이터의 LLM 스타일 흔적 | 다중 LLM 혼합 생성(Claude/Qwen 7:3), 표현 다양성 검수 |
| 등급별 어휘 누설 (예: "특급기밀" 키워드가 항상 TS에 등장) | 후처리로 직접 라벨 단어 제거·치환 |
| 도메인 편향 | §1.3 분포 기준 모니터링 |
| 검수자 1인 편향 | 이중 검수 + 카파 측정 |

## 7. 일정 (PoC 4주와 정합)

```
W1  [데이터 신청·수집]      D1/D3 신청·승인 / D2/D4/D5/D6 즉시 수집
    [합성 인프라 준비]       M1 SyntheticDocGenerator 골격 + 프롬프트
    [P4 시작]                 추출 라이브러리 검증 (D1 표본)
W2  [합성 1차 실행]           1,500건 생성, 검수 큐 적재
    [P2 임베딩 시작]          D5 가이드 RAG 인덱스 구축
W3  [검수 진행]                전수 1,600건 검수 (이중)
    [공개 데이터 라벨링]      D1/D2/D6 라벨링

    [P5 E2E 스모크]            업로드→분류 통과
    [데이터셋 v1.0 동결]      manifests/dataset_v1.0.yaml 확정
```
