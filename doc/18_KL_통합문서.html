KL 통합 가이드

보관본 — 현행 연동 계약으로 사용하지 마십시오.
이 문서는 2026-05 PoC v1의 21개 endpoint 설명을 보존합니다. 현행 KL 연동 계약의 정본은 doc/03_openapi_koipa_kl.yaml이며, 코드와의 정합성 검사를 통과한 62개 외부 API operation을 정의합니다.

KL 시스템이 Koipa AI API를 연동하기 위한 인증·엔드포인트·상태값·오류 처리 레퍼런스. 21개 엔드포인트, 실제 구현 기준 작성.

⚠️
PoC 단계 제약

현재 PoC v1 기준입니다. Idempotency Key와 Rate Limit 헤더는 미구현 상태이며 본사업 전 추가될 예정입니다. 비동기 작업 큐는 메모리 기반(재시작 시 초기화)입니다.

§2  인증

API Key 방식. 모든 엔드포인트에 필수.

헤더

X-API-Key: <your-api-key>
헤더타입필수설명
X-API-Key string 필수 사전 발급된 API 키. 미포함 또는 잘못된 키 → 401 Unauthorized
X-Request-ID string (UUID) 선택 클라이언트 제공 요청 추적 ID. 미제공 시 서버가 UUID 생성 후 응답 헤더에 반환.
⚠️
SSO / JWT 협의 필요

현재 API Key 방식입니다. KL이 SSO/JWT 기반을 요구할 경우 명세 갱신이 필요합니다 (K3 협의 항목). 결정 전까지 API Key로 통합 테스트 진행 가능합니다.

Actor 메타 (선택)

요청 본문에 actor 객체를 포함해 KL 관리자 정보를 전달할 수 있습니다. 감사 로그(audit_log)에 기록됩니다.

{
  "actor": {
    "user_id": "kl-admin-001",
    "role": "admin",
    "tenant_id": "koipa"
  }
}

§4  상태값 레퍼런스

도메인별 상태 문자열 — 이넘 아닌 string 타입으로 DB 저장

ℹ️
구현 노트

PoC v1에서 상태값은 Python Enum 클래스 없이 DB string 컬럼으로 관리됩니다. 예외: 등급(grade)은 Grade(str, Enum)으로 정의됨 (TS/S1/S2/S3).

분류(Classification) 상태

상태값의미전이 조건
stagingAI 추론 완료, 관리자 확정 대기분류 완료 직후 초기값
confirmed관리자가 AI 등급을 그대로 확정POST /confirm 호출
corrected관리자가 등급을 수정해서 확정POST /relabel 호출

문서(Document) 처리 상태

상태값의미
pending전처리 대기
processing전처리 진행 중
done전처리 완료, 분류 가능
failed전처리 실패

학습(TrainingRun) 상태

상태값의미
queued큐 대기
preprocessing데이터 전처리
training학습 진행 중
evaluating평가 중
registering모델 등록 중
done완료
failed실패

합성 문서(SampleDocument) 검수 상태

상태값의미
pending_review검수 대기
approved검수 승인
rejected검수 반려

비동기 Job 상태

상태값의미
queued작업 큐 대기
running처리 중
done완료
failed실패

§5  오류 코드

HTTP 상태 코드 + 응답 본문 구조

표준 오류 응답 형식

{
  "error_code": "INVALID_GRADE",
  "message":    "grade must be one of: TS, S1, S2, S3",
  "request_id": "req-uuid-001"
}
HTTPerror_code원인대응
400VALIDATION_ERROR필수 파라미터 누락, 잘못된 형식요청 본문 검토
400INVALID_GRADEgrade 값이 TS/S1/S2/S3 외 값허용 값 확인
401UNAUTHORIZEDX-API-Key 누락 또는 잘못된 키키 재확인
403FORBIDDEN권한 부족 (role 불일치)actor.role 확인
404NOT_FOUNDdoc_id / job_id / guide_id 없음ID 재확인
409ALREADY_CONFIRMED이미 confirmed/corrected 상태인 문서에 재확정 시도상태 확인 후 relabel 사용
413BATCH_TOO_LARGE배치 1000건 초과청크로 분할 요청
422UNPROCESSABLE파싱 불가 문서 (빈 콘텐츠 등)문서 내용 검토
429RATE_LIMITED(본사업 추가 예정) 속도 제한 초과Retry-After 헤더 참조
500INTERNAL_ERROR서버 내부 오류X-Request-ID로 로그 추적
503SERVICE_UNAVAILABLE모델 로딩 중 / GPU 자원 부족헬스체크 후 재시도
ℹ️
요청 추적

모든 응답 헤더에 X-Request-ID가 포함됩니다. 오류 발생 시 이 값을 한국지식재산보호원 기술지원에 전달하면 서버 로그에서 즉시 추적 가능합니다.

§6  PoC 미구현 — 본사업 예정

현재 PoC v1에서 구현되지 않은 항목. 본사업 전 추가 예정.

항목설명예정 시점
Idempotency Key 동일 요청 중복 처리 방지. Idempotency-Key 헤더 기반 Redis 캐싱으로 구현 예정. 본사업 W1
Rate Limit IP/API-Key 기준 속도 제한. X-RateLimit-Limit, X-RateLimit-Remaining, Retry-After 헤더 제공 예정. 본사업 W1
영속 Job 큐 현재 메모리 기반 → Redis/DB 기반으로 교체. 재시작 시 작업 유지. 본사업 W2
Webhook 비동기 작업 완료 시 KL 시스템에 push 알림. 폴링 제거 가능. 본사업 W3
멀티 테넌트 K5 협의 결과에 따라 tenant_id 기반 데이터 격리 강화. (DB 컬럼은 이미 존재) K5 회신 후
실 학습 로직 POST /train 현재 stub. GPU 확보(Q1) 후 KF-DeBERTa 파인튜닝 활성화. Q1 회신 후

§7  KL 통합 체크리스트

통합 테스트 전 KL 측 확인 항목

인프라 / 인증

  • ☐
    API Key 발급 확인
    한국지식재산보호원로부터 API Key 수령 및 테스트 환경 접속 확인
  • ☐
    인증 방식 최종 결정 (K3 협의)
    API Key 유지 or SSO/JWT 전환 결정 후 통합 일정 확정
  • ☐
    네트워크 접근 권한
    KL 서버 → Koipa AI 서버 포트 8000 허용 (또는 HTTPS 포트)

기본 연동

  • ☐
    헬스체크 확인
    GET /api/v1/healthz → 200 OK 응답 확인
  • ☐
    단건 분류 테스트
    POST /api/v1/classify — 실제 문서로 grade 반환 확인
  • ☐
    confirm / relabel 워크플로우
    staging → confirmed / corrected 상태 전이 KL UI 연동 확인
  • ☐
    가이드 문서 업로드
    POST /api/v1/guide/documents — KOIPA 가이드 PDF 업로드 및 indexed: true 확인

고급 연동

  • ☐
    배치 분류 + 폴링
    POST /classify/batch → GET /classify/jobs/{id} 폴링 2초 간격 확인
  • ☐
    메트릭 대시보드 연동
    GET /metrics/latest 데이터를 KL 대시보드에 표시
  • ☐
    오류 처리 확인
    401, 404, 409, 413 등 오류 응답을 KL UI에서 적절히 표시
  • ☐
    X-Request-ID 로깅
    KL 애플리케이션 로그에 X-Request-ID 기록 (오류 추적용)

협의 대기 항목 (K1~K5)

  • ⏳
    K1 — KL 인프라 현황 회신
    PostgreSQL·ES·Redis·인증 사용 여부 → ES 있으면 Qdrant 대체 검토
  • ⏳
    K2 — OpenAPI 명세 검토
    03_openapi_koipa_kl.yaml 16개 엔드포인트 KL 검토 의견
  • ⏳
    K3 — 인증 방식 최종 결정
    API Key / SSO / JWT 결정 → 명세 갱신 여부
  • ⏳
    K4 — KL 통합 일정 마일스톤
    통합 테스트 가능 시점 확인 → PoC E2E 시연 일정 조율
  • ⏳
    K5 — 멀티 테넌트 요구 강도
    단일 or N개사 → Qdrant 네임스페이스·Postgres tenant_id 정책 결정
