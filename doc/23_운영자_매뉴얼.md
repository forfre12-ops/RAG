| Alertmanager | http://am:9093 | FIRING 알람 없음 |

## 3. 백업 운영

### 3.1 자동 백업 cron (doc/11 §6 인용)
- 매일 01:00: `python scripts/backup_postgres.py` → MinIO `backups/pg/`
- 매일 02:00: `python scripts/backup_es_snapshot.py` → ES snapshot repo
- 매일 03:00: `python scripts/backup_minio_mirror.py` → 보조 스토리지

### 3.2 백업 검증 (주 1회 일요일)
```bash
python scripts/dr_restore_check.py --target staging
```
- 최신 dump를 staging 인스턴스에 복원하여 schema 일치·핵심 카운트 검증
- 실패 시 즉시 `incident-backup` 알람 채널 통지

### 3.3 보존 정책
- pg dump 30일, ES snapshot 30일, MinIO 미러 90일
- 운영 진입 후 발주처 요청 시 보존 기간 별도 협의

## 4. ES 인덱스 운영

### 4.1 색인 상태 확인
```bash
curl -s http://es:9200/_cat/indices/lloydk-*?v
```
주요 인덱스:
- `lloydk-docs-{tenant_id}` — 문서 청크
- `lloydk-guide-{tenant_id}` — 등급분류 가이드

### 4.2 재색인 (Reindex)
- 가이드 v2 도착 등 매핑 변경 필요 시:
```bash
python scripts/reindex_documents.py --tenant <id> --target lloydk-docs-v2
```
- alias `lloydk-docs-{tenant_id}` 를 새 인덱스로 swap → 무중단 전환

### 4.3 임베딩 사전 캐시 빌드
GPU/임베딩 모델 변경 시:
```bash
python scripts/build_embedding_cache.py --rebuild
```

### 4.4 Nori 사용자 사전 갱신
1. `poc/infra/es/userdict_ko.txt` 편집
2. `docker compose restart es` (단일 노드) 또는 rolling restart
3. 영향 인덱스 reindex 필요 (mapping 분석기 적용)

## 5. 사용자·검수자 관리

### 5.1 검수자 추가
```bash
# DB 직접 (운영자 권한)
INSERT INTO users (id, email, role, tenant_id, created_at)
VALUES (gen_random_uuid(), 'reviewer@org.kr', 'REVIEWER', '<tenant_id>', now());
```
- `role`: ADMIN / REVIEWER / VIEWER
- `tenant_id`: 멀티테넌트 격리 (K5 동결)

### 5.2 API 키 발급 (운영 기본: X-API-Key)
```bash
python scripts/issue_api_key.py --tenant <id> --role REVIEWER --expires 90d
```
- 출력은 1회만 표시 — 안전한 채널로 전달
- 회전: `--rotate` 옵션으로 신키 발급 + 구키 grace 7일

### 5.3 JWT 전환 (P1-C3 도입 후)
- `settings.auth_mode=jwt` 설정
- JWKS 엔드포인트 `/.well-known/jwks.json` 공개
- 키 로테이션: `scripts/rotate_jwt_keys.py --rotate` (kid 변경)

## 6. 장애 1차 대응 절차

### 6.1 알람 등급
| 등급 | 정의 | 1차 대응 시간 |
|---|---|---|
| P1 | 서비스 전면 중단 | 15분 이내 |
| P2 | 핵심 기능(분류·색인) 장애 | 1시간 이내 |
| P3 | 보조 기능(가이드 업로드 등) 장애 | 4시간 이내 |
| P4 | KPI 회귀·드리프트 | 익영업일 |

### 6.2 표준 분기 (Decision Tree)
1. **/health 200?** → 아니오 → §6.3 API down
2. **ES green?** → 아니오 → §6.4 ES yellow/red
3. **Celery 큐 적체?** → 예 → §6.5 worker scaling
4. **드리프트 알람?** → §6.6 모델 회귀

### 6.3 API down
```bash
docker compose logs api --tail 200
docker compose restart api
# 30초 후 /health 재확인. 실패 시 직전 이미지로 롤백
docker compose pull api:prev && docker compose up -d api
```

### 6.4 ES yellow/red
```bash
curl -s http://es:9200/_cat/shards | grep UNASSIGNED
# 1차: replica가 미배치된 단일 노드 → 정상(yellow)
# 2차: 디스크 watermark — flood_stage 초과 시 데이터 정리
curl -X PUT http://es:9200/_cluster/settings -H "Content-Type: application/json" -d '{
  "transient": {"cluster.routing.allocation.disk.watermark.high": "85%"}
}'
```

### 6.5 Celery 큐 적체
```bash
celery -A lloydk.workers.celery_app inspect active
# 워커 스케일 아웃
docker compose up -d --scale worker=8
# 비상 — 큐 분리 (P1-D3 적용 후)
celery -A lloydk.workers.celery_app worker -Q ingest -c 4 &
```

### 6.6 KPI 회귀(drift)
- PSH 알람(F2)에서 자동 GitHub Issue 생성됨
- 1차: 직전 모델 버전으로 롤백
```bash
python scripts/rollback_model.py --to <model_version>
```
- 2차: drift 원인 분석 (B4 drift monitor 결과 + 신규 합성 문서 분포)
