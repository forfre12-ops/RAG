## 2. 목표 아키텍처 — 2 게이트

| | 질문 | 방식 | 데이터 |
|---|---|---|---|
| **Gate 1 출처** | 이미 공개된 문서인가? | **규칙**(메타데이터). 공개경로→S3 하드 (= 비공지성 게이트) | 출처 메타데이터 |
| **Gate 2 내용** | 출처 모르고 내용만 보면 얼마나 민감? | **ML** (진짜 문제는 여기뿐) | §3 유추-문서 |

비공지성을 가중합 요소에서 **필요조건 게이트로 복원** — 부정경쟁방지법 §2.2("공공연히 알려져 있지 아니하고")와 정합. 공개된 정보는 경제가치·관리수준과 무관하게 영업비밀 불성립.

## 3. 데이터 전략

- **합성 시나리오 117건 제거** — 단 진짜 대체재(아래) 확보 *후*. (선제거 시 고위험 등급 학습 붕괴)
- **학습셋 진짜 공개판례 → S3 재라벨** — 과분류 근본 편향 제거. 게이트는 출처 아는 것만 막으므로 학습 라벨도 같이 고쳐야 출처 불명 문서까지 해결.
- **Gate 2용 진짜 "유추-문서"** = 내용은 비밀등급인데 공식 경로로 공개된 실제 문서:

| 소스 | 등급 | 비고 |
|---|---|---|
| **특허/공개특허 (KIPRIS)** ★ | TS/S1 | 특허 = 공개를 택한 영업비밀. 국가핵심기술 분야 직결, 무료·대량 |
| 공정위 의결서 | S2 | 기업 제출 가격·원가·전략이 공식 공개 |
| FOIA·회생/파산·DART 비밀해제 | S1/S2 | 실제 내부문서가 공식 공개 |
| 영업비밀 판례 별지/인정사실 (재구성) | S1/S2 | 보조. verbatim 금지 |
| 공개판례·공시 | S3 | 진짜 네거티브 |

**배제:** 유출·해킹 문건(합법성·평판 리스크).

### ⚠ 재구성 함정 (반드시 준수)
영업비밀 판례 *본문*은 그 자체가 공개문서(S3). 법원의 비밀 묘사를 verbatim으로 S1/S2 라벨링하면 "공개 판례체 = 비밀"을 다시 학습 → 85% 버그 재발. **내부문서 형태로 rewrite + FPR 테스트풀과 disjoint** 유지.

## 6. 실행 순서 (순서가 곧 안전장치)

```
0) 가이드 v1.1 (비공지성 게이트 보강)               ← 앵커        [본 권장안과 함께]
1) 게이트 ON + 학습셋 공개판례 → S3 재라벨 → 재학습   ← 즉시·근본   [진행]
2) 특허(TS/S1) → 공정위·FOIA(S2) → 판례별지  진짜 유추-코퍼스
3) 합성 117건 ↔ 진짜로 교체 (교체 후 제거)
4) 재학습 → 두 테스트 재측정 (과분류↓ & 고위험 recall 유지)
5) 두 테스트 CI 상시 게이트화
```

0)·1)은 데이터 마이닝 없이 가능 — 가장 싸고 효과 큼. 그게 끝나야 ML(Gate 2)이 측정 가능한 문제로 좁혀짐.

### 1단계 실측 결과 (2026-06-03) — 게이트가 정답 레버, 데이터 재라벨은 아님

진짜 공개판례 기준 3개 접근 비교:

| 접근 | 과분류(진짜 공개문서 600건) | 고위험 recall(진짜 비밀) |
|---|---|---|
| cost2 (기존 배포) | 0.85 [0.82,0.88] ❌ | 유지 (홀드아웃 FNR 0.056*) |
| **콘텐츠 모델 재라벨** | **0.00** ✅ | **붕괴** ❌ (합성 fnr_high 0.18→0.80, 홀드아웃 FNR_underclass 0.056→0.33) |
| **게이트(cost2 + source_prior=S3)** | **0.00** ✅ | **유지** ✅ (게이트는 공개출처만 발동, 콘텐츠 모델 무손상) |

(*홀드아웃 FNR은 합성 비중이 커 낙관적. 진짜 측정은 reports/p1_real_public_fpr.)

**결론 (실증):**
1. **출처는 결정론적 게이트(Gate 1)로 처리한다.** `source_prior_enabled=True, cap="S3"` 활성화. 공개출처 문서를 트레이드오프 0으로 S3 강제. 검증: `scripts/verify_gate.py` — 메타데이터 없으면 93% 과분류, source=판례면 0%.
2. **콘텐츠 모델 데이터 재라벨은 하지 않는다.** 진짜 고위험 데이터(2단계) 없이 공개판례만 S3로 내리면 모델이 전부 S3로 무너져(비밀 80% 미탐) — 과분류를 정반대 과소분류로 뒤집을 뿐. → "교체 후 제거" 순서가 실증됨. 재라벨 모델은 `artifacts/classifier_p1_retrain_v4_relabel` (애블레이션 보존, 미배포).
3. **출처 불명 문서의 과분류는 미해결** — 게이트는 출처 아는 것만 막음. 이건 2단계 진짜 유추-데이터로 콘텐츠 모델을 재균형해야 풀린다(재라벨-다운 + 진짜 고위험-업 동시).

배포 모델은 cost2 유지 + 게이트 ON. 다음은 2단계(특허·공정위 진짜 유추-코퍼스).

### 2단계 조사 결과 (2026-06-03) — 진짜 고위험 *내용*은 본 환경에서 구조적 차단

| 소스 | 상태 |
|---|---|
| 특허(KIPRIS) ★ | ❌ API키 필요. HF 한국특허 = 28행 Q&A(무용) / 25K는 영어 |
| 공정위·DART·AIHub | ❌ 키·승인 필요 (datasets/raw/manifest.yaml `auto_collect=false`) |
| court-grounded (85K 판례) | ⚠ 358건 추출했으나 **93%가 기술실체 0** — 레닥션(법원이 비밀 실체 미기재) |
| 클라우드 LLM | ❌ 키 없음 / 로컬 LLM(qwen3:14b) ✅ 가용(생성=합성) |

**근본 원인 데이터 확정:** 학습셋의 "비밀" 데이터(labeled_oss_v1 등)는 **진짜 공개 판례를 키워드로 TS/S1/S2 라벨한 것** — 모델이 배울 진짜 기밀 문서가 프로젝트에 없음. 비밀탐지 = 공개 법률문서 패턴매칭. 이것이 공개문서 85% 과분류의 데이터 차원 원인.

**결론:** 진짜 고위험 내용은 (a) KIPRIS 특허(키) 또는 (b) 발주처 실제 분류문서 외엔 없음. 추가 합성은 진단한 문제 재생산이라 지양.

**경로 결정: KIPRIS 특허(진짜).** 파이프라인 구축 완료 — KIPRIS Plus API 라이브 검증(2026-06-03): 엔드포인트 `kipo-api/kipi/patUtiliInfoSearchSevice/getWordSearch`, 키 파라미터 `ServiceKey` 확정(DUMMY→resultCode 30 SERVICE_KEY_IS_NOT_REGISTERED). **유일한 잔여 선행조건 = 무료 키 발급.**

KIPRIS 키 발급: https://plus.kipris.or.kr 가입(무료) → API 서비스 신청 → "특허실용신안 단어검색(getWordSearch)" → 발급된 ServiceKey를 `poc/.env`에 `KIPRIS_SERVICE_KEY=...` 추가.

키 확보 후 실행 순서(전부 준비됨):
```
1) python scripts/kipris_collect.py --probe                  # 키 동작 확인
2) python scripts/kipris_collect.py --per-keyword 60         # 진짜 특허 초록 수집(TS/S1)
3) python scripts/build_step2_dataset.py                     # 재라벨(판례→S3)+특허(TS/S1) 병합 + 특허 홀드아웃 분리
4) python scripts/p1_train_classifier.py --mode full --train-path datasets/labeled_p1_retrain_v4_step2/train.jsonl \
     --val-path datasets/labeled_oss_v1/val.jsonl --test-path datasets/labeled_oss_v1/test.jsonl \
     --fnr-cost-multiplier 2.0 --early-stop-metric fnr_high --epochs 5 \
     --output-dir artifacts/classifier_p1_retrain_v4_step2 --no-mlflow
5) python scripts/eval_real_public_fpr.py --model-dir <new> --report reports/p1_real_public_fpr_step2
   python scripts/eval_trusted_ci.py    --model-dir <new> --report reports/p1_trusted_ci_step2
   python scripts/eval_patent_recall.py --model-dir <new>   # 진짜 고위험 recall(구조적 최초)
```
기대: 과분류 낮게 유지(판례→S3) + 진짜 특허에서 고위험 recall 회복(1단계 relabel-only 붕괴와 대비). `eval_patent_recall`은 합성 아닌 *진짜* 고위험 recall의 첫 측정(단 선택편향 — §5).
