용도: AI 분류 결과 확인·정정·등급 경계 판단 가이드

## 1. 검수자의 역할

AI(Lloydk 분류기)는 4등급(TS·S1·S2·S3) 중 1개를 자동 판정하지만, **법적 책임은 인간 검수자에게** 있습니다. 검수자는:

1. AI 판정 결과와 근거(evidence·factors·RAG context)를 확인
2. 동의 → **confirm** (그대로 확정)
3. 이의 → **relabel** (수정 라벨 + 사유 입력)
4. 모호 → **escalate** (선임 검수자 또는 AI팀 협의)

→ relabel/escalate 누적 데이터는 **Active Learning** 큐에 적재되어 재학습 트리거가 됩니다 (doc/04 §6.3).

## 3. 4등급 판단 기준 (doc/22 가이드 v1 인용)

| 등급 | 표지 | 정의 | 대표 키워드 |
|---|---|---|---|
| **TS** 특급기밀 | 빨강 | 유출 시 **회사 존립 위협** | M&A·핵심 원천기술·신약 후보·암호키 |
| **S1** 1급 비밀 | 주황 | 유출 시 **중대 손해** | 미공개 사업계획·고객 핵심정보·재무 미공개 |
| **S2** 2급 대외비 | 노랑 | 유출 시 **경쟁상 불이익** | 내부 단가표·운영 매뉴얼 내부판 |
| **S3** 3급 공개/일반 | 초록 | 유출 시 **영향 미미** | 보도자료·공시·공개 API 문서 |

### 3.1 정본 3요건(S·V·M) 곱셈 산정 (B안)
- **등급 = 비공지성(S) × 경제적 유용성(V) × 비밀관리성(M)** (각 0·1·2점)
- 매핑: 8→특급 / 4→1급 / 1·2→2급 / 0→3급. **한 요소라도 0이면 곱=0 → 공개**(비공지성 게이트)
- (구 4요소 가중합 30·25·15·30은 A안 100점 보조용으로만 보존)

### 3.2 등급 경계 판단 팁
- **TS ↔ S1**: "회사 존립 위협"이 핵심. M&A, 핵심 원천기술, 안보·국가핵심기술 연계는 TS.
- **S1 ↔ S2**: 외부 누출 시 "법적 분쟁/소송 가능성"이면 S1, "경쟁상 단순 불이익"이면 S2.
- **S2 ↔ S3**: 이미 공개 채널(IR·보도자료·공시)에 있으면 S3.

## 4. 작업 흐름

### 4.1 동의(Confirm)
- AI 판정에 동의할 때
- 클릭 후 `audit_log`에 confirm 기록 + correction 큐에는 추가 안 됨

### 4.2 수정(Relabel)
필수 항목:
- **수정 라벨**: TS/S1/S2/S3 중 1
- **사유 카테고리** (3요건 S/V/M 중 어느 게 오판단인지)
- **자유 사유 텍스트** (≥10자 권장)

수정 영향:
- `corrections` 테이블에 적재 → Active Learning 트리거 후보
- 동일 문서·동일 검수자는 1회만 (중복 방지)

### 4.3 Escalate
- 등급 경계 모호, 신규 도메인, 정책 충돌 시
- 선임 검수자(SR_REVIEWER) 또는 AI팀에게 알람 발송

---

## 5. Active Learning 트리거 임계 (doc/04 §6.3)

| 상태 | 정의 |
|---|---|
| **OK** | corrections < 50 |
| **RETRAIN_RECOMMENDED** | corrections ≥ 50 |
| **URGENT_RETRAIN** | corrections ≥ 50 **AND** underclass(보안 미탐) ≥ 10 |

- URGENT는 보안에 직접적 영향 — AI팀이 즉시 학습 트리거
- RECOMMENDED는 다음 주간 정기 재학습에 포함

검수자는 임계 도달 알람을 받으면, 가급적 24시간 내 추가 검수 보류(데이터 안정성) 후 AI팀 재학습 완료 통지를 기다리세요.

## 6. 자주 묻는 질문 (FAQ)

**Q1. AI 판정이 명백히 틀렸을 때, 사유는 얼마나 자세히?**
- 최소 10자 이상, 가능하면 어느 평가요소가 잘못 판정됐는지 명시 (예: "M&A 키워드를 놓침 — 경제적 가치 가중 0.30 → 0.85 상향 필요")

**Q2. 같은 문서를 둘 이상의 검수자가 검토하나?**
- 기본은 1인. 등급 경계 또는 escalate는 SR_REVIEWER 추가 검토 1인. 발주처 정책에 따라 cross-review 활성화 가능 (settings.cross_review=true).

**Q3. confidence가 낮을 때 (예: 0.55) 어떻게?**
- confidence < 0.7 문서는 자동으로 "검수 우선" 큐에 적재됨. 시간을 더 들여 evidence + RAG context를 확인. 사실상 등급 경계 케이스로 처리.

**Q4. RAG context가 비어있을 때?**
- 가이드 또는 과거 사례 매칭이 없다는 뜻. 신규 도메인일 가능성. doc/22 가이드 §3 등급 정의 + 3요건(S/V/M)으로 직접 판단 + escalate 권장.

**Q5. AI가 PII(주민번호·계좌)를 마스킹 안 했어요.**
- 운영 정책상 사전 마스킹은 P1-A8(NER)이 처리. 누락 사례는 즉시 AI팀에게 보고 (드리프트 신호).

**Q6. 등급 변경 후 문서가 어디로?**
- relabel은 분류만 갱신. 문서 자체의 ACL·암호화는 별도 워크플로우(KL 측). AI 시스템은 등급 라벨 + 검수 이력만 관리.

## 7. 운영상 주의 (보안)

- **계정 공유 금지**: API 키·로그인은 1인 1개
- **화면 캡처/외부 송신 금지**: 검수 화면에는 영업비밀 내용이 표시됨
