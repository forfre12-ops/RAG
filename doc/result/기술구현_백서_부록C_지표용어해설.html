지표·용어 해설

기술 구현 백서 §6~§7에 나오는 평가지표와 용어를, 비전문가도 이해할 수 있도록 풀어 설명한다. 각 지표를 어떤 모델·오픈소스로, 어떻게 측정해 수치를 얻는지까지 정리한 참고 자료다. 등급 산정은 3요건(비공지성 S × 경제적 유용성 V × 비밀관리성 M) 곱셈식을 기준으로 한다(2026-06-20 갱신).

먼저, 두 가지 공통 원리

① 정확도·재현율류 지표는 "정답지(라벨)"가 있어야 측정된다. 모델이 예측 → 정답과 대조 → 공식으로 환산한다. 정답지가 없으면 측정 자체가 불가능하다. 그래서 신뢰할 수 있는 수치는 좋은 정답지(실데이터 라벨)가 있어야 나온다.

② 속도 지표는 타이머로 잰다. 같은 작업을 여러 번 돌려 중앙값(p50)·상위 95%(p95)로 본다. 한두 번 빠른 건 의미가 없어 분포로 본다.

기호

≥ 이상(그 값 또는 더 큼 — 클수록 좋은 지표에 사용) · ≤ 이하(그 값 또는 더 작음 — 작을수록 좋은 지표에 사용) · 합격선 = 프로토타입이 통과로 인정받기 위한 최소 기준.

핵심 지표 용어
용어한 줄 뜻풀이
등급 산정 (S×V×M)3요건 곱셈식으로 등급 결정등급 = 비공지성(S) × 경제적 유용성(V) × 비밀관리성(M). 각 요건을 0·1·2점으로 독립 판독한 뒤 곱한다. 곱 매핑: 8→TS · 4→S1 · 1·2→S2 · 0→S3. 한 요건이라도 0이면 곱이 0이 되어 S3(공개)로 떨어진다. 코드 grade_from_svm(). (이전의 "4요소 가산·100점" 방식은 폐기되고 곱셈식으로 전환됨.)
S · V · M세 요건의 0·1·2 점수S(비공지성) 0=이미 공개 / 1=통상적 입수 곤란 / 2=보유자 통하지 않곤 모름. V(경제적 유용성) 0=가치 없음 / 1=비용·노력 투입 / 2=상당한 비용·노력. M(비밀관리성) 0=공개·관리 안됨 / 1=임직원 일부 공유 / 2=승인된 자만 접근.
등급 4단계 (TS·S1·S2·S3)민감도 순 분류 등급TS(특급기밀) · S1(1급비밀) · S2(2급대외비) · S3(3급/공개). 순서는 GRADE_ORDER로 정의(TS<S1<S2<S3, 숫자 1·2·3·4). 등급 간 우열 비교·미탐 방향 판정의 기준이 된다.
F1_macro분류 정확도 종합 점수 (0~1)"맞다고 한 것 중 진짜인 비율(정밀도)"과 "진짜 중 찾아낸 비율(재현율)"을 합친 균형 점수의 4등급 단순평균(macro). 등급 분포가 한쪽으로 쏠려도 속지 않아 단순 정답률 대신 쓴다. 운영 모델(KF-DeBERTa) 실측 0.686(홀드아웃 109건).
Precision · Recall · Accuracy정밀도 · 재현율 · 정답률Precision(정밀도) = 그 등급으로 예측한 것 중 진짜 비율(과분류↓). Recall(재현율) = 실제 그 등급 중 찾아낸 비율(미탐↓). Accuracy(정답률) = 전체 중 맞힌 비율. 미탐 방지가 최우선이라 고등급 Recall을 가장 중시한다.
미탐률 (FNR)비밀을 더 낮은 등급으로 흘리는 비율FNR = 1 − Recall(고등급). 핵심은 방향성 FNR — 고등급(TS·S1)을 더 낮은 등급으로 분류한 경우만 센다(저등급을 고등급으로 올린 과분류는 제외). 이 사업에서 가장 위험한 오류라 가장 엄격히 관리한다. 코드 fnr_underclass_overall / fnr_underclass_by_grade.
fnr_high고등급 평균 미탐률 (배포 게이트·롤백 기준)고등급의 방향성 FNR 평균(예: (FNR_TS+FNR_S1)/2). 배포 게이트·자동 롤백의 baseline 기준값으로 쓰여, 신규 모델의 fnr_high가 기준+허용오차를 넘으면 배포 거부·직전 모델로 복귀한다.
review_burden · high_to_s3검수 부담 · 고등급→S3 오분류review_burden = 모델이 고등급으로 판정한 비율(사람이 검수해야 할 양). high_to_s3 = 고등급(TS·S1) 문서를 S3(공개)로 잘못 떨어뜨린 비율 — 가장 치명적인 미탐 형태라 별도 추적한다.
Recall@5 (재현율@5)검색이 정답을 상위 5건에 올리는 비율검색해서 상위 5건을 가져왔을 때 정답 문서가 그 안에 든 비율. 0.80 = 10번 중 8번은 상위 5건 안에 정답이 있음. "@5"는 "상위 5건 기준".
MRR · Precision@K검색 순위 품질 지표MRR(평균 역순위) = 정답이 처음 등장한 순위의 역수 평균(정답이 위쪽에 올수록 높음). Precision@K = 상위 K건 중 정답 비율. Recall@5와 함께 검색(RAG) 품질을 본다.
ECE · temperature신뢰도 보정(캘리브레이션) 지표ECE(기대 보정 오차) = 모델 confidence와 실제 정답률의 차이(작을수록 잘 보정됨). temperature(온도) = softmax 보정 계수로 temperature.json을 자동 로드해 적용. T>1이면 과신을 완화한다(confidence 게이트가 보정된 값 위에서 동작). 서빙은 temperature를 *적용*만 하므로, 보정이 실제로 맞는지는 아래 캘리브레이션 측정 항목처럼 런타임에서 ECE로 점검한다.
캘리브레이션 측정 (ECE·Brier·reliability)0.7 게이트가 실제 정확도와 맞는지 런타임 점검서빙은 temperature 보정을 적용만 하므로, 그 보정이 실제로 맞는지를 런타임에서 측정한다. DB의 분류 결과 + 검수 교정에서 (confidence, 정답여부)를 뽑아 ① ECE(기대 보정 오차) = bin별 |평균 confidence − 실제 정확도|를 표본수로 가중 평균(0=완벽 보정), ② Brier score = 예측 confidence와 정답(1/0)의 제곱오차 평균(낮을수록 보정·정확), ③ reliability bin = confidence를 10등분해 bin별 평균 confidence·실제 정확도·격차(gap)를 산출 — 을 계산한다. 핵심은 0.7 confidence 게이트가 실제 정확도와 정합하는지 점검하는 것. ECE↑이면 temperature 재보정 신호다. 코드 m6_evaluation/calibration.py(expected_calibration_error·brier_score·reliability_bins), 평가 리포트(report.py)에 reliability 섹션(ECE·Brier·표본수 + bin 표)으로 노출.
임베딩 (Embedding)문서를 숫자 벡터로 바꾸는 기술"의미가 비슷한지"를 계산할 수 있도록 문서를 벡터로 변환한다. 근거 검색(RAG)의 핵심 기술.
라벨 일치도학습 데이터 품질 지표합성 LLM이 "이 등급으로 만들었다"고 한 문서가 실제 그 등급 기준에 맞게 생성됐는지의 일치율. 라벨이 틀린 데이터로 배우면 모델도 틀리게 배운다.
누락률 · 품질문서 추출 정확도누락률 = 원문 중 추출에서 빠진 비율(낮을수록 좋음). 품질 = 추출 텍스트가 원문과 얼마나 일치하는지 점수(0~1).
E2E (End-to-End)전체 흐름 테스트업로드부터 등급 산출까지 시스템이 끝까지 정상 동작하는지 확인하는 테스트.
confidence (신뢰도)분류 결과의 확신 정도 (0~1)모델이 이 등급 판단을 얼마나 확신하는지(temperature 보정 적용 후 값). 기준 미만이면 거부가 아니라 사람 검수 큐로 보낸다.
reviewer reliability (검수자 신뢰도)동료 합의 기반 검수자 신뢰도 (recency 편향 제거)검수자별 신뢰도를 동료 합의(peer corroboration)로 산정한다 — 한 교정이 신뢰도 표본이 되려면 그 분류의 최종 등급을 본인 이외의 검수자도 함께 선택했어야 한다(reliability = agreed ÷ comparable, comparable = 동료 비교 가능 표본). 과거 방식은 "분류의 최신 교정"을 그 자체로 합의로 삼고 최신 보정자를 자동으로 합의에 동의로 카운트해, 마지막에 손댄 사람의 신뢰도가 무조건 오르는 self-reference·recency 편향이 있었다. 이를 제거해 정확성이 아닌 최신성을 보상하던 게이밍 여지를 막았다. 본인만 손댄 분류(동료 비교 불가)는 표본에서 제외하며, 표본 부족 검수자는 게이트가 신뢰 기본값(1.0)으로 취급해 신규·소수 보정자 신뢰 의도를 보존한다. 코드 m6_evaluation/reviewer_trust.py(compute_reviewer_reliability).
도구 · 플랫폼 용어
이름한 줄풀이
HuggingFaceAI 모델계의 "앱스토어"전 세계가 만든 오픈소스 AI 모델·데이터를 올리고 내려받는 플랫폼. 우리가 쓴 분류·임베딩 모델을 여기서 받는다. 폐쇄망에는 미리 다운로드해 오프라인 번들에 담아 인터넷 없이 운영한다.
scikit-learn표준 머신러닝 계산 라이브러리F1·혼동행렬 같은 분류 지표를 계산하는 업계 표준 오픈소스.
transformersAI 모델 실행·학습 도구HuggingFace의 모델을 불러오고 학습·추론하는 오픈소스 라이브러리.
Elasticsearch검색 엔진의미 검색(벡터)과 키워드 검색을 함께 처리하는 검색 엔진. 한국어 형태소 분석 플러그인(nori)을 적용한다.
Ollama로컬 LLM 실행기외부 인터넷 없이 자체 서버(GPU)에서 LLM(Qwen3)을 돌리는 도구. 폐쇄망 운영에 적합.
혼동행렬 (Confusion Matrix)예측 vs 정답 채점표어떤 등급을 어떤 등급으로 맞혔는지/틀렸는지를 행렬로 정리한 표. 여기서 F1·미탐률을 뽑는다.
출처 게이트 (비공지성·Gate-1)공개 출처면 S3로 상한판례·공시 등 이미 공개된 출처 문서는 내용이 비밀급이어도 영업비밀이 될 수 없어(부정경쟁방지법 §2.2 비공지성) 등급을 S3로 cap한다 — S×V×M에서 S(비공지성)=0 → 곱=0 → S3와 같은 귀결이다. 내부 문서엔 적용 안 됨. (학습셋 오염 사례: 공개 판례·심결을 고등급으로 오라벨한 데이터를 정제·제외해 고등급 미탐을 크게 낮췄다.)
충돌 라우팅 (cap-conflict)출처 cap이 고등급을 덮으면 사람에게출처 게이트(하향)가 콘텐츠 가드(상향, TS/S1)를 덮을 때 자동 확정하지 않고 검수자에게 보낸다. 진짜 공개문서는 사람이 확인, 내부비밀의 출처 오태깅은 여기서 걸러진다.
최고-위험 청크 집계 (max-pooling)고등급은 가장 강한 청크 채택긴 문서를 청크로 나눠 분류할 때, 고등급(TS·S1)은 평균이 아니라 가장 강한 청크로 잡아 한 단락의 비밀이 평균에 희석되어 미탐되는 것을 막는다.
룰 폴백 집계 (severe-agg + escalation τ)모델 미로드 시에도 룰 폴백을 고등급 max-pooling + τ로 집계모델 가중치가 로드되지 않아 룰 기반 폴백으로 분류할 때도, 모델 경로와 동일하게 청크별 등급을 most-severe-wins(고등급 max-pooling, 대상 등급은 severe_agg_codes 기본 TS·S1)로 집계하고 escalation τ(classifier_escalation_tau)를 적용한다. 과거 룰 폴백은 문서를 1회 라벨링해 청크 집계·τ를 우회했는데, 그러면 한 청크에 든 비밀 신호가 다수의 평범한 청크에 희석되어 모델 경로보다 미탐(FNR) 위험이 컸다. τ를 적용하면 가장 심각한 등급부터 prob≥τ인 첫 등급을 채택하고, τ=None이면 argmax(기존 동작 보존)다. 코드 m5_inference/pipeline.py(_run_rule_fallback·_aggregate_chunk_probs·_select_pred_idx).
캘리브레이션 (temperature scaling)모델 신뢰도 과신 보정분류기가 학습에 없던 새 문체에서 과하게 확신(과신)하는 것을 완화해, confidence 게이트가 보정된 값 위에서 동작하게 한다. temperature.json을 자동 로드해 서빙 softmax에 적용하며, T>1이면 과신을 완화한다(보정 품질은 ECE로 측정).
드리프트 (Drift)운영 분포 변화 감지운영 입력의 임베딩 분포(centroid)·분류 신뢰도·정정율을 학습 시점과 비교해 성능 저하를 조기 감지·경보한다. 학습 시 임베딩 centroid를 저장해 운영 분포와의 거리로 판정한다(거버넌스 C-drift). 판정 신호는 학습 분포 대비 KL divergence와 아래 cosine_mean shift를 함께 본다.
drift 히스테리시스 (연속위반)단발 스파이크 무시, N회 연속 위반 시 경보임베딩 drift 경보가 일시적 단발 스파이크에 바로 켜지지 않도록, 임계를 N회 연속 위반했을 때만 alert를 켠다. 연속 위반 횟수는 상태 파일(drift_state.json)에 영속하며, 위반이 아니면 0으로 리셋해 스파이크가 누적되지 않게 한다. 필요 연속 횟수는 설정 LLOYDK_DRIFT_CONSECUTIVE_REQUIRED로 조정(기본 1 = 기존 단발 동작 보존, 2~3으로 올리면 단발 억제). 코드 services/drift_monitor.py(run_drift_check).
drift unknown 표기 (은폐 방지)bin 불일치 시 KL=0 폴백 대신 재샘플링/unknown저장된 학습 히스토그램의 bin 수가 현재와 다를 때, 과거에는 KL=0(=drift 없음)으로 폴백해 진짜 drift를 숨기는 false-negative(은폐) 위험이 있었다. 개선: bin이 다르면 누적분포(CDF) 선형보간 재샘플링으로 같은 bin 수에 맞춰 분포 대 분포로 KL을 산출하고, 재샘플링조차 불가능한 경우(히스토그램 부재 등)에만 alert_status="unknown"으로 표기해 'drift 없음'으로 오인되지 않게 한다.
cosine_mean shift분포 중심 이동 신호 (KL과 별개)학습 표본은 자기 centroid 대비 cosine이 1.0 부근에 몰리므로, 운영 입력의 평균 cosine(cosine_mean)이 1.0에서 멀어질수록 분포 중심이 이동(=drift)했다고 본다. KL divergence와 독립된 보조 신호로, 임계(LLOYDK_DRIFT_COSINE_SHIFT_THRESHOLD, 기본 0=비활성)를 넘으면 위반으로 판정한다. KL을 신뢰할 수 없는 unknown 상황에서는 이 cosine 이동 신호만으로 보수적으로 판단한다.
FNR-safe 오버라이드불일치 시 더 높은 등급 채택S×V×M 등급과 콘텐츠(룰·모델) 등급이 어긋날 때 더 민감한(높은) 등급을 채택해 미탐을 막는 안전장치. 서빙 경로에 항상 적용되어 원시 argmax보다 미탐률이 크게 낮아진다.
needs_review거부 아닌 사람 검수 라우팅저신뢰·충돌 등으로 자동 확정이 부적절할 때의 응답 상태. 분류를 막지 않고 검수자 큐로 보내 사람이 최종 확정한다.

약어한 줄풀이
C-esc에스컬레이션 임계값 (escalation τ)고등급 미탐을 더 강하게 막기 위한 confidence 임계값. 기본은 None(argmax) — 서빙 경로의 방향성 FNR이 이미 0.018, FNR_TS=0이라 추가 조정이 불필요. 발주처 요구 시 τ=0.35로 고등급(TS·S1) 미탐을 모두 0으로 강제할 수 있으나 F1이 약 2.8%p 하락한다(τ≤0.25는 과분류 급증으로 비권장). 같은 τ·most-severe-wins 규칙은 모델 미로드 시의 룰 폴백 경로에도 동일하게 적용된다(위 "룰 폴백 집계" 항목 참조).
C-eval서빙경로 평가 (evaluate_via_serving)모델을 실제 배포(서빙) 경로 전체 — 캘리브레이션 + FNR-safe 오버라이드 + 최고-위험 청크 집계 — 를 통과시켜 측정하는 평가 방식. 평가 결과가 실배포 동작과 일치함을 보장한다. 원시 argmax로 재면 미탐을 약 9배 과소평가(원시 FNR 0.167 vs 서빙 FNR 0.018).
C-cons검수자 신뢰도 · 2인 검토 (reviewer trust)검수자별 신뢰도 = 동료 합의(peer corroboration)와 일치한 비율(agreed/comparable)로 산출하고 번복(overturned) 이력을 추적한다. 고등급 문서는 신뢰도 기준을 적용한 2인 검토 게이트로 확정한다. (아래 "reviewer reliability" 항목 참조 — 본인 최신 보정에 자동 동의하던 self-reference·recency 편향을 제거.)
C-ver모델 버전 · 롤백 (version & rollback)학습된 모델은 항상 버전으로 등록(이력 보존)되며, 배포 게이트를 통과하고 자동 활성화가 켜진 경우에만 활성화한다(기본은 수동·보수적). 라이브 운영 데이터의 fnr_high가 기준을 초과하면 직전 활성 버전으로 자동 롤백한다.
C-drift드리프트 centroid (분포 변화 감지)학습 시점의 임베딩 centroid를 저장해 운영 입력 분포와 비교, 거리가 멀어지면 성능 저하를 조기 경보한다(위 "드리프트" 항목 참조).
지표별 측정 방법 — 어떤 모델·오픈소스로, 어떻게

P1 — F1 · 방향성 미탐률 (분류 모델)

모델 / 오픈소스: 분류기 = KF-DeBERTa(kakaobank/kf-deberta-base), 실행 = HuggingFace transformers, 지표 계산 = scikit-learn.

측정 방법: ① 정답이 달린 평가셋 문서를 모델에 넣어 예측 등급을 받는다(평가도 서빙 경로 전체를 통과시키는 C-eval 방식). ② 예측 vs 정답을 한 칸씩 대조해 혼동행렬(confusion_matrix)을 만든다. ③ F1_macro = f1_score(정답, 예측, average='macro') — 4등급별 정밀도·재현율을 평균낸 종합 점수. ④ 방향성 미탐률(FNR) = 실제 고등급(TS·S1)인데 더 낮은 등급으로 예측한 건수 ÷ 실제 고등급 총건수(과분류는 제외, fnr_underclass). 등급별로 산출하고, 그 평균인 fnr_high를 배포 게이트·자동 롤백의 baseline으로 쓴다(고등급 ≈0% 목표). → "정답지에 모델을 서빙 경로로 돌려 채점표를 만들고, 거기서 F1과 방향성 FNR을 뽑는다."

※ 평가↔서빙 갭(핵심): 동일 모델·홀드아웃(109건)이라도 원시 argmax로 재면 방향성 FNR 0.167·F1 0.632인 반면, 실배포 서빙 경로(캘리브레이션+FNR-safe 오버라이드+최고-위험 청크 집계)로 재면 방향성 FNR 0.018(FNR_TS=0.000)·F1_macro 0.686·Accuracy 0.706이다. 약 9배 차이라, 안전성은 반드시 서빙 경로 기준으로 측정한다.

P2 — Recall@5 · 응답속도 (검색 / 임베딩)

모델 / 오픈소스: 임베딩 = BGE-M3(BAAI/bge-m3, HuggingFace), 검색 = Elasticsearch(+한국어 nori), 속도 백분위 = numpy.

측정 방법: ① 쿼리마다 "정답 문서"가 미리 지정된 평가용 쿼리 세트를 준비한다. ② 쿼리를 임베딩으로 벡터화 → Elasticsearch에서 상위 5건 검색. ③ Recall@5 = 정답이 상위 5건에 든 쿼리 수 ÷ 전체 쿼리 수. ④ 응답속도 = 검색 호출마다 시간을 측정해 p50/p95로 보고. → 핵심은 "정답 문서가 미리 태깅된 쿼리 세트"가 있어야 측정된다는 점.

P3 — 라벨 일치도 · 미탐률 (합성 LLM)

모델 / 오픈소스: 합성 LLM = Qwen3-14B(로컬 서빙 = Ollama), 검증 = 키워드 룰 라벨러 + JSON 파서 + 정규식(개인정보 탐지).

측정 방법: ① LLM에 "TS 등급 문서 생성"을 시키면 문서 + 스스로 붙인 등급(라벨)이 나온다. ② 라벨 일치도 = 생성 문서를 독립 검증기(S×V×M 룰 라벨러)로 다시 채점해 의도한 등급과 일치한 비율. ③ JSON 성공률 = 출력이 올바른 구조로 파싱된 비율. ④ 방향성 미탐률·개인정보 = 비밀급으로 만들어야 할 문서가 더 낮은 등급으로 매겨진 비율 / 개인정보 패턴이 걸린 건수.

※ 한계: 이때 생성기와 검증기가 같은 키워드 기준을 일부 공유해 일치도가 높게 나오는 측면이 있다(내부 일관성). 따라서 이 수치는 실데이터 일반화 성능이 아니며, 본개발에서 실데이터로 재측정한다(백서 §10).

P4 — 누락 · 품질 (문서 추출)

오픈소스: hwp5(HWP) · python-docx(DOCX) · pdfminer.six(PDF) · openpyxl(Excel) · python-pptx(PPTX). (PDF는 라이선스 위험이 있는 라이브러리 대신 pdfminer.six 사용)

측정 방법: 추출 라이브러리로 텍스트를 뽑아 원문(정답 텍스트)과 대조한다. 누락률 = 빠진 내용 ÷ 원문 전체, 품질 = 추출 텍스트와 원문의 유사도(문자 일치·편집거리 기반).

※ 현황: 파이프라인은 구현됐으나 HWP 실문서가 없어 최종 측정은 보류이며, 실문서 확보 후 산출한다(백서 §7.3).

P5 — 정상응답 · 라벨 100% · ≤30초 (전체 흐름 E2E)

오픈소스: FastAPI 서버 + 실제 스택(Elasticsearch · PostgreSQL · 모델), 테스트 = pytest + HTTP 클라이언트.

측정 방법: 실제 API를 띄우고 테스트 문서를 업로드한다. 정상 응답 = 오류 없이 정상(200) 응답, 라벨 100% = 넣은 문서 전부 등급 반환(실패 0), ≤30초 = 업로드→응답 시간 측정(근거 검색 ON/OFF 각각).

이 수치를 어떻게 믿을 수 있나

모든 정확도 지표는 정답지(라벨)와 대조해 업계 표준 방식·오픈소스로 측정하며, 학습 데이터와 평가 데이터를 분리해 객관성을 확보한다. 즉 모델이 외운 답이 아니라 새 문서에도 통하는지를 본다.

정답지의 품질이 곧 신뢰도이므로, 실제 운영 정확도는 발주처 실데이터로 검증하는 본개발 단계에서 확정한다. 프로토타입 수치는 타당성 확인과 모델 선정을 위한 것이다(백서 §10 · §11).

골든셋 계층 — 채점 정답이 부여된 평가용 문서 집합으로 단계적으로 확장한다. golden100(100건, 1차 실증·분류근거 보고 대상) → golden500(500건, 확장 평가셋) → 본개발 1,000건(발주처 실데이터 기반 목표). 문서별 인용 시점이 달라 건수가 다르게 보일 수 있다.
