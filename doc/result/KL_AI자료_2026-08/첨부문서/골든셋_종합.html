합성 코퍼스·프록시 평가 종합 — locked 평가와의 구분

현행 배포본 = v5_clean(v-fe4b386b) · 2026-08-02 기준: 2026-07-29 자동 게이트 3축(경화 홀드아웃 + 공개 판례 FPR + 적대 veto) PASS로 승격됐으며, 경화 홀드아웃(n=42) F1_macro 0.917 · S1 recall 0.857 · 공개 판례(n=400) 과분류 0.79→0.04 · high→S3 위험 미탐 0이다(프록시 홀드아웃 109에서는 v5≈v4로 개선을 주장하지 않는다). 골든셋 구성·라벨 신뢰도·사람서명 0건이라는 이 문서의 구조적 판단은 v5에서도 그대로 유효하다 — 바뀐 것은 분류기이지 정답지가 아니다. 건별 판정 근거는 골든셋 분류근거(v5 카드형·777건 전수) 참조.
운영 전제 — 검수·평가의 단계 분리: 지재원 단계는 공개·합성 데이터로 모델을 만드는 구축 단계다. 비밀 실문서 검수와 사람 서명 평가는 고객사 폐쇄망 운영 단계에서 수행하며, 실문서는 반출하지 않는다(사업 설계). 따라서 현재 locked_gold_eval 0건은 누락이 아니라 단계 분리의 결과이고, 이 단계에서 배포 전 운영 정확도는 주장하지 않는다. 합성/LLM 라벨은 학습 시드·상대비교·회귀 테스트용이며, 이 문서의 F1/FNR/PASS 수치는 합성·OOD·프록시 또는 메커니즘 검증으로만 해석한다. 현재 목표는 "검증된 분류기 배포"가 아니라 룰 우선 안전 부트스트랩 + 보수적 검수 라우팅 + 운영 관리자 확정에서 배우는 루프다.

이 문서는 과거 "골든셋"으로 부르던 데이터들을 새 전제에 맞춰 재해석한다. 합성·LLM·공개 프록시 라벨은 학습 시드, 상대비교 holdout, 회귀 테스트로는 유용하지만 locked 평가 진실은 아니다. 평가 진실은 사람 서명 전용이며, 현재 제약에서는 0건/휴면 상태가 정상이다.

한눈에 보기 (비전문가용)

① 분류 = 합성/프록시 라벨 기반 상대비교 · ② 검색 = 근거문서 회수 품질 · ③ 적대적 = 치명 미탐 회귀 테스트.
핵심 한 줄: 양은 있어도 locked 사람서명은 0건 — 그래서 배포 전 정확도 검증이 아니라 안전 부트스트랩과 운영 확정 루프가 본체다.

02각 골든셋 상세

① 분류 proxy/holdout — 운영 전 상대비교

의미 : 합성·공개·LLM 라벨로 만든 상대비교용 데이터. 채점 형식은 text + label이지만, 이 label은 locked 평가 진실이 아니라 프록시다.

채점 : 정답 vs 예측 혼동행렬 → F1-macro + 방향성 미탐(FNR_underclass). 심각도순 TS < S1 < S2 < S3에서 정답보다 낮은 등급으로 예측한 것만 미탐으로 셈(과분류는 보안상 안전오류라 제외). TS→S3 같은 치명 미탐은 1건만 있어도 critical 알람.

실측 — 현행 배포본 v5_clean v-fe4b386b : 경화 홀드아웃(n=42, 누출 0) F1_macro 0.917 · S1 recall 0.857, 공개 판례(n=400) 과분류 0.79→0.04, high→S3 위험 미탐 0. 2026-07-29 자동 게이트 3축(경화 홀드아웃 + 공개 판례 FPR + 적대 veto) PASS로 승격.

직전 배포본 v4_clean v-dd3abab9(비교용) : 출처직결 라벨(public·nkt) F1 0.83·TS/S1 recall≈1.0이지만, 진짜 실문서(llm_judge holdout)는 F1 0.63·S1 recall 0.26~0.32로 붕괴. 운영 미탐 0.018은 모델이 아니라 서빙 룰/게이트(FNR-safe override·most-severe 집계)가 막아낸 값. — 프록시 홀드아웃 109에서는 v5≈v4로, 개선을 주장하지 않는다.

라벨 신뢰도(label_source) — ★★★★★는 0건

llm_judge_primary 524 · koipa_case_based 80 · llm_judge_consensus 67 · public_definitive 50 · nkt_designated 30 · codex_review 19 · curated_scenario 6 · human_review 1 (2026-08-02 정본 classification_gold.jsonl 실측). 등급분포 S3 577 · S2 89 · S1 56 · TS 55(고등급 14%)(2026-07-22 판례-프록시 디오염 후). 정답이 사람검증이 아니라 룰+LLM 합의라 target_grade_oss와 불일치도 존재.

주의 — 위 human_review 1은 라벨 출처 태그다. 별개 필드인 human_review 플래그는 777건 전부 0이다. 즉 사람이 검수한 이력 1건 / 사람이 서명한 locked 평가정답 0건으로 읽어야 한다 — 두 값을 같은 것으로 보면 "사람 검증을 거친 정답지"라는 잘못된 결론이 나온다. 평가정답의 사람 서명은 지재원 단계에서 구조적으로 0이며(실데이터·현장검수·반출 0), 이 문서의 모든 지표는 그 전제 위에서 해석한다.

② 검색 골든셋 (retrieval, 80 + NL 190)

의미 : "질의 → 나와야 할 정답 문서" 쌍(현재 질의당 정답 1건). relevant_doc_ids를 상위 k에 회수하면 성공.

채점 : 상위 5개에 정답 doc_id가 있나 → Recall@5(+ Precision@5·MRR·nDCG@5). P2 합격선 Recall@5 ≥ 0.80, 지연 p50 ≤ 200ms.

실측·함정 : base 질의는 정답 본문 발췌 그대로라 글자만 겹쳐도 맞음(천장 0.89). 이를 고치려 NL 변종(패러프레이즈·글자겹침 <10 필터)을 만들었고, NL·실임베더 기준 정직값은 ~0.55~0.70(NL변종·dense 단독 보수 천장 → 이 셋 기준 P2 0.80 미달). 단 실 PG 하이브리드 랭커 측정은 0.85(2026-06-24)로 대상 셋·랭커에 따라 P2 판정이 갈린다 — 제출 시 측정셋 명시 필요(테스트_전략 참조). S1 검색은 25%로 붕괴, reranker는 +1%p로 무용.

③ 적대적 골든셋 (golden_100, 100) — 안전 게이트

의미 : 실문서가 아니라 한 문장 함정 100개. 성능 벤치마크가 아니라 "기밀을 공개(S3)로 흘리는 치명적 미탐이 늘었는지" 감시하는 회귀 트립와이어.

채점 : 배포 분류기를 함정에 돌려 고위험 미탐(gold TS/S1/S2 → S3) 건수 ≤ 임계면 PASS(현재 4건, PASS). 정확도 41%는 함정이라 정상.

03관통하는 진실

3종을 관통하는 5가지

핵심

1. 정본은 있으나 "사람검증"이 0 — gold_real 777은 다 LLM/룰/공개정의 기반, human_review ★★★★★ = 0건.
2. 고등급(특히 S1)이 약점 — S1 recall 0.26~0.32, 검색 S1 25% 붕괴. 원인 = 실데이터 부족(합성증강으로 못 메움, 실측 확정).
3. "쉬운 숫자"의 함정 — 발췌질의 0.89·출처직결 0.83은 부풀림, 정직값은 0.55~0.70. 이 구분을 못 하면 성능 오해.
4. 위생은 강화됨 — text-hash dedup·누출게이트(raw→정규화)·순환성 차단·AI 위장서명 가드.
5. 합성 ≠ locked 평가 — 합성은 방법론·균형·콜드스타트용 마중물. 운영 진실은 관리자 확정과 사람서명 locked뿐.

04추가·반영 방법

나중에 어떻게 추가하나 — 통합 빌더(구현됨)

나중에 골든셋을 늘리는 절차는 이제 설계가 아니라 구현된 파이프라인이다:

/golden/build 파이프라인

① 위생(중복·누출 제거) → ② 라벨(룰 + LLM) → ③ 합의(gold 후보 / 검수대상) → ④ run-스코프 후보파일 (정본 직접변경 금지) → ⑤ 검토본 HTML → ⑥ 지재원 관리자 검수·서명(human_review 승급) → ⑦ promote 게이트(중복·누출·비gold 차단) → 정본 편입.

두 검수 루프 분리(혼동 금지) : 합성/후보 검수는 학습 시드·프록시 품질관리이고, 운영 업로드 검수는 회원사 폐쇄망에서 관리자 확정으로 tb_corrections에 적재되는 유일한 진짜 데이터다. 교정·원문은 망 내 잔류하며, 기본 반영은 exact-match 선례·집계 진단이다. 회원사 교정은 admission gate와 사람서명 없이는 locked 평가가 되지 않는다.

제약 완화 또는 운영 확정 : 사람서명 locked로 승급하려면 관리자 실계정·서명·감사로그가 필요하다. 머신/ai_assist 라벨은 locked로 승급하지 않는다.
