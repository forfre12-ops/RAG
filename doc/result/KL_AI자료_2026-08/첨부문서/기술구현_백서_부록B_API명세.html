Koipa(수행사) AI 코어 API — 분류·설명·검수·학습·합성·등급체계·문서 수집(M2)·운영. KL ↔ Koipa 서버 간 통신 기준이며 Koipa는 KL 단일 신뢰 클라이언트를 전제로 한다. 등급 산정은 비공지성(S) × 경제적 유용성(V) × 비밀관리성(M) 곱셈식(각 0·1·2점)이며 — 분류 응답의 evaluation_factors는 3요건(secrecy·value·management)을 노출한다.

본 부록은 Koipa(AI 에이전트)가 제공하는 API만 다룬다. 가이드 관리·문서 메타데이터·LLM 비용 등 KL 소유 대상 API는 KL이 직접 제공하므로 제외한다. 회원사 자가진단(tb_self_assessments 등 자가진단 요소)·고객사 연동 API는 신설 대상으로 소유·인터페이스를 KL과 협의 필요. 협의 필요(주황색)는 KL과 인터페이스 합의가 남은 항목이다.

인증 모드

AUTH_MODE 설정: jwt(JWT 전용) · api_key(API 키 전용) · both(둘 다 허용). 설정한 모드가 모든 라우터에 일괄 적용된다. API 키 검증은 타이밍 사이드채널을 차단하도록 수행된다.

신뢰 경계 — KL 단일 연동 (고객사 격리는 KL 포털)

KL이 고객사(회원사) 페이지를 일원 구축하므로, 고객사 간 데이터 격리(어느 회원사가 어느 문서를 보는지)는 KL 포털 계층에서 처리한다. Koipa는 KL 백엔드를 단일 신뢰 클라이언트로 받는 분류 엔진이다. 인증 신원(actor_id·role)은 request.state에 저장되어 역할 기반 권한(RBAC)과 감사 로그 actor 식별에만 쓰인다. 감사 로그의 actor_id는 위조 가능 헤더 대신 인증 컨텍스트에서 도출된다. 협의 필요 고객사 식별자(예: external_ref 규약)를 Koipa 응답·감사에 어느 수준까지 남길지는 KL과 합의.

Rate Limit

전역 기본 한도는 없다. 한도는 아래 9개 라우트에만 개별로 걸려 있고, 표에 없는 엔드포인트(/documents · /golden/* · /confirm · /relabel · /promotions/* · /admin/* · /metrics/* 등)에는 서버측 호출 한도가 적용되지 않는다. 한도 키는 인증된 신원(actor) 우선, 미인증 시 IP 폴백이다. 초과 시 429 + Retry-After 헤더로 응답한다.
