1. 한눈에 보기

이 문서는 학습 데이터를 왜 지금 형태로 구성했는지를 실측으로 설명합니다. 요약하면 세 가지입니다.

둘째, 생성 문서를 더 만들어 넣는 방식은 측정 결과 한계에 도달했습니다. 생성 모델을 바꿔가며 같은 조건에서 반복 측정했으나 개선이 확인되지 않았습니다.

셋째, 정확도를 올리는 남은 수단은 실제 문서의 확정 라벨입니다. 그래서 현재 구조는 생성 규모를 키우는 대신 검수·게이트·안전 라우팅에 무게를 두고 있습니다.

3. 실패로 확인한 것

성공한 구성만 남기지 않고 실패한 구성도 산출물로 보존했습니다. 판단 근거로 쓰이기 때문입니다.

3.1 학습 데이터에 공개문서가 섞여 있었다

초기 학습셋 5,911건을 점검한 결과 3,320건(56%)이 판례·심결이었고, 그중 2,210건(67%)이 고등급으로 잘못 라벨되어 있었습니다. 이미 공개되어 비밀로 성립할 수 없는 문서가 고등급으로 학습되면 미탐과 과분류가 동시에 커집니다. 법률 코퍼스를 분리해 재학습한 결과 모든 지표가 개선됐습니다(§2 계보 ⑤).

근거: 기술구현 백서 v7 §7.7

3.2 평가셋 자체가 답을 흘리고 있었다

모델을 재기 전에 재는 자를 먼저 점검했습니다. 봉인해 둔 평가셋 800건을 검사하자 본문 길이만 보고도 등급을 96% 맞힐 수 있었습니다. 등급별 글자 수 구간이 거의 겹치지 않게 만들어져 있었기 때문입니다. 이 상태로는 “새 모델이 더 좋다”는 판단 자체가 성립하지 않습니다. 평가셋을 다시 만들어 무작위 수준으로 되돌렸습니다.

3.3 자동 게이트가 나쁜 후보를 실제로 막았다

재학습으로 만들어진 후보 모델은 자동 배포되지 않고 게이트를 통과해야 합니다. 2026-08-16 재학습 후보는 고등급 미탐 지표가 나빠져 게이트에서 차단됐고 배포되지 않았습니다. 8월 15일 후보 두 건은 게이트를 통과했으나 설계대로 후보 등록 단계에 머물렀습니다.

근거: tb_training_runs.final_metrics->deploy->gate

3.4 실패한 접근을 다른 방식으로 해결했다

§2 계보 ⑦ 에서 학습 데이터의 판례 라벨을 통째로 바꾸는 방식은 실패했습니다. 같은 문제(공개문서를 비밀로 과분류)를 학습 단계가 아니라 판정 단계에서 다시 풀었습니다 — 이미 공개된 출처의 문서는 내용과 무관하게 3급으로 제한하는 규칙을 판정에 넣었습니다. 그 결과 공개 판례 400건 기준 과분류가 0.79 에서 0.04 로 내려갔고, 학습 데이터는 건드리지 않았으므로 고등급 미탐이 악화되지 않았습니다.

4. 생성 문서를 더 만드는 방식의 한계

가장 약한 등급인 1급 비밀을 대상으로 학습 데이터만 늘렸을 때 좋아지는지를 직접 측정했습니다. 기준 구성과 학습 조건을 고정하고 생성 모델만 바꿔, 서로 다른 난수 조건으로 네 번씩 반복했습니다.

읽는 법. 1급 학습 데이터를 3.2배로 늘린 조건입니다. 그런데 A 의 개선폭(+0.030)은 반복 간 편차(0.041)보다 작습니다 — 난수 조건을 바꾸면 사라지는 크기입니다. B 는 오히려 나빠졌습니다. 1급 재현율은 여덟 번 중 일곱 번이 변화 없음이었습니다.

측정의 한계도 함께 적습니다. 이 실험의 평가셋은 42건(1급 12건), 추가 문서는 60건, 반복은 4회입니다. 작은 폭의 개선은 이 규모로 판별할 수 없습니다. 따라서 확인된 결론은 “3.2배 증량으로는 확인 가능한 개선이 없었다”이며, “어떤 규모로도 불가능하다”가 아닙니다.

6. 그래서 구조를 이렇게 구성했습니다

위 측정이 가리키는 방향은 일관됩니다. 생성 문서를 더 만드는 축에서는 더 얻을 것이 없고, 실제 문서의 확정 라벨에서만 얻을 수 있습니다. 교차 검증에서도 같은 결론이 나옵니다 — 생성 문서만으로 학습한 모델을 실문서로 평가하면 F1 0.26, 실제 문서를 포함해 학습한 모델은 0.736 입니다.

검수 대상 문서는 120건이 준비되어 있으며, 현재 서명 기록은 테스트 계정 2건으로 실 검수는 시작 전입니다. 이 단계가 진행되면 평가 정본이 확보되고, 그때부터 운영 환경의 정확도를 수치로 확정해 보고할 수 있습니다.
