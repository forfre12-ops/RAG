발주처 모의문서·골든셋 생성·갱신 지원

발주처가 운영 단계에서 자체적으로 생성·갱신할 수 있는가 — 방식·주체·권한·주기 · 2026-08-02
결론 — 지원됩니다. 생성 3경로 · 갱신 1루프가 모두 구현·배선돼 있고, 전 과정이 발주처 망 안에서 끝납니다(무반출).
① 모의문서 생성(합성 LLM) ② 골든셋 빌드(자동 라벨 → 사람 서명 승격) ③ 실문서 블라인드 인테이크(발주처 담당자가 실문서에 직접 등급 확정 — 2026-08-01 신규) ④ 갱신은 운영 검수 교정이 현장 CPU 야간 증분재학습으로 자동 환류. 주체는 발주처 관리자·검수자이고, 로이드케이는 도구·파이프라인만 제공합니다.

0. 먼저 용어 — "모의문서"와 "골든셋"은 다른 것

둘을 섞으면 이후 논의가 어긋나므로 먼저 분리합니다. 모의문서 = 입력(학습·시연에 쓸 문서), 골든셋 = 정답지(채점 기준)이며, 골든셋은 신뢰도에 따라 3계층으로 분리 관리됩니다.

구분라벨 출처쓰임 · 규칙
모의문서(합성문서)LLM 생성학습 시드·시연·회귀 테스트용 입력 문서. 등급명을 본문에 직접 쓰지 않음(누출 차단)
silver_train룰 + LLM 합의학습용 정답. 기계 라벨이라 평가에는 쓰지 않음
gold_candidate합의 통과분사람 검수 대기 후보. 서명 전에는 평가 정답이 아님
locked_gold_eval사람 서명평가 정답지. 실계정 서명·감사로그 필수. 기계 계정·AI 위장서명은 게이트에서 거부
현재 상태(정직 고지). 현행 골든 파일에서 label_source=human_review(사람 확정)은 사실상 없습니다(전체 777건 중 1건). 즉 지금까지의 정확도 수치는 전부 기계가 만든 정답으로 기계를 채점한 값입니다. 발주처가 실문서에 등급을 확정하는 순간 그것이 이 사업 최초의 평가 정답지가 되며, 그래서 아래 §3 경로가 이번 사업에서 가장 값이 큰 작업입니다.

1. 생성 경로 A — 모의문서 합성 구현

등급별 상황 프롬프트로 문서를 생성하고, 룰 라벨러가 목표 등급과 맞는지 역검증한 뒤에만 학습셋으로 편입합니다. 사람은 큐에서 승인/반려만 하면 됩니다.

  1. POST /synth/generate — 등급·건수·도메인을 지정해 배치 생성admin · kl_backend
  2. 자동 합격판정 — 룰 라벨러 재검증(라벨 일치율 ≥90% · 고등급 미탐 ≤5%) 미달분은 자동 탈락
  3. GET /synth/queue — 검수 대기(pending_review) 목록 조회admin · reviewer
  4. POST /synth/{id}/review — 담당자가 승인/반려admin · reviewer
  5. 승인분만 학습 데이터셋 빌드에 편입 — 반려분은 학습에 들어가지 않음

※ 합성 LLM은 폐쇄망에서 로컬 Qwen3-14B(Apache-2.0)를 사용합니다. 이 가중치는 본 번들에 동봉하지 않으며, GPU를 보유한 고객사가 vLLM/Ollama로 직접 기동한 망 내 엔드포인트를 연결하는 방식입니다(무GPU 현장은 본 경로 A 구동 불가 → 경로 B·C로 대체). 외부 전송이 없으며, LLM을 교체해도 호출부 코드 변경이 필요 없습니다(어댑터 분리).

2. 생성 경로 B — 골든셋 빌드 + 서명 승격 구현

흩어진 문서를 넣으면 위생검사 → 자동 라벨 → 합의 → 검토본 HTML까지 한 번에 나옵니다. 담당자는 그 검토본을 보고 서명하며, 서명 전에는 어떤 것도 평가 정답지가 되지 않습니다.

  1. POST /golden/build — 위생(중복·누출 제거) → 룰+LLM 라벨 → 합의 판정admin · kl_backend
  2. 결과는 run 스코프 후보 파일로만 기록 — 정본 직접 변경 금지(사고 시 정본 무손상)
  3. GET /golden/jobs/{id} — 담당자용 검토본 HTML(문서별 등급·근거·신뢰도)admin · reviewer
  4. POST /golden/jobs/{id}/signoff — 실계정 서명admin · reviewer
  5. 승격 게이트(promote_to_locked) 통과분만 locked_gold_eval로 편입 — 기계 계정·미서명·등급 누락·서명자 불일치는 거부

※ 기본은 독립 검수자 1인 서명이며, 옵션(dual_for_upper)으로 TS·S1 고등급만 2인 서명을 강제할 수 있습니다. 발주처 내부 규정에 맞춰 선택 가능합니다.

3. 생성 경로 C — 발주처 실문서 블라인드 인테이크 신규 2026-08-01

발주처가 보유한 진짜 업무문서에 담당자가 직접 등급을 매겨 평가 정답지를 만드는 경로입니다(scripts/golden_intake.py). 감리에서 "정확도 근거가 무엇이냐"에 답할 수 있는 유일한 경로입니다.

왜 블라인드인가

시스템이 매긴 등급을 보고 나서 사람이 정답을 정하면 그 답에 끌립니다(앵커링). 그 정답지로 정확도를 재면 순환 논리가 되어 "정답을 시스템이 알려준 것 아니냐"에 반박할 수 없습니다. 그래서 이 도구는 분류를 일절 돌리지 않고 텍스트만 추출하며, 등급 칸을 비운 채 시트를 냅니다.

  1. golden_intake.py scan --docs-dir <문서폴더> — 텍스트 추출 후 등급 빈칸 기입 시트(CSV) 생성발주처 실무
  2. 담당자가 원본 문서를 직접 열어 보고 등급·판단근거·확정자·확정일을 기입(미리보기는 식별용일 뿐)발주처 검수자
  3. golden_intake.py build --intake-dir ... — 운영 서명 게이트를 통과시켜 locked_gold_eval 생성발주처 관리자
  4. 기존 학습셋과 텍스트 해시를 대조해 겹치는 문서를 자동 제외 — train-on-test(시험문제 유출) 차단
항목내용
지원 형식.hwp · .hwpx · .pdf · .docx · .doc · .xlsx · .xls · .pptx · .txt · .md
기입 항목등급(TS/S1/S2/S3) · 판단근거 · 확정자 · 확정일 — 4칸이면 충분
담당자 준비물문서 폴더 1개. 별도 시스템 접속·학습 불필요(엑셀만 다루면 됨)
반출없음 — 산출물(CSV·JSONL)에 본문이 담기므로 망 내 잔류가 원칙

4. 갱신 — 운영 검수 교정 → 야간 증분재학습 구현

골든셋을 "다시 만드는" 것이 아니라, 운영하면서 쌓이는 관리자 확정·교정이 그대로 학습에 환류되는 구조입니다. 발주처가 별도로 작업할 것이 없다는 점이 핵심입니다.

  1. 운영 중 관리자가 분류 결과를 확정·교정(POST /confirm · POST /relabel) → tb_corrections 적재발주처 관리자
  2. 매일 02:00 야간 배치가 교정분을 기존 학습셋과 섞어 CPU 증분재학습(enable_incremental_retrain) — GPU 불필요
  3. 재학습본은 후보로만 등록(retrain_auto_activate=False) — 미검증 모델이 스스로 서비스에 올라가지 않음
  4. shadow 검증 후 현장 관리자가 활성화를 결정할 때만 서비스 전환발주처 관리자
항목실측 · 설정값
재학습 소요약 1시간 / 1,000건 (CPU 기준 · 야간 무인 배치라 업무시간 영향 없음)
실행 시각매일 02:00 (KST) — 스케줄러 고정, 변경 가능
필요 하드웨어CPU만. 운영 서버에 GPU가 없어도 성립(학습·합성용 GPU는 지재원 모델공장에만 필요)
자동 활성화꺼짐(기본값) — 사람이 켜야 전환

7. 정직한 경계 — 되는 것과 안 되는 것

가부내용
가능발주처가 자체적으로 모의문서 생성 · 골든셋 빌드 · 실문서 등급 확정 · 교정 환류 · 재학습·활성화까지 전부 수행
※ 모의문서 생성(경로 A)은 합성 LLM(Qwen3-14B)을 고객사 GPU로 구동해야 하므로 GPU 보유 현장에 한합니다. 무GPU 운영 현장은 경로 B·C와 갱신 루프(§4)로 정답지·학습셋을 확보합니다.
가능운영 서버 GPU 없이 갱신 루프 유지(야간 CPU 증분재학습)
조건부평가 정답지(locked_gold_eval) 확보 — 담당자의 실계정 서명 작업이 필요합니다. 자동 생성으로는 만들 수 없습니다(만들면 순환 논리)
조건부정확도의 실질 개선 — 교정 데이터가 쌓이는 만큼 좋아집니다. 초기 소량으로는 체감 변화가 작습니다
불가모의문서(합성)만으로 실세계 정확도를 끌어올리는 것 — 구조적 천장이 실측으로 확인됐습니다. 합성은 콜드스타트 마중물이지 성능 레버가 아닙니다
불가로이드케이가 발주처 실문서를 받아 대신 라벨링 — 반출 0 원칙에 위배되며, 그래서 도구를 넘겨드리는 방식으로 설계했습니다

8. 발주처 준비사항 (요청)

  1. 등급 확정 담당자 지정 — 영업비밀 등급을 판단할 수 있는 실무자 1~2인(검수자 계정 발급 대상)
  2. 대상 문서 폴더 — 실 업무문서 수백 건 규모. 등급이 골고루 섞이게 뽑는 것이 중요(S3만 모이면 평가가 성립하지 않음)
  3. 고등급(TS·S1) 2인 서명 여부 결정 — 내부 규정에 따라 옵션으로 강제 가능
  4. 재학습 활성화 승인 절차 — 야간 재학습본을 누가 어떤 기준으로 켜는지(현장 운영 규정)
위 4가지가 정해지면 도구는 이미 준비돼 있어 즉시 착수 가능합니다. 특히 ①②는 11월 테스트 사전점검 전까지 확보되면, 종료 감리에서 사람이 확정한 정답지 기준 정확도를 제시할 수 있습니다.
