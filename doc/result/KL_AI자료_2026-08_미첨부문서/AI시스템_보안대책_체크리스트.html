점검 범위시스템 구성요소 · 배포 구성 · 운영 절차 (공통 30 · 에이전틱 17 · 피지컬 10 = 57개 항목)
점검 방법항목별 보안대책의 구현 근거를 소스 · 설정 · 절차 문서에서 직접 확인
점검 일자2026. 9. 8.
작성주식회사 로이드케이

이 표가 뜻하는 것. 체크리스트가 묻는 것은 “대책을 마련하였는가”이며, ‘예’는 그 대책이 구현되어 근거 파일을 제시할 수 있다는 뜻이다. 운영 서버에서의 실측 검증과는 다르다. 이 구분이 필요한 항목에는 ‘단서’를 함께 적었다.

근거 자료(항목별 구현 위치 · 설정값 · 검증 결과)는 별도 보유하며, 요청 시 제출한다.

전체 57개 항목. 항목별로 해당 보안대책이 구현된 위치를 지정하고 그 구현이 실재하는지 확인하는 방식으로 판정하였다. 명칭이 유사하나 목적이 다른 구성요소를 근거로 계상하지 않도록, 항목마다 근거를 개별 지정하여 대조하였다.

점검 결론

공통 30개 항목 중 시스템이 담당하는 27개 항목에 보안대책이 모두 갖춰져 있다.

미적용 항목은 없다. 나머지 3개(M06 · M29 · M30)는 기관 내부 절차 · 수급인 점검 · 사용자 교육에 해당하여 발주기관이 수행한다.

에이전틱 AI(17개) · 피지컬 AI(10개)는 시스템 특성상 해당하지 않으며, 사유는 각 절에 적었다.

가. 보안대책 체크리스트 (공통)

순번항목 적용여부대책 내용 · 근거
M01신뢰할 수 있는 출처의 데이터 활용예
적용		외부 생성형 AI 로 데이터를 전송할 때 출처가 확인된 구분(공개 실문서 · 합성문서)만 허용하는 허용목록을 적용한다. 출처가 확인되지 않은 자료는 자동 차단하며, 전송 대상에 하나라도 포함되면 해당 실행 전체를 외부 전송 없이 처리한다.
M02신뢰할 수 있는 출처의 AI모델 · 라이브러리 활용예
적용		의존 패키지는 잠금 파일로 버전을 고정하고 CI 가 잠금본으로만 설치한다. 컨테이너 이미지는 태그가 아닌 다이제스트(SHA-256)로 고정한다. 오픈소스 구성요소는 라이선스 대장으로 관리한다.
M03데이터 검사 (오염 · 비인가 민감정보)예
적용		수집 · 전처리 단계에서 개인정보를 검출 · 마스킹한다. 학습 데이터는 품질 기준 검사와 등급 정보 노출 검사를 통과한 것만 학습에 사용한다.
M04데이터 암호화 (저장)예
적용		원본 문서는 AES-256-GCM 으로 암호화하여 저장한다. 운영 배포 구성에서 강제 적용되며, 암호화 키가 설정되지 않으면 기동을 거부하여 평문 저장을 차단한다.
M05데이터 접근통제예
적용		역할 기반 접근통제를 적용하고, 관리 화면은 공유 인증키를 거부하고 개인 계정 기반 토큰 인증만 허용한다. 등급 결정 행위를 실계정으로 식별하기 위한 조치다.
M06민감정보 사용 사전 승인발주기관
기관 수행 항목		기관 내부 보고 · 승인 절차에 해당한다. 시스템은 문서 보안등급과 처리 이력을 기록하여 승인 판단에 필요한 근거를 제공한다.
M07보안등급에 맞는 학습데이터 구성 · 활용예
적용		데이터를 4개 보안등급(TS · S1 · S2 · S3)으로 구분하여 구성 · 활용하며, 등급별 · 분야별 구성 현황을 확인할 수 있다. 평가 기준 데이터는 검수자 서명을 거친 것만 편입한다.
M08데이터 로깅 · 모니터링 (원시 · 학습데이터)예
적용		데이터 접근 · 변경 기록을 해시 연결 구조의 감사 기록으로 남겨 변조를 탐지한다. 학습 수행 이력은 별도 이력으로 보관한다.
M09AI시스템 로깅 · 모니터링 (입 · 출력)예
적용		모든 요청이 감사 기록 계층을 거치며 입 · 출력 정보가 기록된다. 운영 지표는 표준 모니터링 규격으로 수집한다.
M10데이터 수집 명세서 관리 (출처 · 일자 · 해시)예
적용		학습 · 평가 데이터는 명세 파일로 관리하며 파일마다 SHA-256 해시를 기록한다. 서버 이전 시에도 동일 명세로 대조하여 전송 중 손상을 검출한다.
M11AI시스템 구성요소 명세서 관리예
적용		시스템 구성요소 명세(SBOM)를 산출하고, 릴리스 단위로 구성 · 버전 · 변경 이력을 기록한다.
M12AI시스템 구성요소 무결성 검증예
적용		빌드 식별자를 이미지에 기록하고 배포 시 대조한다. 추론 파이프라인은 배포본 계약 해시가 일치하지 않으면 모델 적재를 거부한다.
M13입 · 출력 필터링예
적용		입력 문서는 개인정보 마스킹을 거친다. 외부 생성형 AI 로의 출력 전송은 출처 허용목록으로 통제하며, 확인되지 않은 자료는 차단한다.
M14입력 길이 · 형식 제한예
적용		요청 본문 크기 상한을 문서 해석 이전 단계에서 적용하여 과대 요청을 차단한다. 업로드 파일의 형식과 크기도 제한한다.
M15가드레일 다중화예
적용		모델 추론과 규칙 판정을 중첩 적용하고 두 결과의 합치 여부를 검수 라우팅에 반영한다. 안전 게이트가 비활성화된 상태로는 기동되지 않도록 하여 보호장치가 조용히 해제되는 것을 방지한다.
M16AI모델 구조 · 가중치 유출 방지예
적용		모델 저장 영역을 읽기 전용으로 마운트하고 폐쇄망 내부에 배치한다. 모델 활성 전환 · 회수는 관리자 권한으로만 수행할 수 있다.
M17AI시스템 경계보안 강화예
적용		데이터베이스 · 캐시 · 응용 서버를 호스트 내부 주소에만 바인딩하고, 외부 연계 구간은 역방향 프록시에서 종단한다. 배포 검증 절차가 설정 파일이 아니라 기동된 컨테이너의 실제 포트 바인딩을 확인하여, 응용 서버가 외부에 직접 노출된 상태로 운영되지 않도록 한다.
단서 배포 검증 항목이므로 차기 서버 구축 시 수행된다.
M18AI시스템 통신구간 보호예
적용		연계 구간은 상호 TLS(mTLS)로 보호하며 클라이언트 인증서를 검증하고 TLS 1.3 만 허용한다. 인증 토큰은 스크립트 접근이 차단된 쿠키로 전달한다. 응용 서버는 호스트 내부 주소에만 바인딩하며 외부 노출은 프록시를 통해서만 이루어진다.
단서 바인딩 설정은 차기 서버 구축 시 반영된다. mTLS 운영 인증서(PKI)는 발주기관 발급 사항이며, 발급 후 적용한다.
M19과도한 권한 부여 제한예
적용		역할에 따라 접근 가능한 기능과 데이터를 제한한다. 컨테이너는 관리자 권한이 아닌 전용 계정으로 실행하며, 호스트 사전점검 절차가 권한 불일치를 배포 전에 확인한다.
M20민감 명령 승인 절차 마련예
적용		모델 활성 전환 · 회수는 관리자 권한 API 로만 수행되며 동시 실행이 직렬화된다. 평가 기준 데이터 편입은 검수자 서명 절차를 거치지 않으면 성립하지 않는다.
M21비상대응 체계 마련예
적용		오동작이 확인된 모델은 프로세스 재기동 없이 이전 배포본으로 즉시 회수할 수 있다. 데이터 · 모델 백업과 복구 절차를 별도로 운영한다.
M22설명 가능한 AI 구성예
적용		판정 결과에 근거 문장과 요인별 판단 근거를 함께 제시한다. 검수 화면은 신뢰도 수치가 아니라 처리 결정(자동확정 · 검수 대상 및 사유)을 우선 표시한다.
M23AI모델 대상 적대적 모의공격 수행예
적용		적대적 시나리오 평가 집합을 상시 회귀 검사에 포함한다. 고보안 문서를 낮은 등급으로 판정하는 방향의 오류가 기준치를 초과하면 배포 검사를 실패 처리한다.
M24AI모델에 적대적 공격유형 학습예
적용		용어 혼동 · 출처 오인 등 오판단 유도 유형을 수집한 평가 집합을 학습 · 평가 경로에 유지하고 회귀를 지속 감시한다.
M25구성요소 취약점 점검 및 보안업데이트예
적용		CI 가 잠금된 의존성 목록에 대해 알려진 취약점 점검을 수행한다. 예외 처리 항목은 별도 목록으로 명시 관리한다.
M26AI모델 복구예
적용		데이터 · 모델 백업과 복구 절차를 운영하며, 모델은 버전 단위로 보관하여 이전 배포본으로 복원할 수 있다.
M27요청속도 제한예
적용		요청 속도 제한을 적용하고 초과 시 표준 오류 응답으로 차단한다. 요청 본문 크기 상한을 함께 적용한다.
M28AI시스템 구성요소 완전 삭제 (폐기 시)예
적용		폐기 절차와 전용 도구를 두어 구성요소를 삭제하고 <strong>삭제되었음을 재확인</strong>한다. 원본 문서는 <strong>암호 소거</strong> 방식으로 처리한다 &mdash; AES-256-GCM 으로 암호화 저장되어 있어 암호화 키를 파기하면 잔존 암호문은 복호할 수 없으며, 대용량 원본을 물리적으로 덮어쓸 필요가 없다. 그 밖의 구성요소는 데이터 볼륨 6종 &middot; 모델 &middot; 학습 데이터 &middot; 컨테이너를 삭제한 뒤 동일 절차로 잔존 여부를 재확인하고 폐기 확인서를 산출한다. 되돌릴 수 없는 작업이므로 기본 동작은 모의 실행이며, 실제 삭제에는 대상 재확인과 키 파기 확인이 필요하다. 키 파기는 백업 &middot; 인수인계본 등 도구가 관할하지 않는 사본이 있을 수 있어 운영자 확인 절차로 둔다.
단서 시스템 폐기 시점에 수행하는 절차다.
M29용역업체 보안관리발주기관
기관 수행 항목		발주기관이 수급인의 보안관리 실태를 점검하는 항목으로, 수급인 자체 점검으로 갈음할 수 없다. 점검 요청 시 필요한 자료를 제출한다.
M30사용자 교육 및 보안정책 수립발주기관
기관 수행 항목		기관 사용자 대상 교육 및 내부 보안정책 수립에 해당한다. 시스템 사용 방법과 검수 절차는 관리자 사용 매뉴얼로 제공한다.

나. 에이전틱 AI (자율형 AI)

이 시스템은 문서 등급 분류기다. 스스로 목표를 세우거나 도구를 자율 호출하지 않고, 에이전트끼리 통신하지도 않는다. 합성문서 생성에서 외부 상용 LLM 을 부르는 구간이 있으나 그것은 에이전틱 AI 가 아니라 가이드북 제2장 유형②(내부 시스템의 외부 AI 연계)에 해당하며, 중점 항목 M09·M13·M14·M24·M27 로 위 공통 표에서 이미 점검했다.
