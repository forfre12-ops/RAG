부록 B API Spec 2026-06-19 갱신 · FastAPI · OpenAPI 3.0 · Base URL: /api/v1

API 명세

31개 라우트(full-train 프로파일 · 고유 경로 기준; lite-noapi는 학습 3종 제외 28개) 전체 명세 (2026-06-19 기준). KL ↔ Lloydk 서버 간 통신 기준. 등급 산정은 비공지성(S) × 경제적 유용성(V) × 비밀관리성(M) 곱셈식(각 0·1·2점)으로 전환됨 — 분류 응답의 evaluation_factors는 3요건(secrecy·value·management)을 노출한다. 능동학습 폐곡선(relabel → corrections → 재학습 → 모델 핫리로드)이 배선됨.

인증 모드

AUTH_MODE 설정: jwt(JWT 전용) · apikey(API 키 전용) · both(둘 다 허용). 모든 라우터가 require_auth로 통일되어 설정이 실제 적용된다. X-Tenant-Id 헤더와 JWT claim의 tenant 불일치 시 401 반환 (하위호환: 헤더 없으면 JWT claim 신뢰).

객체 수준 권한 (테넌트 격리 · IDOR/BOLA 차단)

인증 신원이 request.state에 저장되고, 요청 body의 tenant_id는 인증된 tenant에 결속된다(resolve_effective_tenant). body tenant_id가 인증 tenant와 불일치하면 403 반환. JWT에 tenant claim이 없는데 tenant_id를 주장해도 403. 모든 doc 조회(본문 fetch · 검증 등급 · 최근 분류 결과)는 이 유효 tenant로 스코프되어 타 tenant의 doc_id로 본문·등급·분류 결과를 열람할 수 없다(앱 레이어 enforcement, DB 스키마 변경 없음). 감사 로그의 actor_id/tenant_id도 위조 가능 헤더 대신 인증 컨텍스트에서 도출된다.

Rate Limit

SlowAPI 기반. 기본 120 req/min, 라우터별 별도 한도 (분류 동기 60/분 · /answer 30/분 · /synth/generate 10/분 · /train 10/시간). 키는 검증된 신원(인증 tenant→actor) 우선, 미인증 시 IP 폴백 — 위조 가능한 원시 X-Tenant-Id 헤더는 키로 쓰지 않는다(한도 우회·버킷 고갈 차단). 초과 시 429 + Retry-After 헤더. RATE_LIMIT_DISABLED=1로 비활성(테스트·dryrun).

미들웨어

모든 요청은 api/middleware.py를 통해 감사 로그(audit_log)에 기록되고, OTel span이 생성된다.

분류
POST /api/v1/classify 동기 문서 분류 JWT

문서 텍스트를 4등급(TS/S1/S2/S3)으로 분류한다. M2 전처리 → M5 추론 순서로 실행. confidence가 임계값(review_confidence_threshold=0.7) 미만이면 응답 status="needs_review"로 표시하고 warning에 검수 권고를 남긴다(거부 아님 — 고위험 FNR 보호). 검수자 큐는 동률 시 저신뢰를 우선 정렬한다. body의 tenant_id는 인증 tenant에 결속되며 불일치 시 403.

POST /api/v1/classify/stream SSE 스트리밍 분류 JWT

RAG · 설명
POST /api/v1/answer RAG 질의 응답 JWT

RAG 질의응답. 검색 facade(expand_then_search: 쿼리 확장 → RRF 융합 → reranker)로 관련 청크를 수집하고 LLM(Qwen3/Claude)으로 한국어 답변을 합성한다. 검색·LLM 어느 쪽이 실패해도 200 + warnings에 사유, deterministic_fallback=true로 처리(5xx는 진짜 예외만). 검색은 인증 tenant로만 스코프되고, 결과를 payload.tenant_id로 사후 필터해 교차테넌트 누출을 fail-CLOSED로 차단한다. 분당 30 한도. 본 엔드포인트는 등급 분류를 하지 않으며, grade는 호출자가 별도 단계에서 전달할 수 있다.
