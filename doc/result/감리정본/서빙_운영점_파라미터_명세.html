02 서빙 경로 한눈에

한 문서가 등급을 받고 자동확정/검수로 갈리기까지 — 어느 단계에서 어느 노브가 작동하나.

분류는 두 층을 지난다: 분류 핫패스(InferencePipeline.run)가 등급·신뢰도를 만들고, 자동확정 판정(classify/confirm 서비스)이 게이트로 자동확정 여부를 가른다.

#단계작동하는 노브층
1모델 추론 (logit → softmax)온도보정 logits / T — softmax 직전 과신 완화핫패스
2청크 집계 → 재정규화most-severe-wins severe_agg_codes(TS·S1 max-pool) → confidence=scores[pred]핫패스
3예측 등급 선택escalation τ classifier_escalation_tau — 가장 심각한 등급부터 prob≥τ 채택핫패스
4룰 상향 안전장치FNR-safe override fnr_rule_ts/s1/s2_threshold — 룰 고등급 신호가 강하면 상향핫패스
5출처 하향비공지성 cap source_prior_enabled — 공개출처면 S3로 cap(충돌 시 검수)핫패스

※ 1·3은 모델 경로와 룰-폴백 경로에 동일하게 적용된다(m5_inference/pipeline.py). 7의 라우팅 게이트는 분류를 막지 않고 검수 큐로 보낼 뿐이며, 등급을 무인으로 바꾸지 않는다.

04 보정 — temperature scaling

분류기 softmax의 과신을 깎아, 신뢰도 게이트가 보정된 값 위에서 동작하게 한다.

설정 키
classifier_
temperature
float, 양수만
기본값
1.0
무보정(동작 보존)
온도 보정 T
운영 3.0
측정 최적 2.0(ECE 0.045) 대비 FNR-보수 마진
OOD 잔존
ECE 0.184
구 후보셋 golden500 — 전이 안 됨

무엇: softmax 직전 logit을 T로 나눠 분포를 평탄화한다 — temp = self._temperature; if temp != 1.0: logits = logits / temp (m5_inference/pipeline.py _run_model). T>1이면 과신(overconfident)이 완화된다.

왜: 분류기는 학습에 없던 새 문체(OOD)에서 과신해, conf 게이트(0.7)가 부풀려진 값 위에 서면 틀린 예측이 conf=1.0으로 자동확정되는 무인 미탐이 난다.

적용 순서: 모델 폴더에 temperature.json이 있으면 서빙이 자동 로드한다. settings.classifier_temperature가 명시값(≠1.0)이면 그게 최우선, 아니면 모델 동봉값, 둘 다 없으면 1.0.

⚠
보정은 필요조건이지 충분조건이 아니다. val에서 ECE 0.045였던 같은 보정이 분포가 다른 구 후보셋 golden500(OOD)에선 ECE 0.184로 다시 나빠진다. 즉 온도보정만으로 confidence가 자동확정의 신뢰 근거가 되지 않는다 — 그래서 §6의 게이트가 필요하다. (보고서 §04)

05 신뢰도 — confidence

다이얼이 아니라 계기판 숫자다. 그리고 이 숫자는 단독으로 못 믿는다.

conf 0.9 구간 실제 정답률
68.9%
과신 갭 +25%p

무엇: 설정이 아니라 산출값이다 — 파이프라인이 logit → 온도 → softmax → 청크집계 → 정규화로 만든 예측 등급의 확률 질량(scores[pred]), [0,1]로 clamp. softmax 분류기는 "정답 맞히기"만 학습하므로 OOD에서 과신하는 게 정설이고(코드 감사상 버그 아님), 그게 그대로 재현됐다.

그래서 어떻게 쓰나: confidence는 §6의 conf 게이트가 소비하는 입력 신호다. 단, 변별력이 동전던지기 수준(AUROC 0.58)이라 conf 단독 자동확정은 금지이고, 확신은 등급차등 + 룰·모델 합의라는 독립 신호에서 얻는다. 등급별로는 S3(공개)만 conf 신뢰(94%), S2는 51%, TS·S1은 67~75%. (보고서 §05)

06 게이트 임계 7종

"게이트 임계"는 단일값이 아니라 등급을 바꾸거나 검수로 라우팅하는 컷오프의 묶음이다.

6.1 escalation τ — classifier_escalation_tau

기본 / 운영None(순수 argmax) / onprem·full-train 0.30
유효범위None 또는 0 < τ < 1 (양 끝 배제)
동작가장 심각한 등급(GRADE_ORDER)부터 검사해 prob ≥ τ인 첫 등급 채택, 없으면 argmax 폴백 (_select_pred_idx). 평가 스윕과 동일 규칙(서빙↔평가 정합).
효과·방향τ↓ → 고등급 적극 채택 → 미탐↓·과분류↑
측정τ=0.30: clean 77행 미탐 FNR 0.174→0.087(절반)·검토 +5pp·TS recall 0.91→1.0(저regret). τ=0.35면 고등급(TS·S1) 미탐 전부 0(F1 −2.8%p). τ≤0.25는 과분류 급증으로 비권장.

6.2 conf 게이트 — review_confidence_threshold

기본값0.7
동작confidence가 이 값 미만이면 자동확정 안 하고 needs_review 큐로. 거부가 아니라 사람 검수 라우팅.
효과·방향↑ → 검수 증가·안전 증가. 단 §5대로 conf 자체가 약신호라 이 값만 올려도 정밀도는 거의 안 오른다(0.7→0.9: 63→69%).

6.3 희소근거 게이트 — rule_fallback_min_evidence

기본값0.9
동작룰-폴백 경로에서 룰 총점이 0 < 점수 < 0.9면(약한 단일 키워드 매치) confidence와 무관하게 'sparse-evidence' 경고 → 검수. 단 하나의 약한 매치가 conf=1.0으로 자동확정되는 silent FNR 차단.
측정golden100 무성 TS 미탐 5 → 0(결정론적). 검수 부하 +18/100. 임계 0이면 동작 원복(하위호환).

6.4 합의 게이트 — agreement_gate_enabled

기본 / 운영False / onprem·full-train True
동작자동확정 조건을 좁힌다: 공개등급(S3) 예측은 conf 단독 허용(S3 conf 정밀도 94%), 그 외(TS·S1·S2)는 룰엔진 원시등급 == 모델등급일 때만 자동확정·불일치면 검수. 등급은 무인 변경 없이 라우팅만.
측정구 후보셋 golden500 자동확정 정밀도 63→81%·고등급 미탐 46→8(~6배↓). 대가는 자동확정 커버리지↓(검수↑). 적대적 9에이전트·5차원 리뷰 통과(correctness 결함 0).

6.5 FNR-safe override — fnr_rule_ts/s1/s2_threshold

기본값TS 3.0 · S1 2.2 · S2 1.6
동작룰 엔진이 고등급을 이 점수 이상으로 잡는데 모델이 더 낮은 등급을 주면, 더 민감한(높은) 등급으로 상향(run() override). 모델이 미학습 도메인(M&A·암호·국방 등)을 낮게 줄 때 방어. 항상 적용.
기각된 변형임계 3.0→1.5 인하는 구 후보셋 golden100 +1로 싸 보였으나 golden500 +12로 일반화 실패(과적합) → 미반영(보고서 §7.2).

6.6 비공지성 cap — source_prior_enabled / source_prior_cap_grade

기본값True / "S3"
동작이미 공개된 출처(판례·공시·보도자료·공개특허 등)의 문서는 내용이 비밀급이어도 영업비밀 불성립(부정경쟁방지법 §2.2 비공지성) → 등급을 S3로 cap. 단 강한 상향신호(TS/S1)를 cap이 덮으면 'cap-conflict'로 검수 라우팅(무인 미탐 방지). metadata.source가 공개 출처일 때만 발동 → 내부문서 탐지엔 영향 없음.
측정게이트 미적용 시 진짜 공개판례의 85%가 비밀로 과분류(구 판례 legacy 실험값 reports/p1_real_public_fpr) — 현행 v5(v-fe4b386b) 게이트 적용 시 공개 과분류 79%→4%(n=400)로 억제. 유일 위험=출처 메타데이터 무결성(ingest 책임).

6.7 메타데이터 floor — metadata_floor_enabled

기본값False (opt-in)
동작KL ICD R6 보안표시·접근범위를 상향 신호로. ① security_marking이 예측보다 높으면 그 등급으로 상향 floor(명시표기 우선, 하향 안 함); ② 표기 없고 access_scope가 제한적(approved_only/designated/department)인데 예측이 낮으면 'metadata-access-conflict' 검수.
측정인사·재무 사각지대 7건: 보안표시=기밀 → 7/7 S1 상향, 접근범위=임원한정 → 7/7 검수. 메타데이터 신뢰도에 전적 의존(KL이 정확히 줘야) — 부재·오기는 사각지대 잔존.
ℹ
보너스 — LLM 2차의견(model_secondopinion_llm_enabled, 기본 False). 모델이 비-TS를 자동확정할 때 로컬 LLM(qwen3:14b)에게 2차의견을 받는 방식. golden100에서 검수 19→49 폭증·TS 누출 잔존·비용 21분이라 기각(비권장 보존). 모든 게이트는 기본 off이며, 켜는 것은 검수 인력·SLA를 고려한 운영 결정이다.

07 청크 집계 — most-severe-wins

긴 문서의 핵심 비밀 한 단락이 평범한 다수 청크에 희석돼 미탐되는 것을 막는다.

설정 키severe_agg_codes
기본값TS · S1
동작청크별 확률을 문서 확률로 합칠 때, 저등급(S2/S3)은 길이 가중 평균, 고등급(TS/S1)은 가장 강한 청크의 확률(max-pool)로 잡는다(_aggregate_chunk_probs). 단조 비감소라 평균보다 낮아질 수 없어 미탐 방향으로 후퇴하지 않는다.
효과·방향한 청크의 강한 비밀 신호가 평균에 묻히지 않게 → 미탐↓. 모델 경로·룰 폴백 경로에 동일 적용.

08 검색 융합 — RRF

⚠ 이건 등급분류가 아니라 RAG 검색 쪽 노브다 — "합의 보정 게이트"와는 결이 다른 축.

코드 상수_RRF_K = 60 (Cormack 2009 표준) · _CAND_N = 50 (후보 윈도우)
동작dense(pgvector) + 어휘(ts_rank_cd) 두 검색결과를 RRF(Reciprocal Rank Fusion)로 결합 — inc = 1.0 / (k + rank), 같은 문서가 여러 모달리티/쿼리에 뜨면 점수 누적(_rrf_combine · pg_store.search_hybrid).
"가중치"의 실체모달리티별 스칼라 weight가 아니라 RRF 상수 k=60(랭크 기반 균등 융합). 점수 스케일이 다른 dense/lexical을 순위로 정규화해 섞는다.
측정하이브리드 85% > dense 단독 76%(의사결정_대장 §03).
⚠
두 가지 정직 고지. ① 융합 가중치는 분류 핫패스가 아니라 RAG 검색 경로의 노브이며, RAG/answer는 현재 산출물에서 휴면(보조) 처리된 기능이다 — 등급결정 품질과는 별개 축. ② §9의 Optuna 튜너 docstring 제목은 "fusion 튜너"라 적혀 있으나 실제 탐색공간엔 융합 노브가 없다(보정·게이트·conf만 탐색). 융합 상수는 현재 자동탐색 대상이 아니다.

09 튜닝 — Optuna 자동탐색

재학습 없이 후처리 노브를 골든셋 기준으로 자동 탐색한다 — 전부 CPU·무GPU.

목적함수: maximize F1_macro subject to FNR_고등급(TS·S1) ≤ target(기본 0 = 미탐 0 요구). 제약 위반분만큼 페널티로 차감해 부드럽게 수렴(m6_evaluation/optuna_tuner.py). 평가는 서빙 경로 전체(evaluate_via_serving)를 재사용해 측정↔배포 동작을 일치시킨다.
