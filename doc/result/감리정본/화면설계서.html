사용자 인터페이스는 앱에 정적 마운트되는 시연·관제 콘솔 2종(/demo/)과 서버가 후보 파일을 읽어 렌더하는 골든셋 검수·서명 뷰 1종(/api/v1/golden/..., 주소 2개)으로 구성된다. 모든 화면은 별도 백엔드를 두지 않고 기존 /api/v1 엔드포인트를 그대로 호출한다. 각 화면의 주요 구성요소·기능·연계 API·상태표시를 코드 기준으로 정의한다.

범위 · 기준

본 화면설계서는 구현된 4개 화면(합성-only PoC 기준)을 소스에서 확인해 화면정의서 형식으로 정리한다. 화면 내 표기 수치·안내 문구는 데모 콘텐츠이며, 발주처 실문서 반입 후 갱신 대상이다.

접근 경로

시연·관제 콘솔의 상호 이동은 각 화면 네비게이션 링크(분류 콘솔 ↔ 거버넌스 콘솔)로 연결된다. 파싱·분류 시연은 2026-08-24 부터 분류 콘솔 안에 있어 이동 대상이 아니다. 골든 검수·서명 뷰는 거버넌스 콘솔의 「리뷰 HTML 열기」 또는 골든 잡 job_id로 직접 접근한다. GET 화면은 브라우저 직접 접속용이라 헤더 인증을 붙일 수 없어 GOLDEN_HTML_URL_SECRET 설정 시 ?t= HMAC 토큰을 강제하고, 서명 POST는 역할과 로그인 신원(JWT sub)을 강제한다 — 화면은 검수자 이름·API 키를 받지 않는다.

권한 신뢰 조건

X-Actor-Role 헤더 신뢰는 개발 기본값(api_key_trust_actor_role_header=True)에서만 적용된다. 운영(poc_mode=full)에서는 .env의 API_KEY_ROLE로 역할을 고정한다.

02실시간 등급분류 콘솔 (UI-01)

FUN-005 FUN-022 한국어 문서 본문 또는 업무 문서 파일을 받아 4단계 보안등급(TS·S1·S2·S3)을 자동 판정하고, 분류 과정과 근거(3요소 S·V·M·근거 키워드·법령)를 표시한다. 본문 입력은 SSE 6단계 실시간 점등, 파일 업로드는 서버가 돌려준 실제 처리 단계(추출 → 정규화·PII마스킹 → 청킹 → 검수 게이트 → 분류)를 표시한다. 파일: poc/src/koipa/api/static/index.html(+app.js).

2026-08-24 통합

별도 구역이던 UI-02(파싱·분류 시연)를 이 화면의 입력·결과 구역으로 흡수했다. 흡수 전에는 같은 엔드포인트(POST /documents/analyze)를 두 코드가 각각 호출하고 등급 결과 카드를 두 벌 그렸다. 지금은 결과 렌더가 한 곳(§2 결과)이고, 파일에만 있는 파싱 세부와 검수 게이트만 그 안의 접이식 「파싱 상세」로 내렸다. 배선은 app.js(ES module) 한 곳이며 인라인 전역 스크립트는 없앴다.

05골든 검수 뷰 (UI-04 — UI-05와 동일 화면)

골든 평가 인프라 UI-05와 같은 화면이다. 2026-08-18 검토본과 서명 화면을 하나로 합쳤다 — 같은 잡의 같은 후보를 보는데 화면이 둘이라 검수자가 같은 목록을 두 번 봤다. 이 주소는 그대로 두고 서명 화면을 제공한다(poc/src/koipa/api/golden.py의 golden_job_review_html → GoldenBuildService.render_signoff). 화면 구성요소·기능·상태 표시는 06 골든 서명 뷰(UI-05)와 동일하다.

주소를 남기는 이유

오프라인 번들 생성(build_offline_bundle.py)·E2E 시연(demo_e2e_golden.py)·검수 잡 등록(register_review_signoff_job.py)·운영 런북(OPERATION.md)이 이 주소를 참조한다. 주소를 없애면 그 경로가 404가 되므로, 주소는 유지하고 같은 화면을 준다.

종전 서술과의 차이

2026-08-18 이전에는 이 주소가 상태 변경 기능이 없는 읽기 전용 검토본(본문 미리보기 150자·#stats·#cnt·.card)이었다. 지금은 결정 폼과 제출 버튼이 있는 서명 화면이며, 본문은 미리보기가 아니라 전문을 보여준다. 합의 미달 후보는 같은 목록에 보기 전용으로 섞여 나온다.

06골든 서명 뷰 (UI-05)

골든 평가 인프라 gold 후보를 화면에서 클릭 서명하는 화면. 각 후보에 승인/등급변경/거부 폼을 붙이고, 제출 시 결정을 서버로 보내 locked_gold_eval(사람서명 평가정답)로 승격한다. 룰·LLM 합의 미달 후보는 결정 폼 없이 같은 목록에 보기 전용으로 함께 보여준다 — 종전 검토본(UI-04)이 하던 일이다. 검수자가 jsonl을 손으로 편집하는 대신 화면 클릭 서명으로 서명 캡처 갭을 해소한다. 렌더: poc/src/koipa/golden_review_html.py (render_signoff_html).

상태 표시

  • 카드: decided(초록)·rejected(적) 테두리
  • 서명 진행 「결정 N / 서명 대상 M」과 등급별 승격 예정 — 배포 게이트의 등급별 최소 건수를 서버 값으로 받아 미달을 표시한다
  • 중간 결정은 잡 단위로 이 브라우저에 남는다(서버 전송 아님). 창을 닫아도 이어서 할 수 있다
  • 제출 결과: locked 승격 건수·등급별 분포·readiness(ready/per_grade)·publish 반영 여부·서명자 신원
  • 미결정 후보는 제출에서 제외. 결정 0건이면 오류 배너. 보기 전용 후보는 결정 대상이 아니다
서명자 신원

화면은 검수자 이름·API 키를 받지 않는다. 서명자는 로그인 쿠키(JWT sub)로만 확정된다(2026-08-17). 이름을 손으로 적을 수 있는 한 원장에 남는 서명자는 자칭이기 때문이다. 서버는 is_human_reviewer로 머신·기본값 계정 서명을 거부한다. 고등급 이중서명 옵션(dual_for_upper)은 2026-08-06 제거됐다 — RFP·RTM에 근거가 없었다.
