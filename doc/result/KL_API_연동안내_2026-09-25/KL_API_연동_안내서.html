2. 접속과 인증

  • 주소 형식은 http://<엔진 주소>:8000/api/v1 입니다(온프레미스 Docker 내부망 기준 http://koipa-api:8000/api/v1). 실제 주소와 키 값은 배포 시 확정됩니다.
  • 서버 간 호출은 X-API-Key: <키> 헤더로 인증합니다. 헤더가 없거나 키가 다르면 401 입니다. 예: {"detail":"missing authorization"}
  • 요청은 JSON(Content-Type: application/json) 또는 등록만 multipart/form-data 입니다. 응답은 UTF-8 JSON, 시각은 ISO 8601 UTC 입니다.
  • 준비 확인 GET /api/v1/healthz 는 인증이 없고, 200 과 함께 status · model_version · uptime_sec 를 돌려줍니다. 그 밖의 필드는 운영 진단용이라 바뀔 수 있습니다.
export BASE="http://<엔진 주소>:8000/api/v1"
export KOIPA_API_KEY="<발급받은 키>"

curl "$BASE/healthz"

3. 호출 상세와 예시

3-1. 문서 등록 — IF-02

curl -X POST "$BASE/documents" \
  -H "X-API-Key: $KOIPA_API_KEY" \
  -F 'actor={"user_id":"kl-portal","role":"kl_backend"}' \
  -F 'source_type=internal' \
  -F 'security_marking=confidential' \
  -F 'access_scope=department' \
  -F 'file=@cost_report.txt;type=text/plain'

actor 는 JSON 문자열이며 role 은 admin · reviewer · system · kl_backend 중 하나입니다. KL 자체 문서번호는 엔진에 저장하지 않습니다 — 응답의 doc_id 와 KL 문서번호의 대응은 KL 쪽에서 보관하십시오.

필드형식필수설명
actor문자열필수호출자 정보 JSON 문자열: {"user_id": "...", "role": "..."}. 감사 기록에 남습니다.
source_type문자열선택ICD §3.1 출처: public | registered_patent | academic | internal | external_confidential. 공개 출처면 분류 시 S3 로 cap 된다.
security_marking문자열선택ICD §3.2 보안표시: top_secret | secret | confidential | none. 표기가 있으면 접근범위보다 우선한다.
access_scope문자열선택ICD §3.3 접근범위: approved_only | designated | department | all_employees. 보안표시가 none 일 때 관리수준(M)을 정하는 주 입력.
enqueue_classificationtrue/false선택true 면 등록과 동시에 비동기 분류를 큐에 건다(응답에 classification_job_id).
file파일필수등록할 원본 파일. 지원 형식은 아래 '등록에서 알아 둘 점'을 봅니다.

응답(201) 예시:

필드형식필수설명
doc_id문자열 · null 가능필수DB 적재 성공 시 UUID, 미가용 시 null. 같은 내용(SHA-256 동일)의 파일을 다시 등록하면 새로 만들지 않고 기존 doc_id 를 돌려준다.
filename문자열필수업로드한 파일 이름
source_format문자열필수감지한 파일 형식(확장자)

file_size_bytes정수필수파일 크기(바이트)

extraction_quality숫자필수추출 품질(0~1). 낮으면 requires_review 가 켜질 수 있다.
char_count정수필수추출된 글자 수. 0 이면 분류할 본문이 없다(지원하지 않는 형식 등) — warnings 를 확인한다.
chunk_count정수필수본문을 나눈 조각 수
pages_total정수 · null 가능선택전체 쪽수. 쪽 개념이 없는 형식은 null
classification_job_id문자열 · null 가능선택enqueue_classification=true 로 등록했을 때만 채워진다.
classification_status문자열 · null 가능선택enqueue_classification=true 로 등록했을 때만 채워진다.
classification_status_url문자열 · null 가능선택enqueue_classification=true 로 등록했을 때만 채워진다(호스트 없는 경로).

warnings문자열 배열필수

review_reasons문자열 배열선택requires_review 가 true 인 사유 목록

등록에서 알아 둘 점

  • 같은 내용의 파일을 다시 등록하면 새 문서를 만들지 않고 기존 doc_id 를 돌려줍니다(파일 내용의 SHA-256 기준). 이때 함께 보낸 메타데이터는 갱신되지 않습니다. 바꿀 값은 분류 요청의 metadata 로 보냅니다(5장).
  • 지원하지 않는 형식이거나 본문이 추출되지 않아도 201 로 등록됩니다. 이때 char_count 가 0 이고 warnings 에 사유가 담깁니다(예: ["extract: unsupported: exe", "no text extracted"]). 분류를 요청하기 전에 char_count 를 확인하십시오.
  • 지원 형식: txt · md · log · csv / hwp · hwpx / docx · doc / xlsx · xlsm · xls / pptx · pptm / pdf. 이미지(jpg · png 등)와 스캔 PDF 는 OCR 을 하지 않으므로 본문 없이 등록됩니다(char_count 0).
  • requires_review 가 true 이면 추출 품질이 낮아 분류 전에 검수가 필요하다는 표시이며, 자동분류를 그대로 통과하지 않습니다.

3-2. 분류 요청 — IF-03

curl -X POST "$BASE/classify/async" \
  -H "X-API-Key: $KOIPA_API_KEY" -H "Content-Type: application/json" \
  -d '{"doc_id":"ce3b4e0d-6ceb-452b-acbc-d5d7822a0f73"}'

content 는 보내지 않는 것이 표준입니다. 생략하면 등록할 때 저장한 본문을 사용합니다.

필드형식필수설명
doc_id문자열필수등록(IF-02)이 돌려준 doc_id(UUID). KL 자체 문서번호가 아닙니다.
content문자열선택분류할 본문 텍스트(선택). 생략하는 것이 표준이며, 생략하면 POST /documents 로 등록할 때 저장한 본문을 쓴다. 최대 1,048,576자.
metadata객체선택선택. 5장의 세 필드(source_type · security_marking · access_scope)를 담는 객체입니다. 요청에 있는 값이 저장된 값보다 우선합니다.
text_already_preprocessedtrue/false선택true 면 엔진의 본문 정규화 단계를 건너뛴다. 보내지 않아도 된다.
return_evidencetrue/false선택근거(evidence)를 응답에 담을지 여부
callback_url문자열선택완료·실패 시 엔진이 결과 JSON 을 POST 할 주소(선택). http/https 만 허용하고 loopback· link-local 주소는 거부한다 — 거부돼도 요청은 202 로 접수되므로 상태는 IF-05 로도 확인한다. 응답이 2xx 가 아니면 최대 5회 재시도하고 그래도 실패하면 엔진 쪽 DLQ 에 보관한다. 본문은 완료 시 {"job_id","status":"done","results":[ClassifyJobResult]}, 실패 시 {"job_id","status":"failed","error"} 이다. 서명 헤더는 붙이지 않는다.

응답(202) 예시:

{
  "job_id": "aea27889-4f0e-4b38-a70c-262b05a9a62a",
  "status": "queued",
  "status_url": "/api/v1/classify/jobs/aea27889-4f0e-4b38-a70c-262b05a9a62a"
}
필드형식필수설명
job_id문자열필수작업 식별자. IF-05 조회에 쓴다.
status문자열선택접수 직후 값. 큐 처리 경로는 queued, 즉시 처리 경로는 이미 done 또는 failed 일 수 있다.
status_url문자열필수상태 조회 경로(호스트 없는 상대 경로). 예 /api/v1/classify/jobs/{job_id}
  • 같은 doc_id 로 다시 요청하면 새 작업이 만들어집니다. IF-06 은 가장 최근 결과를 돌려줍니다.
  • 등록하지 않은 doc_id 를 보내면 오류가 아니라 최고 등급(TS) · needs_review 결과가 오고, 사유는 warnings 에 담깁니다(본문을 확인할 수 없어 안전 쪽으로 처리). 이 결과는 검수 목록과 판정 이력에 저장되지 않습니다. 반드시 등록한 뒤 분류를 요청하십시오.

3-3. 결과 조회 — IF-05

curl "$BASE/classify/jobs/aea27889-4f0e-4b38-a70c-262b05a9a62a" -H "X-API-Key: $KOIPA_API_KEY"

status 가 done 이 될 때까지 조회합니다. 시험 환경에서 1건은 접수부터 완료까지 약 7초가 걸렸고(1회 측정), 배포 환경과 문서 길이에 따라 다릅니다. 1초 간격 조회를 권장하며, 작업 상태는 기본 24시간 보관하므로 그 안에 결과를 KL 쪽에 저장하십시오.

status뜻조치
queued큐에 접수되어 처리 전잠시 뒤 다시 조회합니다
done성공. results[0] 에 결과가 있습니다(단건 요청은 길이 1)결과를 저장합니다
failed실패. error 에 사유가 있습니다사유를 확인하고 요청을 다시 보냅니다
partial다건 작업에서 일부만 성공. failed_doc_ids · errors 참조단건 연동에서는 나오지 않습니다
필드형식필수설명
job_id문자열필수작업 식별자
statusstring (queued | running | done | failed | partial | cancelled)필수현행 코드가 내는 값은 queued · done · failed · partial 이다. partial — 일부 건은 성공·일부는 영구 실패(다건 작업). completed/failed 로 분포를 확인한다.
total정수 · null 가능선택요청 건수(단건은 1)
completed정수 · null 가능선택성공 건 수
failed정수 · null 가능선택retry 모두 실패한 건 수
failed_doc_ids문자열 배열선택영구 실패한 doc_id 목록
errors객체 배열선택영구 실패 사유(doc_id · error_type · message · attempts)
resultsClassifyJobResult 객체 배열선택분류 결과. done 이면 채워지고 단건 요청은 길이 1 이다.
error문자열 · null 가능선택failed 일 때 사유

3-4. 문서 단위 조회 — IF-06

curl "$BASE/classify/ce3b4e0d-6ceb-452b-acbc-d5d7822a0f73" -H "X-API-Key: $KOIPA_API_KEY"

doc_id 는 등록이 돌려준 UUID 여야 합니다(아니면 422). 분류 이력이 없으면 404 입니다. IF-06 은 저장된 값으로 응답을 만들기 때문에 등급 · 확률 · 모델 버전 · 상태와 사람이 확정한 등급(confirmed_*)만 담습니다. 근거(evidence) · 경고(warnings) · 룰/모델 판정이 필요하면 IF-05 의 작업 결과를 사용합니다.

필드형식필수설명

3-5. 검수 확정 통보 — IF-07

지재원 포털에서 사람이 검수해 등급을 확정하면, KL 웹시스템이 이 결과를 엔진으로 돌려보냅니다 (①~④ 와 반대 방향 — KL → 엔진). 저희는 예측 label 을 그대로 감사 증적으로 남기고, 확정 등급은 다음 재학습의 입력으로 씁니다.

curl -X POST "$BASE/confirm" -H "X-API-Key: $KOIPA_API_KEY" -H "Content-Type: application/json" \
  -d '{"doc_id":"ce3b4e0d-6ceb-452b-acbc-d5d7822a0f73","confirmed_label":"S2","actor":{"user_id":"<지재원 포털의 실제 검수자 ID>","role":"kl_backend"}}}'

actor.user_id 에는 저희 쪽 계정이 아니라 지재원 포털에서 실제로 검수한 사람의 식별자를 담아 보내 주십시오 — 감사 로그와 재학습 라벨 출처에 그 값이 그대로 남습니다. actor.role 은 kl_backend 로 고정입니다.

6. 오류와 재시도

오류는 HTTP 상태 코드로 구분합니다. 본문은 대부분 {"detail": "사유"} 이며(422 는 항목별 배열), code 필드는 413(JSON 본문 한도) · 429 · 500 에만 있습니다. code 문자열이 아니라 상태 코드로 분기하십시오.

상태본문 예언제처리
401{"detail":"missing authorization"}키가 없거나 틀림키를 확인합니다. 재시도해도 같습니다
404{"detail":"job not found"}
{"detail":"no classification for doc_id"}		없는 job_id(보관 24시간 경과 포함) / 분류 이력 없는 doc_idIF-05 는 IF-06 으로, IF-06 은 분류 요청부터 다시 진행합니다
413{"detail":"file too large: …"}
{"detail":"request body too large","code":"KOIPA_BODY_TOO_LARGE"}		파일 20MB 초과 / JSON 본문 25MB 초과(기본값)크기를 줄여 다시 보냅니다
422{"detail":[{"type":"missing","loc":["body","doc_id"],"msg":"Field required",…}]}
{"detail":"empty file"}
{"detail":"doc_id must be a UUID"}		필수 필드 누락 · 형식 오류 · 빈 파일loc 가 가리키는 필드를 고쳐 다시 보냅니다
429{"code":"KOIPA_RATE_LIMIT","message":"rate limit exceeded: 60 per 1 minute","retry_after_sec":60}분류 요청이 분당 60건 초과Retry-After 헤더(초) 뒤에 다시 보냅니다
500{"code":"KOIPA_INTERNAL","message":"internal server error","request_id":"…","retryable":true}엔진 내부 오류retryable 이 true 이므로 다시 보낼 수 있습니다. 반복되면 request_id 와 함께 알려 주십시오
503{"detail":"service temporarily unavailable"}IF-06 조회 중 DB 일시 장애잠시 뒤 다시 조회합니다

등록(IF-02)은 같은 파일이면 같은 doc_id 를 돌려주므로 재시도해도 안전합니다.

7. 완료 통보(IF-04) — 선택

분류 요청(IF-03)에 callback_url 을 넣으면, 작업이 끝났을 때 엔진이 그 주소로 JSON 을 POST 합니다. 넣지 않으면 통보는 없고 IF-05 로 조회합니다.

완료   {"job_id": "…", "status": "done",   "results": [ { …ClassifyJobResult… } ]}
실패   {"job_id": "…", "status": "failed", "error": "…"}
  • 발송은 60초 주기로 처리되므로 완료 후 최대 약 1분 뒤에 도착할 수 있습니다. 즉시성이 필요하면 IF-05 조회를 사용하십시오.
  • 수신 서버가 2xx 를 돌려주면 성공입니다. 그 밖의 응답이면 최대 5회까지 다시 보내고, 그래도 실패하면 엔진의 실패 보관함에 남으며 더는 자동으로 보내지 않습니다.
  • 허용 주소는 http · https 입니다. loopback(localhost · 127.x) · link-local(169.254.x) · 클라우드 메타데이터 · 예약·멀티캐스트 주소는 거부되며, 이때에도 분류 요청은 202 로 접수되고 통보만 가지 않습니다. 사설망 주소(10.x · 172.16~31.x · 192.168.x)는 기본 설정에서 허용됩니다.
  • 엔진은 통보에 서명이나 인증 헤더를 붙이지 않습니다. 수신 주소는 내부망 접근 제한이나 URL 에 넣은 1회용 토큰 등으로 보호하시기 바랍니다.
  • 통보가 유실될 수 있으므로 IF-05 조회를 함께 두는 것을 권장합니다.
