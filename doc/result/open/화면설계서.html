영업비밀 자동 등급분류·RAG 시스템 화면설계서

사용자 인터페이스는 앱에 정적 마운트되는 시연·관제 콘솔 3종(/demo/)과 서버가 후보 파일을 읽어 렌더하는 골든셋 검수·서명 뷰 2종(/api/v1/golden/...)으로 구성된다. 모든 화면은 별도 백엔드를 두지 않고 기존 /api/v1 엔드포인트를 그대로 호출한다. 각 화면의 주요 구성요소·기능·연계 API·상태표시를 코드 기준으로 정의한다.

범위 · 기준

본 화면설계서는 구현된 5개 화면(합성-only PoC 기준)을 소스에서 확인해 화면정의서 형식으로 정리한다. 화면 내 표기 수치·안내 문구는 데모 콘텐츠이며, 발주처 실문서 반입 후 갱신 대상이다.

01화면 목록

화면은 실데이터·검수·반출이 없는 합성-only PoC 기준으로 5종이 구현되어 있다. 시연·관제 콘솔 3종은 정적 자산(StaticFiles)으로 /demo/에 마운트되고, 골든셋 검수·서명 뷰 2종은 서버가 골든 잡의 후보 build_*.jsonl을 읽어 렌더하는 동적 HTML이다.

접근 경로

시연·관제 콘솔의 상호 이동은 각 화면 네비게이션 링크(분류 콘솔 ↔ 파싱·분류 시연 ↔ 거버넌스 콘솔)로 연결된다. 골든 검수·서명 뷰는 거버넌스 콘솔의 「리뷰 HTML 열기」 또는 골든 잡 job_id로 직접 접근하며, GET 네비게이션은 인증 없이 열리되 서명 POST는 인증·역할·검수자 계정을 강제한다.

권한 신뢰 조건

X-Actor-Role 헤더 신뢰는 개발 기본값(api_key_trust_actor_role_header=True)에서만 적용된다. 운영(poc_mode=full)에서는 .env의 API_KEY_ROLE로 역할을 고정한다.

  • 검수대상: status-txt.uncertain(붉은 테두리) 「검수대상」; gold 후보는 일반 상태 텍스트
  • 룰·LLM 「일치 / 불일치」 라벨 표기
성격

본 뷰는 정답이 아닌 검토 후보를 보는 화면이며 상태 변경 기능이 없다. locked_gold_eval(사람서명 평가정답) 승격은 서명 뷰(UI-05)에서 수행한다.

06골든 서명 뷰 (UI-05)

골든 평가 인프라 gold 후보를 화면에서 클릭 서명하는 화면. 각 후보에 승인/등급변경/거부 폼을 붙이고, 제출 시 결정을 서버로 보내 locked_gold_eval(사람서명 평가정답)로 승격한다. 검수자가 jsonl을 손으로 편집하는 대신 화면 클릭 서명으로 서명 캡처 갭을 해소한다. 렌더: poc/src/lloydk/golden_review_html.py (render_signoff_html).
