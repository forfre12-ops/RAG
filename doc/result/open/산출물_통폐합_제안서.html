본 제안은 문서를 없애는 것이 아니라 묶는 것이다. 병합 대상의 본문은 모두 흡수처에 보존한다. 참고자료 정리도 §05 외 자료에 한하며, 그중 2종은 삭제가 아니라 현행 배포모델 기준 보고서로 교체다.

02왜 줄이는가 — 중복 비용 실측

산출물이 많은 것 자체보다, 같은 사실이 여러 문서에 흩어져 사는 것이 더 큰 리스크다. 값 하나가 바뀌면 여러 문서를 동시에 고쳐야 하고, 하나라도 빠지면 문서 간 상충으로 감리 지적이 된다. 2026-08-01 정본 전수 스캔 실측:

사실반복 문서 수바뀔 때 수정 범위
골든셋 규모 777건37골든셋 재빌드 시 37개 문서
배포 모델 v-fe4b386b11모델 승격·롤백 시 11개 문서

실제로 이 구조 때문에 발생한 사례가 있다. (1) 시험 수치가 낡아 10개 문서를 동시에 정정했고, (2) GPU 토폴로지가 4개 문서에서 서로 다르게 기술돼 있었으며, (3) 문서 ID DOC-DEC-01이 두 산출물에 중복 부여됐다. 셋 다 "같은 사실이 여러 곳에 산다"는 하나의 원인에서 나왔다.

따라서

종수 축소만으로는 부족하다. §07의 숫자 단일출처 규율이 함께 가야 실질적인 상충 위험이 줄어든다.

07숫자 단일출처 규율

§02에서 본 중복은 종수를 줄여도 사라지지 않는다. 28종으로 줄여도 v-fe4b386b가 8개 문서에 남으면 같은 문제다. 아래 규율을 함께 확정할 것을 제안한다.

동결 시점에 자동 검사를 걸 수 있다. 번들 생성기(scripts/build_supervision_bundle.py)가 이미 문서 ID·산출물 수를 계산으로 고정하고 SHA-256 무결성을 발급하므로, 지정 수치의 다중 출현 검사를 같은 자리에 추가하면 재동결마다 상충이 자동 검출된다.

08확정 요청 사항

사업수행계획서 §05 비고는 최종 제출본의 산출물 구성·명칭·서식을 발주처·감리 확정 대상으로 둔다. 수행사는 아래 3건의 확정을 요청한다.

번호확정 요청확정 시 조치
1제안 A — 부록·원본형식을 상위 산출물의 하위로 계수(34종 → 30종, 파일 변경 없음)manifest 계수 규칙만 조정
2제안 B — WBS 2종 → 1종, 시험 2종 → 1종 병합(30종 → 28종)정본 병합 후 새 release_id 로 재동결
3§07 숫자 단일출처 규율 채택정본 정리 + 동결 시 자동 검사 배선
미확정 시

확정 전까지는 현행 34종 구성을 그대로 유지한다. 확정 없이 수행사가 산출물을 줄이면 감리 체크리스트와 어긋나 누락 지적이 될 수 있으므로, 본 제안은 실행이 아니라 협의 안건으로 제출한다.
