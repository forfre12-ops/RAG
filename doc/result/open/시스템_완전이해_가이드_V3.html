이 문서 하나만 읽어도 시스템 전체가 이해됩니다. 서버 구조, 동작 흐름, 각 단계 합격 기준, 어떤 모델을 쓰는지, 어떤 상황에서 어떤 로직이 실행되는지 — 모두 담았습니다.

⚡ 핵심만 먼저 — 10줄 요약
  • 회사 문서에 등급을 자동으로 붙여주는 AI 시스템입니다.
  • TS(최고기밀) / S1 / S2 / S3 4단계로 분류합니다.
  • 등급 = 비공지성(S) × 경제적 유용성(V) × 비밀관리성(M) 곱셈 — 한 요건이라도 0이면 공개(S3).
  • 문서 업로드 → 2~3초 → 등급 + 판단 근거 반환.
  • "영업비밀"이란 단어가 없어도 내용의 의미를 보고 판단합니다.
  • 현행 모델 KF-DeBERTa F1 0.686 · 미탐율(FNR) 0.018 (서빙경로, 홀드아웃 109건).
  • AI가 틀리면 사람이 수정 — 정정은 진단·교정 데이터로 축적되며, 재학습 반영 방식은 미확정(A 무반출 기본 / B 온사이트 / C 문서반출 — 확인안 §6)이고 모델은 상시 재학습하지 않습니다(지재원 자기 골든셋 1차학습 + 드리프트 트리거 단발).
  • 인터넷 없는 폐쇄망에서도 로컬 AI 모델로 완전 동작합니다.
  • 모든 분류 요청이 감사 로그에 기록됩니다.
  • AI는 보조, 사람이 최종 판단 — 이 원칙을 시스템이 강제합니다.
00-A 왜 AI가 필요한가?

키워드 검색으로 안 되나요?

"영업비밀", "기밀"이라는 단어만 찾으면 되는 거 아닌가요? 안 됩니다. 이유를 봅시다.

❌ 기존 방식 — 키워드·수작업
  • "M&A 실사 보고서"라는 단어가 없어도 그 내용이면 TS
  • "배터리 전해질 합성 비율"에 기밀이라고 안 써있어도 TS
  • 사람마다 기준이 달라 같은 문서도 담당자에 따라 등급이 다름
  • 10,000건 문서를 사람이 분류하면 수개월 소요
  • 퇴사나 부서 이동 시 분류 기준이 사라짐
✓ AI 방식 — 의미 이해
  • "EUV 노광 에너지 설정값" → 기술적 의미를 보고 TS 판정
  • "우리 회사만 아는 공정 노하우" → 맥락으로 S1 판정
  • 같은 기준으로 24시간 일관된 분류
  • 10,000건도 수시간 내 처리
  • 사람은 AI가 헷갈리는 경계 케이스만 검토
📖 "의미를 본다"는 게 어떻게 가능한가?

AI 모델은 수억 개의 한국어 문서를 학습해서 단어들 간의 관계를 수치로 알고 있습니다. "반도체 공정 파라미터"라는 표현이 나오면, 이 문장이 회사 내부에서만 공유되는 핵심 기술 문서와 같은 맥락이라는 것을 학습을 통해 파악합니다. 키워드 검색은 단어가 있는지만 보고, AI는 문장이 무엇을 의미하는지를 봅니다.

🔍 한 걸음 더 — "검색"과 "분류기"는 일하는 방식이 다릅니다

같은 "의미"를 쓰더라도 방식이 갈립니다. 키워드·벡터 검색은 "찾아보기(조회)"입니다. 새 문서가 들어오면 예전에 본 문서 중 가장 비슷한 것을 찾아 그 옆 문서의 등급을 빌려옵니다. 비슷한 예가 있으면 맞지만, 표현이 조금만 바뀌거나 닮은 예가 없으면 엉뚱한 등급을 빌려옵니다.

분류기는 "문서를 직접 읽기"입니다. 옆 문서를 빌리지 않고, 문장 속에서 각 단어가 그 맥락에서 무슨 뜻인지를 따져 직접 등급을 매깁니다 — 경험 많은 검수자가 처음 보는 문서라도 끝까지 읽고 판단하는 것과 같습니다. 그래서 처음 보는 표현에도 더 안정적이고, 실측에서도 분류기가 정확도·미탐(FNR) 모두 앞섭니다. (실제로는 분류기가 등급을 결정하고, 키워드 룰은 근거 표시·교차검증으로 함께 씁니다.)

👉 두 방식을 같은 데이터로 직접 맞붙인 결과는 검색 단독 vs 검색+분류기 등급분류 비교 문서에서 자세히 볼 수 있습니다.

00-B 이 설계가 최선인 이유

왜 이런 구조로 만들었나요?

설계마다 이유가 있습니다. "왜 이걸 썼나요?"라는 질문에 대한 답변입니다.

🤖 왜 KF-DeBERTa?
한국어 금융·법률 문서에 최적화된 모델입니다. 영업비밀 문서는 대부분 한국어 법령·계약·기술 문서입니다. 일반 BERT보다 한국어 법률/기술 문맥 이해도가 높아 현행 운영값 F1=0.686 · 미탐율(FNR) 0.018을 달성했습니다. GPT-4를 쓰면 더 정확할 수 있지만, 폐쇄망 불가, 비용 과다, 데이터 외부 전송 문제가 있습니다.
🔍 왜 KURE-v1?
한국어 의미 검색에서 Recall@5 = 0.808로 BGE-M3(0.790)보다 높습니다. 한국어 특화 임베딩 모델로, 판례·기술 문서에서 의미적 유사도를 더 정확히 계산합니다. 영어 중심인 범용 모델보다 한국어 문서 검색에서 consistently 우수합니다.
📦 왜 PostgreSQL pgvector?
AI 개발을 맡은 로이드케이가 검색·벡터 엔진으로 PostgreSQL pgvector를 채택해 시스템에 포함·납품합니다. 의미 검색·키워드 검색·트랜잭션을 하나의 DB에서 처리하는 것이 핵심 이유입니다. pgvector(의미 dense) + bigram tsvector·ts_rank(어휘)를 PostgreSQL 안에서 RRF로 결합하고, 감사장부·확정/보정 트랜잭션도 같은 DB가 담당합니다. 별도 검색엔진(Elasticsearch 등)을 붙이면 서버·JVM·라이선스(RRF=platinum)·이중쓰기 정합 부담이 추가되는데, PG는 어차피 필수라 신규 컴포넌트 0으로 끝납니다. 실 PG 풀스택 측정(2026-06-24)으로 하이브리드(85%)가 dense 단독(76%)보다 우수함을 확인했습니다(쿼리가 합성·LLM 생성이라 실 운영쿼리 모니터는 본개발 · 의사결정_대장 §03, ES→PG 단일화).
💬 왜 Claude 기본?
한국어 이해도와 99.9% SLA가 현재 최선이며, LLM은 선택적 보조 용도입니다. 그러나 환경변수 하나로 GPT-4o, 로컬 Qwen3 등으로 교체 가능하게 설계했습니다. 폐쇄망에서는 Qwen3-14B로 자동 전환됩니다. 벤더 종속 없음.
🛡 왜 FNR-safe 오버라이드?
AI가 "S3"이라고 해도 규칙 엔진이 "TS 특징이 강하다"고 판단하면 강제로 TS로 올립니다. 보안 도메인에서 미탐(기밀을 공개로 분류) 1건 = 보안 사고입니다. 과탐(공개를 기밀로 분류)은 사람이 수정하면 됩니다. 방향이 다른 비대칭 리스크.
💾 왜 Best-effort 저장?
DB 저장이 실패해도 분류 응답은 정상으로 반환합니다. DB 장애가 서비스 장애로 전파되지 않습니다. 영업비밀 분류는 실시간성이 중요하고, 저장 실패는 나중에 재처리할 수 있습니다. 실패 시 warnings 필드에 이유를 기록해 투명성을 보장합니다.
✂️ 왜 청킹 1200자?
oss_corpus 문서 평균 3842자 → 기존 1500자 잘라내기 방식은 중반 이후 내용을 검색할 수 없었습니다. 1200자 × 100자 겹침으로 청킹하면 3754문서 → 약 1.5만 벡터(4.1배), Recall@5 0.624→0.808 달성. 더 작게 쪼개면 문맥이 끊기고, 더 크게 하면 정밀도가 낮아집니다. 실험으로 1200자가 최적임을 확인.
🏢 왜 멀티테넌트를 안 쓰나?
고객사 간 분리는 구조로 끝납니다 — 각 고객사가 독립 폐쇄망에 따로 배포되고 고객사 페이지·접근은 KL(원청) 포털이 일원 관리하므로, 한 서버가 여러 고객사를 섞어 담는 멀티테넌시 자체가 필요 없습니다. 단일 기관 배포 내부의 실제 접근통제(누가 어떤 등급 문서를 보는가)는 권한(RBAC)·등급 인가로 처리합니다.
01 이 시스템이 뭔가요?

한 문장으로 설명하면

회사 내부 문서를 AI가 읽고, 영업비밀 등급(TS / S1 / S2 / S3) 4가지 중 하나로 자동 분류해주는 시스템입니다.

예를 들어 "반도체 공정 레시피 문서"를 시스템에 넣으면, AI가 내용을 분석해서 "이건 최고기밀(TS)입니다"라고 판정합니다. 동시에 "왜 그렇게 판단했는지" 근거 구간도 함께 알려줍니다.

💡 왜 이게 필요한가?

회사마다 수만 건의 문서가 있는데, 사람이 일일이 등급을 매기면 시간도 오래 걸리고 기준도 일관되지 않습니다. AI를 쓰면 빠르고 일관된 기준으로 분류할 수 있고, 사람은 AI가 애매하게 판단한 것만 검토하면 됩니다.

4가지 등급 — TS / S1 / S2 / S3

등급이 높을수록 더 민감한 문서입니다. 유출됐을 때 피해가 클수록 높은 등급을 받습니다.

TS
특급기밀 (Top Secret)
유출되면 회사 존립이 위협받는 최고 기밀. 극소수 임원만 접근 가능.
예시 ▸ 반도체 EUV 공정 파라미터 · M&A 협상 가격 · 신약 후보물질 합성 경로 · HSM 암호화 마스터 키 · 방위산업 핵심 알고리즘
S1
1급 비밀 (Secret)
유출되면 경쟁우위 상실 또는 영업비밀 침해가 발생하는 기밀.
예시 ▸ 제조 공정 노하우 · 원가 구조 분석 · 핵심 고객 데이터베이스 · 미공개 마케팅 전략 · 독자 개발 AI 모델
S2
2급 대외비 (Confidential)
외부 공개 시 협상력 약화 또는 이미지 손상이 우려되는 내부 자료.
예시 ▸ 미확정 분기 매출 초안 · 사업 계획 내부 검토안 · 거래처 협상 조건 · 내부 감사 결과 · 임원 인사 계획
S3
3급 공개 (Restricted)
공개 예정이거나 이미 공개된 정보. 민감도가 낮은 일반 사내 자료.
예시 ▸ 보도자료 · 채용공고 · 공시 자료 · 회사 소개서 · 이용약관 · 법원 공개 판결문
🔖 S1 판단 기준 명문화 — v2.2 기준

비밀관리성 M=0이어도 비공지성 S=2 · 경제적 유용성 V=2이면 S1 확정.
형식적 관리 체계가 없더라도 내용 자체가 비공개·고가치이면 S1로 판정합니다(부정경쟁방지법 §2.2 실질 해석 기준).

전형 유형 6가지:

  • 알고리즘 파라미터 — 내부 미공개 모델 가중치·하이퍼파라미터
  • 축적 노하우 — 반복 실험으로 쌓인 공정 최적화 조건
  • 비공식 열람 제한 전략 — 공식 DRM 없이 구두·이메일로만 열람 통제된 전략 문서
  • NDA만 있는 문서 — 비밀유지계약서만 존재하고 별도 보안 시스템 없는 계약 조건
  • 승인 전 임상 데이터 — 규제기관 제출 전 미공개 임상시험 결과
  • 계리 테이블 — 보험·금융사의 내부 손해율·요율 산출 테이블

등급은 어떻게 정해지나? — 3요건 곱셈 (S × V × M)

등급은 점수를 더해서 매기지 않습니다. 부정경쟁방지법의 영업비밀 3요건을 각각 0·1·2점으로 채점한 뒤 세 점수를 곱해서 등급을 정합니다. 곱셈이므로 한 요건이라도 0점이면 곱이 0 → 무조건 공개(S3)가 됩니다. 예를 들어 아무리 가치 있는 정보라도 이미 공개됐다면(비공지성 0) 영업비밀이 아닙니다.

요건0점1점2점
S — 비공지성
(외부에 알려지지 않음)		이미 공개됨통상적으로 입수 곤란보유자를 통하지 않곤 알 수 없음
V — 경제적 유용성
(돈이 되는 가치)		가치 없음비용·노력이 투입됨상당한 비용·노력이 투입됨
M — 비밀관리성
(접근 제한·관리)		공개·관리 안 됨임직원 일부에게만 공유승인된 자만 접근
S × V × M = 8→TS (특급기밀, 2×2×2)
S × V × M = 4→S1 (1급 비밀)
S × V × M = 1 또는 2→S2 (2급 대외비)
S × V × M = 0→S3 (공개 — 한 요건이라도 0)
⚠ 가이드 원본 vs v2.2 보정 — 정책 승인 필요

위 4단계 매핑은 발주처 정본 가이드 원본(스캔본 11~12p 직접 대조) 그대로입니다. v2.2는 골든셋 실증으로 2곳을 보정했습니다 — ① S=2·V=2·M=0: 가이드는 곱=0이라 공개(S3)지만 v2.2는 S1(미탐 방지), ② S=1·V=2·M=2 등 S<2의 곱=4: 가이드는 1급 비밀이나 v2.2는 S2(과분류 방지). 가이드 예시값을 정정하는 것이라 "가이드 기본값 + 보정 토글"로 분리해 정책 승인 후 적용을 권고합니다. A안(Σ5요소 100점)은 경영·재무 판단값 65점을 포함해 AI 산출 불가 → 사람 수기 자가진단. (상세: 등급분류 기준 적용서 v2.2 §3.7)

골든셋 실증 기반 — 등급 결정 분기표

곱셈 결과만으로 등급이 확정되지 않는 경계 케이스를 처리하는 v2.2 분기 로직입니다. S=2·V=2 조합은 M 값에 따라 TS 또는 S1로 분기됩니다.

조건 세부 분기 결정 등급 비고
S=2 AND V=2 M=0 S1 비밀관리성 없어도 고비공지·고가치 → S1 확정 (v2.2 명문화)
S=2 AND V=2 M=1 TS 접근자 지정만 있어도 최고기밀 수준 충족
S=2 AND V=2 M=2 TS 3요건 모두 최고점 → TS (S×V×M = 8)
그 외 S=0 (공개됨) S3 비공지성 0 → 영업비밀 요건 미충족
그 외 S×V×M ≥ 1 S2 1~2점대 — 대외비 수준
그 외 S×V×M = 0 S3 한 요건이라도 0 → 공개

골든셋 실증 기반 — 도메인별 S·V·M 앵커 표 (100건 실증)

골든셋 100건을 도메인별로 분석해 도출한 S·V·M 점수 앵커입니다. 신규 문서 판정 시 해당 유형과 대조하여 채점 기준으로 활용합니다.

📖 왜 더하기가 아니라 곱하기인가?

예전에는 4가지 요소(경제적가치·비공지성·관리수준·유출영향도)에 가중치를 곱해 100점 만점으로 더하는 방식이었습니다. 하지만 가산 방식은 "이미 공개된 정보(비공지성 0)"인데도 다른 점수가 높으면 기밀로 잘못 매겨질 수 있는 허점이 있었습니다. 그래서 2026-06-18부터 법 요건 그대로 3요건 곱셈식(B안)으로 전환했습니다. 곱셈은 "세 요건을 모두 충족해야 영업비밀"이라는 법리(부정경쟁방지법 §2.2)를 정확히 반영합니다. 옛 4요소는 키워드 시드 태그로만 남아 자동으로 3요건에 접혀 들어갑니다(유출영향도→경제적유용성). 코드: rule_engine.py의 grade_from_svm(), SVM_GRADE_MAP={8:TS,4:S1,2:S2,1:S2,0:S3}.

⚠️ 설계 철학 — 미탐(FNR)이 더 위험하다

분류 오류에는 두 종류가 있습니다: 미탐(기밀을 공개로 잘못 판정)과 과탐(공개를 기밀로 과도 판정). 이 시스템은 미탐 방지를 최우선으로 합니다. 기밀 문서를 공개로 잘못 판정하면 보안 사고가 됩니다. 공개 문서를 기밀로 잘못 판정하면 사용자가 수정하면 됩니다. AI가 애매하면 더 높은 등급을 부여하도록 설계되어 있습니다(곱셈 등급과 내용 등급이 다르면 더 민감한 쪽 채택 — FNR-safe).

📖 F1 / Recall@5 가 뭔가요?

F1 점수는 분류 정확도를 0~1로 나타낸 것입니다. 0.686은 100건 중 약 69건을 올바르게 분류(4등급 균형 난이도 기준).
Recall@5는 "관련 문서가 검색 결과 상위 5개 안에 있을 확률"입니다. 0.808이면 80.8%의 질문에서 정답 문서를 상위 5개 안에 찾아냄.

📊 핵심 발견 — "평가 ↔ 서빙 갭" (실배포 경로로 재측정)

같은 모델·같은 홀드아웃 109건이라도 어떻게 재느냐에 따라 안전성 수치가 9배 차이가 납니다. 모델 출력을 그냥 최댓값으로 읽는 원시 argmax로 재면 방향성 미탐율(FNR) 0.167·F1 0.632이지만, 실제 배포되는 서빙 경로(보정 + FNR-safe 상향 + 청크 최댓값 집계)를 통과시켜 재면 미탐율 0.018·FNR_TS 0.000·F1 0.686이 됩니다.
→ 서빙 경로의 미탐이 약 9배 낮습니다. 그래서 우리는 평가도 실배포 경로 그대로(evaluate_via_serving) 측정합니다 — 평가 수치가 곧 운영 동작이 되도록.

05 전체 워크플로우

문서를 넣으면 무슨 일이 일어나나요?

문서를 API로 전송하면 아래 6단계를 거쳐서 분류 결과가 나옵니다.

한눈에 보기 — 6개 모듈이 두 흐름에 나뉘어 동작

M1~M6 모듈은 ① 문서를 분류할 때와 ② 모델을 재학습할 때 서로 다르게 등장합니다.

① 문서 업로드시 — 실시간 분류 (모델 사용)
M2 전처리 → M5 추론 (내부에 M3 규칙엔진 FNR-safe) → 관리자 최종확정
텍스트 추출·청킹 → AI 분류(+규칙 안전망) → 임시저장 → 사람 확정. M1·M4·M6은 안 씀(이미 학습된 모델을 쓰기만).
② 재학습시 — 능동학습 폐곡선 (모델 개선)

4
AI 분류 추론 (InferencePipeline) — 핵심 단계

텍스트를 AI 모델에 넣어서 TS/S1/S2/S3 중 하나와 신뢰도 점수를 얻습니다.

경로 A: ML 모델이 있을 때 (운영 모드)

KF-DeBERTa-base 모델을 사용합니다. 텍스트를 입력하면 각 등급별 확률 점수가 나오고, 가장 높은 점수의 등급이 최종 예측값이 됩니다.

경로 B: ML 모델이 없을 때 (폴백 모드)

키워드 기반 규칙 엔진이 대신 분류합니다. 약 400개의 키워드 목록에서 텍스트에 등장하는 키워드와 가중치를 계산해서 등급을 결정합니다.

🛡 FNR-safe 오버라이드 — 미탐 방지 안전장치

ML 모델이 낮은 등급(예: S3)을 예측해도, 규칙 엔진이 "이건 TS 특징이 강하다"고 판단하면 더 높은 등급으로 강제 상향됩니다.

  • 규칙 엔진 TS 점수 ≥ 3.0 → TS로 상향 (fnr_rule_ts_threshold)
  • 규칙 엔진 S1 점수 ≥ 2.2 → S1로 상향 (fnr_rule_s1_threshold)
  • 규칙 엔진 S2 점수 ≥ 1.6 → S2로 상향 (fnr_rule_s2_threshold)

이 덕분에 현재 시스템의 서빙 경로 방향성 미탐율(FNR) = 0.018, FNR_TS = 0.000입니다(홀드아웃 109건, 원시 argmax 0.167 대비 9배 낮음).

⚖ 출처 게이트 + 청크 집계 — 상·하향 양방향 보정
  • 청크 집계(max-pooling): 긴 문서를 토막내 분류할 때 고급 비밀(TS·S1)은 평균이 아니라 가장 강한 토막을 따릅니다 — 한 단락의 비밀이 평균에 묻혀 미탐되지 않게(S2·S3는 표준 평균).
  • 출처 게이트(비공지성, 기본 ON): 공개 출처(판례·공시·공개특허 등)는 내용과 무관하게 S3로 하향(cap) — 이미 공개된 건 영업비밀이 아니므로(부정경쟁방지법 §2.2). 실데이터 과분류 0.85→0.002.
  • 메타데이터 floor 게이트(metadata_floor_enabled, opt-in·기본 OFF): 출처 하향의 상향 대칭 — KL ICD R6 보안표시(top_secret→TS·secret→S1·confidential→S2)가 예측보다 높으면 그 등급으로 상향 floor하고(명시표기 우선·하향 안 함), 접근범위가 제한적인데 예측이 낮으면 검수로 라우팅합니다.
  • 충돌 시 사람에게(cap-conflict): 출처 하향이 고급 비밀 신호를 덮으면 자동 확정하지 않고 needs_review로 보냅니다 — 내부 비밀이 '공개'로 오태깅돼 새는 것을 막기 위함.

5
DB 저장 (Best-effort)

분류 결과를 PostgreSQL에 저장합니다. "Best-effort"란 저장에 실패해도 응답은 정상적으로 반환한다는 뜻입니다. DB 장애가 있어도 분류 서비스가 중단되지 않습니다.

저장 항목: tb_classifications (예측 등급, 신뢰도, 모델), tb_classification_evidence (근거 구간), tb_chunks (텍스트 조각), tb_audit_log (감사 기록)

원본 파일은 로컬 파일시스템에 at-rest 암호화(AES-256-GCM)로 보관하고, 분류·검색 경로에는 PII 마스킹된 텍스트만 사용합니다(원본·마스킹본 분리 — 원본은 증빙용).

📖 등급별 성능 (홀드아웃 109건)

TS는 미탐을 막는 게 최우선이라 재현율(Recall)을 높게 잡았습니다: TS 정밀도 0.533 / 재현율 0.941 · S1 0.667 / 0.316 · S2 0.600 / 0.600 · S3 0.850 / 0.791. TS 재현율이 높다는 건 진짜 특급기밀을 거의 놓치지 않는다는 뜻입니다(미탐 0).

📦 정답셋(골든셋) — 500건 4등급 균형

모델 성능을 채점하는 기준 정답지(골든셋)는 본셋 500건으로, TS/S1/S2/S3 각 125건씩 4등급을 균형(25%)있게 맞췄습니다. 한 등급에 쏠려 있으면 점수가 부풀 수 있어 일부러 고르게 분포시킵니다. 도메인은 반도체(EUV)·방위사업·M&A·AI·바이오약물·보안 6종, 각 600~1,000자에 구체적 기술 지표를 담았습니다. S/V/M을 독립적으로 판독한 뒤 곱한 등급이 정답 등급과 500/500 정합함을 검증했습니다. (초기 파일럿은 52건이었고, 그중 67%가 전문가 검수가 필요한 경계 케이스였습니다.)

📖 DeBERTa가 뭔가요?

Microsoft가 만든 BERT 계열 언어 모델입니다. "disentangled attention"이라는 기술로 단어의 위치와 내용을 분리해서 처리하기 때문에 기존 BERT보다 문맥 이해 능력이 높습니다. KF 버전은 금융/법률 한국어에 최적화되어 있습니다.

⚡ 신규 — 저신뢰 자동 검수 라우팅 (needs_review)

이제 신뢰도가 임계값(review_confidence_threshold = 0.7) 미만이면 시스템이 자동으로 응답 status를 "needs_review"로 표시하고 warnings에 검수 권고를 남깁니다. 거부(reject)가 아니라 표시입니다 — 고위험 미탐(FNR)을 막기 위해 결과는 그대로 반환하되 사람 검토로 라우팅합니다. 검수 큐는 신뢰도가 같을 때 저신뢰 항목을 먼저 보여주도록 정렬됩니다.

⚡ 신규 — 자동확정/검수는 confidence 단독이 아니라 다단 게이트로 결정 (둘 다 opt-in · 기본 OFF)

confidence는 분류기가 학습한 신뢰도가 아니라 softmax 파생값이라 OOD(학습 분포 밖)에서 과신하며 정답/오답 판별력이 낮습니다(골든500 AUROC 0.58). 그래서 자동확정은 confidence 임계(기본 0.7) 단독이 아니라 아래 게이트들로 판단합니다. 모두 opt-in이며 기본은 OFF라 켜기 전에는 기존 동작이 그대로입니다.

  • ① 희소근거 게이트(rule_fallback_min_evidence) — 단일 약한 키워드만으로 conf=1.0이 되는 룰-폴백 자동확정을 차단합니다(golden100 무성 TS 미탐 5→0).
  • ② 합의 게이트(agreement_gate_enabled) — 자동확정은 예측이 공개등급(S3)이거나 룰등급==모델등급일 때만 허용하고, 그 외 불일치는 사람 검수로 보냅니다(자동확정 정밀도 63→81%, 고등급 TS/S1 미탐 46→8). TS/S1 자동확정분은 표본감사합니다.
  • ③ 메타데이터 floor 게이트(metadata_floor_enabled) — KL ICD R6의 보안표시·접근범위로, 내용 분류기가 못 보는 비밀관리성(M)·출처(S)를 보완합니다. 출처 게이트(공개출처→S3 하향)의 상향 대칭으로, ① 보안표시(top_secret→TS·secret→S1·confidential→S2)가 예측보다 높으면 그 등급으로 상향 floor(명시표기 우선·하향은 하지 않음), ② 접근범위가 제한적(approved_only/designated/department)인데 예측이 낮으면 검수로 라우팅합니다. 인사·재무 S1 사각지대를 재학습 전 결정론적으로 차단합니다(KL 마킹 신뢰 전제).

합의 게이트 적용 시 재생성 기준 — golden100: 자동확정 35 / 검수 65 (미탐 0), golden500: 자동확정 189 / 검수 311 (TS·S1 미탐 8). 모든 수치는 합성 골든셋(OOD) 기준이며 실데이터(human_review) 검증 전에는 정식 FNR/정확도 수치가 아닙니다.

⚠️ 중요: TS/S1은 신뢰도에 관계없이 상향 유지

신뢰도가 낮더라도 TS 또는 S1로 판정된 경우 함부로 내리지 마세요. 시스템은 FNR-safe 원칙으로 설계됐습니다 — 기밀이 아닌 것을 기밀로 올리는 건 괜찮지만, 기밀을 내리는 건 위험합니다. 내릴 때는 반드시 근거가 명확해야 합니다.

⚙️ 운영점 — 미탐 강제 0이 필요하면 escalation τ

기본 운영점은 τ = None (그냥 argmax)입니다 — 서빙 경로가 이미 미탐율 0.018 · FNR_TS 0을 달성해 추가 조정이 불필요하기 때문입니다. 발주처가 "고등급 미탐 절대 0"을 요구하면 선택적으로 τ = 0.35를 켜서 TS·S1 미탐을 모두 0으로 강제할 수 있습니다(대신 F1 약 −2.8%p). 너무 낮게(τ ≤ 0.25) 잡으면 과분류가 급증해 검수 부담이 커지므로 비권장(F1 −8%p)입니다.

13 비용 시나리오

API와 GPU는 각각 어디에 쓰나요?

기본은 무GPU(CPU)입니다. 민감 데이터를 다루는 추론(분류·임베딩)은 폐쇄망 CPU에서 처리하고(LLM-free 핫패스), 상용 LLM(Claude 등)은 데이터 반출이 허용되는 공개·개발용으로만 씁니다. GPU는 학습 가속 옵션(요건상 발주처 제공·CSAP 샌드박스)으로 필수가 아닙니다.

기능실행 위치비고
문서 분류 (KF-DeBERTa)CPU핵심 요건 · LLM-free 핫패스 · 무GPU(≈333ms/건)
임베딩·검색 (KURE-v1)CPU온프렘 인덱싱·검색(CPU로 충분)
분류기 학습 (재학습 시)GPU 선택발주처 GPU 제공 시 가속 · 미제공 시 CPU(느림)
상용 LLM (Claude)공개데이터만골든·합성 생성 보조 · 비밀 본문 미투입
🔒 왜 무GPU(CPU)인가

영업비밀은 데이터 외부 반출이 금지되어, 폐쇄망 운영에서는 상용 LLM·클라우드를 비밀 분류 본경로에 쓸 수 없습니다. 그래서 비밀 분류는 학습된 분류기+룰로 CPU에서 처리(LLM-free)하고, 임베딩·검색도 CPU로 충분합니다 — 무GPU로도 동작. GPU는 (요건상 발주처 제공 시) 학습 가속에만 쓰고 추론엔 불필요합니다. 상용 LLM은 공개·합성 데이터 가공에만 활용합니다. (상세 용량·비용은 본개발에서 별도 제시)

헷갈리는 용어 한눈에 보기

이 문서에서 나오는 기술 용어를 처음 보는 분을 위한 사전입니다.

AI 모델
Artificial Intelligence Model
수백만~수억 개의 문서를 읽고 학습해서 패턴을 파악한 수학 함수. 텍스트를 넣으면 학습된 패턴으로 예측값을 반환합니다.
예: KF-DeBERTa는 한국어 금융/법률 문서로 학습된 분류 모델
S × V × M 곱셈 등급
Secrecy × Value × Management
영업비밀 3요건(비공지성·경제적 유용성·비밀관리성)을 각 0·1·2점으로 채점한 뒤 곱해서 등급을 정하는 방식. 8→TS, 4→S1, 1·2→S2, 0→S3. 한 요건이라도 0이면 곱이 0이라 공개(S3).
예: S2 × V2 × M2 = 8 → TS / S0(이미 공개) × … = 0 → S3
능동학습 폐곡선
Active Learning Closed Loop
사람이 고친 정정을 모아 모델을 다시 학습하고, 검증을 통과하면 프로세스 재기동 없이 즉시 교체(핫리로드)한 뒤, 운영 중 성능이 나빠지면 직전 버전으로 되돌리는(롤백) 닫힌 고리.
예: 정정 50건 누적 → 재학습 → 배포 게이트 통과 → 핫리로드
임베딩 / 벡터
Embedding / Vector
텍스트를 1024개의 숫자 배열로 변환한 것. "반도체 공정"과 "칩 제조 레시피"는 다른 단어지만 비슷한 숫자 배열을 가져서 검색이 됩니다.
예: "영업비밀" → [0.23, -0.87, 0.45, ...] 1024개 숫자
토큰
Token
AI 모델이 텍스트를 처리하는 최소 단위. 한국어는 보통 1~2글자가 1토큰. AI 모델마다 한 번에 처리할 수 있는 토큰 수 제한이 있습니다.
예: "반도체 공정" = 약 4~5토큰. 256토큰 = 약 512~1024글자
파인튜닝
Fine-tuning
이미 학습된 AI 모델에 우리 도메인 데이터로 추가 학습을 시키는 것. 범용 모델을 영업비밀 분류에 특화시키는 과정.
예: KF-DeBERTa (범용) + 약 2,591건 영업비밀 데이터(정제 학습셋) → 분류 특화 모델
사전학습
Pre-training
AI 모델이 처음 만들어질 때 대량의 텍스트로 언어의 기초를 배우는 단계. 우리가 직접 하지 않고 모델 제공사(카카오뱅크 등)가 미리 해둔 것을 받아서 씁니다.
예: KF-DeBERTa는 카카오뱅크가 금융 문서 수억 건으로 사전학습
RAG
Retrieval-Augmented Generation
관련 문서를 검색(Retrieval)해 근거 후보로 활용하는 방식. 본 시스템에서는 검수 보조용 검색 인덱스(청킹)로만 활용하며, 분류 등급 판정에는 사용하지 않습니다.
예: 질의 → 관련 규정 문서 상위 5개 검색(하이브리드)
F1 점수
F1 Score
분류 정확도를 0~1로 표현한 수치. 정밀도(맞다고 한 것 중 실제로 맞은 비율)와 재현율(실제 맞는 것 중 찾아낸 비율)의 조화 평균. F1_macro는 4등급 F1의 단순 평균.
예: F1=0.686 = 100건 중 약 69건을 올바르게 분류(서빙경로)
FNR (미탐율)
False Negative Rate
실제 TS/S1인 문서를 낮은 등급으로 잘못 분류하는 비율(미탐). 보안 시스템에서 가장 위험한 오류 유형. 방향성 FNR은 고등급→저등급 방향만 셈(과분류는 제외)하는 핵심 KPI. 현행 서빙경로 0.018·FNR_TS 0.000.
예: TS 문서를 S3로 분류 = FNR 발생 = 보안 사고
Confidence (신뢰도)
Confidence Score
logits→온도→softmax→청크집계→정규화로 만든 softmax 파생 점수(0~1)이며, 보정된 정답확률이 아닙니다. OOD에서 과신하고(골든500 ECE 0.18, 정답/오답 AUROC 0.58) 높은 confidence가 정확을 보장하지 않습니다. 그래서 자동확정은 confidence 단독이 아니라 합의 게이트로 판단합니다.
예: confidence=0.932은 softmax 파생 점수가 0.932라는 뜻이며 "정답일 확률 93.2%"가 아닙니다.
청킹
Chunking
긴 문서를 AI가 처리할 수 있는 작은 조각으로 나누는 작업. 조각들이 겹치는 부분(overlap)을 두어 문맥이 끊기지 않도록 합니다.
예: 10,000자 문서 → 1200자 청크 약 9개 (100자씩 겹침)
Hybrid 검색
Hybrid Search
키워드가 일치하는 문서를 찾는 어휘 방식(PG ts_rank) + 의미가 비슷한 문서를 찾는 Dense 방식(pgvector)을 RRF로 결합. 두 방식의 장점을 합쳐 검색 정확도를 높입니다.
예: "반도체 EUV" 검색 → 어휘(ts_rank)로 정확한 용어 + Dense로 유사 개념 모두 검색
BM25
Best Match 25
키워드가 문서에 얼마나 자주, 적절히 나타나는지 점수를 매기는 알고리즘. 구글 같은 검색 엔진이 수십 년간 사용해온 방식.
예: "M&A"라는 단어가 포함된 문서를 정확히 찾을 때 효과적
멀티테넌트
Multi-tenant
여러 회사가 한 서버를 공유하며 데이터가 격리되는 구조. 본 시스템은 미채택 — 고객사마다 독립 폐쇄망에 분리 배포하므로 한 서버가 여러 고객사를 담지 않습니다.
예: 본 시스템은 고객사마다 별도 배포 → 멀티테넌시 불요
API
Application Programming Interface
프로그램끼리 소통하는 규칙과 창구. 클라이언트 프로그램이 HTTP 요청을 보내면 시스템이 처리하고 결과를 반환하는 방식.
예: 문서 관리 시스템이 분류 API를 호출 → 등급 받아서 자동 저장
컨테이너 (Docker)
Container
각 서비스를 독립된 "상자" 안에서 실행하는 방식. 상자 안에 필요한 모든 프로그램이 들어있어 어느 컴퓨터에서도 동일하게 실행됩니다.
예: PostgreSQL, Redis, API 서버 각각 별도 컨테이너로 실행
LLM
Large Language Model
수천억 개의 파라미터로 이루어진 대형 AI 언어 모델. 문장을 이해하고 생성하는 능력이 탁월합니다. Claude, GPT-4, Qwen3 등이 여기 속합니다.
예: Claude Sonnet 4.6 · Qwen3-14B · GPT-4o
