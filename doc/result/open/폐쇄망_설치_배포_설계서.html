폐쇄망 설치·배포 설계서

KOIPA 영업비밀관리시스템(Lloydk AI 코어)을 인터넷이 차단된 운영망에 설치·기동하기 위한 설계서. 무엇을 깔고(인벤토리), 누가 준비하며(책임 경계), 어떤 순서로 설치·검증하는지를 한 곳에 규정한다.

책임 주체 범례

발주처/KL 운영 인프라(서버·OS·망·GPU 스택·매체반입) 사전 준비 · 로이드케이 AI 코어 스택 설치·기동·검증 · 확인필요 설계 미팅에서 확정할 항목

01개요 · 적용 범위

이 문서가 답하는 질문

"운영망(폐쇄망)에 설치해야 하는 오픈소스·서버·DB는 무엇이고, 그중 로이드케이가 설치·기동하는 범위는 어디까지인가"에 대한 단일 출처다. AI 코어는 단일 노드 docker compose 스택으로 패키징된 폐쇄망 배포 번들로 반입·설치된다.

항목값
대상 환경KOIPA AI 영업비밀관리시스템 운영망 (폐쇄망/에어갭 — 인터넷 차단, 매체 반입)
배포 단위폐쇄망 배포 번들 (docker 이미지 + python 의존성 + 모델 + DB 마이그레이션 + 구성)
추정 크기~23GB (매체 반입 1회)
아키텍처단일 노드 docker compose 스택 — API·Worker·Beat + PostgreSQL(pgvector)·MinIO·Redis·MLflow
망 등급폐쇄망 전제 · 확인필요 매체 반입 신청·승인 절차
전제

본 설계서는 설계·인벤토리·책임 경계 규정용이다. 실제 설치는 §11 선결 과제 확정 + 단계별 상세 절차서와 함께 수행한다 — 이 문서 단독으로 설치가 완결되지는 않는다.

인프라 컴포넌트 (오픈소스 · 서버 · DB)

모델·바이너리 사전 동봉 (중요)

폐쇄망에서는 런타임 다운로드가 불가하므로, 분류기 학습 가중치+보정값(temperature), 임베딩(KURE-v1/BGE-M3), 로컬 LLM(Qwen3-14B), OCR 바이너리를 모두 반입 매체에 사전 동봉해야 한다. 베이스 모델만 넣으면 미학습·무보정으로 동작하고, 임베딩 모델이 빠지면 검색이 동작하지 않는다.

03책임 경계 (R&R)

누가 무엇을 준비/설치하는가 — 핵심

운영 인프라(서버·OS·망·GPU 스택·매체반입)는 발주처/원청이 사전 제공하고, 그 위의 AI 코어 스택 설치·기동·검증은 로이드케이가 수행한다. 경계를 아래 표로 명문화해 설치 일정 지연을 방지한다.

구분책임항목

OSUbuntu 22.04 LTS

04사전 요건 (Prerequisites)

설치 전 점검

  • OS·런타임 — Ubuntu 22.04 LTS, Docker Engine + Compose v2 정상 동작.
  • GPU — nvidia-smi 인식 + --gpus all 동작 확인. 확인필요 Driver·CUDA·Container Toolkit 버전. 미충족 시 CPU 프로파일로 폴백(추론 성능 하락).
  • 디스크 — 번들 ~23GB + 이미지·모델·데이터 볼륨. Data SSD 여유 확인.
  • 포트 — 5432·9000·9001·6379·5000·8000 (+ mTLS 443) 내부 가용. 방화벽 규칙은 망 정책에 맞춰 신청.
  • 커널 파라미터 — 기본값으로 충분(별도 검색엔진 mmap·memlock 튜닝 불요 — pgvector 통합).
  • 로컬 LLM 서버 — onprem-local 프로파일은 vLLM/Ollama 서버 기동 + Qwen3-14B 적재가 선행되어야 한다(별도 프로세스).
  • OCR — 스캔 PDF 처리를 위해 Tesseract(한국어 데이터)·poppler 시스템 바이너리 설치(번들 동봉분 사용).
  • 시간·로캘 — NTP 동기, UTF-8 로캘(한국어 텍스트 처리).
05번들 구성 · 반입

번들 레이아웃

lloydk-airgap-bundle/
├── docker-images/     # docker load 대상 (api·worker·infra, ~23GB)
├── python-deps/       # 오프라인 wheel + 설치 목록
├── models/            # 학습 가중치 + 보정값 (동봉 필수)
├── infra-config/      # docker-compose.yml · .env.template (검색엔진 산출물 불요 — pgvector 통합)
├── db-migrations/     # 스키마 마이그레이션
├── install.sh · verify.sh · manifest.yaml · CHECKSUMS
└── docs/ · licenses/
매체 반입

매체로 ~23GB를 반입하고, 반입 직후 체크섬을 검증해 전송 무결성을 확인한다. 망 등급에 따라 보안 검토·반입 신청이 선행되어야 한다(확인필요).

06설치 절차

표준 순서

# 1) 무결성 검증
bash verify.sh

# 2) 이미지 적재 + 의존성·OCR 설치
bash install.sh            # docker load + wheel 설치 + OCR 바이너리(Tesseract/poppler)
#   torch는 GPU 환경에 맞춰 별도 설치 (또는 CPU)

# 3) 로컬 LLM 서버 기동 (onprem-local)
#   vLLM/Ollama 기동 → Qwen3-14B 적재 → endpoint 확인

# 4) 구성
cp infra-config/.env.template .env
vi .env   # 엔드포인트·시크릿·배포 프로파일·로컬 LLM endpoint

# 5) 인프라 기동 → DB 부트스트랩
docker compose up -d postgres minio redis mlflow
docker compose run --rm api alembic upgrade head   # 스키마 + 파티션 + 벡터(tb_rag_vectors) (컨테이너 내 실행)

# 6) 스토리지 초기화
#   MinIO 버킷: lloydk-docs / lloydk-models / mlflow
#   벡터검색: 별도 초기화 불요 (tb_rag_vectors는 alembic 마이그레이션이 생성)

# 7) 모델 배치 → 전체 기동
#   분류기 학습본·보정값·임베딩·LLM 모델 배치 후
docker compose up -d
# (옵션) docker compose --profile mtls up -d nginx-mtls
07부트스트랩 · 초기화 상세

DB · 스토리지 · 인덱스

  • 스키마 — 마이그레이션이 baseline + 후속 변경(핫패스 인덱스, 13개월 월 파티션 백필)을 멱등 적용.
  • 객체스토리지 버킷 — 원문·모델·아티팩트용 버킷 생성.
  • 벡터검색 초기화 — 별도 절차 불요. tb_rag_vectors(pgvector dense + bigram-tsvector ts_rank)는 alembic 마이그레이션이 생성, 색인은 적재 시 자동.
  • 모델 — 학습 가중치를 서빙 위치에 배치, 보정값(temperature) 동반(부재 시 무보정·과신 위험).
  • 파티션 — 주기작업(beat)이 매일 향후 월 파티션을 선생성.

09설치 검증

기동 후 점검

  • 헬스체크 — /api/v1/healthz/live(프로세스)·/ready(의존성 실측)·/deep(전체).
  • 컨테이너 — API·Worker·Beat·PostgreSQL(pgvector)·MinIO·Redis·MLflow 전부 기동. Worker는 전 큐 구독, Beat는 단일 인스턴스.
  • 스모크 분류 — 샘플 문서 업로드 → 분류 → 등급·신뢰도 반환 확인.
  • 검색 — pgvector 확장 설치 + tb_rag_vectors 적재 건수 확인, /ready 의존성 통과.
  • 관측성 — 모니터링 타깃 정상, KPI 대시보드·알람 로드.
10보안 · 라이선스

망분리 · 시크릿 · 컴플라이언스

  • 아웃바운드 0 — 폐쇄망 표준(onprem-local)은 외부 호출이 없어야 한다. 모델·LLM·임베딩 모두 로컬.
  • 시크릿 — 환경변수의 모든 비밀값은 템플릿 기본값을 운영용 강한 값으로 교체. 시크릿 관리(env/Vault 등) 추상화 지원.
  • mTLS — 옵션. 운영 인증서는 발주처/KL PKI 산출물로 교체.
  • 인증 — API Key 인증·RBAC. 고객사 간 격리는 폐쇄망 분리배포·KL 포털.
  • 라이선스 — MinIO(AGPL) 상용구매/교체, PDF 추출 라이브러리 BSD 전환 등 컴플라이언스 점검. 운영 전환 시 SBOM(CycloneDX) 첨부.
11현재 번들 상태 · 선결 과제

이 설계서만으로 설치가 완결되지 않는다

본 문서는 인벤토리·책임 경계·설치 순서를 규정하는 설계서이며, 실제 설치는 단계별 절차서(docs/INSTALL.md)와 함께 수행한다. 현 배포 번들은 RC1 스캐폴드이며, 아래는 솔직한 진척 현황이다(PM 조율용).
