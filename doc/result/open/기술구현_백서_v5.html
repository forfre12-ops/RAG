01 프로젝트 개요

KOIPA AI 영업비밀관리시스템에서 Lloydk가 담당하는 AI 코어의 목적·범위·타임라인.

1.1 시스템 목적

한국지식재산보호원(KOIPA) 영업비밀관리시스템은 기업 내부 문서를 4단계 보안등급으로 자동 분류하고, 등급에 따른 접근제어·워터마크·감사로그를 통합 관리하는 시스템이다. AI 분류 자동화 없이는 담당자가 문서 업로드 시 수동으로 등급을 지정해야 하는 운영 부담과 오분류 리스크가 상존한다.

1.3 개발 진행 단계

프로토타입(PoC)으로 핵심 기술의 타당성과 모델 선정을 먼저 검증하고, 그 결과를 바탕으로 발주처 실데이터를 적용한 본개발을 진행한다.

  • 1단계 · 완료
    설계·아키텍처 확정
    시스템 구조와 문서 분류 워크플로우 설계, 핵심 기술 스택(검색엔진·벡터DB) 결정.
  • 2단계 · 완료
    프로토타입(PoC) 구축
    AI 코어 6개 기능(전처리·라벨링·학습·추론·검색)의 동작 가능성을 프로토타입으로 구현·확인.
  • 3단계 · 완료
    모델 선정 검증
    분류 모델·합성 LLM·임베딩 모델을 후보 비교 실측으로 선정(§3·§7).
  • 4단계 · 완료
    폐쇄망 구동 검증
    온프렘 GPU 환경에서 업로드 → 분류 → 검수 전체 파이프라인 구동 확인.
  • 5단계 · 예정
    본개발 — 실데이터 학습·정밀화
    발주처 실데이터로 분류 모델을 학습·정밀화하고, 운영 환경에 통합한다(§11).
  • 6단계 · 예정
    실데이터 시범 운영 → 정식 오픈
    운영 환경에서 사람 확정 모드로 시범 운영하며 실제 정확도(미탐률)를 측정하고, 기준 충족 시 정식 오픈한다(§11.1).

2.3 신뢰성·보안 설계

대량 문서를 안정적으로 처리하고 영업비밀 데이터를 안전하게 다루기 위해 다음 4가지를 설계 원칙으로 둔다.

작업 유실 방지
업로드된 분류 작업은 비동기 큐로 처리하되, 제출과 기록을 원자적으로 묶어 유실을 막고 실패 작업은 재처리 경로로 보장한다.
변조 방지 감사로그
모든 처리 단계를 해시 체인으로 기록해 사후 변조를 탐지한다. 행위자·조직 정보는 위조 가능한 요청 값이 아니라 인증 정보에서 도출한다.
조직 간 접근 격리
인증 신원에 결속된 조직(tenant)으로 모든 조회·검색을 강제 스코프하고, 조직 미확정 시 빈 결과를 반환한다(fail-closed). ES 단일 클러스터의 교차조직 유출은 쿼리 단위 tenant 필터로 차단하며, 검수 화면의 RAG 유사사례 노출에는 열람권한(등급) 스코프를 함께 적용한다.
저신뢰 검수 라우팅
분류 신뢰도가 기준 미만이면 거부가 아니라 검수자 큐로 자동 배분해 사람이 확인하게 한다(미탐 위험 보호).

2.4 시스템 워크플로우

이 절은 운영 서버에서 상시 도는 흐름만을 기준으로 기술한다. 운영 중 자동으로 동작하는 것은 문서 분류 워크플로우(①–⑧) 하나뿐이다 — 문서가 업로드되면 파싱·마스킹을 거쳐 분류기(M5)가 등급 + confidence를 산출하고, 마지막 확정은 항상 사람이 한다. 학습 데이터 준비·초기 학습·색인은 운영 전 구축 단계에서 1회 수행하며(하단 구축 단계 표), 모델 재학습은 운영 중 자동으로 돌지 않는다 — 관리자 수동 절차로만 수행한다(하단 모델 갱신 절차 · §2.4.1). 모든 단계는 감사 체인(PG tb_audit_log)에 기록된다(§9).

ℹ
워크플로우 3대 원칙 (오해 방지)
① 분류기는 항상 판단한다. "판단 불가" 상태는 없으며, 항상 등급 + confidence를 산출한다. confidence가 낮다는 것은 "판단했으나 사람 검증이 필요"라는 플래그이지 "분류기가 못 했다"가 아니다.
② RAG는 불확실 시 켜지는 폴백이 아니라 추론 단계에서 분류와 병렬로 도는 참고 보강이다. 유사 기준문서 Top-K를 근거로 첨부할 뿐 등급 결정을 바꾸지 않으며, 검색이 실패해도 분류는 그대로 진행된다(graceful degradation).
③ "기준값 변경"은 임계값 자동조정이 아니라 모델 재학습(가중치)이다. confidence 임계값(기본 0.7)은 고정 설정이며, 재학습은 자동이 아닌 관리자 수동 절차다(하단 모델 갱신 절차).

운영 분류 워크플로우 — 단계별 상세 (①–⑧)

다이어그램의 각 박스 번호와 1:1 대응한다. 문서 1건 업로드 시 서버 내부에서 일어나는 일의 전부다.

분류기의 RAG "참고" 방식 — 근거 첨부, 등급 불개입

"분류기가 RAG를 참고한다"의 정확한 의미는 다음과 같다.

  • 언제: ⑥ 등급 추론과 병렬로 실행된다. 분류가 RAG 응답을 기다리지 않는다.
  • 어떻게: 문서에서 만든 쿼리를 확장한 뒤, ES에서 dense 벡터 + BM25(Nori) RRF 하이브리드로 사전 색인된 기준문서 중 유사 문서 Top-K를 검색한다.
  • 결과의 용도: 검색된 유사 기준문서는 분류 결과에 "판단 근거" 목록으로 첨부된다 — "이 문서는 이런 기존 기준문서들과 유사하다"를 사람(관리자·검수자)이 확정 판단 시 참고할 수 있게 하는 자료다. (검수 화면 안에서 유사 기존-라벨 사례를 직접 제시하는 보조 기능은 Phase 2 로드맵, §2.4.1.)
  • 하지 않는 것: RAG 결과는 등급 계산(softmax·집계·confidence)에 입력되지 않는다. 검색 결과가 무엇이든 등급은 변하지 않는다.
  • 실패 시: ES 검색이 실패하면 근거 없이 분류만 정상 진행한다(graceful degradation). RAG는 운영 분류의 가용성 의존점이 아니다.

등급 하향 방어 — 출처·콘텐츠 2-게이트와 미탐 판정 가드

미탐(비밀문서를 낮은 등급으로 떨어뜨리는 오류)은 이 시스템의 1순위 리스크다. 그래서 ⑥ 등급 산출에는 저신뢰 검수 라우팅(⑦)과 별개로, 판정 시점에 작동하는 비대칭 방어 3겹을 둔다.

방어동작방향
① 최고-위험 청크 우선 집계고등급(TS·S1)은 청크 평균이 아니라 가장 강한 청크(max-pooling)로 잡는다. 50쪽 중 한 단락의 비밀 신호가 보일러플레이트 평균에 희석되어 묻히지 않는다. S2·S3는 표준(길이가중) 집계 — S2→S3 희석은 고등급 미탐보다 저위험이고 S2까지 max하면 과분류가 늘어, 적용 범위는 설정값으로 조정한다.상향 (미탐↓)
② 콘텐츠 미탐 가드키워드·기준 룰이 고등급 신호를 강하게 잡으면 모델 confidence와 무관하게 등급을 끌어올린다. "자신만만하게 틀린" 하향 오분류를 신뢰도 게이트와 별개로 차단. 임계는 등급별로 둔다.상향 (미탐↓)
③ 출처 게이트 (비공지성)이미 공개된 출처(판례·공시·보도자료·공개특허 등)는 내용과 무관하게 상한을 S3로 cap한다 — 부정경쟁방지법 §2.2 비공지성 미충족 시 영업비밀 불성립. 단, 신뢰된(시스템이 적재한) 프로비넌스에만 발동하고 출처가 모호하면 cap하지 않는다(내부로 fail-safe). 비공개(내부) 문서에는 적용되지 않아 미탐 트레이드오프가 없다.하향 (과분류↓)
⚠
설계 핵심 — confidence 게이트만으로는 미탐을 못 막는다. 0.7 신뢰도 게이트는 저신뢰 오류만 검수로 보낸다. 학습에 없던 새 문체(OOD)에서 모델이 높은 confidence로 하향 오분류하면 게이트를 그대로 통과하므로, 위 ①·②의 판정 시점 상향 가드로 별도 차단한다. 이 가드의 실제 미탐 차단율은 합성 데이터로는 측정할 수 없으며 본개발 실데이터로 확정한다(§10·§11). ③ 출처 게이트는 ingest가 문서 출처(provenance)를 정확히 태깅할 때 작동하므로, 출처 메타데이터 적재·전달을 본개발에서 배선한다(§11.2). ②·③ 충돌 규칙: 출처 게이트(③, 하향)가 강한 상향 신호(①·②)를 덮을 때는 자동 확정하지 않고 검수자에게 보낸다(needs_review) — 진짜 공개문서는 사람이 즉시 확인하고, 내부 비밀문서가 '공개'로 오태깅된 경우(silent miss)는 여기서 걸러진다. 즉 출처 cap은 콘텐츠 상향 가드를 무인으로 덮지 않는다.

  • 비동기 작업 실패: DLQ(Dead Letter Queue) 스트림에 적재 후 재처리 경로를 보장한다. Outbox 원자 발행으로 제출 단계 유실도 차단(§2.3).
  • 교차 테넌트 접근: 인증 신원 결속 + tenant 스코프 조회 3겹으로 403 차단(IDOR/BOLA, §2.3).
  • 모델 드리프트: 분류 결과 분포를 주기적으로 학습 시점과 비교해 모델 성능 변화를 감지하고 경보한다(§9.3).
  • FNR 회귀 방지: 갱신 모델은 평가 게이트 + 사람 사인오프 없이는 배포되지 않는다(§2.4.1).

구축 단계 워크플로우 — 운영 전 1회 (학습 데이터 준비 · 초기 학습 · 색인)

아래는 운영이 아닌 구축(납품 준비) 단계의 절차다. 운영 전환 후에는 상시 동작하지 않으며, 운영 중 기준문서를 추가 색인할 때만 B5를 부분 실행한다.

ℹ
용어 명확화 — "자동 라벨링(M3)"은 운영 분류기가 아니다. M3는 학습 데이터를 만들 때 라벨 "후보"를 달아주는 준비 도구다(키워드 룰 엔진 1차 → 확신 미달 시 LLM 폴백 2차). 후보는 반드시 사람(관리자) 검수를 거쳐 학습셋에 편입되며(FUN-003), 운영 중 실문서의 등급을 결정하는 주체는 M5 분류기 + 사람 확정(①–⑧)뿐이다.
단계주체동작
B1

B2

B3

B4

모델 갱신 절차 — 관리자 검토·승인 기반 (자동 활성 기본 OFF)

⚠
데이터 자동 학습은 신중히 검토 후 진행한다. 운영 중 쌓인 검수 결과로 모델을 다시 학습시키는 "능동학습"은, 데이터 분포가 변하면 정확성을 일정하게 보장하기 어렵고 잘못된 자동 반영이 미탐(비밀문서 누락) 위험으로 이어질 수 있다. 따라서 본 사업에서는 수집·재학습·배포·롤백 폐곡선을 모두 갖추되 자동 활성·자동 롤백은 기본 OFF로 두고(§2.4.1), 모델 교체는 관리자가 평가 결과를 신중히 검토·승인한 경우에만 단계적으로 진행한다.

운영 중 상시 자동은 G1(검수 결과 수집)이며, 누적 임계 도달 시 스케줄러(Celery beat, 30분 주기)가 G2(재학습)·G3(평가 게이트)까지 자동 수행해 새 "후보 모델"을 만들 수 있다. 다만 G4(운영 교체·활성)는 retrain_auto_activate 기본 OFF로 차단되어 관리자 사인오프가 있어야만 일어난다 — 즉 무인(無人) 자동 '배포'는 없다(후보 생성·채점은 자동이어도 운영 반영은 사람 승인). 이 절차가 진행 중이거나 수행되지 않아도 운영 분류(①–⑧)는 기존 모델로 정상 동작한다.

단계자동/수동동작
G1
수집		자동 (상시)검수자가 ⑦b에서 수정한 라벨이 tb_corrections 테이블에 쌓인다. 이 수집은 상시 자동이다.
G2
재학습 실행		스케줄러 자동 / 또는 수동tb_corrections 누적이 임계(권장 기본 50, 보안 미탐 누적 ≥10 시 긴급) 도달 시 스케줄러(또는 관리자)가 트리거하여 새 모델 "후보"를 배치 학습한다(M4). 학습 중에도 기존 운영 모델은 그대로 서비스한다.
G3
검증 (평가 게이트)		수동 트리거 · 자동 채점새 후보를 평가셋으로 채점한다 — F1 · FNR(비밀문서 미탐률, TS·S1 핵심) · 적대 케이스. 하나라도 기준 미달이면 후보를 폐기한다(M6). 결과는 MLflow에 지표·혼동행렬로 남는다.
G4
승인 · 교체		수동관리자가 G3 결과를 확인하고 사인오프한 경우에만 운영 모델을 교체한다(MLflow/MinIO 이력). 자동 활성 스위치(retrain_auto_activate)는 기본 비활성(OFF)이라, 끄여 있는 한 무인 자동 배포는 일어나지 않는다(§2.4.1 폐곡선). 교체는 핫리로드(/admin/model/reload)로 프로세스 재기동 없이 반영된다.

※ 이 절차는 선택적 유지보수다 — 수행하지 않아도 운영 분류(①–⑧)는 정상 동작하며, 수행 여부·주기는 발주처 운영 정책에 따른다. FUN-024의 "능동학습 체계"는 수집(G1)~평가 게이트(G3) 파이프라인 구축으로 충족한다(§2.4.1).

재학습은 어떻게 / 평가 게이트는 무엇을 보나

위 절차의 "재학습(G2)"과 "평가 게이트(G3)"가 구체적으로 무엇인지 정리하면 다음과 같다.

재학습 — 무엇을, 어떤 모델로
운영 분류기와 동일한 모델(KF-DeBERTa)을, [기존 학습 데이터 + 검수자가 실제로 고친 라벨]로 다시 미세조정(fine-tune)해 새 "후보 모델"을 만든다. 새로운 종류의 모델로 갈아끼우는 것이 아니라 같은 분류기를 더 좋은 데이터로 다시 가르치는 것이다. 학습 시 비밀문서 누락(미탐)에 더 큰 페널티를 주어, 비밀을 공개로 떨어뜨리지 않는 방향으로 학습한다. 학습 중에도 기존 운영 모델은 그대로 서비스한다.
평가 게이트 — 무엇을 보나
학습에 쓰지 않은 고정 평가셋 + 함정(적대) 문서 묶음으로 후보를 채점한다. ① 전체 정확도(F1) ② 미탐률(FNR) ≤ 기준 ③ 기존 모델 대비 어느 지표도 나빠지지 않을 것(회귀 금지) ④ 함정 케이스 통과 — 이 중 하나라도 미달이면 후보를 폐기하고 기존 모델을 유지한다. 통과하더라도 관리자가 지표·혼동행렬을 확인하고 사인오프해야 교체된다.
ℹ
핵심: 평가 게이트는 "새 모델이 비밀 누락(미탐)을 늘리지 않는다"를 보증하는 안전장치다. 교체 후 실운영에서 미탐률이 악화되면 즉시 이전 모델로 롤백한다(§9.4 장애 대응).

2.4.1 능동학습(Active Learning) 운영 정책 — 사람-승인형

오분류를 사람이 수정하면 모델이 개선되는 능동학습 체계(FUN-024)는 구축하되, 운영은 자동 재학습이 아니라 사람이 검토·승인하는 3층 구조로 한다. 데이터 분포가 바뀌면 정확성을 일정하게 보장하기 어렵고, 잘못된 자동 반영이 비밀문서 미탐으로 이어질 수 있기 때문이다. 따라서 자동 학습은 신중히 검토 후 단계적으로 진행한다.

2.4.1 등급체계·룰셋 변경 거버넌스 — 모델과 동급의 안전 규율

콘텐츠 미탐 가드(②, §2 '등급 하향 방어')가 도입되면서 키워드·기준 룰셋(등급체계)이 "학습데이터 라벨 후보 보조"를 넘어 운영 추론의 등급 결정 입력으로 격상됐다. 모델은 G1~G4 게이트로 엄격히 변경관리되는데, 관리자가 코드 없이 수정하는 룰셋이 같은 규율을 받지 못하면 — 잘못된 키워드 수정 한 번이 ②의 미탐 가드를 조용히 약화시킬 수 있다.

⚠
그래서 룰셋·등급체계 변경도 모델과 같은 안전 규율을 받는다: ① 변경은 버전·감사 기록(누가·언제·무엇을 — API 감사 미들웨어로 기록), ② 이전 버전으로 롤백 가능, ③ 변경 시 평가셋을 재채점해 FNR(특히 TS·S1) 회귀가 없음을 확인한 뒤에만 활성화. 모델과 룰셋이 등급 결정에 같은 비중으로 개입하는 만큼 같은 통제를 받는다(본개발 §11.2).

M4학습
FUN-004

분류 모델 학습

KF-DeBERTa 학습 · 실험 추적 · 모델 버전 관리

선정한 분류 모델(KF-DeBERTa)을 4등급 분류기로 학습한다. 학습 데이터는 등급별 층화 70/15/15로 학습/검증/평가셋에 자동 분리하며, 같은 내용이 학습·평가에 동시 포함되는 누수를 차단(정규화 텍스트 dedup)해 평가셋이 모델이 한 번도 보지 않은 데이터가 되도록 보장한다. 평가셋 기준으로 정확도·정밀도·재현율·F1 리포트를 산출하고, 본 사업 핵심 KPI인 미탐율(FNR — 고등급을 낮은 등급으로 흘린 비율)을 등급별로 분리 보고한다.

모델 선정은 단순 정확도가 아니라 미탐 최소화를 기준으로 한다. 고등급(TS·S1) 표본에 비대칭 손실 가중을 주고, '전부 고등급 찍기' 식 게이밍을 막는 합성 지표(미탐율 + 과분류율 + 단일클래스 패널티)로 best 모델을 선택한다. 평가는 신뢰수준을 구분한 다층 체계(합성 일관성 → LLM pseudo-gold → 디오염 홀드아웃 → 발주처 사람 라벨)로 운영하며, 보고 수치는 학습 누수가 없는 디오염 홀드아웃·운영 파이프라인 기준을 사용한다. 학습 과정·결과는 실험 추적 도구(MLflow)로 기록하고, 모델은 버전 단위로 저장·배포한다(온프렘 GPU). RAG 인덱싱은 선택 옵션이다.

데이터 단계 구분 — 위 학습/검증/평가셋은 모델을 만드는 개발·검증 단계에서만 쓰는 라벨링된 데이터다. 실운영 단계에서는 이 셋을 쓰지 않는다. 운영 시에는 그날그날 새로 들어온 실문서를 학습된 모델이 분류하고, 검수자가 교정(correction)한 값을 정답 삼아 정확도·미탐율을 실데이터 기준으로 재측정한다. (요약: 학습셋 = 시험 준비용 / 실운영 = 실제 업무 — 둘은 별개 데이터다.)

※ 현재 디오염 홀드아웃·운영 파이프라인 기준 미탐율 2.8%(TS 전건 검출)로 보안 축은 통과하며, 최종 납품 게이트는 발주처 실문서 기반 사람 검수 라벨(human_review) 입수 후 확정된다.

5.2 합성 학습 데이터 생성

실제 비밀문서는 외부 반출이 어려우므로, 선정한 LLM(Qwen3)으로 보안등급 정의에 맞춘 학습용 문서를 등급별로 균형 있게 생성한다. 짧은 문서부터 장문까지 길이를 다양화해 표현이 단조로워지지 않도록 한다. 생성된 데이터는 학습 데이터로 사용하기 전 검수를 거친다.

5.3 독립 평가 데이터 구성

8.2 멀티 고객 납품

본 제품은 이 고객사에 우선 납품하되, 다른 기업에도 납품 가능하도록 설계한다. 고객사별 차이는 코드 수정 없이 설정·데이터로만 흡수한다.

공통 분류기 + 고객사별 설정

모델은 버전 단위 아티팩트로 배포·갱신해 고객사 간 일관된 릴리즈를 보장한다.

8.3 폐쇄망 오프라인 설치

외부 인터넷 연결 없이 설치·운영할 수 있도록, 필요한 모델·구성요소를 하나의 오프라인 설치 번들로 묶어 제공한다(무결성 검증 포함). 예상 용량은 약 25~30GB다.

성능 검증·본개발 환경은 NVIDIA A100 80GB × 2 · 32코어+ · 메모리 192GB · Ubuntu 22.04 LTS로 확정했다. LLM 합성·임베딩·분류 추론·온프렘 GPU 학습을 모두 이 단일 노드에서 수행한다.

8.4 서버 간 보안 통신

KL 웹 시스템과 Lloydk AI 서버 간 통신은 상호 인증(mTLS)으로 보호하며, 내부 인증서로 발급·갱신한다.

8.5 배포 절차

배포는 컨테이너 구동 → 데이터베이스 초기화 → 모델 적재 → 서비스 기동 순으로 자동화되어 있으며, 정해진 절차대로 온프렘 환경에 설치한다.

9.3 모델 드리프트 감지 제안가치 · 요건 외

운영 중 입력 문서의 임베딩 분포를 학습 시점 분포와 주기적으로 비교(KL divergence)해, 학습에 없던 새 문체·도메인이 유입되는 입력 드리프트를 감지한다. 여기에 분류 신뢰도(confidence) 분포와 검수자 정정율(correction rate)을 함께 추적한다 — 출력 등급 분포만 보면 "자신만만하게 틀린" 하향 오분류가 정상 분포에 묻혀 보이지 않으므로, 신뢰도 캘리브레이션 모니터링으로 이 사각을 메운다. 기준을 벗어나면 경보 → 점검 → 롤백으로 연결한다. 감지 주기는 시범운영 저볼륨에서 표본이 부족하면 노이즈가 크므로, 최소 표본 수를 채울 때만 판정하도록 윈도우를 적응 조정한다. ※ 임베딩 분포 드리프트 감지는 제안요청서 명시 요건은 아니며, 운영 안전을 위해 로이드케이가 추가 제공하는 보강(제안가치)이다.

ℹ
고도화 옵션 (선택). 드리프트 원인 분석·모델 건전성 진단·전용 모니터링 대시보드 등 정밀 드리프트 분석이 필요한 경우, 본 사업의 기본 감지와는 별도로 전문 모니터링 솔루션과 연계해 확장할 수 있다. 운영 안전에 필요한 감지는 기본 제공되므로, 정밀 분석은 운영 정책에 따라 추후 선택적으로 도입하면 된다.

10 프로토타입 한계·본개발 정밀화

프로토타입 수치를 읽을 때의 전제와, 본개발에서 정밀화할 항목.

프로토타입 단계의 전제

① 합성·공개 데이터 기반

프로토타입의 학습·검증은 합성 데이터와 공개 문서를 기반으로 했다. 실제 업무 문서(특히 비밀 등급)는 외부 반출이 어렵기 때문이며, 따라서 현재 수치는 타당성 확인과 모델 선정을 위한 것이다. 실제 운영 정확도는 발주처 실데이터로 학습하는 본개발 단계에서 확정된다.

② 새로운 문체에 대한 일반화

학습에 포함되지 않은 새로운 문체의 문서에서는 일부 등급이 실제보다 낮게 분류되는 경향이 관찰되었다. 비밀문서 누락(미탐)을 최우선 관리 지표로 두고, 실데이터 보강 + 저신뢰 검수 라우팅으로 보완하는 것이 본개발의 핵심 과제다.

③ 검색 정확도와 데이터 다양성

프로토타입의 검색 정확도가 목표(Recall@5 0.80)에 미달한 것은 합성 데이터 본문이 비슷한 표현을 반복하는 한계 때문으로, 검색 알고리즘이 아니라 데이터 다양성의 문제다. 실제 문서 본문의 다양성이 확보되면 향상된다.

④ 신뢰도 캘리브레이션 (서빙 반영됨 · 실데이터 재보정 예정)

분류기 softmax 점수는 학습에 없던 새 문체(OOD)에서 과신(overconfident)하는 경향이 있어, 0.7 신뢰도 게이트가 보정되지 않은 값 위에 설 수 있다. 이를 위해 temperature scaling 보정을 서빙 경로에 반영했다 — temperature.json을 자동 로드해(T>1이면 과신 완화) 서빙 softmax에 적용한다(로직감사 A1 완료). 다만 보정 계수는 합성·공개 데이터로 산출한 값이므로, 본개발에서 실데이터로 재보정하고 캘리브레이션 모니터링(ECE)에 연결한다(§9.3).

⑤ 미탐 판정 가드의 효과는 실데이터로만 확정된다

§2의 판정 시점 상향 가드(최고-위험 청크 집계·콘텐츠 가드)는 설계상 미탐을 줄이는 방향이지만, 그 실제 차단율은 룰·모델의 재현율에 달려 있어 합성·공개 데이터로는 측정할 수 없다. 진짜 비밀문서 표본이 쌓이는 시범 운영에서만 등급별 미탐률로 확정된다.

⑥ 출처 게이트의 프로비넌스 의존 (양방향 리스크)

③ 출처 게이트(비공지성)는 ingest가 문서 출처(공개 판례·공시 등)를 정확히 태깅할 때만 작동한다. 출처 메타가 비면 게이트가 발동하지 않아 과분류 방어가 약해진다. 반대로 내부 비밀문서가 '공개'로 잘못 태깅되면 S3로 cap되어 미탐(silent miss)이 될 수 있다 — 하향 경로는 곧 미탐 벡터이기 때문이다. 그래서 게이트는 신뢰된 프로비넌스에만 발동하고, 강한 상향 신호와 충돌하면 자동 확정 대신 검수로 라우팅한다(§2 '등급 하향 방어'). 출처 적재·전달·신뢰 게이팅을 본개발에서 배선한다(§11.2).

⑦ 확정 라벨의 신선도(staleness)

사람이 확정한 라벨이 있으면 재분류를 생략하고 즉시 사용한다(검수 효율). 동일성 판정은 문서 식별자(doc_id) 기준인데, ingest가 내용 변경분을 새 식별자(내용 해시)로 적재하므로 내용이 바뀐 재업로드는 옛 라벨이 붙지 않는다. 다만 식별자를 유지한 채 내용을 교체하는 경로가 생기면 옛 라벨이 고착될 수 있어, 라벨 시점 내용 해시를 함께 저장해 불일치 시 재분류하도록 본개발에서 가드한다(§11.2).

⑧ 위협 모델 경계 — 분류·검수 보조이지 DLP가 아니다

본 시스템의 미탐 방어는 키워드·모델 신호 + 사람 최종확정에 기반한다. 따라서 정직하게 업로드된 문서의 등급 분류·검수 보조를 목적으로 하며, 트리거 표현을 의도적으로 지운 내부자의 적대적 회피나 고의 유출 방지(DLP)는 보장 범위 밖이다. 회피·유출 대응은 KL의 접근제어·워터마크·반출승인·화면보안과 감사체인(SHA-256)·사람 최종확정이 백스톱이며, 본 AI 코어는 그 위에서 동작한다(발주처의 DLP급 보증 오해와 수행사 책임 범위를 함께 정리).

✓
프로토타입 단계에서 시스템 구조·워크플로우 설계, 핵심 모델 선정, 전체 흐름(E2E) 동작을 확정했다. 본개발에서는 발주처 실데이터를 적용해 분류 모델을 학습·정밀화하고, 운영 환경에 통합·안정화한다.

11.1 단계별 본개발 · 오픈 — 실데이터 시범 운영

합성·공개 데이터로 만든 초기 모델은 시동용이다. 실제 정확도(특히 비밀문서 미탐률)는 합성 데이터로 보장할 수 없으므로, 운영 환경에 올린 뒤 실데이터로 검증·정밀화한 다음 정식 오픈한다.

ℹ
오픈 시점은 "기간"이 아니라 "기준"으로 판단한다. 시범 운영 기간(약 1개월 이상)은 기본값이며, 정식 오픈은 실데이터 충분량 확보 + 미탐률 임계 충족을 만족할 때 한다. 비밀등급(특히 TS·S1) 문서가 충분히 쌓이지 않으면 기간을 연장한다.
  1. ① 초기 학습(시동) — 합성·공개 데이터로 부트스트랩 모델을 만든다.
  2. ② 실데이터 시범 운영(약 1개월+) — 운영 환경에 올리되 AI는 등급을 "제안"만 하고 사람이 전수 확정하는 모드로 운영한다(워크플로우 ⑧). 오분류가 접근제어로 새지 않으므로 안전하게 실데이터로 측정할 수 있다. 이 기간에 실문서·실라벨을 쌓고 실제 미탐률·정확도를 측정한다.
  3. ③ 실데이터 재학습·정밀화 — 쌓인 실데이터로 모델을 재학습하고 평가 게이트로 검증한다(재학습·게이트 방식은 §2.4).
  4. ④ 정식 오픈 — 등급별 미탐률 기준 충족 시 자동 분류의 신뢰 범위를 점진적으로 넓히되, 고등급(TS·S1)은 사람 전수 확정을 유지한다. 신뢰 범위 확대는 등급별로 차등 적용하며, 사람 최종 확정 원칙과 판정 시점 미탐 가드(§2)는 그대로 둔다.
