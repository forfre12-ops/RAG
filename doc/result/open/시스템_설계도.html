02

배포 구조 — 지재원(학습) / 고객사(추론)

지재원은 골든셋·학습을 담당하고, 학습된 모델을 오프라인 골든 번들로 고객사에 배포. 고객사는 추론만 수행한다. 운영 환류 방식은 미확정 결정(무반출·온사이트·반출 3안 — 확인안 §6)이며 기본 권고=무반출: 교정·원문은 망 내 잔류(반출 금지), 망 밖으로는 집계 진단지표(오분류율·혼동행렬, 문서식별 불가)만 환류.

분류 등급은 모델이 산출(검색은 근거·답변 보조) → 검색 품질이 등급 정확도를 좌우하지 않으므로 정합성·운영 단순성을 우선해도 안전.
분류 모델 KF-DeBERTa 한국어 특화 분류기. 정확도 65–78% · 고등급 미탐 14–21%(룰 대비 미탐 반감). 미보정 과신 방지용 온도 보정(temperature scaling) 적용(학습 후 사후 캘리브레이션) — 보정계수는 골든셋 반입 후 확정.
LLM
Qwen3-14B		 Qwen3 vs Gemma 실측 비교로 선정(품질·라이선스·폐쇄망 적합). 지재원=합성 학습데이터·골든 자동라벨 / 고객사=RAG /answer 답변합성·선택적 2차판정. 분류 등급결정 핫패스는 LLM-free(분류기+룰+RAG검색+메타, 333ms CPU). 2차판정 게이트는 기본 OFF이며, 켜도 등급을 바꾸지 않고 상향 시 검수로만 라우팅.
말뭉치: 학습·평가 4,554건 · 골든셋 1,000건 이상 목표(현재 후보 500건, TS·S1·S2·S3 균형)
왜 pgvector인가 — Elasticsearch 대비 (실측 기반)

ES는 검색은 강하나 별도 시스템이라 이중쓰기·동기화가 필요하다. 분류는 모델이 하므로(검색=보조) 정합성·운영을 우선한다.

검색 차이로 우려됐던 한국어 lexical은 실 PG 풀스택으로 측정(2026-06-24: PG ts_rank-bigram 87% ≈ nori 89%, 하이브리드 85% > dense 76%)했고 dense 벡터검색은 동일하다(쿼리가 합성·LLM 생성이라 실 운영쿼리 모니터는 본개발). 그러나 분류 정확도는 동일 비교조건에서 분류기 59–77% vs 검색기반 kNN 38–49%(헤드라인 65–78%는 배포 실측 기준) — 분류는 검색이 아니라 모델이 한다. 따라서 검색엔진은 정합성·운영(pgvector)을 택해도 등급 정확도에 영향이 없다. (수치 전부 실측 · 본 코퍼스 기준, pgvector 한국어 lexical 실 PG 측정 2026-06-24 — ts_rank-bigram 87%≈nori, 하이브리드 85%>dense 76%)

운영 라이프사이클 — 골든셋 → 학습 → 배포 (폐곡선)

데이터(골든셋) → 모델(학습) → 배포 → 운영의 사이클. 지재원이 A·B(골든셋·학습)를, 고객사가 C(배포·운영)를 맡는다. 운영 환류는 미확정 결정(무반출·온사이트·반출 3안 — 확인안 §6): 기본(무반출)에선 집계 진단지표만 지재원으로 가고(문서·교정은 망 내 잔류), 재학습은 지재원이 자기 골든셋으로 실데이터 1차학습 후 드리프트/이벤트 단발로 수행한다.
