3. 우선 협의 요청 사항

아래 넷은 협의로 정해야 하는 사항입니다. 구현이 아니라 규약·범위에 관한 것입니다.
#사안내용
1결과 수신 항목 제안서의 콜백은 label(등급) 중심입니다. 등급만 전달되면 검수 대상을 고를 수 없어 미탐 최소화 설계가 작동하지 않습니다. confidence·status·warnings 세 가지를 함께 받으실 것을 요청드립니다 (회신서 §5 · API 회신 §3)
2요청 절차 2단계 문서 등록 후 분류를 요청하는 구조입니다. 이력·검수 연계를 위해 등록 절차를 포함하는 방안을 권고드립니다 (API 회신 §2)
3스캔 문서 취급 글자가 이미지로만 있는 문서는 OCR 이 필요한데 납품 번들에 OCR 이 없습니다 (요건 외). 스캔본은 느린 것이 아니라 처리되지 않습니다. 회원사 문서에 포함될 예정이면 요건 확정을 요청드립니다 (회신서 §4)
4검수 화면을 어디에 두는가 ICD 합의 안건 K7 — 검수·등급확정 화면을 ⓐ 독립 콘솔로 둘지 ⓑ 포털에 통합할지(API 제공)가 협의 항목으로 남아 있습니다. 현재 콘솔로 검수가 가능하며, 배치가 확정되면 그에 맞추어 API 로 제공합니다. 접수 초안의 콜백 항목 구성은 화면을 포털이 담당하는 쪽에 가깝습니다. 범위를 가르는 사항이라 확정 회신을 요청드립니다 (ICD §06 K7)
