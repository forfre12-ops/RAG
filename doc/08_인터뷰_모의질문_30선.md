## 카테고리 1: AI 분류 모델 (FUN-004·005) — 10문

**Q1. 분류 모델로 KF-DeBERTa를 선택한 이유는?**  
금융·법률 문서로 사전학습된 한국어 특화 모델로, 영업비밀 문서(경영·기술)와 도메인이 가장 근접합니다. 동일 조건에서 KoELECTRA 대비 F1 +3~5%p 높았으며 MIT 라이선스로 라이선스 리스크가 없습니다. 경량 환경을 위해 KoELECTRA도 선택 옵션으로 유지합니다.

**Q2. 특급기밀 문서를 2급 대외비로 잘못 분류하는 미탐(FNR)을 어떻게 최소화하나요?**  
세 가지 방어선을 적용합니다. ① 학습 시 특급→하위 오분류에 비대칭 손실 가중치(cross-entropy class_weight) 부여, ② 신뢰도 임계값을 0.30~0.50으로 낮춰 불확실 케이스를 관리자 확인 큐로 전송, ③ 능동학습 루프로 FNR 높은 샘플을 우선 재라벨링합니다. 합성 5k 학습 기준 FNR 0% 달성했으며, 실문서 기반 재측정 후 최종 확인 예정입니다.

**Q3. 4등급(특급/1급/2급/3급) 분류 정확도 수치는?**  
합성 5,000건 + Qwen3 라벨 학습 기준: F1-macro 1.0, FNR 0%. 실측 합격선은 F1 ≥ 0.75, FNR ≤ 5%입니다. 발주처 실문서 제공 시 동일 파이프라인으로 재측정하며, 실 데이터 분포에 따라 수치가 달라질 수 있습니다.

**Q4. 학습 데이터가 부족할 때 어떻게 대응하나요?**  
세 가지 경로를 준비했습니다. ① LLM 기반 합성 문서(FUN-003): Qwen3-14B 또는 Claude로 등급별 5,000건 생성 → 라벨 일치도 100% 확인 완료. ② 공개 코퍼스(AI Hub 법률·경영 문서) + 도메인 키워드 시드 313개 적용. ③ 능동학습(FUN-024): 신뢰도 낮은 실문서 우선 라벨링 요청. 최소 500건 실문서로도 파인튜닝 가능합니다.

**Q5. 문서 길이가 매우 긴 경우(수십 페이지) 어떻게 처리하나요?**  
청크 분할(기본 512 토큰, 오버랩 64) 후 각 청크를 독립 분류하고, 소프트맥스 확률의 가중 평균으로 문서 전체 등급을 집계합니다. KoBigBird(4096 토큰)로 롱컨텍스트 단일 추론도 선택 가능하나, 청크 전략이 성능·속도 균형에서 우수함을 Phase 2에서 확인했습니다.

**Q6. 모델 버전 관리와 롤백은 어떻게 하나요?**  
MLflow로 모델 레지스트리를 운영합니다. 각 학습 결과는 run_id + 타임스탬프로 버전화되고, Elasticsearch alias 스왑으로 무중단 교체합니다. 이전 버전으로의 롤백은 alias를 이전 인덱스로 되돌리는 것으로 1분 이내 완료됩니다. Runbook §4에 절차가 문서화되어 있습니다.

**Q7. 모델 성능 저하(드리프트)를 어떻게 감지하나요?**  
Celery beat로 15분마다 실시간 추론 결과와 학습 시 centroid 간 코사인 거리를 계산합니다. 임계값(0.15) 초과 시 Prometheus alert → Runbook §8 PSH 대응 절차가 자동으로 트리거됩니다. Grafana 대시보드에서 5가지 KPI 시계열을 실시간 확인할 수 있습니다.

**Q8. 추론 응답 시간은 얼마나 걸리나요?**  
RAG OFF 기준 380ms (p95), RAG ON 기준 9.2s (p95) — Phase 4 E2E 실측 기준. 합격선(RAG OFF ≤ 10s, RAG ON ≤ 30s) 대비 각각 26배, 3.3배 여유입니다. BERT 추론이 전체 시간의 99%를 차지하며, GPU 사용 시 1.18s로 단축됩니다.

**Q9. GPU가 없는 환경에서도 동작하나요?**  
네. `DEPLOY_PROFILE=lite-noapi` 설정 시 CPU 전용으로 동작합니다. KF-DeBERTa CPU 추론은 약 8~12초이며, 규칙 기반 폴백(keywords 313개)으로 GPU 없이도 서비스 가능합니다. GPU가 있으면 RTX 3090 기준 1~2초, RTX 5070 Ti 기준 1.18초입니다.

**Q10. 분류 근거(Evidence)를 사용자에게 어떻게 제공하나요?**  
세 가지 코표(citation)를 제공합니다. ① 실측 근거: 모델이 높게 활성화한 토큰 span 하이라이트(attention 기반). ② 명세 근거: RAG로 검색된 가이드 문서 인용 구절(citations ≥ 3건). ③ 참고 근거: 학습 시드 키워드 매칭. `/explain` API와 데모 콘솔에서 확인 가능합니다.

## 카테고리 2: RAG 및 검색 (FUN-004) — 6문

**Q11. RAG를 왜 사용하나요? BERT 분류만으로는 부족한가요?**  
BERT는 학습 데이터에 없는 새로운 유형의 비밀 문서나 업종별 특수 용어에 취약합니다. RAG는 ① 등급분류 가이드 최신 버전을 실시간 참조해 오분류를 줄이고, ② 답변에 법적 근거 인용을 첨부해 감사 대응을 강화합니다. 분류 정확도 +5~8%p, FNR -2%p 개선을 목표로 합니다.

**Q12. 검색 정확도(Recall@5)는 얼마나 되나요?**  
합성 코퍼스 기준 BGE-M3 dense 0.70, KURE-v1 0.67입니다. 합격선 0.80은 실 가이드 문서(발주처 제공 예정) 기반에서 달성 가능하며, ES BM25 하이브리드 + RRF 조합으로 추가 향상을 계획합니다. 합성 문서 boilerplate 한계로 현재 천장은 0.70입니다.

**Q13. 검색 엔진으로 Elasticsearch를 선택한 이유는?**  
dense 벡터 검색(int8_hnsw)과 BM25 키워드 검색을 단일 클러스터에서 RRF로 결합할 수 있습니다. Nori 형태소 분석기로 한국어 처리에 최적화되어 있으며, 사용자 사전 1,002개 항목을 등록했습니다. 라이선스는 Elastic License 2.0(비경쟁 조항)으로 납품 목적 사용에 문제없습니다.

**Q14. 가이드 문서가 업데이트되면 어떻게 반영하나요?**  
`PUT /guide/documents` API로 파일 업로드 → M2(파싱·청크) → M3(라벨링) → ES 인덱싱이 자동으로 이루어집니다. alias 스왑 방식으로 무중단 재인덱싱을 지원하며, 이전 인덱스는 30일 보관 후 자동 삭제됩니다.

**Q15. 폐쇄망에서 RAG가 동작하나요?**  
네. 모든 모델(KURE-v1 1.2GB, BGE-M3 2.0GB)과 ES가 로컬에 포함되어 있습니다. 폐쇄망 번들(22.8GB)은 docker-images + models + python-deps + es-plugins를 모두 포함하며, 외부 인터넷 없이 `install.sh`만 실행하면 됩니다.

**Q16. 멀티테넌트(기업별 격리)를 어떻게 구현하나요?**  
ES 인덱스 prefix(`tenant_id`), PostgreSQL RLS(Row Level Security), API 미들웨어 tenant 필터 세 층으로 격리합니다. 한 기업의 문서가 다른 기업의 RAG 결과에 노출되지 않도록 설계되었으며, `test_kl_integration.py` S13 시나리오로 격리 검증을 자동화했습니다.

## 카테고리 3: 데이터 파이프라인 (FUN-022·023) — 5문

**Q17. HWP 파일을 처리할 수 있나요?**  
네. LibreOffice headless를 통해 HWP → DOCX → 텍스트 변환을 지원합니다. `python-docx`로 단락·표·각주를 구조화하여 추출하며, 추출 누락률 0%, 품질 0.986(Phase 4 실측)입니다.

**Q18. OCR이 필요한 스캔 PDF는 어떻게 처리하나요?**  
Tesseract OCR(한국어 패키지 포함)로 처리합니다. 텍스트 PDF는 pdfminer.six(BSD-3, AGPL 없음)로 직접 추출하며, 이미지 PDF 감지 시 자동으로 OCR 경로로 전환합니다. 국문·영문 혼용 문서도 지원합니다.

**Q19. 개인정보(PII) 포함 문서는 어떻게 처리하나요?**  
M2 전처리 단계에서 12가지 PII 패턴(주민등록번호, 전화번호, 이메일, 계좌번호 등)을 정규식으로 마스킹합니다. 마스킹된 텍스트가 학습·추론에 사용되며, 원본은 MinIO에 암호화 저장됩니다. 감사 로그에 마스킹 여부가 기록됩니다.

**Q20. 등급 체계가 변경되면 재학습 없이 반영 가능한가요?**  
`PUT /schema/grades` API로 등급 정의를 수정하면, 키워드 시드와 라벨링 로직이 즉시 반영됩니다. 삭제된 등급은 `is_active=False`로 마킹되어 기존 데이터 정합성을 유지합니다. 새 등급 추가 시에는 합성 데이터 생성 후 재학습을 권장합니다.

**Q21. 대용량 문서(1000건 이상)를 일괄 처리할 수 있나요?**  
`POST /classify/async` API로 비동기 배치 처리를 지원합니다. Celery worker가 Redis 큐에서 작업을 소비하며, 진행 상태는 `GET /classify/jobs/{job_id}`로 폴링합니다. 1,000건 기준 처리 시간은 GPU 환경 약 20분, CPU 환경 약 3시간입니다.

## 카테고리 4: 보안·감사·운영 — 5문

**Q22. 분류 이력을 변조할 수 없게 하는 메커니즘이 있나요?**  
SHA-256 해시 체인(audit_chain)을 구현했습니다. 각 분류 결과에 이전 결과의 해시를 포함해 체인을 형성하며, 임의 수정 시 체인이 끊어집니다. 해시값은 감사 로그에 기록되며 PostgreSQL에 저장됩니다.

**Q23. API 키 노출 시 대응 절차는?**  
① Vault/AWS Secrets Manager에서 즉시 키 폐기, ② `LLOYDK_API_KEY` 재발급 후 `.env` 업데이트, ③ gitleaks CI 스캔으로 git history 검사. Runbook §7에 보안 사고 대응 단계별 절차가 문서화되어 있습니다.

**Q24. 장애 발생 시 복구 시간(RTO)은?**  
RTO 4시간, RPO 24시간입니다. PostgreSQL dump(1시간 주기), ES snapshot, MinIO mirror를 자동화했습니다. DR 리허설 스크립트(`dr_drill.py`)를 통해 2026-05-30 1회 실측했으며, PG 복원 확인 완료입니다.

**Q25. OSS 라이선스 문제가 없나요?**  
주요 위험 항목을 모두 해소했습니다. ① PyMuPDF(AGPL) → pdfminer.six(BSD-3)으로 교체 완료. ② MinIO(AGPL) → 납품 목적은 AGPL 허용 범위 내 확인. ③ SBOM(CycloneDX 형식)을 CI에서 자동 생성합니다. 203개 패키지 중 strong(AGPL/GPL) 2개이며, 교체 또는 격리 처리 완료입니다.

**Q26. mTLS 인증을 지원하나요?**  
`--profile mtls` 옵션으로 nginx mTLS 게이트웨이를 활성화합니다. CA 인증서 기반 클라이언트 인증으로 KL 시스템과의 내부 통신을 보호합니다. 개발 인증서 자동 생성 스크립트와 운영 PKI 연동 가이드를 doc/25에 포함했습니다.

## 카테고리 5: 납품·배포·협업 — 4문

**Q27. 폐쇄망 배포 패키지 크기는 어느 정도인가요?**  
22.8GB(LLM 포함) 또는 약 8~10GB(LLM 제외, 분류+RAG만)입니다. Docker 이미지 + 모델 + Python wheel + ES 플러그인을 포함하며, `verify.sh`로 설치 후 자동 검증합니다. USB 또는 내부 미디어로 반입 가능하도록 tar 분할 압축을 지원합니다.

**Q28. KL 시스템과의 연동 방식은?**  
OpenAPI 3.1 기반 REST API(16개 엔드포인트)로 연동합니다. API Key + Rate Limit(30 req/min) + HMAC 서명 검증을 지원하며, Webhook Outbox 패턴으로 콜백 신뢰성을 보장합니다. 8개 통합 시나리오(S1~S8) 자동 테스트를 제공합니다.

**Q29. 발주처 GPU 환경에서 추가 학습은 어떻게 진행하나요?**  
`POST /train` API 또는 `p1_train_classifier.py` 스크립트로 실행합니다. KF-DeBERTa 5,000건 1epoch 기준 33초(RTX 5070 Ti), 약 10분(RTX 3090 예상). MLflow에 실험이 자동 기록되며, 학습 완료 후 `/metrics/latest`로 KPI를 확인할 수 있습니다.

**Q30. PoC 이후 운영 단계로 이행 시 추가 비용은?**  
외부 API(Anthropic/OpenAI) 없이 Qwen3-14B 온프레미스 운영 시 추가 API 비용 0원입니다. 발주처 GPU 인프라 활용 시 인프라 비용도 발생하지 않습니다. 유지보수는 MLflow 대시보드 모니터링 + 연 1~2회 재학습으로 운영됩니다. 합성 데이터 추가 생성이 필요한 경우 Qwen3 온프레미스로 자체 처리 가능합니다.
