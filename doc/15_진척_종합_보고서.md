## 9. W10·W11 신규 기능 상세 (v4 신규 §)

### 9.1 PSH (Performance Scenario Harness) — W10

- **위치**: [`poc/src/lloydk/perf/`](../poc/src/lloydk/perf/) (harness·scenarios·kpis·env)
- **진입점**: [`poc/scripts/run_perf_scenarios.py`](../poc/scripts/run_perf_scenarios.py)
- **목적**: 단위 테스트가 잡지 못하는 **시나리오 단위 KPI**(latency·정확도·throughput·격리·인용 충실도)를 매 PR/main push 시 자동 측정 → CI 게이트
- **시나리오 11종**: S1 분류 동기 · S2 async/batch · S3 confirm/relabel · S4 schema/grades · S5 가이드 RAG · S6 합성 · S7 URGENT_RETRAIN · S8 metrics · S9 적대적 FNR · S11 부하 · S13 멀티 테넌트
- **모드**: dryrun(외부 의존 0·~30초·CI 기본) / full(실 LLM·ES·PG·trained_model 필요)
- **자원 게이팅**: KPI에 `requires=[pg|es|llm|trained_model|...]` 명시 → 미충족 시 자동 SKIP (`AvailableResources.from_env_snapshot()`)

### 9.2 회귀 자동 탐지 — W11

- **위치**: [`poc/src/lloydk/perf/regression.py`](../poc/src/lloydk/perf/regression.py)
- **방식**: `compare=le`(latency·FNR) 증가 또는 `compare=ge`(recall·throughput) 감소가 직전 회차 대비 ≥30% 발생 시 회귀로 판정
- **CI 동작**: `--fail-on-regression` 플래그로 회귀 1건이라도 발견 시 exit 1
- **첫 회차 보호**: 직전 회차 없으면 회귀 비교 비활성 (누적 후부터 작동)
- **JSON 출력**: `reports/perf/perf_{ts}_{sha}.json`의 `regressions` 키에 `{kpi_id, prev, curr, delta_pct, direction}` 배열로 누적

### 9.3 PR 코멘트 자동 게시 — W11

- **위치**: [`.github/workflows/poc-ci.yml`](../.github/workflows/poc-ci.yml) `actions/github-script@v7` 스텝
- **내용**: KPI PASS/FAIL/SKIP 요약 · 회귀 탐지 표 · FAIL KPI 목록 · artifact 다운로드 안내
- **조건**: `github.event_name == 'pull_request'` 자동 발동

### 9.4 GitHub Pages publish — W11

- **위치**: `.github/workflows/poc-ci.yml` `peaceiris/actions-gh-pages@v4` 스텝
- **내용**: main 푸시 시 [doc/20_시나리오_성능_보고서.html](20_시나리오_성능_보고서.html)을 gh-pages 브랜치 `/index.html`로 publish + `/perf/*.json` 누적 동봉
- **조건**: `github.ref == 'refs/heads/main'` 자동 발동
- **URL**: `https://forfre12-ops.github.io/rag/`

### 9.5 Prometheus pushgateway 연동 (선택) — W11

- **위치**: [`poc/src/lloydk/perf/pushgateway.py`](../poc/src/lloydk/perf/pushgateway.py)
- **사용**: `--push-prom http://pushgw:9091` 또는 `PROM_PUSHGATEWAY_URL` 환경변수
- **메트릭**: `lloydk_psh_*` (pass·fail·skip·total·pass_rate·kpi_measured·kpi_threshold·kpi_passed)
- **폐쇄망 호환**: 미가용 시 silent fail · prometheus_client 의존성 없이 stdlib urllib만 사용

### 9.6 doc/11 §8 PSH 운영 절차 (v1.1) — W11

- **30초 1차 행동**: PR 코멘트·GitHub Pages·artifact 3채널 우선순위
- **KPI×모듈 매핑 19종**: S1.1~S18.3 각 KPI에 대해 1차 책임 모듈·디버그 명령 명시
- **회귀 ≥30% 분기**: 비핵심 KPI는 PR 보완 / 핵심 KPI 5종(S1.4 FNR·S1.3 F1·S5.4 Recall@5·S9.2 적대적 FNR·S13.1 교차 노출) 회귀 ≥30% 시 즉시 직전 main commit으로 revert
- **false positive 가이드**: GitHub Actions runner 부하 편차·dryrun 임계 갭(S5.3 등) 식별 + re-run 정책

### 9.7 pyproject extras 정리 — W11

- 신규 `[psh]`·`[evaluation]` 그룹 명시 (matplotlib base 포함) → 시나리오 측정·HTML 렌더 모듈 분리
- 기본 dev 설치만으로 PSH 가동 가능 (CI는 `pip install -e ".[dev]"`만 사용)
